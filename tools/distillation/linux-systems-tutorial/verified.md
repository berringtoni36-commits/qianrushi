# Linux 教程三重验证结果

| ID | 候选 | V1 跨文档 | V2 预测力 | V3 独特性 | 结论 |
|---|---|---|---|---|---|
| l01 | 构建—加载—运行证据链 | GCC、库、Makefile、GDB 四个独立章节 | 可定位“编译成功但运行失败” | 将链接期/加载期明确分开 | 通过 |
| l02 | fd 统一 I/O 模型 | 文件 I/O、重定向、Socket 三个语境 | 可解释管道/Socket/标准流混合故障 | 用生命周期而非 API 清单组织 | 通过 |
| l03 | 消息与就绪分层 | 线程同步、TCP 粘包、select/epoll | 可分析非阻塞服务器短读和竞态 | 把三个经常混淆的层次拆开 | 通过 |
| l04 | 构建故障分阶段原则 | GCC 与动态库章节 | 可设计最小复现证据 | 比“检查编译器”更具体 | 通过 |
| l05 | 最小临界区原则 | 线程同步、线程池、进程通信 | 可分析锁粒度和吞吐权衡 | 将资源边界与锁边界绑定 | 通过 |
| l06 | TCP framing 原则 | TCP 粘包、Socket 读写、并发服务器 | 可处理拆包/合包/半包 | 明确应用协议责任 | 通过 |
| l07 | 就绪不等于消费完成 | select、poll、epoll 和 Socket 读写 | 可定位 EOF/EAGAIN/短读问题 | 纠正常见“有事件=有完整数据”误解 | 通过 |
| l08 | 进程/信号/守护生命周期审计 | 进程控制、信号、守护进程和 IPC 章节 | 可从僵尸、SIGTERM 不退出、守护环境异常或 IPC 残留反推责任链 | 把进程图、信号图、服务图和资源图组合，区分发送/递达/退出/回收 | 通过 |
| l09 | pthread 共享状态与线程池关闭审计 | 多线程、线程同步、C/C++ 线程池章节 | 可从锁环、条件变量误用、worker 不退出和提前 free 反推生命周期缺口 | 将共享不变量、wait-for 图和 join/detach 回收链组合起来 | 通过 |
| l10 | 网络接收路径 IRQ—NAPI—softirq—Socket 证据链 | 软中断、Linux 收发网络包、网络性能指标 + 独立驱动/网络资料 | 可从 NET_RX 高但 overruns 为零、抓包有包而应用超时，推导继续检查 skb、协议栈、四元组、Socket 和应用读取 | 用 Δ硬 IRQ→ΔNET_RX→ΔRX 统计/PPS→tcpdump→Socket Recv-Q→app recv/read 区分接收路径与 TCP 端到端/framing | 通过 |
