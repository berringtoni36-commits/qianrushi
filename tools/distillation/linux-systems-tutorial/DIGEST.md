# 大丙 Linux 教程 — 高密度精华

## 一条主线

Linux 用户态问题可以沿着“源代码 → 构建产物 → 进程资源 → I/O 状态 → 应用协议 → 并发调度”追踪。遇到错误时，先问它发生在构建、加载、资源、数据还是调度哪一层。

## 构建与运行

GCC 教程把编译拆为预处理、编译/优化、汇编和链接。静态库的目标代码在链接阶段被选入最终程序；动态库则需要同时检查链接时的 `-L/-l` 和运行时动态加载器的搜索规则。Makefile 把目标、依赖和命令组织成增量构建图；GDB 用断点、单步、栈和变量把运行期事实补上。最小排查顺序是：命令/版本 → 预处理输出 → 编译诊断 → 符号/链接 → `ldd`/加载器 → GDB 运行证据。

## fd 与并发

文件、管道、终端和 Socket 都可以从 fd 生命周期理解：创建、继承/复制、读写、阻塞/就绪、关闭。`fork` 复制地址空间的逻辑视图，但父子 fd 可能共享底层打开文件状态；所以既要区分内存隔离，也要检查文件偏移和关闭时机。线程同步先找共享资源、读改写临界区和生命周期，再选择互斥锁、读写锁、条件变量或信号量。锁要覆盖完整的状态转移，且不应无谓包住慢 I/O。

## Socket 与多路复用

TCP 是有连接的可靠字节流，UDP 是无连接报文服务；“可靠”不意味着应用层消息边界自动存在。协议要规定消息 framing、半包缓存、关闭和错误语义。select/poll/epoll 的核心不是“自动读数据”，而是等待多个 fd 的就绪事件；事件到达后仍要循环读写并处理 EOF、短读、错误和背压。epoll 将监听集合维护与等待分离，但具体性能取决于连接规模、触发模式、非阻塞策略和用户态处理。

## 不能背过头

- 教程示例中的命令、地址、权限和路径不是当前机器的事实。
- “epoll 没有拷贝”“动态库一定按某顺序搜索”“一次 read 就是一条消息”等绝对说法需要降级为待核对表述。
- Linux 用户态线程模型与 FreeRTOS 任务模型相似处有限；遇到中断/ISR 语境应切换 RTOS Skill。

## 进程、信号与线程关闭

`fork` 是创建进程，`exec` 是替换当前进程映像，`waitpid` 才是父进程回收子进程；`kill` 成功只说明发送动作成功。遇到僵尸、SIGTERM 不退出或 SIGCHLD 漏回收，要画 PID/PPID/PGID/SID、阻塞/未决信号和唯一回收者。

守护化的 `setsid/chdir/umask/dup2` 只改变局部运行环境，不自动提供日志、权限降级、单实例和 supervisor 合同。mmap/System V 共享内存只提供共享位置，释放前要证明所有使用者已退出、detach/munmap 已完成，`IPC_RMID` 是删除标记而非立即清空。

pthread 问题则画共享状态图、wait-for 图和生命周期图：完整保护读改写不变量，用 `while` 重检条件变量谓词，按一致顺序取多把锁；shutdown 必须等待所有 joinable worker 退出或建立 detached worker 的 quiescence 证明，再销毁同步对象和释放队列。
