# 嵌入式知识库蒸馏包使用说明

## 在 ZCode 中使用

这批 Skill 的规范源是 distillation/skills/，唯一活动副本是用户目录 ~/.zcode/skills/。它们只面向 ZCode，不再安装到 Codex、全局 Claude 或 Obsidian Claudian。

使用步骤：

1. 启动 ZCode。
2. 新建会话，或重启 ZCode，使它重新扫描用户级 Skill。
3. 直接用自然语言提问，例如：

   - 帮我排查 FreeRTOS 任务偶尔卡死，DMA 完成但任务没醒。
   - STM32 偶发 HardFault，按源码和配置给我列证据链。
   - 审计这个 eBPF 项目：文档说的和源码实际做的一样吗？
   - 视觉模型输入报 shape 错，检查 HWC/CHW、mask 和路径。
   - 帮我准备这个 RTOS 项目的 1 分钟介绍和技术追问。

如果 ZCode 支持显式 Skill 命令，可以输入：

    /rtos-runtime-fault-diagnosis

完整的自然语言入口见 skill-trigger-index.md；项目学习入口见 嵌入式知识库总索引.md。

## 推荐学习顺序

1. embedded-core：C/C++ 生命周期、存储/链接、通信总线和 ARM Linux 启动。
2. rtos-project：任务、ISR、同步、传感器、电机闭环和 IAP。
3. linux-memory-ebpf：eBPF 链路、Map、伙伴系统和源码审计。
4. linux-vision：视觉输入、模型推理、性能优化和项目真实性。
5. linux-systems-tutorial：构建、文件描述符、进程线程和 Socket。
6. leetcode-algorithm-learning：题型选择、状态推导和主动回忆。
7. workbench-learning-state：学习状态、来源映射和复习队列。

各知识域的 BOOK_OVERVIEW.md 说明范围和事实边界，DIGEST.md 适合快速复习，GLOSSARY.md 适合查术语，source-map.md 用来追溯结论。

## 如何更新

从 Obsidian Vault 根目录运行：

    python3 distillation/scripts/sync_zcode_skills.py --dry-run --allow-conflicts
    python3 distillation/scripts/sync_zcode_skills.py --allow-conflicts

ZCode 专用同步器只复制缺失目录，不覆盖已有活动副本。旧的 distillation/scripts/sync_skills.py 已停用，避免误把 Skill 安装到其他客户端。

完整回归：

    python3 distillation/scripts/run_regression.py

只检查已有产物：

    python3 distillation/scripts/run_regression.py --check-only

审计报告会检查：

- 原始来源是否仍被排除在派生目录之外。
- 56 个规范 Skill 是否包含 R/I/A1/A2/E/B、来源和测试合同。
- ZCode 活动副本是否完整。
- 相对链接、来源新鲜度、项目 provenance 和工作台状态是否一致。

## 项目和源码审计

代码、配置和文档可以支持静态事实，但不能自动证明构建、烧录、启动、硬件运行或真实性能。遇到项目问题时：

1. 先从各域 source-map.md 找到文档和源码。
2. 用函数、宏、配置项或模型输入输出符号核对控制流和数据流。
3. 把结论分为源码事实、文档设计意图、推断/风险和硬件/运行实测。
4. 没有证据的个人贡献、性能数字和可靠性不要补写。

## 作用域边界

这批 Skill 已从 Codex、全局 Claude 和 Obsidian Claudian 的活动发现目录中移除；ZCode 使用的唯一活动位置是用户级 ~/.zcode/skills/。用户原有的非蒸馏 Skill 不受影响。

静态测试 6/6 只表示结构化测试清单完整，不等于 ZCode 新会话真实命中率。真实验证应使用每个 Skill 的 test-prompts.json，分别测试正例、诱饵和边界。
