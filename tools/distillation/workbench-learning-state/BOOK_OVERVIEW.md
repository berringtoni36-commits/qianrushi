# 学习工作台 — 全局理解

## 基本信息

- 类型：嵌入式学习状态、来源指针和复习入口的管理层，不是新的技术知识源。
- 原始范围：`工作台/`，包括 360 条条目记录、学习总账、学习日志、项目快刷、资料地图和 Bases 配置。
- 派生范围：`records.tsv`、`STATUS_AUDIT.md`、`source-map.md` 以及本域的摘要、验证和候选审计。
- 派生复习入口：`REVIEW_QUEUE.md`；它是基于状态字段的建议排序，不是掌握度测量。
- 处理边界：不复制答案，不推断真实掌握，不自动修改原始记录。

## 1. 结构

工作台由四层组成：

1. **状态记录层**：每个条目用 `mastery`、`review_flag`、`last_studied` 保存学习证据。
2. **来源指针层**：`source` 链回原始八股、项目题组、章节或文章；条目正文不替代主源。
3. **统计入口层**：`八股进度.base` 按主线、模块、项目和状态筛选，不改变记录事实。
4. **复习闭环层**：`学习日志.md` 只追加真实学习；`学习总账.md` 和 `项目快刷.md` 解释口径与入口。

主线规模为：150 题 150 条、项目八股 81 条、小林系统 35 条、小林网络 39 条、杂七杂八 14 条、大丙 Linux 41 条，共 360 条。

## 2. 核心状态语义

| 状态 | 允许推断 | 不允许推断 |
|---|---|---|
| `未学` | 当前记录没有正式处理声明 | 不代表完全没有接触过相关知识 |
| `学过` | 用户记录为看过 | 不代表能脱稿复述、能写代码或掌握 |
| `掌握` | 用户记录为能脱稿解释并应对基本追问 | 仍不代表硬件实测、项目源码贡献或永久不遗忘 |
| `待回看` | 当前条目被列入回看队列 | 不代表一定遗忘，也不代表未学 |
| `已回看` | 已完成一次记录层面的回看标记 | 不代表回看质量或掌握等级自动提升 |

`mastery` 与 `review_flag` 是正交维度：一个条目可以“掌握但待回看”，也可以“学过且已回看”。

## 3. 解释框架

工作台解决的不是“答案是什么”，而是四个管理问题：

- 我有哪些学习单元，分别来自哪里？
- 我声明自己处于什么状态，这个状态的证据边界是什么？
- 下一次应该优先回忆哪些条目，为什么？
- 回看之后，什么行为证据足以升级状态？

因此推荐的操作顺序是：先审计记录完整性 → 再按状态和风险排序 → 回到原始来源 → 进行无提示口述/代码或项目追问 → 记录真实结果 → 最后由用户决定是否更新原记录。

## 4. 批判与限制

- 当前 360 条记录全部为 `待回看`，其中 307 条标为 `学过`、53 条标为 `未学`、0 条标为 `掌握`；这是当前文件中的声明快照，不是模型对学习效果的测量。
- 条目标题、模块和来源链接可审计，但不能证明用户实际完成过对应学习。
- 同一主源可以被多条记录引用，例如 150 题主源对应 150 个题目；这不是重复知识结论。
- `last_studied` 为空时不能用文件修改时间、审计时间或排序位置冒充学习日期。
- 工作台管理 Skill 不替代算法题推导、FreeRTOS 排障或项目源码审计 Skill。

## 5. 可迁移方法论

本域唯一适合独立 Skill 化的单元是：**以来源可追溯性为前提，用正交状态记录和行为证据驱动嵌入式学习复习**。它可以输出审计报告、复习优先级和一次主动回忆会话，但不代替技术答案，也不代替用户确认状态。
