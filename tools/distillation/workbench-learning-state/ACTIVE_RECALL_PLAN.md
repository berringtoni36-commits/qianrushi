# 工作台 360 条主动回忆复习计划

审计日期：2026-08-14

> 本文件和 [`review-queue.tsv`](review-queue.tsv) 都是 `工作台/` 的派生复习入口。它们只决定“先复习什么、如何取证、何时建议重新排队”，不复制答案、不回写原始条目，也不证明学习者真实掌握。

## 1. 状态边界与当前快照

当前队列覆盖 360 条记录，按主线为：150题 150 条、项目八股 81 条、小林系统 35 条、小林网络 39 条、杂七杂八 14 条、大丙Linux 41 条。

| 当前记录字段 | 条数 | 只能怎样解释 |
|---|---:|---|
| `mastery=学过` | 307 | 原记录声明“看过，但不能稳定复述或解释”；不是会答率。 |
| `mastery=未学` | 53 | 原记录声明尚未正式处理；不是能力评分。 |
| `mastery=掌握` | 0 | 当前没有条目被记录为掌握；不能据此推断真实掌握率。 |
| `review_flag=待回看` | 360 | 当前都需要进入回忆队列；与 `mastery` 正交。 |
| `source_exists=yes` | 360 | `source_target` 文件均存在；不证明原文正确或学习者读过。 |

`records.tsv` 的表头第 9 列虽然叫 `last_studied`，当前值实际是 `order: N` 排序信息；原始条目的 `last_studied` 仍为空。因此本计划不把它当日期，也不生成预计日期。只有真实发生复习后，才由用户按原工作台规则填写实际日期并追加学习日志。

力扣是独立可选系统，见 [`工作台/力扣入口.md`](力扣入口.md)，不进入这 360 条队列；项目入口见 [`工作台/项目快刷.md`](项目快刷.md)。

## 2. 分层与队列顺序

`review-queue.tsv` 每行对应一条原始工作台记录，`queue_rank` 只表达建议顺序，不表达能力排序。先按层，再按项目/主线入口顺序和原记录 `order` 排列，保证项目题的 A0、Q01 等不会被词典序打乱。

| 层 | 覆盖记录 | 进入条件 | 抽样与轮换规则 |
|---|---:|---|---|
| `T1-project` | 项目八股 81 | `学过 + 待回看`，且需要项目、源码和个人贡献证据 | 每个项目复习轮次从 RTOS、Linux视觉、Linux物理内存三个分层各抽至少 1 条；失败项在下一轮优先重抽，未抽项按 `order` 轮换。 |
| `T2-150` | 150题 150 | `学过 + 待回看` 的核心嵌入式题 | 按 C/C++、STM32、通信、FreeRTOS、Linux 五个模块分层轮换；每轮让已选模块都有代表，具体样本量由用户决定。 |
| `T3-studied-supplement` | 小林系统 35、大丙Linux 41 | `学过 + 待回看` 的系统与 Linux 补充材料 | 按主线/模块轮换；连续两轮不重复同一小批，优先补齐未抽模块，再回到已抽模块做迁移题。 |
| `T4-unlearned` | 小林网络 39、杂七杂八 14 | `未学 + 待回看`，在前三层需要理解或当前目标相关时进入 | 每轮从两个主线各抽样，再回到 `source_target` 阅读；未完成真实阅读前不评价掌握，不把阅读完成当作 `学过`。 |

这些是分层抽样规则，不是每日配额、倒计时或客户端任务。`1/7/30` 等相对间隔只在实际复习发生后作为建议：独立通过可在下一次、较长一次和更长一次真实复习中抽查；提示后或失败则回到下一可用轮次。不要预先把这些间隔写进 `last_studied`。

## 3. 一条记录的主动回忆闭环

每次只打开队列行里的记录文件和 `source_link` 定位，不先看答案：

1. **定位**：先读标题、`record_file` 和 `source_target`，确认问题所属主线/模块；项目题先打开 [`工作台/项目快刷.md`](项目快刷.md) 对应主源。
2. **独立回答**：脱稿回答“是什么、机制/因果、如何验证或观测、边界/反例”。章节或文章也要给出一个可检验的关系，不以复述标题算完成。
3. **最小提示**：卡住时只给一个关键词、一个来源位置或一个符号，再让学习者重新组织；不直接展示整段答案。
4. **迁移追问**：换一个没有在题目标题中原样出现的场景，检查能否把机制迁移到 RTOS、Linux、通信、视觉或实际调试条件。
5. **留证**：记录本次是独立完成、提示后完成、仍不稳定，及缺失的回答维度。项目题还要写出原始源码路径/符号、仓库事实与个人贡献的边界；没有个人证据时只能标为设计理解或待核对。

### 最小回答证据

| 证据标签 | 要求 | 能否单独支持 `掌握` 建议 |
|---|---|---|
| `independent` | 首次无提示覆盖定义、机制、验证、边界 | 还需要迁移追问；项目题还需要来源符号与贡献边界。 |
| `hinted` | 只在一个最小提示后完成 | 不能；保留 `学过`，继续待回看。 |
| `incomplete` | 只能说出名词、结论或局部步骤 | 不能；记录具体缺口，不代填状态。 |
| `transfer` | 能处理一个变式、反例或新场景 | 与独立回答合并后才构成较强证据。 |
| `source-symbol` | 项目题能指出原始文件、函数/符号或可核验位置 | 只能证明来源定位；不能替代个人贡献证明。 |
| `user-confirmed` | 学习者确认这次真实表现及是否调整状态 | 状态更新的必要确认，不由审计或模型代替。 |

## 4. 状态更新规则

本计划只提出建议；除非用户明确授权，不修改 `工作台/条目记录/`、`工作台/学习日志.md` 或全局状态。

| 当前状态 | 实际证据 | 建议处理 |
|---|---|---|
| `未学` | 没有真实阅读/回答 | 保持 `未学`；继续留在 T4。 |
| `未学` | 真实阅读后能说出核心关系，但尚不能稳定追问 | 可由用户确认改为 `学过`；不能直接改为 `掌握`。 |
| `学过` | 独立覆盖四维回答并完成迁移；项目题补齐来源符号和贡献边界 | 向用户建议 `掌握`，只有用户确认后才可改；若仍需巩固，保持 `学过`。 |
| `学过` | 提示后完成、只完成局部或迁移失败 | 保持 `学过`、`review_flag=待回看`，把缺口作为下一次提示入口。 |
| 任意状态 | 真实复习/学习已经发生 | 由用户填写真实 `last_studied` 并追加日志；审计时间、文件修改时间和计划日期都不能代替它。 |
| `掌握` | 新变式暴露薄弱点 | 不自动降级；可由用户保留 `掌握` 声明并把 `review_flag` 改回 `待回看`，或按实际证据调整。 |

一次回答完成但仍不稳定时，`review_flag` 可以继续是 `待回看`；它表示“是否需要继续复习”，不是“是否曾经打开过来源”。只有真实复习完成且学习者认为暂时不需回看时，才建议标记 `已回看`。

## 5. 来源、事实与复核边界

- 队列的 `source_link`/`source_target` 是原始笔记、项目题组、章节或文章的定位，不是新答案源。
- 项目题必须把原始文档事实、源码事实、学习者自述和推断分开；工作台记录本身不能证明个人负责过某段代码。
- 来源存在只证明路径可达；231 条带锚点的来源已逐字核对标题，129 条整篇链接不需要锚点。内容正确性和实测结果仍需回到原始资料或专项 Skill。
- 需要具体 RTOS、Linux、视觉、eBPF 或算法技术解答时，转对应专项 Skill；本域只管理选择、回忆证据和状态建议。

执行入口：先按本文件的层规则取样，再打开 [`review-queue.tsv`](review-queue.tsv) 对应行；完成真实回忆后由学习者决定是否回写原始状态。
