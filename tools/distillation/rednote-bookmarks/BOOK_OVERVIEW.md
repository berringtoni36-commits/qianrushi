# RedNote 收藏 — 外部参考域整体理解

## 基本信息

- 类型：从 Obsidian 导入的小红书收藏、专辑索引和图片/视频附件。
- 角色：外部观察材料，不是用户原创经历，也不是嵌入式项目主源。
- 当前边界：以当前审计生成的 `source-inventory-current.tsv` 为准；媒体只作为证据层。
- 主要用途：补充嵌入式求职、八股复习、项目面试表达、AI/Obsidian 工作流和工具安全观察。

## 内容骨架

1. **嵌入式学习与求职参考**：C/MCU、RTOS、通信、Linux/驱动、机器人方向和投递节奏的个人经验。
2. **面试与简历方法**：先搭知识框架、口述输出、项目追问、经历采集、录音复盘和事实边界。
3. **AI/Skill/Obsidian 工具观察**：第三方对 Skill、Agent、Obsidian 插件和远程开发工具的推荐或评价。
4. **招聘与薪资外部信息**：岗位广告、行业判断、实习/校招个案和样本报告。
5. **非本领域收藏**：健康、Mac、普通效率和教育史等，只归档，不进入嵌入式知识主线。

## 可复用方法论

- 用“知识框架 → 口述输出 → 错题/面试复盘 → 项目映射 → 间隔复习”构造学习闭环。
- 用“岗位要求 → 项目证据 → 可追问细节 → 不能宣称的内容”检查简历和面试回答。
- 把录音、转写、问答、弱点和改进记录放进可追踪的知识库，避免只留在聊天窗口。
- 对第三方 Skill 的 Star、安装量、成本下降、安全性和功能描述先做来源与版本核验。

## 批判与事实边界

- 帖子中的“亲测”“上岸”“进面率”“薪资”“节省比例”和工具功能均属于作者叙述；除非有独立数据、仓库、版本或原始实验记录支撑，不升级为市场事实。
- 别人的学习路线和项目经验不能写成用户经历；用户自己的项目事实仍以 vault 项目文档、源码、构建和实测记录为准。
- 帖子图片、视频和专辑索引是导出/附件层，不与 Markdown 正文重复计数。
- RedNote 内容变化快，职业市场、工具版本、安装量和价格需要在使用时重新核验。

## 不生成规范 Skill 的原因

本域没有通过“跨文档事实 + 可执行独特方法 + 用户自身案例”的完整条件来生成独立 Skill。它更适合做外部参考索引，并与已有的 `embedded-interview-layered-answer`、`rtos-project-storytelling`、`algorithm-active-recall-loop` 和来源审计 Skill 组合使用。
