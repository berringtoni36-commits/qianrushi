## Linux 教程

### G-L01 CMake 配置与构建目录隔离

- 原则/清单：用 `cmake -S <source> -B <build>` 明确源目录与构建目录；排障时把配置、生成和编译分成三个阶段，分别记录命令、生成器、缓存和首个错误。不要在源码目录里用残留缓存掩盖配置变化。
- 来源：`archive/大丙Linux教程/番外/03 CMake 保姆级教程（上）.md`；`archive/大丙Linux教程/番外/04 CMake 保姆级教程（下）.md`。
- 适用边界：具体 CMake 版本、生成器、工具链文件和工程目录策略仍需目标项目验证；该规则不替代已有 Linux 构建链 Skill 的全链路诊断。
- V1/V2/V3 初判：高 / 高 / 中高。

### G-L02 CMake 依赖必须目标化，链接期与运行期分开

- 原则/清单：优先使用 `target_link_libraries(... PRIVATE/PUBLIC/INTERFACE)` 和目标级 include/compile 属性；`link_directories` 只影响链接搜索，不能证明运行时能找到共享库；运行期还要核对 RPATH/RUNPATH、动态加载器缓存和部署目录。
- 来源：`archive/大丙Linux教程/番外/03 CMake 保姆级教程（上）.md`；`archive/大丙Linux教程/番外/04 CMake 保姆级教程（下）.md`。
- 适用边界：这是已有 `linux-build-debug-chain` 的补充候选/暂缓升格；具体库发现方式、RPATH 安全策略和跨平台行为需按目标工程确认。
- V1/V2/V3 初判：高 / 高 / 中。

### G-L03 CMake 源文件发现不能掩盖增量构建缺口

- 原则/清单：优先维护显式源文件列表；使用 `GLOB` 时必须确认新增文件是否会触发重新配置，必要时使用 `CONFIGURE_DEPENDS`，并用一次“新增源文件后直接构建”的实验验证增量行为。构建成功不等于新文件已进入目标。
- 来源：`archive/大丙Linux教程/番外/03 CMake 保姆级教程（上）.md`。
- 适用边界：小型教学工程与大型工程在维护成本上的取舍不同；具体生成器对重新配置的行为要实测。
- V1/V2/V3 初判：中高 / 高 / 高。

### G-L04 `find`、`grep`、`locate` 按证据类型选择

- 原则/清单：文件属性、路径和时间用 `find`；文件内容用 `grep`；`locate` 只作快速候选，结果必须考虑数据库陈旧。批量处理优先 `-exec ... {} +` 或 `-print0 | xargs -0`；删除前先预览目标并使用交互确认或更窄条件。
- 来源：`archive/大丙Linux教程/第1章 Linux 基础/05 查找命令.md`。
- 适用边界：选项、权限模型、命令实现和安全策略依发行版；涉及删除、跨挂载点或特殊文件时需额外限制范围。
- V1/V2/V3 初判：高 / 高 / 高。

### G-L05 目录遍历必须区分 EOF、错误和未知类型

- 原则/清单：`readdir()` 返回 `NULL` 后检查 `errno`，区分正常结束和读取错误；跳过 `.`/`..`；遇到 `DT_UNKNOWN` 时回退到 `stat`/`lstat`/`fstatat`；无论中途错误与否都保证 `closedir()`，并检查路径拼接和缓冲区边界。
- 来源：`archive/大丙Linux教程/第2章 文件IO/05 目录的遍历.md`；`archive/大丙Linux教程/第2章 文件IO/03 文件状态和属性信息.md`。
- 适用边界：符号链接、挂载点、权限变化和循环目录需要调用方定义跟随/不跟随和去重策略；网络文件系统的目录一致性不能由该规则保证。
- V1/V2/V3 初判：高 / 高 / 高。

### G-L06 权限排障要同时看用户、环境和授权来源

- 原则/清单：先确认当前 UID、组和工作目录；区分 `su` 与 `su -` 带来的环境和路径差异。修改 sudo 权限使用 `visudo` 或 `/etc/sudoers.d/`，按发行版加入 `sudo`/`wheel` 组，不把 sudoers 权限改成 777；重新登录后用 `sudo -l` 验证实际授权。
- 来源：`archive/大丙Linux教程/第1章 Linux 基础/03 用户管理命令.md`；`archive/大丙Linux教程/番外/01 普通用户添加 sudo 权限.md`。
- 适用边界：发行版组名、PAM、sudo 默认环境和企业授权插件不同；容器、远程会话和 systemd 服务的身份环境要单独核对。
- V1/V2/V3 初判：高 / 高 / 高。

### G-L07 `stat`/`lstat` 与符号链接的对象身份必须明确

- 原则/清单：先决定要检查链接本身还是链接目标，再选择 `lstat` 或 `stat`；排障记录 inode、硬链接计数、权限、文件类型以及 atime/mtime/ctime 的语义，不能只凭扩展名或文件名判断类型。遇到“文件存在但打不开”时同时核对目标解析和权限链路。
- 来源：`archive/大丙Linux教程/第2章 文件IO/03 文件状态和属性信息.md`。
- 适用边界：时间戳更新时机受访问模式、挂载选项和文件系统影响；竞态敏感场景应使用基于 fd 的接口，不能把路径检查当作安全授权。
- V1/V2/V3 初判：高 / 中高 / 高。

### G-L08 TCP 状态、半关闭和端口复用分开排障（补充候选/暂缓升格）

- 原则/清单：用 `ss`/`netstat` 对照连接四元组和状态；`TIME_WAIT` 不等于进程仍在运行。需要方向性关闭时使用 `shutdown()` 并验证对端 EOF/错误语义，不把 `close()` 当成单向关闭；需要地址复用时在 `bind()` 前按场景设置 `SO_REUSEADDR`，再验证实际绑定结果。
- 来源：`archive/大丙Linux教程/第4章 套接字通信/02 三次握手、四次挥手.md`；`archive/大丙Linux教程/第4章 套接字通信/03 TCP状态转换.md`；`archive/大丙Linux教程/第4章 套接字通信/06 套接字通信类的封装.md`。
- 适用边界：与现有 `linux-socket-multiplexing-design`、`linux-tcp-loss-path-diagnosis` 有交集，保留为状态/半关闭/复用的补充切面；状态持续时间和复用行为依内核、地址族与套接字组合。
- V1/V2/V3 初判：高 / 高 / 中高。

## 小林图解与系统八股

### G-S01 CPU 缓存优化必须从访问模式和实测开始

- 原则/清单：先根据数据布局和访问顺序识别连续访问、跨步访问、局部性和可能的 cache line 争用，再选择循环重排、数据布局、分支整理或 CPU 亲和性；每项优化都用 benchmark/perf 对照基线，不能由“更接近硬件”直接推出收益。
- 来源：`projects/嵌入式八股/2. 小林图解/图解系统/02｜硬件结构篇/2.3 如何写出让 CPU 跑得更快的代码？.md`。
- 适用边界：缓存层级、cache line、分支预测、NUMA 和调度器行为依架构与内核；微基准收益不能直接外推到端到端业务。
- V1/V2/V3 初判：中高 / 高 / 中高。

### G-S02 网络接收故障沿 NAPI、软中断和 RingBuffer 路径检查

- 原则/清单：遇到 RX drops、overruns 或 softirq 占比异常，依次核对网卡 RingBuffer、驱动/NAPI poll、软中断分布、协议栈/Socket 队列和应用读取速度；对照网卡、内核和应用侧计数器，不能看到“TCP 丢包”就直接归因于 TCP。
- 来源：`projects/嵌入式八股/2. 小林图解/图解系统/02｜硬件结构篇/2.6 什么是软中断？.md`；`projects/嵌入式八股/2. 小林图解/图解系统/99｜附录/Linux 系统是如何收发网络包的？.md`；`projects/嵌入式八股/2. 小林图解/图解系统/10｜Linux 命令篇/10.1 如何查看网络的性能指标？.md`。
- 适用边界：网卡驱动、内核版本、虚拟化层和统计字段不同；已有 TCP 丢包规范 Skill 覆盖传输路径，本条强调接收路径的分层证据。
- V1/V2/V3 初判：高 / 高 / 高。

### G-S03 Reactor/Proactor 按“就绪/完成”语义与平台选择（补充候选/暂缓升格）

- 原则/清单：先确认通知的是“现在可以进行 I/O”还是“异步操作已经完成”；Reactor 收到事件后应用仍需正确处理 `read`/`write`、短 I/O 和错误，Proactor 则要求核实平台真正提供的完成通知语义。无论模型如何，不能把 epoll 事件当作完整消息。
- 来源：`projects/嵌入式八股/2. 小林图解/图解系统/09｜网络系统篇/9.2 I／O 多路复用：select／poll／epoll.md`；`projects/嵌入式八股/2. 小林图解/图解系统/09｜网络系统篇/9.3 高性能网络模式：Reactor 和 Proactor.md`。
- 适用边界：与现有 `linux-socket-multiplexing-design` 有明显交集，暂不独立升格；具体完成队列、线程模型、边沿/水平触发行为必须按平台和实现核实。
- V1/V2/V3 初判：高 / 高 / 中。

### G-S04 “零拷贝”必须核对真实拷贝边界

- 原则/清单：画出用户态、Socket 缓冲、协议栈、驱动、DMA 和目标设备之间的数据路径，逐段标明复制、映射和校验；API 名称或宣传语不等于零拷贝，必须用 CPU、内存带宽、系统调用和端到端吞吐数据验证收益。
- 来源：`projects/嵌入式八股/2. 小林图解/图解系统/09｜网络系统篇/9.1 什么是零拷贝？.md`；`projects/嵌入式八股/2. 小林图解/图解系统/99｜附录/Linux 系统是如何收发网络包的？.md`。

## RTOS 入门、环境与模块

### G-R01 RTOS 构建可复现性由“工程配置合同”决定

- 原则/清单：构建排障同时核对 `.uvprojx`、芯片与 Pack、ARMCC 版本、宏定义、IncludePath、startup/port、IROM/IRAM、HEX/AXF/MAP；不能只看源码目录或“能打开工程”就认定配置一致。对发布物以 MAP、链接地址和产物哈希复核。
- 来源：`projects/RTOS项目/文档/1 入门指南/1.1 项目概述：STM32 + FreeRTOS 油烟机控制系统.md`；`projects/RTOS项目/文档/1 入门指南/1.2 快速入门：从零搭建开发环境并运行项目.md`；`projects/RTOS项目/文档/1 入门指南/1.3 开发环境配置/1.3.1 Keil MDK 工程配置与编译.md`；`projects/RTOS项目/文档/2 系统架构与设计/2.2 目录结构与模块职责划分.md`。
- 适用边界：文档中的 STM32F103C8/C8T6、64 KB/20 KB 等项目化声明需以工程文件、链接脚本和 MAP 为准；不同 Keil、编译器和 Pack 不能直接互换。
- V1/V2/V3 初判：高 / 高 / 高。

### G-R02 J-Link 烧录排障按“连接—算法—地址—向量—运行”分层

- 原则/清单：先查 SWDIO/SWCLK/GND/供电/BOOT0，再查 Flash algorithm 和擦除范围；随后核对 `0x08000000` 或实际 APP 地址、向量表、栈顶、Reset & Run。日常开发避免误用整片擦除，并保留可恢复的擦除/下载日志。
- 来源：`projects/RTOS项目/文档/1 入门指南/1.3 开发环境配置/1.3.2 J-Link 调试器配置与烧录.md`。
- 适用边界：仓库没有实际独立 APP 链接工程；`0x0800F000` 只能作为条件性 IAP 规划，不能据此断言当前固件布局。
- V1/V2/V3 初判：高 / 高 / 高。

### G-R03 串口调试与 IAP 传输要分成两个合同

- 原则/清单：无串口输出先核对 TX/RX、115200-8-N-1、DEBUG 宏、USB-TTL 电平和复位状态；升级失败再核对二进制文件、CRC、固定 `buff_size`、DMA 通道和发送方式。不能把终端粘贴文本当作文件传输，也不能用“串口能打印”证明 IAP 协议正确。
- 来源：`projects/RTOS项目/文档/1 入门指南/1.3 开发环境配置/1.3.3 串口调试工具使用.md`；`projects/RTOS项目/文档/1 入门指南/1.2 快速入门：从零搭建开发环境并运行项目.md`。
- 适用边界：当前项目文档默认 `ifopen=0`；串口 ISP 与项目 IAP 协议是不同合同，DMA、帧格式和校验字段需以实际源码为准。
- V1/V2/V3 初判：高 / 高 / 高。

### G-R04 新模块接入必须同时完成“目录—工程—接口—初始化—测试”

- 原则/清单：BSP 模块保持单一职责；新增 `.c/.h` 后同步更新 IncludePath、工程分组和编译宏，明确初始化顺序、上层接口、资源所有权与调试开关，并至少完成一次编译、启动和接口测试。文件放进目录不等于模块已经接入。
- 来源：`projects/RTOS项目/文档/2 系统架构与设计/2.2 目录结构与模块职责划分.md`；`projects/RTOS项目/文档/1 入门指南/1.3 开发环境配置/1.3.1 Keil MDK 工程配置与编译.md`。
- 适用边界：适用于本项目的 Keil/BSP 分层；其他构建系统的工程注册方式不同，但仍需完成等价的编译、初始化和接口验证。
- V1/V2/V3 初判：高 / 高 / 高。

### G-R05 调试暂停会改变 RTOS/定时器时序

- 原则/清单：断点暂停时确认 SysTick、TIM、DMA 和外设事件是否继续运行；恢复后若出现事件积压、超时突发或周期跳变，检查 DBGMCU 定时器停止位和调试配置。不要随意停止 SysTick 后再用断点行为推断正常调度。
- 来源：`projects/RTOS项目/文档/1 入门指南/1.3 开发环境配置/1.3.2 J-Link 调试器配置与烧录.md`。
- 适用边界：暂停行为与调试器、芯片型号、外设和 DBGMCU 配置相关；本条是时序审计候选，不替代已有 RTOS 运行时故障 Skill。
- V1/V2/V3 初判：高 / 高 / 高。

## 视觉 Qt、LIME 与模型

### G-V01 Qt 槽函数不得阻塞主事件循环

- 原则/清单：按钮槽中禁止用 `waitKey(10000)`、长轮询或同步等待外部推理；使用 `QProcess::finished`/`error`/`readyRead`、QTimer 或 watcher 驱动状态机，并为超时、取消、重复启动和异常退出定义状态。
- 来源：`projects/linux视觉感知项目/文档/02 Qt 上位机/2.2 信号槽机制与交互.md`；`projects/linux视觉感知项目/文档/02 Qt 上位机/2.3 QProcess 进程管理.md`。
- 适用边界：文件 IPC 的路径、编号和完成标记属于已有 `linux-vision-file-ipc-lifecycle-audit` 边界；本条聚焦 Qt 事件循环和异步生命周期。
- V1/V2/V3 初判：高 / 高 / 中高。

### G-V02 Qt 信号槽必须审计自动绑定与手动绑定的重复

- 原则/清单：`connectSlotsByName` 与显式 `connect()` 不要同时绑定同一动作；动态连接采用“先 disconnect 再 connect”或明确唯一连接策略。出现一次点击多次执行时，先检查连接数量、对象生命周期和重复初始化，再怀疑摄像头或模型。
- 来源：`projects/linux视觉感知项目/文档/02 Qt 上位机/2.2 信号槽机制与交互.md`。
- 适用边界：具体连接类型、线程归属、Queued/Direct 语义和 Qt 版本需核对源码；本条不覆盖完整进程间文件协议。
- V1/V2/V3 初判：高 / 高 / 高。

### G-V03 Mat→QImage 转换要核对颜色、stride 与生命周期

### G-A01 数组/矩阵先按操作类型选工具

- 原则/清单：频繁区间求和优先前缀和；区间增量优先差分；有原地空间约束时考虑标记位或边界复用；矩阵遍历先写空矩阵、边界收缩和访问顺序不变量，再编码。选择工具前先明确查询与更新的主操作。
- 来源：`archive/力扣刷题/02-Wiki/专题总结/03-数组与矩阵.md`；`archive/力扣刷题/03-学习笔记/Day03-数组与矩阵.md`。

### G-A02 链表先固定指针角色和边界

- 原则/清单：删除、合并和头节点可能变化时优先 dummy；判环、中点、倒数节点用快慢指针并先定义相遇/步数条件；翻转明确 `pre`/`cur`/`nxt`；分段归并前断开链。先画出空链、单节点和尾节点，再改指针。
- 来源：`archive/力扣刷题/02-Wiki/专题总结/04-链表.md`；`archive/力扣刷题/03-学习笔记/Day04-链表基础.md`；`archive/力扣刷题/03-学习笔记/Day05-链表进阶.md`。

### G-A03 二叉树遍历顺序由“需要的信息出现时机”决定

- 原则/清单：前序用于构造、复制和翻转；中序利用 BST 有序性质；后序用于子树聚合、深度和直径；BFS 用于层级与最短层数。明确函数返回值与全局答案的职责，避免在错误遍历时机读取尚未完成的子树信息。
- 来源：`archive/力扣刷题/02-Wiki/专题总结/05-二叉树.md`；`archive/力扣刷题/03-学习笔记/Day06-二叉树基础.md`。
- 适用边界：递归深度可能导致栈限制，超深树需迭代；“中序有序”只对满足 BST 约束的树成立，不能推广到任意二叉树。
- V1/V2/V3 初判：高 / 高 / 高。

### G-A04 网格/图问题先判断“传播、连通还是依赖”

- 原则/清单：连通块用 DFS/BFS 标记；多源扩散时间用多源 BFS 分层；依赖关系用拓扑排序和入度更新。每次入队/出队都明确 `visited` 的写入时机，拓扑过程记录入度减一和新入队节点，避免重复访问或漏更新。
- 来源：`archive/力扣刷题/03-学习笔记/Day08-图论与栈.md`；`archive/力扣刷题/02-Wiki/专题总结/07-图论.md`。
- 适用边界：图是否有向、是否带权、是否允许重复边会改变算法；带权最短路不能用普通 BFS 替代，拓扑排序只适用于有向无环依赖。

### G-A05 单调栈与堆按输出关系选择

- 原则/清单：下一个更大/更小元素和最近边界优先单调栈；Top-K、动态中位数和持续取极值用堆或双堆。每次 push/pop 都写出栈序不变量；堆删除或滑窗场景要定义过期元素的识别和清理策略。
