# LeetCode Hot 100 学习体系 — 全局理解

## 基本信息

- 内容类型：C++17 Hot 100 题单、专题模板、逐题讲解、14 天学习笔记和 AI 教练操作手册。
- 来源：`archive/力扣刷题/` 140 个知识文档及其配置；`acwing/算法基础课模板大全-C++版本.pdf` 是独立算法模板证据。
- 处理原则：题目详解是案例库；Skill 抽取可迁移的识别、推导和复习方法，不为 100 多道题各造一个 Skill。

## 1. 结构

一句话主旨：用题型框架降低新题识别成本，用系统化拆题和主动回忆把“看懂题解”推进到“独立实现并能迁移”。

五个一级主题：

1. 题型地图：哈希、双指针/滑窗、数组矩阵、链表、树、图、栈堆、回溯、二分、DP、贪心和技巧。
2. 框架识别：先判断数据结构、状态、单调性、窗口条件、递归关系或可行性边界，再选模板。
3. 推导与实现：用不变量、状态定义、转移、边界、复杂度和代码模板完成闭环。
4. 复习反馈：独立思考、提示后 AC、独立 AC、无提示重写，配合学习日志和进度看板。
5. 三种体系融合：labuladong 偏框架，代码随想录偏专题和步骤，灵茶山艾府偏题单/难度心流；本仓库采用组合而非全盘照搬。

关系是递进的：题单提供覆盖，框架负责识别，推导负责正确性，主动回忆负责长期掌握。

## 2. 解释

| 术语 | 本域用法 | 关键区别 |
|---|---|---|
| 框架 | 能覆盖一类题目的结构和模板 | 不等于背某道题代码 |
| 五步法 | 学模板→读题→独立思考→编码→总结 | 题解阅读不是完成 |
| 不变量 | 循环/递归过程中始终成立的条件 | 是证明指针、二分和窗口正确性的工具 |
| 状态定义 | DP/搜索中一个子问题的精确含义 | 不清楚含义就不能可靠写转移 |
| 题单驱动 | 按知识点和难度安排相邻题 | 不能代替对方法的归纳 |
| 主动回忆 | 遮住答案，先口述/默写/重写 | 看过不等于掌握 |
| 举反例验证 | 对贪心或边界规则主动寻找反例 | 不能把一个样例当证明 |

## 3. 核心命题

1. 做题的高价值产物是可迁移的框架，而不是 AC 数字。
2. 任何模板都要和适用条件、不变量、边界以及复杂度一起记。
3. DP 先定义状态和转移，再决定遍历顺序和空间优化；不要从代码反推含义。
4. 回溯先确定选择列表、路径和结束条件，再处理剪枝与去重。
5. 贪心必须说明局部选择为什么不会损失全局最优，或用反例暴露假设。
6. 学习闭环需要“独立尝试—最小提示—代码—复盘—间隔重写”，只读题解会产生虚假熟练。
7. 三种外部体系各有偏向；14 天计划是时间约束下的取舍，不是普适学习定律。

## 4. 批判与边界

- Hot 100 和 14 天计划优化的是面试覆盖率，不代表完整算法课程或真实工程算法能力。
- 题目题解、YXC 代码和专题模板可能存在多种写法；“唯一最终提交版”是仓库约定，不是唯一正确实现。
- 复杂度和模板需结合数据范围、语言标准、整数溢出和内存限制复核。
- AI 教练流程要求读写学习状态文件；在 Codex Skill 中只把它作为学习策略证据，不擅自修改用户日志。

## 5. Skill 化潜力

通过三重验证：

- `algorithm-problem-framework-selection`：从题目约束和结构信号选择模板。
- `algorithm-state-and-invariant-derivation`：用状态定义、不变量和反例完成推导与正确性检查。
- `algorithm-active-recall-loop`：把刷题、提示、复盘、间隔复习和薄弱点更新成学习闭环。

题目级内容降级为案例索引和题型矩阵，不重复复制完整题解。
