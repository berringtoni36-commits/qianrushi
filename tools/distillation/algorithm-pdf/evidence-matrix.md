## 字段解释

- `page`、`chapter`、`topic_anchor`：源 PDF 页码、按内容边界划分的章节和该页首个非空文本锚点。锚点只用于定位，不是完整标题识别。
- `pdf_text_chars`、`pdf_text_nonws`、`pdf_text_words`：PyMuPDF `text` 和 `words` 的可复现统计。
- `md_page_marker`、`text_evidence`：现有快照是否有页标记，以及快照页段与 PDF 页文本去空白后是否匹配。
- `formula_signal`、`formula_status`：只表达抽取证据状态。`text-cue` 是关键词或公式说明进入文本；`rendered-math/variable-visible` 表示 PDF 渲染可见但文本层有空洞；`raster-formula-or-diagram` 表示内容在栅格 asset 中，未转录。
- `raster_image_objects`、`asset_files`、`asset_status`：PDF 图像对象与现有附件的页码映射。`extracted-unlinked` 明确表示 Markdown 没有对应图片引用。
- `vector_drawings`、`layout_status`：页面向量对象数量和版面风险标记。数量高不是错误计数，只是文本统计无法覆盖的对象较多。
- `ocr_status`：本轮没有 OCR；PDF 有文本层不等于 OCR 已完成。
- `evidence_grade`：`E1-TEXT` 为有限文本定位，`E1-IMAGE` 为文本加未完整复核的图像，`E1-GAP` 为已知公式/变量/图文关系缺口。本轮没有完整理解等级。
- `learning_use`：允许进入学习材料的方式。所有模板仍需结合约束、不变量、编译和测试。

## 证据使用规则

1. `E1-TEXT` 只能支持“某页有该主题/代码线索”，不能单独支持公式、复杂度或模板正确性。
2. `E1-IMAGE` 和 `E1-GAP` 必须回到原始 PDF 渲染页；抽取稿的空白处不是公式值，也不是缺页证明。
3. 学习材料可以引用页码、主题和代码候选，但应明确“有限文本证据”，并补做题目约束、状态/不变量、边界、整数范围、复杂度和编译测试。
4. 不把本矩阵、图片 assets 或 PDF 抽取稿当作新增算法 Skill；统一方法论仍回链到 LeetCode 域规范源。
