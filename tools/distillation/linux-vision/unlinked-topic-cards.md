# Linux vision 未回链主题卡（候选登记）

> 本文件是来源覆盖后的保守候选层，不是新的规范 Skill，也不是对视觉项目“已经跑通”的证明。所有候选都必须继续区分文档声称、源码实际行为、历史构建产物和目标 ARM/Qt/OpenCV/模型实测。

## 候选主题与证据边界

### 1. Qt 事件循环、槽内阻塞与 QProcess 生命周期

- 文档和 `mainwindow.cpp` 同时提供证据，能把 `waitKey`、同步读文件、事件循环和子进程信号连接起来。
- 候选价值：预测 UI 假死、子进程退出无人处理、stderr/超时丢失等问题。
- 事实边界：静态源码只能证明调用和连接是否存在，不能证明某个设备上的卡顿频率。

### 2. 文件型 IPC 的帧编号、路径与完成合同

- `1.6`、`5.3` 与上位机代码共同覆盖“写帧—外部程序—读结果”的边界。
- 候选价值：用帧身份、就绪条件、超时、清理和错误传播解释陈旧帧/竞态，而不是只说“用文件通信”。
- 已知风险：摄像头路径、LSTR 默认路径和编号起点存在需要核对的分裂；不能自动宣称主链闭合。

### 3. 摄像头/视频帧到推理再到 Qt 显示的主链

- 全景图、完整流程文档和 `mainwindow.cpp` 提供跨来源骨架。
- 候选价值：面试讲解、故障定位和链路断点标注可以共享同一张帧级地图。
- 事实边界：视频路径与摄像头路径、模型分支和显示结果需要运行时日志或实机复核。

### 4. LIME/ADMM 收敛、参数调优与代价解释

- ADMM 框架、收敛参数和性能对比文档构成方法论候选。
- 候选价值：回答“为什么这样调参”“速度和质量如何权衡”“优化前后数字从哪来”。
- 事实边界：性能数字、停止条件和输入样本只有在 benchmark 日志与构建身份闭合后才能作为实测结果。

### 5. LSTR 与 Unet/NCNN 双模型部署分支

- 模型部署文档与两个源代码树提供输入/输出及分支级证据。
- 候选价值：预测 HWC/CHW、双输入、输出解码和模型选择错误。
- 处置：优先并入现有 `vision-model-tensor-contract-audit`，不要把“文档上存在两个模型”写成“同一主链同时运行”。

### 6. NEON/OpenMP 优化与尾部/归约边界

- NEON、OpenMP 文档与 `lime_opt.cpp` 能形成从优化意图到实现的证据链。
- 候选价值：检查向量尾部、并行归约、编译 flags 和性能测量边界。
- 事实边界：没有独立、可复现的输入/版本/平台 benchmark，就不能承诺加速倍数。

### 7. CMake target、历史 build 与运行时加载身份

- 构建指南、两个 CMakeLists 和既有 build 目录可用于 provenance 审计。
- 候选价值：回答“我改的源文件是否进入目标”“运行的是哪份二进制”“库是否由当前配置加载”。
- 处置：并入 `linux-vision-build-provenance-audit` 和 CMake source-discovery 审计，不复制为普通构建教程。

### 8. cv::Mat→QImage/QPixmap 与显示/遥测边界

- Mat 格式转换与 CPU/内存监控分别有文档和源码证据。
- 候选价值：可定位颜色通道、step、连续性、外部缓冲所有权、首样本和单位错误。
- 处置：降级为两个已有合同 Skill 的补证入口，避免把图像缓冲和 `/proc` 采样混为一个大 Skill。
