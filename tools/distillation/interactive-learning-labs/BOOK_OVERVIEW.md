# 交互学习实验与算法 PDF — 全局理解

## 基本信息

- 内容类型：Linux 物理内存、RTOS、Linux 视觉的 HTML/JS 交互实验，配套测试和思维导图；另含一份中文算法模板 PDF。
- 来源：历史 `archive/项目交互动画/`、`archive/思维导图/`、`acwing/算法基础课模板大全-C++版本.pdf`；当前快照中交互 HTML/JS 文件已不存在，当前 Skill 只引用仍存在的项目审计文档。
- 处理原则：可运行代码用于验证“交互模型实际表达了什么”；HTML 中的教学数据不自动升级为项目实测事实。

## 1. 结构

1. 交互层：导航、步骤、状态机、速度和答题反馈。
2. 模型层：伙伴系统分配/合并、碎片指数计算、RTOS 任务/PID/IAP 演示、视觉流水线与性能图表。
3. 证据层：`source`、`code`、`boundary` 字段、测试断言、项目图片和源码路径。
4. 派生图层：Canvas 节点/边把项目文档、图像和复习主线连接起来。
5. 算法模板层：PDF 以代码模板覆盖排序、二分、数学、图论、DP 等基础算法；当前 OCR 失败，需以本地文本抽取为有限证据。

## 2. 核心命题

- 一个好的学习实验同时展示路径、可调输入、预期结果和事实边界。
- `source`/`code`/`boundary` 三元组比漂亮动画更重要：它能说明数据从哪里来、代码承担什么职责、模型哪里不能外推。
- 测试应验证数据、状态转换、公式和风险说明，而不只是页面能打开。
- 交互模型可以帮助主动回忆，但它仍是派生实现；项目源码和测量记录优先级更高。
- Canvas 是关系证据，不是另一份独立正文；文件节点指向的 Markdown/资产才是主来源。

## 3. 重要事实边界

- 历史物理内存实验中的三组指数场景是教学手算模型，不能替代目标内核 `/proc`、debugfs 或实际 workload；当前快照无法重新运行该实验。
- RTOS 动画明确展示 `ifopen=0`、IAP 风险和安全模型/源码模型的区别；不能据动画宣称固件升级已在硬件上验证。
- 视觉性能页区分真实处理结果与教学计算，图表数字的来源要回到项目文档和测量上下文。
- Canvas 中存在重复文件节点和派生链接，覆盖统计必须去重。
- PDF 120 页需要 OCR，但本地 Ark 凭证返回 401；本域引用 PDF 时必须标记公式/图片未完整复核。
