本文档系统梳理本项目中两条车道线检测模型链——**LSTR（ONNX Runtime）**与**Unet（NCNN）**——的部署核心知识、代码实现差异与高频面试追问。内容覆盖模型架构选择、数据布局转换、输入输出语义、后处理逻辑以及性能取舍，帮助开发者在面试中清晰表达"为什么这样部署、代码做了什么、有哪些边界风险"。

---

## 两条模型链的核心区别：像素级分割 vs 参数化曲线检测

在面试中，第一个高频问题是"为什么项目里同时保留 Unet 和 LSTR"。答案的关键在于两者的**输出语义完全不同**。

| 维度 | Unet（NCNN） | LSTR（ONNX Runtime） |
|------|--------------|----------------------|
| 检测范式 | 像素级语义分割 | 参数化曲线检测 |
| 模型输出 | 每个像素的类别概率（多通道 mask） | 候选车道的存在性 logits + 曲线参数 |
| 结果形态 | 逐像素标注"是/不是车道线" | 若干条候选车道的 8 参数曲线 |
| 后处理 | argmax 选类别 → 去 padding → 可视化 | logits 筛选有效候选 → 曲线采样成点集 → 绘制/填充 |
| 速度潜力 | 像素级计算量大，后处理较重 | 直接回归参数，端侧后处理更紧凑 |
| 遮挡鲁棒性 | 像素级结果对遮挡敏感 | 参数化曲线对局部遮挡更鲁棒 |

**记忆口诀**：Unet 是"逐像素画线的画家"，LSTR 是"直接输出曲线方程的数学家"。绿色区域是 C++ 后处理由点集构造的可视化效果，不是 LSTR 模型直接输出的 mask。

Sources: `卷积神经网络/卷积神经网络/Unet_NCNN/src/unet.cpp#L16-L143`、`卷积神经网络/卷积神经网络/LSTR_ONNX/main.cpp#L14-L223`

## Unet NCNN 部署全链路

### 模型格式与加载

NCNN 使用两个文件描述模型：`.param`（网络结构）和 `.bin`（权重数据）。加载时先调用 `load_param()` 读取结构，再调用 `load_model()` 加载权重。

```cpp
ncnn::Net Unet;
Unet.load_param("../models/model.ncnn.param");
Unet.load_model("../models/model.ncnn.bin");
```

**面试追问**：`.param` 和 `.bin` 分别存什么？答：`.param` 存网络层定义和连接关系（文本格式），`.bin` 存各层权重和偏置（二进制格式）。

Sources: `卷积神经网络/卷积神经网络/Unet_NCNN/src/unet.cpp#L22-L25`

### 输入预处理：保持宽高比 → padding → resize → 归一化 → HWC→CHW

这是 Unet 部署中最容易出错的环节，面试中常被追问"每一步为什么不能省"。

| 步骤 | 代码位置 | 作用 | 漏掉会怎样 |
|------|----------|------|------------|
| 等比例黑边 padding | `copyMakeBorder()` L42-L50 | 保持原始宽高比，避免变形 | 车道线被拉伸，分割边界失真 |
| resize 到 720×720 | `cv::resize()` L60 | 匹配模型固定输入尺寸 | 张量维度不匹配，推理失败 |
| 归一化到 [0,1] | `convertTo(CV_32FC3, 1/255.0)` L64 | 匹配训练时的数值范围 | 数值分布偏差，推理精度下降 |
| HWC → CHW | 三重循环 L69-L73 | 匹配 NCNN 的通道优先布局 | 通道/空间信息错乱，输出完全错误 |

HWC→CHW 的转换公式是关键：
```cpp
data[k*H*W + i*W + j] = srcdata[i*W*3 + j*3 + k];
```
OpenCV 的 `Mat` 内存是"行-列-通道"（HWC），而 NCNN 要求"通道-行-列"（CHW）。漏掉这一步，网络会把空间位置当成通道维度来读，输出完全无意义。

Sources: `卷积神经网络/卷积神经网络/Unet_NCNN/src/unet.cpp#L42-L77`

### 推理执行与线程配置

NCNN 通过 `Extractor` 对象执行推理。当前代码启用了轻量模式和 4 线程：

```cpp
ncnn::Extractor ex = Unet.create_extractor();
ex.set_light_mode(true);    // 减少中间内存占用
ex.set_num_threads(4);      // FT2000/4 四核 ARM
ex.input("in0", in);        // 输入节点名必须与 .param 一致
ncnn::Mat mask;
ex.extract("out0", mask);   // 输出节点名必须与 .param 一致
```

**面试追问**：`in0` 和 `out0` 是怎么确定的？答：由训练侧导出 `.param` 时决定，部署时必须与 `.param` 文件中的节点名严格一致，否则推理失败。

Sources: `卷积神经网络/卷积神经网络/Unet_NCNN/src/unet.cpp#L79-L88`

### 后处理：argmax → 去 padding → 可视化

模型输出 `mask` 是多通道张量（每个通道对应一个类别），需要对每个像素做 argmax 选择最大概率类别：

```cpp
for (int k = 0; k < mask.c; k++) {
    if (tmp < srcdata[k*mask.w*mask.h + i*mask.w + j]) {
        tmp = srcdata[k*mask.w*mask.h + i*mask.w + j];
        maxk = k;
    }
}
data[i*INPUT_WIDTH + j] = maxk;
```

然后根据预计算的 padding 边界清除人为填充区域，最后将类别 mask 可视化为绿色覆盖层。

**面试追问**：为什么用 argmax 而不是简单阈值？答：多类别分割需要选出概率最高的类别，简单阈值无法处理类别间竞争。

Sources: `卷积神经网络/卷积神经网络/Unet_NCNN/src/unet.cpp#L90-L124`

## LSTR ONNX Runtime 部署全链路

### 模型格式与会话初始化

LSTR 使用 ONNX 格式（`.onnx`），通过 ONNX Runtime 加载。会话初始化时需要：

1. 加载模型文件
2. 设置图优化级别
3. 获取输入/输出节点信息（名称、维度）
4. 加载预计算数据 `log_space.bin`

```cpp
sessionOptions.SetGraphOptimizationLevel(ORT_ENABLE_BASIC);
ort_session = new Session(env, model_path, sessionOptions);
// 获取输入/输出节点数量、名称、维度
```

`log_space.bin` 是 50 个预计算的采样位置，用于将曲线参数还原为车道点序列。

Sources: `卷积神经网络/卷积神经网络/LSTR_ONNX/main.cpp#L46-L83`

### 输入标准化：按通道 CHW 布局 + ImageNet 均值标准差

LSTR 的输入标准化与 Unet 不同，它使用 ImageNet 的均值和标准差：

```cpp
float mean[3] = { 0.485, 0.456, 0.406 };
float std[3] = { 0.229, 0.224, 0.225 };
// 归一化公式
this->input_image_[c * row * col + i * col + j] = (pix / 255.0 - mean[c]) / std[c];
```

**面试追问**：这里的 `mean/std` 是 RGB 顺序还是 BGR？答：代码直接按 OpenCV 当前通道顺序读取，OpenCV 默认 BGR，但 `mean/std` 看起来是 RGB 顺序。这是一个**潜在 bug**，需要与训练侧预处理核对，必要时显式 `cvtColor`。

Sources: `卷积神经网络/卷积神经网络/LSTR_ONNX/main.cpp#L91-L107`

### 双输入机制：image tensor + mask_tensor

LSTR 需要两个输入：

| 输入 | Shape | 内容 | 作用 |
|------|-------|------|------|
| image tensor | `[1, 3, H, W]` | 归一化后的图像数据 | 提取视觉特征 |
| mask_tensor | `[1, 1, H, W]` | 全零张量 | 模型架构要求的占位输入 |

```cpp
ort_inputs.push_back(Value::CreateTensor<float>(...input_image_..., input_shape_));
ort_inputs.push_back(Value::CreateTensor<float>(...mask_tensor..., mask_shape_));
ort_session->Run(RunOptions{nullptr}, input_names.data(), ort_inputs.data(), 2, output_names.data(), output_names.size());
```

**关键理解**：`mask_tensor` 不是最终可视化 mask，而是模型导出时定义的第二输入；它必须与导出 ONNX 时的输入顺序、shape 和语义一致。

Sources: `卷积神经网络/卷积神经网络/LSTR_ONNX/main.cpp#L118-L129`

### 输出语义：pred_logits 筛选 + pred_curves 参数还原

LSTR 输出两个张量：

| 输出 | 语义 | 处理方式 |
|------|------|----------|
| `pred_logits` | 候选车道的存在性概率 | argmax 筛选有效候选（`max_id == 1`） |
| `pred_curves` | 每条候选车道的 8 参数曲线 | 与 `log_space` 组合还原为车道点 |

曲线参数还原公式：
```cpp
const float y = p_lane_data[0] + log_space[k] * (p_lane_data[1] - p_lane_data[0]);
const float x = p_lane_data[2] / powf(y - p_lane_data[3], 2.0) 
              + p_lane_data[4] / (y - p_lane_data[3]) 
              + p_lane_data[5] + p_lane_data[6] * y - p_lane_data[7];
lane_points[k] = Point(int(x*img_width), int(y*img_height));
```

**面试追问**：为什么 LSTR 的后处理比 Unet 轻量？答：LSTR 直接输出曲线参数，只需采样 50 个点；Unet 需要对整个 720×720 的 mask 做 argmax。

Sources: `卷积神经网络/卷积神经网络/LSTR_ONNX/main.cpp#L130-L167`

### 可视化：车道线绘制与绿色区域填充

LSTR 的可视化分为两步：
1. 绘制车道线点（圆形标记）
2. 若左右车道线数量相等，用 `fillConvexPoly` + `addWeighted` 绘制绿色区域

```cpp
if (right_lane.size() == left_lane.size()) {
    fillConvexPoly(lane_segment_img, points, Scalar(0, 255, 0));
    addWeighted(visualization_img, 0.4, lane_segment_img, 0.6, 0, visualization_img);
}
```

**边界风险**：当 `right_lane` 和 `left_lane` 都为空时，`size() == size()` 仍成立，随后访问 `[0]` 会导致越界。部署时应先检查两侧均非空。

Sources: `卷积神经网络/卷积神经网络/LSTR_ONNX/main.cpp#L170-L204`

## 面试高频追问与标准答法

### "为什么同时保留 Unet 和 LSTR？"

**标准答法**：Unet 是像素级语义分割，擅长给出细致的车道区域与边界，适合需要精确像素级定位的场景；LSTR 是参数化曲线检测，直接回归车道线参数，端侧速度潜力更高，对局部遮挡更鲁棒。两者的速度、遮挡鲁棒性和多车道表现需要在同一数据集、同一硬件上做对比实验才能下结论。

### "Unet 的 NCNN 部署流程是什么？"

**标准答法**：训练模型先转换为 NCNN 的 `.param + .bin`；端侧加载结构和权重；输入图片保持比例后 padding 并 resize，归一化到 [0,1]；把 OpenCV 的 HWC 内存排布转换为模型需要的 CHW；通过 `in0/out0` 执行推理；对输出做 argmax 得到像素类别；最后去掉 padding 区域，叠加显示。

### "LSTR 的两个输入和两个输出分别是什么？"

**标准答法**：输入是经过 resize、归一化并排为 NCHW 的 image tensor，以及模型要求的全零 `mask_tensor`；输出中 `pred_logits` 用于判断候选车道是否有效，`pred_curves` 提供曲线参数。`log_space.bin` 负责提供采样位置，绿色车道区域则是 C++ 后处理由点集构造的可视化效果，不是模型直接输出。

### "HWC→CHW 转换为什么不能省？"

**标准答法**：OpenCV 的 `Mat` 内存是"行-列-通道"（HWC），而 NCNN 要求"通道-行-列"（CHW）。漏掉这一步，网络会把空间位置当成通道维度来读，导致输出完全错误。转换公式 `data[k*H*W + i*W + j] = srcdata[i*W*3 + j*3 + k]` 保证了通道、行、列的正确映射。

### "模型量化是否真的做了？"

**标准答法**：需要区分原作者资料中的方案描述与当前 C++ 推理入口可验证的事实。代码中没有显式启用量化配置，模型文件是否量化需要查看训练侧的转换脚本和配置。面试时应诚实说明"当前代码入口未验证量化是否生效"。

## 部署边界风险清单

### Unet NCNN

| 风险点 | 当前状态 | 建议 |
|--------|----------|------|
| `imread`、`load_param`、`load_model` 返回值未检查 | 无错误处理 | 添加失败检查和日志 |
| `new float[...]` 无对应 `delete[]` | 批量推理时内存泄漏 | 使用智能指针或 RAII |
| padding 清除依赖正确缩放后的边界 | 未验证 | 用单元测试核验目标区域 |
| 节点名 `in0`/`out0` 与 `.param` 不一致 | 假设一致 | 启动时验证节点名 |

### LSTR ONNX Runtime

| 风险点 | 当前状态 | 建议 |
|--------|----------|------|
| `normalize_()` 通道顺序与 `mean/std` 不匹配 | 潜在 bug | 显式 `cvtColor` 或核对训练侧 |
| `mask_tensor` 语义不明确 | 文档不足 | 添加注释说明模型输入要求 |
| `right_lane[0]`/`left_lane[0]` 越界 | 当两者都为空时触发 | 先检查非空再访问 |
| `log_space.bin` 打开失败未处理 | 直接 `fread` | 添加文件存在性检查 |

## 从代码到面试：90 秒讲稿模板

**场景与约束**：低光条件削弱车道线可见性，FT2000/4 端侧 CPU 资源有限，没有合适 GPU 通用计算路径。

**前处理**：用 LIME 估计光照图并增强输入；对热点按缓存、NEON 与多核并行优化，但并行前先确认依赖与正确性。

**两条模型链**：
- **Unet/NCNN**：像素级语义分割，输出每个像素的类别概率，后处理做 argmax、去 padding、可视化。
- **LSTR/ONNX Runtime**：参数化曲线检测，双输入推理输出候选车道的存在性和曲线参数，后处理用 `log_space` 采样成车道点，绘制绿色区域。

**工程取舍**：任何速度结论都绑定输入尺寸、模型、硬件、线程、I/O 和正确性基线；不能把"绿色区域"说成 LSTR 直接输出。
