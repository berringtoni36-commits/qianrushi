# 阶段 0：项目全局地图高频面试问答

## 1. 项目整体解决什么问题？

**面试官问**：你这个 Linux 视觉感知处理系统主要解决什么实际问题？

**建议回答**：  
这个项目面向校园无人配送车的车道线识别场景，运行在飞腾 FT2000/4 四核 ARM 开发板和银河麒麟 V10 系统上。它主要解决两个问题：一是夜晚或弱光环境下道路图像偏暗，车道线和背景对比度低，模型直接识别容易漏检或误检；二是开发板算力有限，不能完全依赖 GPU，所以需要通过 LIME 低照度增强、Unet/LSTR 推理和 NEON/OpenMP 优化，把整条视觉感知链路跑起来。

**追问要点**：平台、弱光痛点、车道线识别、算力受限。

**容易答错**：只说“做低光照增强”，忘了最终目标是提升车道线识别质量。

## 2. 项目的完整数据流是什么？

**面试官问**：从输入到显示，整个系统数据是怎么流动的？

**建议回答**：  
用户先在 Qt 上位机点击按钮，系统读取摄像头或本地视频帧；针对弱光场景，图像先经过 LIME 做低照度增强，提高车道线可见性；增强后的图像再送入 Unet 或 LSTR 做车道线识别；模型生成识别结果后，Qt 负责显示原图、结果图，并通过定时器刷新 CPU 和内存状态。

**追问要点**：Qt 控制、图像输入、LIME 增强、模型推理、Qt 显示监控。

**容易答错**：把 LIME 说成检测模块。LIME 是增强，Unet/LSTR 才是识别。

## 3. Qt 在项目里负责什么？

**面试官问**：Qt 在这个项目里承担什么角色？为什么它不是算法核心？

**建议回答**：  
Qt 是上位机控制和展示层，负责按钮控制、摄像头或视频流程触发、原图和识别结果显示，以及 CPU/内存状态监控。它不是算法核心，因为算法核心是 LIME 图像增强和 Unet/LSTR 模型推理。重算法如果直接跑在 Qt UI 主线程里，会阻塞事件循环，导致按钮无响应、界面卡顿和图像刷新不及时。

**追问要点**：控制、显示、监控；事件循环；重任务不能阻塞 UI 主线程。

**容易答错**：只说 Qt 显示 CPU/内存，漏掉按钮控制、图像显示和结果显示。

## 4. 为什么需要 LIME？

**面试官问**：为什么模型前面要加 LIME 低照度增强？

**建议回答**：  
因为夜晚或弱光环境下，车道线和道路背景的对比度会下降，车道线边缘和纹理特征不明显，直接送入模型容易出现漏检或误检。LIME 的作用是在模型推理前提高低照度图像质量，让车道线更清楚，从而提升后续 Unet 或 LSTR 的输入质量。

**追问要点**：低照度、对比度低、输入质量、漏检/误检。

**容易答错**：把 LIME 说成“直接识别车道线”。它只做图像增强。

## 5. Unet 和 LSTR 的区别是什么？

**面试官问**：项目里为什么同时涉及 Unet 和 LSTR？它们有什么区别？

**建议回答**：  
Unet 偏像素级语义分割，它会判断图像中每个像素是不是车道线，结果更像 mask；LSTR 偏参数化车道线检测，它不是逐像素输出，而是预测车道线的存在性和曲线参数，再通过后处理还原成车道线。简单说，Unet 更像“逐像素画线”，LSTR 更像“直接给出车道线曲线”。

**追问要点**：像素级分割 vs 参数化曲线检测；精细程度和速度取舍。

**容易答错**：说 LSTR 输出绿色 mask。绿色区域是后处理可视化，不是模型直接输出。

## 6. 为什么要分成 Qt、LIME、模型推理几个模块？

**面试官问**：为什么不把界面、增强、推理都写在一起？

**建议回答**：  
分模块是为了让系统边界清晰。Qt 负责控制、显示、监控；LIME 负责低照度增强；Unet/LSTR 负责车道线识别。这样做可以避免重推理阻塞 UI 主线程，也方便后续定位问题：图像质量差就看 LIME，识别效果差就看模型，界面卡顿就看 Qt 调度和进程/线程设计。后续替换模型或替换增强算法也更容易。

**追问要点**：降低耦合、避免 UI 卡顿、便于调试、便于替换。

**容易答错**：只回答“会卡顿”，没说调试、维护和替换成本。

## 7. 为什么要监控 CPU 和内存？

**面试官问**：Qt 里为什么要做 CPU/内存状态监控？

**建议回答**：  
因为项目部署在算力有限的 ARM 开发板上，视觉增强和模型推理都会占用较多资源。CPU/内存监控可以帮助观察系统运行负载、资源占用和部署稳定性，也能辅助比较不同方案在开发板上的运行压力。它不是直接判断模型识别效果的指标，但能反映系统是否适合在目标平台上稳定运行。

**追问要点**：资源占用、运行负载、部署稳定性、方案对比。

**容易答错**：说 CPU/内存监控是为了判断模型“识别效果”。识别效果看结果，资源监控看运行压力。

## 8. 为什么需要 NEON 和 OpenMP？

**面试官问**：项目为什么需要 NEON/OpenMP 这类优化？

**建议回答**：  
飞腾 FT2000/4 是四核 ARM 开发板，算力有限，而且项目没有合适的 GPU 通用计算路径。LIME 低照度增强和模型推理都比较耗时，所以需要利用 CPU 侧优化提高速度。NEON 是 ARM 上的 SIMD，可以让单条指令一次处理多个数据；OpenMP 是多线程并行，可以把独立任务分给多个核心执行。两者目标都是让边缘端处理速度更适合实际部署。

**追问要点**：ARM 算力有限、无合适 GPU、NEON 是 SIMD、OpenMP 是多线程。

**容易答错**：把 NEON 和 OpenMP 混为一谈。NEON 是单核向量化，OpenMP 是多核并行。
