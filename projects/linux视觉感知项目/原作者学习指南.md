# 嵌入式视觉感知系统 - 学习指南

> 基于 FT2000/4 处理器的嵌入式视觉感知系统 | C++/ARM Linux/Neon/OpenMP

---

## 一、简历描述与面试介绍

### 1.1 简历介绍

**项目描述：** 基于**飞腾 FT2000/4 处理器与国产麒麟操作系统**，实现从**摄像头输入、图像预处理、模型推理再到可视化监测**的全流程落地，完成面向校园无人配送车的实时车道线识别系统。

**技术要点：**

1. **预处理实现：** 复现论文《LIME》中的低照度增强算法，解决**夜晚场景下车道线辨识度低**的问题，作为系统的预处理算法；
2. **预处理优化：** 通过**循环重排、循环展开、Arm Neon 指令集优化及 OpenMP 多线程并行加速**等策略提升预处理效率；
3. **模型轻量化：** 对比**Unet 与 Transformer-based LSTR** 两种车道线识别网络的性能差异，采用**卷积核结构优化+量化**实现模型轻量化，基于**NCNN推理框架**完成端侧部署，提升边缘设备推理速度；
4. **性能检测可视化：** 使用 QT 开发上位机完成可视化界面，并编写程序性能检测模块，实时**监测 CPU 占用率、内存使用率**等关键指标可视化。

### 1.2 面试介绍

**硬件背景：** 飞腾教育开发板（FT2000 是处理器，4 是四核），基于 Linux 系统开发了一套实时低照度增强与车道线检测系统。

**系统三大部分：**

1. **低照度增强预处理算法的开发和优化**
2. **车道线识别神经网络的训练和部署**
3. **上位机与性能检测**

**第一部分 - 低照度增强预处理算法的开发和优化：**

对一篇学术论文《LIME》进行了代码实现，作为车道线识别之前的低照度增强预处理算法。由于开发板没有 GPU 加速，只能用 CPU 进行图像处理，并且对实时性要求比较高。因此对复现的算法进行了程序性能优化：

- **数据存储策略优化：** 循环重排（行优先遍历，外用列，确保数据存储顺序与遍历顺序一致，避免不必要的内存跳跃）提升缓存命中率和利用率
- **编译器指令集优化：** Neon 指令集（同时处理四个32位的浮点数）实现并行计算
- **循环展开：** 利用 Neon，减少循环控制的开销，同时提高指令级并行性
- **OpenMP 多线程接口：** 多核处理块等优化策略，显著提高预处理速度

**第二部分 - 车道线识别神经网络的训练和部署：**

模型部署方面，对比两种模型，分别是 Unet 和基于 Transformer 的 LSTR 实现对车道线识别神经网络进行识别，采用深度可分离卷积替换传统卷积、结合参数量化技术来减少参数量；基于 NCNN 推理框架完成轻量化模型的端侧部署，实现模型的高效推理。

**第三部分 - 上位机与性能检测：**

- **上位机展示：** 将神经网络推理后的画面显示在 QT 上位机中
- **性能检测模块：** 采集 CPU 和内存的使用率。使用 QT 上的 timer 定时器并利用终端上的 top 等工具采集系统 CPU 和内存占用率显示在上位机界面中

## 二、简述

### 2.1 开发过程

**硬件连接：** 1 个摄像头通过 USB 连接飞腾教育开发板，1 个显示器通过 HDMI 连接开发板，键盘/鼠标也通过 USB 连接开发板，开发板连接电源。

**开发方式：**
- 在 PC 端 Ubuntu 开发，然后通过 U 盘或 FileZilla 与飞腾开发板传递文件
- 通过 MobaXterm、**SecureCRT、PuTTY** 等 SSH 工具远程连接
- 直接在飞腾教育开发板上开发（类似 Ubuntu 系统，下载 QT、VSCode 等软件）

### 2.2 实现概述

简单来说就是通过 OpenCV 使用摄像头采集画面，传到开发板送到低照度增强程序中进行处理，然后增强后的帧再送到车道线检测模型中进行推理，推理后的画面在 QT 上位机展示，QT 同时还做了性能检测模块，实时检测硬件内存、CPU 等资源使用情况。

**流程：** `摄像头采集 → 低照度增强 → 神经网络推理 → QT上位机显示`

### 2.3 快速学习

#### （1）低照度增强算法

- 可以看一下论文的描述，再对照算法，来弄清楚低照度增强算法的内容，例如他如何实现增强的
- 把其中的优化策略提炼出来：Neon、OpenMP、循环重排和展开，搞清楚他们是在哪个部分使用的，为什么可以达到优化的效果和他们各自的原理
- **优化效果：** 整体测试效果提升很多倍，之前是 1 秒几帧，后面 1 秒十几帧
  - Neon 和 OpenMP 起到的作用最大，可以达到 **4 倍左右**
  - 循环展开和重排也有效果，但没那么明显

> **注意：** Neon 在本项目中不是使用汇编编写，而是使用 C++ 库。OpenMP 同理，如果面试问几个线程，说 4 个就好（四核 CPU 架构的开发板，多了少了都有坏处）。循环重排就是行和列的遍历顺序问题。

#### （2）模型轻量化

卷积核结构优化+量化实现模型轻量化方式有了解，NCNN 推理框架完成端侧部署，提升边缘设备推理速度。

#### （3）QT 上位机

QT 代码主要看性能检测那个文件，其他主要是构建页面的可以简单看一看 QT 的使用方式，特别是 `connect`。其中如何得到性能数据和相关工具的大致原理需要看看。

### 2.4 学习要求

- 需要知道开发板的开发流程、硬件组成
- 需要知道整个系统启动流程：QT 上位机的按钮点击 → 采集画面 → 低照度增强 → 神经网络推理 → 上位机显示

## 三、重点查看——面试常见八股

### 3.1 情况介绍

> 暑期+秋招的七八十场面试中，总体来看有一半的面试会问这个项目，有三家问了如何复现算法的（经纬恒润的实习和大疆的实习面试，秋招就没有人问过了）；其中问此项目的**百分百都会问性能优化这个部分**。

### 3.2 为什么要使用这个预处理算法？

1. 比赛要求
2. 由于会有亮度不够的情况，需要低照度增强

### 3.3 为什么不用 GPU 加速？

此开发板是四核的 ARM v8 架构的开发板，四核主频平均 2.4GHz。GPU 是 AMD 的一个老款的 GPU，不能图像处理，只用来显示。并且实时性要求高，所以此图像处理只能用 CPU 来处理，所以优化思路是利用其多核 CPU 特性和提高缓存命中。

### 3.4 各个优化点的定义

#### Neon

Neon 是 ARMv8 结构特有的指令集，是 SIMD（单指令多数据）指令集，广泛应用于移动设备和嵌入式系统中。通过并行处理多个数据元素，NEON 能够显著提升计算密集型任务（如图像处理、信号处理、视频编解码等）的执行效率。CPU 的执行单元会并发地执行 NEON 指令，允许在一个时钟周期内对多个数据元素进行操作。

> 在代码中的具体应用：使用了哪些指令。此 Neon 是调用 C++ 的库，不是汇编。

#### OpenMP

OpenMP（Open Multi-Processing）是一种用于统一内存访问的共享内存并行编程的 API，它通过在源代码中插入编译指令（pragma），使得开发者能够轻松地将串行代码并行化，以充分利用多核处理器的计算能力。

**OpenMP 多少个线程比较好？** 4 个，因为是四核 CPU，测试过多和少都会效果不正常，原因如下：

#### OpenMP vs Pthread 对比

| 特性 | OpenMP | Pthread |
|------|--------|---------|
| 易用性 | 编译指令声明，无需手动管理线程 | 需手动创建/销毁线程，代码复杂 |
| 开销 | 自动负载均衡，开销低 | 手动调度，开销高 |
| 适用场景 | 数据并行（如图像分块） | 复杂任务调度 |

### 3.5 各部分概念

#### 循环重排（Loop Reordering）

能够提升缓存命中率的根本原因在于**匹配内存存储顺序与访问模式**，从而利用计算机体系结构中的缓存预取机制和局部性原理。

#### 循环展开（Loop Unrolling）

为编译器引导的指令级并行（ILP）优化：通过减少循环迭代次数（或完全消除循环），将循环体中的操作重复多次，从而降低循环控制（如分支判断、计数器更新）的开销。

**使用点：** 通过循环展开，每次加载和处理 4 个浮点数，而不是逐个处理每个元素。这种方式可以减少循环控制的开销，并且利用 ARM Neon 指令集一次性并行处理 4 个浮点数，处理四个像素点的 R、G、B 三通道并求和操作。

#### Cacheline 定义

Cacheline（缓存行）是 CPU 缓存与主存之间数据传输的最小单位，通常为 64 字节。CPU 访问某个地址时，会将该地址所在的整条缓存行一次性加载到 L1 Cache，后续访问同行内其他地址直接命中。若访问不连续（如按列遍历二维数组），每次都会触发新的缓存行加载，导致大量 cache miss，循环重排的目的就是让连续访问的元素落在同一缓存行内。

### 3.6 遇到的困难点

由于比赛需要画面的实时性，并且没有 GPU 来加速预处理算法，导致每秒几帧，所以只能用 CPU 来跑。寻找一些书籍和博客，比如 CSAPP 中的程序性能优化方法的借鉴，采用 Neon、OpenMP、循环展开、循环重排等方式提高速度。

### 3.7 怎么知道的缓存命中率是否增加？

使用 **Perf 工具**查看得知。
