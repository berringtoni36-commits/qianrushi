# Linux视觉感知项目｜快速复习思维导图
## 1. 项目定位与硬件平台
### 场景｜校园无人配送车的实时车道线识别
### 核心痛点｜夜间/弱光导致车道线对比度低，模型容易漏检或误检
### 平台｜飞腾 FT2000/4，四核 ARM，银河麒麟 V10
### 输入输出｜摄像头或视频帧 → 增强/推理 → 车道线结果图
### 技术栈｜C++、OpenCV、Qt、LIME、ONNX Runtime、NCNN
### 约束｜没有可用 GPU 通用计算路径，实时性主要依靠 CPU 优化
### 一句话介绍｜在 ARM Linux 平台完成低照度增强、车道线检测和可视化监控闭环
## 2. 系统架构与完整数据流
### 启动｜Qt 创建 QApplication → MainWindow → show() → a.exec()
### 主链｜摄像头/视频 → OpenCV 采集 → 保存 frames/ → LIME → Unet/LSTR → result/ → Qt 显示
### Qt 上位机｜按钮控制、帧采集、外部进程管理、结果显示、CPU/内存监控
### LIME 程序｜低照度增强，只改善输入图像质量，不负责车道线检测
### 模型程序｜Unet 做像素级分割；LSTR 做参数化曲线检测
### 模块通信｜文件系统交换图像，QProcess 启动/控制外部程序，信号槽读取输出
### 进程边界｜重计算放到独立可执行程序，避免阻塞 Qt UI 事件循环
### 数据目录｜frames/ 保存输入帧；LSTR/result/ 保存推理结果；Qt 读取结果回显
### 故障定位｜界面卡顿看 Qt/进程；图像偏暗看 LIME；识别错误看模型/后处理

## 4. LIME 算法原理
### Retinex 视角｜图像 I = 反射分量 R × 光照分量 T，增强时按通道除以 T
### 初始光照图｜T_hat = max(R, G, B)，每个像素取 RGB 最大值
### ADMM 目标｜用带权 TV 正则优化光照图，处理非光滑项并保持边缘
### 变量｜T 主变量；G 辅助变量；Z 对偶变量；u 惩罚参数；W 边缘权重
### 迭代顺序｜solveT → solveG → solveZ → solveU，顺序对应变量依赖
### solveT｜频域求解主变量，利用 FFT 将卷积/微分问题转成逐元素运算
### solveG｜结合导数、权重和软阈值处理正则项
### 收敛｜用 Frobenius 范数和 epsilon 判断残差，避免无意义继续迭代
### 安全护栏｜normalize(T, 0.2, 1.0)，防止除以接近 0 的光照值
### 输出｜R/T、G/T、B/T → threshold/merge/convertTo → CV_8U 增强图
### 代码地标｜_init_IllumMap()、getMax()、optIllumMap()、solveT/G/Z/U()、enhance()
## 5. NEON、OpenMP 与缓存优化
### 优化递进｜循环重排 → 循环展开 → NEON SIMD → OpenMP 多核并行
### Loop Reordering｜按连续内存访问顺序遍历，提升局部性和缓存命中率
### Loop Unrolling｜一次展开处理多个元素，减少计数、分支和循环控制开销
### NEON｜ARMv8 SIMD 指令集，单条指令并行处理多个 float；本项目通过 C++ 库调用，不是手写汇编
### NEON 热点｜getMax() 通道最大值、Frobenius() 范数、数据密集型像素运算
### OpenMP｜共享内存并行 API，通过 pragma 将独立循环分配给多核 CPU
### 线程数｜FT2000/4 是四核，通常使用 4 个线程；线程过多会增加调度和竞争开销
### OpenMP vs Pthread｜OpenMP 易用且适合数据并行；Pthread 控制细但需要手动管理线程
### Cacheline｜CPU 与内存传输的最小缓存单位，通常 64 字节；连续访问更容易命中
### Perf 验证｜通过 cache-misses、cache-references 等指标验证缓存命中率变化
### 工程原则｜先计时定位热点，再做单项优化，最后回归输出正确性
## 6. LSTR 与 Unet 模型部署
### LSTR 思路｜把车道线建模为参数化曲线，而不是逐像素分类
### LSTR 输入｜归一化图像 [1,3,360,640] + 全零 mask_tensor
### LSTR 输出｜pred_logits 判断候选车道线存在性；pred_curves 提供曲线参数
### 曲线解码｜pred_curves + log_space.bin → 离散采样点 → 坐标映射 → 绿色区域
### LSTR 部署｜ONNX Runtime 加载模型，Run() 执行推理并读取 tensor
### Unet 思路｜Encoder-Decoder + skip connection，输出像素级语义分割 mask
### Unet 输入｜保持比例补边后 resize 到 720×720，再归一化和 HWC→CHW
### Unet 部署｜NCNN 使用 .param + .bin，适合 ARM 端轻量推理
### HWC→CHW｜OpenCV 按像素存通道；卷积推理按通道连续存储，必须重排
### Unet 后处理｜多通道 argmax → 去 padding → 恢复尺寸 → 可视化
### 核心区别｜Unet 像素级画线；LSTR 直接预测曲线参数；绿色显示区域来自后处理
## 7. 系统集成与性能数据
### LIME 性能｜原始 1.6305s；傅里叶重构 1.031s；NEON+OpenMP 0.314s；约 5.19× 加速
### Unet｜平均推理 17.386s → 4.676s；权重约 124MB → 10MB；DICE 93.1% → 84.5%
### LSTR｜平均推理 1.953s → 0.182s；权重 124.7MB → 12MB；准确率 97.4% → 90.7%
### 端到端｜采集/JPEG 约 40ms + LIME 约 314ms + LSTR 约 182ms ≈ 536ms/帧
### 当前瓶颈｜LIME 约占端到端耗时一半，是继续优化的主要方向
### 轻量化｜深度可分离卷积 + FP16/参数量化，压缩模型但需要权衡精度
### 通信权衡｜文件系统简单、可靠、方便调试；共享内存/消息队列性能更高但复杂
### 评价维度｜功能、端到端延迟、精度、CPU/内存、长时间稳定性
## 8. 项目面试表达与设计权衡
### 先讲痛点｜弱光影响识别 + ARM 无 GPU 通用计算 + 需要实时处理
### 再讲主链｜Qt 采集 → LIME 增强 → Unet/LSTR 推理 → Qt 显示与监控
### 模块化原因｜控制显示、增强、推理解耦，便于定位问题和替换模型
### 为什么先增强｜低质量输入会造成漏检/误检，LIME 先改善模型输入
### 为什么双模型｜Unet 擅长像素边界；LSTR 擅长参数化曲线和速度
### 为什么两种框架｜LSTR 需要 ONNX 图兼容性；Unet 更适合 NCNN ARM 优化
### 为什么文件交换｜实现简单、跨进程直观、结果可留存，满足当前场景
### 追问瓶颈｜LIME 迭代/像素计算、模型推理、文件 I/O、内存占用
### 改进方向｜量化剪枝、共享内存、预分配、减少拷贝、跳过不必要增强
### 表达边界｜不要把 LIME 说成检测；不要把绿色区域说成 LSTR 直接输出

##### 答｜通过并行处理多个数据元素，NEON 能够显著提升计算密集型任务（如图像处理、信号处理、视频编解码等）的执行效率。
##### 答｜CPU 的执行单元会并发地执行 NEON 指令，允许在一个时钟周期内对多个数据元素进行操作。
##### 答｜在代码中的具体应用：使用了哪些指令。此 Neon 是调用 C++ 的库，不是汇编。

### Q｜各部分概念
#### 循环重排（Loop Reordering）
##### 答｜能够提升缓存命中率的根本原因在于匹配内存存储顺序与访问模式，从而利用计算机体系结构中的缓存预取机制和局部性原理。
#### 循环展开（Loop Unrolling）
##### 答｜为编译器引导的指令级并行（ILP）优化：通过减少循环迭代次数（或完全消除循环），将循环体中的操作重复多次，从而降低循环控制（如分支判断、
##### 答｜计数器更新）的开销。
##### 答｜使用点： 通过循环展开，每次加载和处理 4 个浮点数，而不是逐个处理每个元素。
##### 答｜这种方式可以减少循环控制的开销，并且利用 ARM Neon 指令集一次性并行处理 4 个浮点数，处理四个像素点的 R、G、B 三通道并求和操作。
#### Cacheline 定义
##### 答｜Cacheline（缓存行）是 CPU 缓存与主存之间数据传输的最小单位，通常为 64 字节。
##### 答｜CPU 访问某个地址时，会将该地址所在的整条缓存行一次性加载到 L1 Cache，后续访问同行内其他地址直接命中。
##### 答｜若访问不连续（如按列遍历二维数组），每次都会触发新的缓存行加载，导致大量 cache miss，
##### 答｜循环重排的目的就是让连续访问的元素落在同一缓存行内。
### Q｜遇到的困难点

#### 答｜寻找一些书籍和博客，比如 CSAPP 中的程序性能优化方法的借鉴，采用 Neon、OpenMP、循环展开、循环重排等方式提高速度。
