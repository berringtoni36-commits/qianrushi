本文档将指导您理解并修复后搭建基于eBPF的Linux物理内存碎片检测工具。完成路径、依赖、内核兼容性与加载验证后，才能开始观察系统物理内存的碎片化状况。

## 项目概述

本项目是一个**基于BCC/eBPF的Linux物理内存碎片实时监控和终端可视化工具**。与传统工具如`/proc/buddyinfo`不同，本工具不仅展示静态快照，还能实时监控内存分配行为，帮助您判断系统是否能顺利分配大块连续物理内存。

**核心价值**：
- 实时监控内存碎片化程度
- 提供可视化终端界面（TUI）
- 支持多种监控模式（zone信息、事件统计、可视化图表）
- 低性能开销的eBPF采集机制

Sources: `linux物理内存检测工具原作者开发文档.md#L1-L22`

## 系统要求

在开始之前，请确保您的系统满足以下要求：

| 要求 | 说明 | 验证命令 |
|------|------|----------|
| **操作系统** | Linux内核版本 ≥ 4.1（支持eBPF） | `uname -r` |
| **权限** | root权限（加载eBPF程序需要） | `whoami` |
| **BCC工具包** | 已安装BCC（BPF Compiler Collection） | `bcc -V` |
| **Python** | Python 3.6+ | `python3 --version` |
| **终端尺寸** | 至少250列 × 50行 | `stty size` |

**重要提示**：本项目需要在Linux环境下运行，Windows系统无法直接执行。请确保您在Linux服务器或虚拟机中操作。

Sources: `exfrag_user.py#L43-L66`

## 项目文件结构

快速了解项目文件结构：

```
Linux物理内存碎片检测/
├── exfrag_user.py          # 用户态主程序（命令行入口）
├── exfrag.py               # 桥梁层（加载BPF、读取map、整理数据）
├── extfraginfo.c           # eBPF程序1：监控外碎片化事件
├── fraginfo.c              # eBPF程序2：统计zone碎片状态
├── bpf/                    # BPF源代码目录（需创建）
│   ├── extfraginfo.c       # 外碎片化事件监控
│   └── fraginfo.c          # zone碎片状态统计
└── linux物理内存检测工具原作者开发文档.md  # 原作者开发文档
```

**关键文件说明**：
1. **`exfrag_user.py`**：用户入口，提供命令行界面和curses可视化
2. **`exfrag.py`**：核心桥梁，负责BPF程序加载和数据处理
3. **`extfraginfo.c`**：使用tracepoint监控`mm_page_alloc_extfrag`事件
4. **`fraginfo.c`**：使用kprobe监控`get_page_from_freelist`函数

Sources: `exfrag.py#L18-L20`, `extfraginfo.c#L1-L60`, `fraginfo.c#L1-L168`

本项目采用标准的"内核态采集 + 用户态展示"双层架构：

```mermaid

    B -->|bpf()系统调用| E

    style A fill:#e1f5fe

```

**运行流程**：
1. Python程序通过BCC加载eBPF程序到内核
2. eBPF程序挂载到内核函数探针点
3. 当内核触发内存分配时，eBPF程序采集数据
4. 数据通过BPF map传递到用户态
5. Python程序读取数据并展示

## 快速搭建步骤

### 步骤1：安装BCC工具包

根据您的Linux发行版选择对应的安装命令：

**Ubuntu/Debian**：
```bash
sudo apt update
sudo apt install bpfcc-tools linux-headers-$(uname -r)
```

**CentOS/RHEL**：
```bash
sudo yum install bcc-tools
```

**验证安装**：
```bash
sudo ls /usr/share/bcc/tools/
```

### 步骤2：创建BPF目录

项目代码需要从`./bpf/`目录加载BPF源代码文件：

```bash
mkdir -p bpf
cp extfraginfo.c bpf/
cp fraginfo.c bpf/
```

### 步骤3：设置权限

确保Python脚本有执行权限：

```bash
chmod +x exfrag_user.py
chmod +x exfrag.py
```

### 步骤4：验证环境

运行以下命令验证环境：

```bash
# 检查eBPF支持
sudo bpftrace -e 'tracepoint:syscalls:sys_enter_openat { printf("eBPF works!\n"); }'

# 检查内核版本
uname -r

# 检查Python版本
python3 --version
```

Sources: `exfrag.py#L18-L20`, `exfrag_user.py#L68-L85`

## 运行方式

### 基本运行

最简单的运行方式（需要root权限）：

```bash
sudo python3 exfrag_user.py
```

这将启动默认模式，显示zone信息并每2秒刷新一次。

### 常用运行模式

根据您的监控需求，选择不同的运行模式：

| 模式 | 命令 | 说明 |
|------|------|------|
| **默认模式** | `sudo python3 exfrag_user.py` | 显示zone信息，2秒刷新 |
| **节点信息** | `sudo python3 exfrag_user.py -n` | 显示NUMA节点信息 |
| **详细zone信息** | `sudo python3 exfrag_user.py -z` | 显示zone详细信息 |
| **事件统计** | `sudo python3 exfrag_user.py -s` | 显示外碎片化事件统计 |
| **可视化图表** | `sudo python3 exfrag_user.py -v` | 显示可视化进度条 |
| **帮助信息** | `sudo python3 exfrag_user.py -h` | 显示帮助信息 |

### 参数详解

以下是完整的命令行参数说明：

| 参数 | 简写 | 说明 | 默认值 |
|------|------|------|--------|
| `--delay` | `-d` | 刷新间隔（秒） | 2 |
| `--node_info` | `-n` | 显示节点信息 | False |
| `--node_id` | `-i` | 指定节点ID过滤 | None |
| `--comm` | `-c` | 按zone名称过滤（如Normal、DMA） | None |
| `--extfrag_index` | `-e` | 仅显示碎片化指数 | False |
| `--unusable_index` | `-u` | 仅显示不可用指数 | False |
| `--output_count` | `-s` | 显示外碎片化事件统计 | False |
| `--bar` | `-b` | 显示碎片化条形图 | False |
| `--zone_info` | `-z` | 显示详细zone信息 | False |
| `--view` | `-v` | 显示可视化进度条 | False |

### 使用示例

**示例1：监控Normal区域，3秒刷新**
```bash
sudo python3 exfrag_user.py -d 3 -c Normal
```

**示例2：查看节点1的详细信息**
```bash
sudo python3 exfrag_user.py -z -i 1
```

**示例3：显示碎片化条形图**
```bash
sudo python3 exfrag_user.py -z -b
```

**示例4：显示可视化进度条**
```bash
sudo python3 exfrag_user.py -v
```

## 监控输出说明

### 输出字段解释

根据不同的监控模式，输出字段含义如下：

#### 节点信息（-n模式）
| 字段 | 说明 |
|------|------|
| `NODE_ID` | NUMA节点ID |
| `Number of Zones` | 节点包含的zone数量 |
| `NODE_START_PFN` | 节点起始页帧号 |

#### zone信息（默认或-z模式）
| 字段 | 说明 |
|------|------|
| `ZONE_COMM` | zone名称（DMA、Normal等） |
| `ZONE_PFN` | zone起始页帧号 |
| `SUM_PAGES` | zone总页数 |
| `FACT_PAGES` | 实际使用页数 |
| `ORDER` | 分配阶数（0-10） |
| `TOTAL` | 空闲块总数 |
| `SUITABLE` | 适合当前order的块数 |
| `FREE` | 空闲页总数 |
| `extfrag_index` | 碎片化指数（-1000到1000） |
| `unusable_index` | 不可用指数（0-1000） |

#### 外碎片化事件（-s模式）
| 字段 | 说明 |
|------|------|
| `COMM` | 进程名称 |
| `PID` | 进程ID |
| `PFN` | 分配的物理页帧号 |
| `ALLOC_ORDER` | 请求的分配阶数 |
| `FALLBACK_ORDER` | 从 fallback migratetype 找到的空闲块阶数，通常不小于请求阶 |
| `COUNT` | 事件发生次数 |

Sources: `linux物理内存检测工具原作者开发文档.md#L25-L70`

### 颜色含义

终端界面使用颜色区分不同状态：

- **绿色**：正常状态
- **红色**：高风险（order > 5且unusable_index > 0.5）
- **蓝色**：标题和表头
- **青色**：辅助信息

Sources: `exfrag_user.py#L278-L305`

## 常见问题与故障排除

### 问题1：权限不足
**错误信息**：`PermissionError: [Errno 13] Permission denied`

**解决方案**：使用sudo运行
```bash
sudo python3 exfrag_user.py
```

### 问题2：终端尺寸不足
**错误信息**：`[ERROR] Screen size is not enough!`

**解决方案**：调整终端窗口大小，确保至少250列×50行，或减小字体大小。

### 问题3：BCC未安装
**错误信息**：`ModuleNotFoundError: No module named 'bpfcc'`

**解决方案**：安装BCC工具包
```bash
# Ubuntu/Debian
sudo apt install bpfcc-tools

# CentOS/RHEL
sudo yum install bcc-tools
```

### 问题4：内核版本过低
**错误信息**：`BPF: kernel doesn't support BPF`

**解决方案**：升级Linux内核到4.1+版本

### 问题5：找不到bpf目录
**错误信息**：`FileNotFoundError: [Errno 2] No such file or directory: './bpf/extfraginfo.c'`

**解决方案**：创建bpf目录并复制文件
```bash
mkdir -p bpf
cp extfraginfo.c bpf/
cp fraginfo.c bpf/
```

### 问题6：无法看到数据更新
**可能原因**：
1. 系统内存分配不频繁
2. 采样间隔设置过大
3. 过滤条件过于严格

**解决方案**：
```bash
# 减少采样间隔
sudo python3 exfrag_user.py -d 1

# 移除过滤条件
sudo python3 exfrag_user.py
```

## 性能优化建议

### 采样频率控制
- 生产环境建议使用1-5秒的采样间隔
- 避免过于频繁的采样（< 1秒）可能影响系统性能
- 使用`-d`参数调整采样频率

### 过滤优化
- 使用`-c`参数过滤特定zone（如Normal、DMA）
- 使用`-i`参数过滤特定NUMA节点
- 减少不必要的监控范围

### 终端优化
- 使用支持256色的终端模拟器
- 确保终端字体清晰可读
- 考虑使用tmux或screen进行后台监控

Sources: `fraginfo.c#L94-L105`, `extfraginfo.c#L22-L32`
