## FreeRTOS软件定时器配置与原理

FreeRTOS软件定时器是基于定时器任务（Timer Service Task）实现的软件层面的定时机制。在本项目中，软件定时器已通过`FreeRTOSConfig.h`启用并配置：

```c
#define configUSE_TIMERS				        1                               //为1时启用软件定时器
#define configTIMER_TASK_PRIORITY		        (configMAX_PRIORITIES-1)        //软件定时器优先级
#define configTIMER_QUEUE_LENGTH		        5                               //软件定时器队列长度
#define configTIMER_TASK_STACK_DEPTH	        (configMINIMAL_STACK_SIZE*2)    //软件定时器任务堆栈大小
```

软件定时器的**核心工作原理**是：系统创建一个专门的定时器服务任务，所有定时器操作（创建、启动、停止、删除等）都通过命令队列发送到该任务执行。定时器回调函数在定时器服务任务上下文中执行，**而不是在中断上下文中**，因此可以调用大部分FreeRTOS API。

Sources: `FreeRTOS/include/FreeRTOSConfig.h#L147-L150`

软件定时器的**时基来源**是系统节拍（SysTick），本项目中配置为1000Hz（1ms周期）：

```c
#define configTICK_RATE_HZ						(1000)                  //时钟节拍频率，这里设置为1000，周期就是1ms
```

这意味着软件定时器的最小定时精度为1ms，所有定时器周期必须是1ms的整数倍。

Sources: `FreeRTOS/include/FreeRTOSConfig.h#L97`

## 硬件定时器TIM4中断驱动速度计算任务

本项目采用**硬件定时器TIM4中断+信号量同步**的模式实现高精度速度计算任务。这种模式在需要精确时间基准的场景中特别有效，因为它不受任务调度延迟的影响。

### TIM4定时器配置

TIM4定时器在`StartTask`中初始化，配置为1ms中断周期：

```c
/* 初始化TIM4定时器（必须在信号量创建后调用，避免HardFault）
 * 参数：5-1=4, 14400-1=14399
 * 定时器频率 = 72MHz / 14400 = 5kHz
 * 中断周期 = 5 / 5kHz = 1ms */
TIM4_init(5-1, 14400-1);
```

初始化函数在`motor.c`中实现：

```c
void TIM4_init(u16 arr,u16 psc)
{
	TIM_TimeBaseInitTypeDef  TIM_TimeBaseStructure;
	NVIC_InitTypeDef NVIC_InitStructure;

	RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM4, ENABLE); 			// 时钟使能

	TIM_TimeBaseStructure.TIM_Period = arr; 						// 设置在下一个更新事件装入自动重装载寄存器周期的值	 
	TIM_TimeBaseStructure.TIM_Prescaler =psc; 						// 设置用来作为TIMx时钟频率除数的预分频值  
	TIM_TimeBaseStructure.TIM_ClockDivision = 0; 					// 设置时钟分割:TDTS = Tck_tim
	TIM_TimeBaseStructure.TIM_CounterMode = TIM_CounterMode_Up;  	// TIM向上计数模式
	TIM_TimeBaseInit(TIM4, &TIM_TimeBaseStructure); 				// 根据TIM_TimeBaseInitStruct中指定的参数初始化TIMx的时间基数单位
	TIM_ITConfig(TIM4,TIM_IT_Update,ENABLE ); 						// 使能指定的TIM4中断，允许更新中断
	
	NVIC_InitStructure.NVIC_IRQChannel = TIM4_IRQn;  				// TIM4中断
	NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 5;  		// 抢占优先级
	NVIC_InitStructure.NVIC_IRQChannelSubPriority = 0;  			// 子优先级0级
	NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE; 				// IRQ通道被使能
	NVIC_Init(&NVIC_InitStructure);  								// 根据NVIC_InitStruct中指定的参数初始化外设NVIC寄存器

	TIM_Cmd(TIM4, ENABLE);  										//使能定时器						 
}
```

Sources: `BSP/MOTOR/motor.c#L242-L264`, `APP_TASK/app_tasks.c#L182-L186`

### 中断服务程序与信号量同步

TIM4中断服务程序通过发送二值信号量通知速度计算任务：

```c
void TIM4_IRQHandler(void)
{
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;
    
    if (TIM_GetITStatus(TIM4, TIM_IT_Update) != RESET)
    {
        TIM_ClearITPendingBit(TIM4, TIM_IT_Update);
        
        /* 发送信号量通知SpeedCalcTask执行速度计算 */
        xSemaphoreGiveFromISR(g_speedCalcSemaphore, &xHigherPriorityTaskWoken);
        
        /* 如果需要，触发上下文切换 */
        portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
    }
}
```

**关键设计点**：
1. 使用`xSemaphoreGiveFromISR()`从ISR发送信号量
2. 使用`xHigherPriorityTaskWoken`变量检测是否需要上下文切换
3. 通过`portYIELD_FROM_ISR()`在必要时触发任务切换

Sources: `APP_TASK/app_tasks.c#L825-L839`

### 速度计算任务实现

速度计算任务在等待信号量后执行实际的速度计算逻辑：

```c
void SpeedCalcTask(void *pvParameters)
{
    int encoderCount;
    
    while (1)
    {
        /* 等待TIM4中断发送的信号量 */
        if (xSemaphoreTake(g_speedCalcSemaphore, portMAX_DELAY) == pdTRUE)
        {
            /* 获取编码器计数值 */
            encoderCount = get_encoder_value();
            
            /* 计算电机转速（50ms计算一次） */
            speed = get_speed(encoderCount, 50);
        }
    }
}
```

## 基于任务延迟的周期执行模式

项目中大多数周期任务采用`delay_ms()`函数实现周期性执行，这是最简单直观的周期任务实现方式。

### delay_ms函数实现原理

`delay_ms()`函数在FreeRTOS环境下会调用`vTaskDelay()`，使任务进入阻塞状态指定的时间：

```c
void delay_ms(u32 nms)
{	
	if(xTaskGetSchedulerState()!=taskSCHEDULER_NOT_STARTED)//系统已经运行
	{		
		if(nms>=fac_ms)						//延时的时间大于OS的最少时间周期 
		{ 
   			vTaskDelay(nms/fac_ms);	 		//FreeRTOS延时
		}
		nms%=fac_ms;						//OS已经无法提供这么小的延时了,采用普通方式延时    
	}
	delay_us((u32)(nms*1000));				//普通方式延时
}
```

**实现机制**：
1. 检查调度器是否已启动
2. 计算需要延迟的系统节拍数
3. 调用`vTaskDelay()`使任务阻塞
4. 对于小于一个节拍的延迟，使用忙等待方式

Sources: `SYSTEM/delay/delay.c#L81-L92`

## 周期任务设计模式对比

### 基于延迟的周期任务（Delay-based）

**实现模式**：
```c
void TaskFunction(void *pvParameters)
{
    while(1)
    {
        // 执行任务逻辑
        DoSomething();
        
        // 延迟指定周期
        delay_ms(period_ms);
    }
}
```

**优点**：
- 实现简单，代码直观
- 任务在延迟期间让出CPU，资源利用率高
- 适合对时间精度要求不高的场景

**缺点**：
- 任务执行时间会影响实际周期
- 如果任务执行时间超过周期，会导致任务延迟累积
- 不适合硬实时要求的场景

**适用场景**：
- 传感器数据采集（SensorTask）
- 用户界面更新（UIDisplayTask）
- 非关键性监控任务

### 中断触发+信号量同步（Interrupt-triggered）

**实现模式**：
```c
void ISR_Function(void)
{
    // 发送信号量通知任务
    xSemaphoreGiveFromISR(semaphore, &xHigherPriorityTaskWoken);
    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}

void TaskFunction(void *pvParameters)
{
    while(1)
    {
        // 等待信号量
        if(xSemaphoreTake(semaphore, portMAX_DELAY) == pdTRUE)
        {
            // 执行任务逻辑
            DoSomething();
        }
    }
}
```

**优点**：
- 时间精度高，不受任务执行时间影响
- 响应及时，适合硬实时要求
- 任务执行频率由硬件定时器精确控制

**缺点**：
- 实现相对复杂
- 需要正确处理中断与任务间的同步
- 频繁中断可能影响系统整体性能

**适用场景**：
- 电机控制（MotorControlTask）
- 速度计算（SpeedCalcTask）
- 需要精确时间基准的控制任务

### FreeRTOS软件定时器（Software Timer）

**实现模式**：
```c
// 创建定时器
TimerHandle_t xTimer = xTimerCreate("Timer", pdMS_TO_TICKS(period_ms), 
                                   pdTRUE, NULL, TimerCallback);

// 启动定时器
xTimerStart(xTimer, 0);

// 定时器回调函数
void TimerCallback(TimerHandle_t xTimer)
{
    // 执行定时任务逻辑
    DoSomething();
}
```

**优点**：
- API简单易用
- 自动管理定时器生命周期
- 支持单次和周期定时器

**缺点**：
- 回调函数在定时器任务上下文中执行，有优先级限制
- 定时器精度受系统节拍影响
- 定时器任务可能成为系统瓶颈

**适用场景**：
- 周期性状态检查
- 超时处理
- 非关键性定时任务

Sources: `FreeRTOS/include/timers.h#L70-L100`

## 周期任务的实时性分析

### 时间精度影响因素

1. **任务调度延迟**：高优先级任务可能抢占当前任务
2. **中断延迟**：中断响应时间受中断嵌套影响
3. **系统负载**：CPU负载影响任务切换速度
4. **临界区保护**：互斥信号量获取时间不确定

### 项目中的优先级设计

```c
#define TASK_START_PRIORITY         1       /* 开始任务优先级 */
#define TASK_KEY_PRIORITY           4       /* 按键扫描任务优先级 */
#define TASK_SENSOR_PRIORITY        3       /* 传感器采集任务优先级 */
#define TASK_WIND_SPEED_PRIORITY    3       /* 风速计算任务优先级 */
#define TASK_MOTOR_PRIORITY         5       /* 电机控制任务优先级 */
#define TASK_UI_PRIORITY            1       /* UI显示任务优先级 */
#define TASK_ANTI_BACKFLOW_PRIORITY 2       /* 防回流任务优先级 */
#define TASK_IAP_PRIORITY           7       /* IAP任务优先级 */
#define TASK_SPEED_CALC_PRIORITY    6       /* 速度计算任务优先级（最高，保证及时响应中断） */
```

**设计原则**：
- 关键控制任务（电机、速度计算）设置较高优先级
- 用户界面任务设置较低优先级，避免影响实时控制
- 中断服务程序优先级高于任务优先级

Sources: `APP_TASK/app_tasks.h#L76-L84`

## 中断优先级配置

### FreeRTOS中断优先级管理

```c
#define configLIBRARY_LOWEST_INTERRUPT_PRIORITY			15                      //中断最低优先级
#define configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY	3                       //系统可管理的最高中断优先级
```

**关键概念**：
- 优先级数值越小，优先级越高
- 优先级3及以上的中断不受FreeRTOS管理
- 优先级3以下的中断不能调用FreeRTOS API

### 项目中的中断优先级分配

```c
/* 由于共计4个中断，设置中断分组为4，4位抢占优先级，0位亚优先级，因为Free不支持亚优先级处理。
 由于Free中存在屏蔽优先级阈值的概念，该工程笔者设置为3，因此我们需要调用API函数的中断优先级不能超过3，
 所以DMA中断优先级为4，定时器4中断优先级为5，TIM2中断优先级为6，从优先级都设置为0*/
NVIC_PriorityGroupConfig(NVIC_PriorityGroup_4);
```

| 中断源 | 优先级 | 说明 |
|-------|--------|------|
| DMA1_Channel5 | 4 | 串口DMA接收中断 |
| TIM4 | 5 | 速度计算定时器中断 |
| TIM2 | 6 | 编码器溢出中断 |

## 周期任务实现的最佳实践

### 任务周期选择原则

- **传感器采集任务**：根据传感器响应时间选择合适周期
  - DHT11：最小采样间隔1秒，项目设置为500ms
  - MQ2：ADC采样周期可较快，项目设置为500ms
- **控制任务**：根据被控对象响应时间选择
  - 电机控制：50ms周期，满足PID调节需求
  - 速度计算：1ms中断触发，50ms实际计算一次
- **用户界面**：根据显示刷新率选择
  - LCD显示：200ms周期，平衡刷新率与CPU负载

### 任务执行时间管理

**避免任务执行时间过长**：
- 将耗时操作分解到多个周期执行
- 使用状态机避免长时间阻塞
- 合理设置任务优先级

**示例：传感器任务优化**
```c
void SensorTask(void *pvParameters)
{
    while (1)
    {
        /* 分两次获取数据，避免单次持有锁时间过长 */
        // 第一次获取DHT11数据
        DHT_Read_Data(&temp, &humi, GPIOC, GPIO_Pin_14, &dht);
        if (ret == 1) {
            if (xSemaphoreTake(g_dataMutex, portMAX_DELAY) == pdTRUE)
            {
                g_systemState.temperature = temp;
                g_systemState.humidity = humi;
                xSemaphoreGive(g_dataMutex);
            }
        }
        
        // 第二次获取MQ2数据
        gasValue = MQ2_GetGasConcentration();
        if (xSemaphoreTake(g_dataMutex, portMAX_DELAY) == pdTRUE)
        {
            g_systemState.gasConcentration = gasValue;
            xSemaphoreGive(g_dataMutex);
        }
        
        delay_ms(500);  /* 500ms采集周期 */
    }
}
```

Sources: `APP_TASK/app_tasks.c#L254-L290`

## 常见问题与解决方案

### 任务周期不稳定

**可能原因**：
- 高优先级任务频繁抢占
- 中断处理时间过长
- 临界区保护时间过长

**解决方案**：
- 优化任务优先级分配
- 减少中断处理时间
- 使用更细粒度的锁机制

### 中断与任务同步问题

**可能原因**：
- 信号量使用不当
- 中断优先级配置错误
- 任务优先级设置不合理

**解决方案**：
- 正确使用`xSemaphoreGiveFromISR()`和`xSemaphoreTake()`
- 确保中断优先级在FreeRTOS管理范围内
- 合理设置任务优先级，避免优先级反转

### CPU负载过高

**可能原因**：
- 任务周期设置过短
- 任务执行时间过长
- 中断频率过高

**解决方案**：
- 根据实际需求调整任务周期
- 优化任务执行效率
- 适当降低中断频率
