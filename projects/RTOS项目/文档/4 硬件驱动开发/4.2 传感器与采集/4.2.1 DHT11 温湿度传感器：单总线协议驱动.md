## DHT11 传感器概述

DHT11是一款含有已校准数字信号输出的温湿度复合传感器，内部集成电阻式感湿元件和NTC测温元件，通过专用的8位单片机进行信号处理和校准。该传感器的核心特征在于**单总线协议**——只使用一根DATA数据线即可完成双向通信，无需额外的时钟线或片选线。

| 参数 | 范围 | 精度 | 分辨率 |
|------|------|------|--------|
| 湿度测量 | 20-90%RH | ±5%RH | 1%RH |
| 温度测量 | 0-50℃ | ±2℃ | 1℃ |
| 供电电压 | 3-5.5V DC | — | — |
| 采样周期 | ≥1秒 | — | — |
| 数据输出 | 40位数字信号 | — | 8bit×5 |

**项目接线**：DHT11的DATA引脚连接到STM32的PC14引脚，通过4.7KΩ上拉电阻保持空闲高电平。传感器供电3.3V，上电后需等待1秒越过不稳定状态。

Sources: `BSP/DHT11/dht11.h#L1-L55`, `书籍_md/DHT11说明书最新版.md#L1-L168`

## 单总线协议原理

单总线（One-Wire）协议的核心思想是**时分复用**：同一根数据线在不同时间段分别承担输出和输入功能。总线空闲状态为高电平，由上拉电阻维持。通信过程由主机（STM32）发起，DHT11作为从机响应。

**为什么DHT11选择单总线协议？** 与I²C、SPI等标准协议不同，DHT11没有专用的硬件控制器支持，必须通过GPIO手动模拟时序。这种设计虽然增加了软件复杂度，但降低了硬件成本和引脚占用。

通信流程遵循严格的时序规范，每个阶段的电平持续时间都有明确要求：



**完整通信时序表**：

| 阶段 | DATA电平 | 持续时间 | 控制方 | 作用 |
|------|----------|----------|--------|------|
| 起始信号 | 低电平 | ≥18ms | MCU | 通知DHT11准备通信 |
| 起始信号 | 高电平 | 20-40μs | MCU | 释放总线，等待响应 |
| 应答信号 | 低电平 | ~80μs | DHT11 | 表示传感器已响应 |
| 应答信号 | 高电平 | ~80μs | DHT11 | 准备发送数据 |
| 数据位 | 低电平 | ~50μs | DHT11 | 每位数据的起始 |
| 数据位 | 高电平 | 26-28μs(0) / ~70μs(1) | DHT11 | 高电平宽度决定bit值 |
| 结束信号 | 低电平 | ~50μs | DHT11 | 数据传输结束 |

Sources: `书籍_md/DHT11说明书最新版.md#L79-L108`, `BSP/DHT11/dht11.c#L1-L175`

## 数据格式与校验机制

DHT11每次完整通信传输**40位数据**（5字节），高位先出。数据格式如下：

| 字节序号 | 缓冲区索引 | 内容 | 取值范围 | 说明 |
|----------|------------|------|----------|------|
| 第1字节 | BUF[0] | 湿度整数 | 0-99 | 相对湿度整数部分 |
| 第2字节 | BUF[1] | 湿度小数 | 0 | DHT11固定为0 |
| 第3字节 | BUF[2] | 温度整数 | 0-50 | 温度整数部分 |
| 第4字节 | BUF[3] | 温度小数 | 0 | DHT11固定为0 |
| 第5字节 | BUF[4] | 校验和 | 0-255 | 前4字节累加和低8位 |

**校验公式**：`BUF[4] == (BUF[0] + BUF[1] + BUF[2] + BUF[3]) & 0xFF`

例如：湿度65%、温度25℃时，校验和 = 65 + 0 + 25 + 0 = 90，若BUF[4]等于90则数据有效。

**为什么需要校验？** 单总线协议没有时钟线，时序完全依赖延时控制，容易受到电磁干扰。40位数据中任何一位出错都会导致温湿度值错误，校验机制是数据可靠性的最后防线。

Sources: `BSP/DHT11/dht11.c#L12-L13`, `BSP/DHT11/dht11.c#L131-L139`

## 驱动架构设计

### GPIO动态切换机制

单总线协议要求同一根数据线既能输出（发送起始信号）又能输入（接收DHT11数据）。驱动通过**GPIO模式动态切换**实现这一需求：

1. **输出模式**（`GPIO_Mode_Out_PP`）：推挽输出，MCU控制引脚电平发送起始信号
2. **输入模式**（`GPIO_Mode_IN_FLOATING`）：浮空输入，MCU读取DHT11发送的数据

**切换时机**：每次读取前先配置为输出模式发送起始信号，然后立即切换为输入模式等待DHT11响应。



Sources: `BSP/DHT11/dht11.c#L21-L36`, `BSP/DHT11/dht11.c#L45-L53`

### led_d 结构体设计

驱动使用`led_d`结构体封装GPIO端口和引脚信息，实现**硬件抽象**：

```c
typedef GPIO_TypeDef*   gpioled;

typedef struct{
    gpioled port;      // GPIO端口指针（GPIOA~GPIOG）
    uint16_t pin;      // GPIO引脚号（GPIO_Pin_0 ~ GPIO_Pin_15）
} led_d;
```

**设计优势**：
- **可移植性**：同一驱动代码可操作任意GPIO引脚
- **模块化**：避免硬编码引脚信息，便于硬件修改
- **复用性**：蜂鸣器、按键等外设也使用相同结构体

**全局实例**：`led_d dht;` 在 `main.h` 中定义，供整个项目使用。

Sources: `BSP/GPIO/gpiox.h#L15-L18`, `USER/main.h#L61`

## 核心函数实现详解

### DHT11_Start() - 发送起始信号

起始信号是整个通信的**触发点**，MCU通过控制DATA引脚电平通知DHT11准备数据：

```c
void DHT11_Start(led_d *io)
{
    GPIO_InitTypeDef GPIO_InitStructure;
    
    chushi(io);                          // 使能对应GPIO端口时钟
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;  // 推挽输出模式
    GPIO_InitStructure.GPIO_Pin = io->pin;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(io->port, &GPIO_InitStructure);
    
    GPIO_ResetBits(io->port, io->pin);   // 拉低DATA线
    delay_ms(20);                        // 保持低电平20ms（≥18ms）
    GPIO_SetBits(io->port, io->pin);     // 拉高DATA线
    delay_us(30);                        // 保持高电平30μs（20-40μs）
    GPIO_ResetBits(io->port, io->pin);   // 再次拉低，结束起始信号
}
```

**时序关键点**：
- **20ms低电平**：确保DHT11从低功耗模式唤醒
- **30μs高电平**：释放总线，给DHT11响应窗口
- **chushi()函数**：根据GPIO端口自动使能对应时钟

Sources: `BSP/DHT11/dht11.c#L21-L36`

### DHT_Read_Byte() - 读取单字节数据

这是驱动的核心算法，实现了**逐位采样**的精确时序控制：

```c
u8 DHT_Read_Byte(led_d *io)
{
    u8 temp;  
    u8 ReadDat = 0; 
    u8 t = 0;
    u8 i; 
 
    for(i = 0; i < 8; i++)  // 读取8位
    {
        while(readpin(io) == 0 && t < 100)  // 等待低电平结束
        {		
            delay_us(1);
            t++;  // 超时计数器，防止卡死
        }
        t = 0;
        
        // 关键采样点：延时30μs后判断电平
        delay_us(30);
        temp = 0;
        if(readpin(io) == 1) temp = 1;  // 高电平=1，低电平=0
            
        while(readpin(io) == 1 && t < 100)  // 等待高电平结束
        {		
            delay_us(1);
            t++;
        }
        t = 0;
        
        ReadDat <<= 1;  // 左移1位，为新数据腾出位置
        ReadDat |= temp; // 存入当前位
    }	
    return ReadDat;
}
```

**为什么delay_us(30)是关键采样点？**



- **数字0**：高电平持续26-28μs
- **数字1**：高电平持续约70μs
- **采样点30μs**：恰好位于两者之间，是最佳判断时机
- 30μs时若为低电平→数字0；若仍为高电平→数字1

**LSB先传机制**：`ReadDat <<= 1; ReadDat |= temp;` 表示先读到的位放在最低位，符合DHT11协议规定的"低位先传"规则。

Sources: `BSP/DHT11/dht11.c#L62-L92`

### DHT_Read_Data() - 完整数据采集

这是驱动的**顶层接口**，协调整个通信流程并提供数据校验：

```c
u8 DHT_Read_Data(u8 *temp, u8 *humi, gpioled port, u16 pin, led_d *io)
{
    u8 i;
    u8 t = 0;
    io->port = port;
    io->pin = pin;
    
    DHT11_Start(io);      // 发送起始信号
    DHT11_Read(io);       // 切换为输入模式
    delay_us(20);         // 等待20μs，检查DHT11响应
    
    if(readpin(io) == 0)  // 读到低电平，DHT11响应了
    {
        // 等待响应信号的低电平结束（剩余60μs）
        while(readpin(io) == 0 && t < 100)
        {
            delay_us(1);
            t++;			
        }
        t = 0;
        
        // 等待响应信号的高电平结束（80μs）
        while(readpin(io) == 1 && t < 100)
        {
            delay_us(1);
            t++;			
        }
        t = 0;
        
        // 读取40位数据（5字节）
        for(i = 0; i < 5; i++)
        {
            BUF[i] = DHT_Read_Byte(io);
        }
        delay_us(50);  // 结束信号延时
    }
    
    // 校验数据完整性
    sum = BUF[0] + BUF[1] + BUF[2] + BUF[3];
    if(BUF[4] == (u8)sum)  // 校验通过
    {
        *humi = BUF[0];  // 湿度整数值
        *temp = BUF[2];  // 温度整数值
        return 1;        // 成功
    }
    else
        return 0;        // 校验失败
}
```

**响应检测逻辑**：
1. 发送起始信号后切换为输入模式
2. 延时20μs后读取DATA引脚
3. 若为低电平（DHT11拉低响应），继续等待响应完成
4. 若为高电平（无响应），直接返回0

**超时保护机制**：所有等待循环都使用`t<100`计数器，防止DHT11故障时程序卡死。每100μs检查一次，超过100次（10ms）自动跳出。

Sources: `BSP/DHT11/dht11.c#L101-L140`

## RTOS集成与数据流

### 任务调度架构

DHT11驱动在RTOS环境中的调用遵循**周期采集+异步消费**模式：

1. **SensorTask**（优先级3，周期500ms）：调用`DHT_Read_Data()`采集温湿度
2. **WindSpeedTask**（优先级3，周期100ms）：读取温湿度参与风速计算
3. **MotorControlTask**（优先级5，周期50ms）：根据风速输出控制电机

**为什么SensorTask周期为500ms？**
- DHT11最快采样率为1Hz（1秒1次）
- 500ms周期在响应速度和传感器寿命间取得平衡
- 系统环境变化相对缓慢，无需更高频率

Sources: `APP_TASK/app_tasks.c#L263-L288`, `APP_TASK/app_tasks.h#L42-L43`

### 互斥量保护机制

多任务环境下，温湿度数据的读写需要**互斥量保护**：

```c
void SensorTask(void *pvParameters)
{
    u8 temp, humi;
    u8 ret;

    while (1)
    {
        // 读取DHT11数据
        ret = DHT_Read_Data(&temp, &humi, GPIOC, GPIO_Pin_14, &dht);
        if (ret == 1)  // 校验成功
        {
            // 使用互斥量保护共享数据
            if (xSemaphoreTake(g_dataMutex, portMAX_DELAY) == pdTRUE)
            {
                g_systemState.temperature = temp;
                g_systemState.humidity = humi;
                xSemaphoreGive(g_dataMutex);
            }
        }
        
        // 读取MQ2数据（使用单独的互斥量保护）
        // ...
        
        delay_ms(500);  // 500ms采集周期
    }
}
```

**为什么使用互斥量而非队列？**
- **数据新鲜度**：互斥量保证读取最新值，队列可能包含过期数据
- **资源开销**：互斥量仅保护临界区，队列需要额外内存和拷贝
- **访问模式**：温湿度数据是"一写多读"，互斥量更适合

Sources: `APP_TASK/app_tasks.c#L263-L288`, `APP_TASK/app_tasks.h#L35`

### 错误处理策略

DHT11读取失败时的处理策略体现了**容错设计**思想：

1. **校验失败**：`DHT_Read_Data()`返回0，SensorTask不更新`g_systemState`
2. **传感器无响应**：同样返回0，保留上一次有效数据
3. **数据连续性**：系统继续使用上次有效温湿度值，避免风速突变

**为什么保留上次数据而非清零？**
- 环境温湿度变化缓慢，上次数据仍有参考价值
- 清零会导致风速算法异常，可能引起电机误动作
- 系统稳定性优先于数据绝对新鲜度

Sources: `APP_TASK/app_tasks.c#L264-L273`

## 常见问题与调试技巧

### DHT11不响应

**可能原因**：
1. 起始信号时间不足（<18ms）
2. GPIO模式未正确切换
3. 上拉电阻缺失或阻值不当
4. 电源不稳定

**调试方法**：
1. 用示波器检查DATA引脚波形
2. 确认起始信号低电平持续时间
3. 检查DHT11供电是否稳定（3.3V±0.3V）

### 数据校验失败

**可能原因**：
1. 采样时机不准确（delay_us(30)偏差）
2. 电磁干扰导致数据位翻转
3. 传感器老化或损坏

**调试方法**：
1. 增加打印调试信息，观察原始BUF值
2. 尝试更换DHT11模块
3. 缩短DATA线长度，增加屏蔽

### 温度值异常

**可能原因**：
1. 传感器靠近热源（如电机、电源模块）
2. 传感器结露影响测量
3. 长期暴露在化学蒸汽中

**解决方案**：
1. 重新布局PCB，远离热源
2. 避免在结露环境下使用
3. 参考DHT11说明书进行恢复处理

Sources: `书籍_md/DHT11说明书最新版.md#L129-L153`

## 设计权衡与优化方向

### 当前实现的权衡

| 设计决策 | 优点 | 缺点 |
|----------|------|------|
| GPIO动态切换 | 通用性强，可接任意引脚 | 每次读取重新配置，增加开销 |
| 500ms采集周期 | 平衡响应速度与传感器寿命 | 环境突变时响应较慢 |
| 互斥量保护 | 保证数据一致性 | 任务可能阻塞等待 |
| 保留上次数据 | 提高系统稳定性 | 可能使用过期数据 |

### 优化方向

1. **硬件优化**：
   - 使用DHT22替代DHT11，获得更高精度（±0.5℃，±2%RH）
   - 增加硬件滤波电容，减少电源噪声
   - 使用带屏蔽的专用传感器线缆

2. **软件优化**：
   - 实现滑动平均滤波，进一步稳定数据
   - 增加传感器健康检测，连续失败时报警
   - 使用DMA+定时器实现更精确的时序控制

3. **架构优化**：
   - 将传感器抽象为统一接口，支持多种温湿度传感器
   - 实现传感器自检和校准功能
   - 增加温度补偿算法，提高测量精度

Sources: `APP_TASK/app_tasks.c#L263-L288`, `BSP/DHT11/dht11.c#L1-L175`
