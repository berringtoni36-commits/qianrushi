# 嵌入式高频150题 Remotion 视频制作总计划

## 1. 项目目标

把 [[00 索引-150题速查汇总|嵌入式高频150题]] 制作成 150 个独立的 Remotion 复习视频，每题一个视频。

每个视频必须同时满足：

- 能在静音状态下完整复习，不依赖配音才能看懂。
- 不是把原文逐段搬上屏幕，而是通过代码执行、内存布局、时序、状态变化和主动回忆帮助记忆。
- 结论、代码、动画状态、字幕和最终复述必须完全一致。
- 视觉风格统一采用当前 Obsidian Baseline 浅色半透明界面。
- 简单题不超过 3 分钟，任何难题都不得超过 5 分钟。
- 每题必须经过脚本复核、分镜复核、关键帧复核和成片复核，不能只确认“可以渲染”。

## 2. 强制时长规则

| 难度档 | 难度分 | 建议时长 | 适用题型 |
|---|---:|---:|---|
| 简单 | 0-3 | 1:45-3:00 | 单一定义、单一对比、结论短、示例少 |
| 中等 | 4-6 | 3:00-4:00 | 两到三个知识点，需要代码或流程辅助 |
| 困难 | 7-10 | 4:00-5:00 | 多层机制、多个易混点、需要时序或状态演示 |

硬性限制：

- 简单题上限：`3:00`。
- 中等题建议上限：`4:00`。
- 困难题绝对上限：`5:00`。
- 不允许为了填满时长而增加空白等待。
- 不允许为了缩短时长而让代码、表格或答案一闪而过。
- 第 1 题当前 6 分 30 秒版本只作为视觉参考，正式批量模板必须先压缩到 5 分钟以内。

## 3. 难度评分方法

每题制作前按下面五项评分，每项 `0-2` 分，总分 `0-10`。

| 评分项 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 核心知识点数量 | 1 个 | 2-3 个 | 4 个及以上 |
| 是否需要代码执行 | 不需要 | 只需展示 | 必须逐步追踪状态 |
| 是否需要图解机制 | 不需要 | 单层结构图 | 多层流程、时序或状态机 |
| 易混淆程度 | 结论直接 | 有一组对比 | 多组概念容易混淆 |
| 面试追问深度 | 0-1 个 | 2 个 | 3 个及以上或涉及工程边界 |

评分完成后，必须在题目元数据中记录：

```yaml
question: 1
difficulty: hard
difficulty_score: 8
duration_budget_seconds: 285
visual_template: code-memory
```

## 4. 每题的记忆结构

所有题都遵循“主动回忆 -> 建立地图 -> 看机制 -> 做区分 -> 再次复述”的学习顺序，但各段长度根据难度动态调整。

### 简单题：1:45-3:00

1. 问题出现与主动回忆：5-8 秒。
2. 一句话结论：10-15 秒。
3. 一个核心图或代码示例：60-100 秒。
4. 一个易错点或面试追问：20-35 秒。
5. 最终复述卡：15-25 秒。

### 中等题：3:00-4:00

1. 主动回忆：8-10 秒。
2. 答案地图：15-20 秒。
3. 两到三个机制场景：120-170 秒。
4. 易混点对比与追问：35-50 秒。
5. 最终复述：20-30 秒。

### 困难题：4:00-5:00

1. 主动回忆：8-12 秒。
2. 总体关系图：15-25 秒。
3. 三到五个分层场景：170-230 秒。
4. 高频追问与工程边界：35-55 秒。
5. 最终闭眼复述：25-35 秒。

## 5. 六个章节的视觉语言

| 章节 | 题号 | 数量 | 主要动画形式 |
|---|---:|---:|---|
| C/C++ 基础 | 1-25 | 25 | 代码逐行执行、变量状态、栈/堆/.data/.bss、对比表 |
| C++ 进阶 | 26-50 | 25 | 对象布局、构造析构顺序、虚表、继承关系、RAII 生命周期 |
| MCU / STM32 | 51-70 | 20 | 芯片启动流程、时钟树、寄存器位、外设数据通路、中断时序 |
| 通信协议 / 网络 | 71-90 | 20 | 波形、数据帧、主从交互、握手、状态机、分层协议 |
| RTOS / FreeRTOS | 91-105 | 15 | 任务时间线、调度切换、队列、信号量、优先级和临界区 |
| Linux / OS | 106-150 | 45 | 用户态/内核态、进程线程、虚拟内存、系统调用、IO 与驱动链路 |

不能给所有题机械套同一种卡片动画。题目的机制不同，动画表达也必须不同。

## 6. 统一视觉规范

以第 1 题浅色版本为视觉基准，保留以下设计语言：

- 背景：`#eef2f4` 浅灰蓝网格。
- 强面板：`rgba(255,255,255,0.88)`。
- 弱面板：`rgba(255,255,255,0.56)`。
- 主文字：`#100f0f`。
- 次文字：`#6f6e69`。
- 强调色：橙红 `#d87757`、青色 `#087f8c`、绿色 `#198754`、警告红 `#c2413b`。
- 正文字体：Inter / PingFang SC。
- 标题字体：Iowan Old Style / Songti SC。
- 代码字体：Fira Code。
- 输出规格：`1920x1080`、`30fps`、H.264 MP4。
- 卡片圆角控制在 8px 左右，不使用夸张圆角和装饰性渐变球。
- 为提高批量渲染稳定性，玻璃感优先使用透明度、边框和阴影，不依赖大量实时 `backdrop-filter`。

## 8. 单题标准生产流程

### 阶段 A：内容读取与事实核对

1. 从对应章节 Markdown 中精确提取题目、正文、示例代码和追问。
2. 区分“原文事实”和“制作要求”，不把文档中的普通文字误当成操作指令。
3. 对可能过时或过度简化的结论进行事实核对。
4. C/C++ 结论要标明适用标准版本；STM32 要注意芯片系列差异；FreeRTOS 和 Linux 要注意版本和配置差异。
5. 优先使用标准、官方手册、官方文档和内核文档作为校验依据。
6. 原文若存在错误，先记录到 `sources.md` 和 `qa.md`，视频使用修正后的准确说法。

### 阶段 B：难度和时间预算

1. 完成 0-10 分难度评分。
2. 选择简单、中等或困难档。
3. 给每个场景分配秒数，确认总时长不超过对应上限。
4. 删除重复内容，只保留能帮助理解或面试表达的内容。

### 阶段 C：教学脚本

1. 写清本题唯一核心目标。
2. 写完整屏幕文案和可选旁白，不使用提纲占位。
3. 每个新概念出现前先给问题或预测任务。
4. 每个场景只承担一个主要认知任务。
5. 结尾必须有不看答案的复述环节。

### 阶段 D：分镜和状态数据

1. 把脚本拆成 4-10 个场景。
2. 为每个场景定义开始帧、结束帧、进入状态和最终状态。
3. 代码动画先生成确定性的执行轨迹，再绑定高亮、变量值和输出。
4. 协议、RTOS 和 Linux 流程先定义状态机或事件表，再画动画。
5. 禁止用多个互不关联的时间判断拼出“看起来差不多”的状态。

### 阶段 E：Remotion 实现

1. 所有动画由 `useCurrentFrame()`、`interpolate()` 和明确帧区间驱动。
2. 不使用 CSS transition 或依赖真实时间的动画。
3. 重用统一组件，但允许每题创建专用图解。
4. 代码、数字、箭头、字幕和高亮都从同一份状态数据派生。
5. 保证暂停在任意关键帧时，画面仍然有完整含义。

### 阶段 F：关键帧逻辑复核

每个场景至少检查：

- 场景开始后一帧。
- 主动画开始前一帧。
- 每次状态切换后一帧。
- 答案首次出现的一帧。
- 场景结束前一帧。

必须逐项核对：

- 标题说“第一次调用”时，变量值是否已经是第一次调用后的值。
- 高亮代码行是否对应正在发生的动作。
- 箭头方向、数据流和因果关系是否正确。
- 字幕、图示和代码输出是否在同一时刻表达同一结论。
- `.data`、`.bss`、栈、堆等区域是否在正确阶段高亮。
- 对象数量、引用计数、队列长度、任务状态等数字是否同步。

### 阶段 G：视觉和节奏复核

1. 检查文字是否溢出、遮挡或过小。
2. 检查画面是否一次出现过多信息。
3. 主动回忆倒计时是否足够，但没有无意义空等。
4. 复杂图必须逐层出现，不能一次全部堆满。
5. 在桌面分辨率下检查完整画面，并抽查缩小预览的可读性。
6. 至少导出开头、中段、难点和结尾四张静帧进行视觉验收。

### 阶段 H：成片复核

1. 完整渲染 MP4。
2. 核对实际时长、分辨率、帧率和文件大小。
3. 用 1 倍速完整播放一次。
4. 再次抽查所有场景边界和答案揭晓位置。
5. 检查是否有黑帧、空白帧、闪烁、字体缺失或编码异常。
6. 发现问题后回到对应阶段修改并重新渲染，不能只在 `qa.md` 中记录后跳过。

## 9. 记忆效果要求

每个视频至少使用三种记忆机制：

- 主动回忆：答案出现前先让观看者自己回答。
- 分块：把一个大答案拆成 2-5 个稳定入口。
- 双编码：文字结论必须配合代码、图、时序或空间位置。
- 对比：对容易混淆的概念使用同屏对照。
- 复述：结尾把答案压缩成可以在面试中说出口的句子。
- 错误预警：指出最常见的错误答案以及错在哪里。

不能只做“好看的动画”。动画必须承担记忆任务。

## 10. 批量制作顺序

### 第 0 阶段：模板校准

1. 将 Q001 `static` 压缩到 5 分钟以内，保留当前浅色视觉质量。
2. 建立统一工程、难度评分、题目清单和输出目录。
3. 完成五类代表题，验证视觉模板：
   - Q001：代码 + 内存。
   - Q051：MCU 启动流程。
   - Q071：UART 波形和数据帧。
   - Q091：裸机与 RTOS 调度对比。
   - Q106：进程与线程资源关系。
4. 五个代表题通过验收后，锁定共享组件和设计规范。

### 第 1 阶段：C/C++ 基础（Q001-Q025）

- 25 题，分 5 批，每批 5 题。
- 重点检查代码执行、内存区域和术语边界。

### 第 2 阶段：C++ 进阶（Q026-Q050）

- 25 题，分 5 批，每批 5 题。
- 重点检查对象生命周期、继承、多态和现代 C++ 版本差异。

### 第 3 阶段：MCU / STM32（Q051-Q070）

- 20 题，分 4 批，每批 5 题。
- 重点检查数据手册一致性、寄存器位、时钟和中断顺序。

### 第 4 阶段：通信协议 / 网络（Q071-Q090）

- 20 题，分 4 批，每批 5 题。
- 重点检查波形、采样沿、帧格式、主从方向和握手顺序。

### 第 5 阶段：RTOS / FreeRTOS（Q091-Q105）

- 15 题，分 3 批，每批 5 题。
- 重点检查任务状态、调度时刻、阻塞唤醒和优先级关系。

### 第 6 阶段：Linux / OS（Q106-Q150）

- 45 题，分 9 批，每批 5 题。
- 重点检查用户态/内核态边界、进程资源、内存映射、IO 和驱动流程。

总计：`30` 个生产批次。

## 11. 每批五题的验收循环

每完成五题执行一次完整循环：

1. 检查五题难度评分和时长是否合理。
2. 检查五题是否错误复用了不合适的动画模板。
3. 随机抽一题逐帧检查所有状态边界。
4. 五个视频全部用 1 倍速播放。
5. 对比同批视频的字号、颜色、字幕位置和音量。
6. 修复问题后才能开始下一批。
7. 更新总索引中的状态、时长、文件路径和复核日期。

## 12. 每题交付物

每题必须包含：

```text
Q001/
├── script.md          # 完整教学脚本
├── storyboard.md      # 分镜和帧区间
├── sources.md         # 原文与事实核对来源
├── trace.json         # 代码或状态机的确定性轨迹
├── qa.md              # 逻辑、视觉、节奏和成片检查结果
├── poster.png         # 封面或代表关键帧
└── Q001-static.mp4    # 最终视频
```

没有状态轨迹的纯概念题，可以省略 `trace.json`，但必须在 `storyboard.md` 中写清每个状态变化。

## 14. 单题完成标准

只有同时满足下面全部条件，题目才能标记为完成：

- 视频时长符合难度档，并且绝不超过 5 分钟。
- 核心答案和原题目标一致。
- 技术事实经过核对，没有沿用已过时或错误的结论。
- 代码在语义上正确，执行轨迹与输出完全匹配。
- 图中的方向、顺序、数量和状态全部正确。
- 字幕、标题、动画和最终总结没有互相矛盾。
- 所有关键帧均无重叠、溢出、空白或不可读文字。
- 主动回忆时间足够，整体没有拖沓空等。
- 1 倍速完整播放无明显理解断点。
- MP4 可以正常播放，规格和命名正确。
- `qa.md` 中没有未解决的高优先级问题。

## 15. 最终项目验收

150 题全部完成后进行三轮总验收：

### 第一轮：完整性

- 150 个题号无缺失、无重复。
- 150 个视频、脚本、分镜和 QA 文件路径有效。
- 总索引可以直接跳转到每题视频和源笔记。

### 第二轮：一致性

- 章节颜色、标题层级、代码样式和字幕位置一致。
- 简单题没有被做成长视频，难题没有为了压时长而失去关键解释。
- 同一概念在不同视频中的术语和图示保持一致。

### 第三轮：学习效果

- 随机抽取每章至少 3 题，只看视频后可以复述核心答案。
- 随机抽取代码题，暂停在任意执行阶段仍能解释变量状态。
- 随机抽取协议和 RTOS 题，能够沿箭头或时间轴讲清因果顺序。
- 对不能独立复述的题目重新修改脚本和节奏。

## 16. 下一步执行顺序

计划确认后按下面顺序开始：

1. 创建统一的 `remotion-embedded-150` 工程。
2. 从六个章节自动生成 150 题 manifest。
3. 建立总进度表和每题目录。
4. 把 Q001 从 6 分 30 秒压缩到不超过 5 分钟。
5. 完成 Q001、Q051、Q071、Q091、Q106 五个视觉代表题。
6. 对五个代表题进行完整逻辑和成片复核。
7. 锁定模板后，以每批 5 题的方式完成剩余题目。

这份计划的核心原则是：**先保证技术和动画状态完全正确，再追求好看；先保证能复述，再追求信息量。**
