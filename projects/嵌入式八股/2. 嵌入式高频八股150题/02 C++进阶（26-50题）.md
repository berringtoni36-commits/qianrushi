### 第26题：C++ 面向对象的三大特性是什么？

> [!tip] 🔗 项目关联
> - [[projects/嵌入式八股/1. 项目八股/RTOS高频面试题#A11. 如何用 C 语言实现面向对象思想？|RTOS项目 A11：用 C 语言实现面向对象思想]]

> **封装隐藏实现、继承复用代码、多态统一接口，三者共同管理复杂度。**

#### ① 三大特性速查表

| **特性** | 一句话解释 | 核心价值 | 嵌入式场景举例 |
|------|-----------|---------|---------------|
| **封装** | 数据 + 方法打包，访问权限隐藏内部细节 | 模块边界清晰 | 一个 `Sensor` 类封装寄存器读写逻辑 |
| **继承** | 子类复用父类属性和行为 | 减少重复代码 | `SPIDevice` 继承 `Device` 基类 |
| **多态** | 同一接口，不同对象有不同行为 | 统一调用接口 | 基类指针调 `read()`，不同传感器执行不同逻辑 |

#### ② 嵌入式实际应用：设备驱动抽象

```cpp
class Sensor {                          // 基类：封装通用接口
public:
    virtual float read() = 0;           // 纯虚函数，定义统一接口
};
class TempSensor : public Sensor {      // 继承：复用接口定义
public:
    float read() override { return readTempReg(); }  // 多态：各自实现
};
class AccelSensor : public Sensor {
public:
    float read() override { return readAccelReg(); }
};
```

#### ③ 面试重点：记住什么

- 封装 → `private/protected/public` 控制访问
- 继承 → 复用代码 + 建立类型层次
- 多态 → 虚函数实现**运行时**多态，函数重载实现**编译期**多态
- 嵌入式注意：虚函数、动态内存、异常在资源受限场景有额外开销，需谨慎使用

#### 面试常问追问

| 追问 | 关键回答 |
|------|---------|
| **多态的实现方式有哪些？** | 编译期多态（函数重载、模板）+ 运行期多态（虚函数） |
| **封装的意义是什么？** | 隐藏实现细节，只暴露必要接口，降低模块耦合 |
| **C++ 的继承默认什么权限？** | `class` 默认 `private`，`struct` 默认 `public` |
| **面向对象在嵌入式中值得用吗？** | 值得，但要注意虚函数和动态内存的开销，按需使用 |

### 第27题：虚函数的底层实现机制是什么？

> **虚函数通过虚函数表（vtable）+ 虚表指针（vptr）实现运行时多态。**

#### ① 虚函数调用流程（ASCII 图）

```text
对象内存布局：                  虚函数表（vtable）：
┌──────────────┐               ┌──────────────────┐
│  vptr ───────┼──────────────>│ [0] &Derived::func1 │
├──────────────┤               │ [1] &Derived::func2 │
│  成员变量     │               │ [2] &Derived::func3 │
└──────────────┘               └──────────────────┘
```

#### ② 调用过程拆解

| **步骤** | 动作 | 说明 |
|------|------|------|
| **1** | 通过对象的 `vptr` 找到对应的 `vtable` | 每个含虚函数的类有一张 vtable |
| **2** | 从 `vtable` 中取出函数地址 | 虚函数在表中的偏移是编译期确定的 |
| **3** | 间接调用该函数 | 实际执行的是派生类重写后的版本 |

#### ③ 代码示例

```cpp
class Base {
public:
    virtual void speak() { cout << "Base" << endl; }  // 虚函数
    void hello() { cout << "Hi" << endl; }            // 普通函数
};
class Dog : public Base {
public:
    void speak() override { cout << "Woof" << endl; } // 重写虚函数
};
Base* p = new Dog();   // 基类指针指向派生类对象
p->speak();            // 输出 "Woof"，运行时通过 vtable 找到 Dog::speak
p->hello();            // 输出 "Hi"，普通函数编译期直接绑定
```

#### ④ 虚函数的代价

| **代价项** | 说明 |
|--------|------|
| **对象体积** | 每个对象多一个 `vptr`（通常 4 或 8 字节） |
| **调用开销** | 多一次间接寻址（vtable 查表） |
| **内联失效** | 虚函数通常无法被内联优化 |

#### 面试常问追问

| 追问 | 关键回答 |
|------|---------|
| **vtable 是每个对象一份还是每个类一份？** | 每个类一份，所有该类对象共享同一张 vtable |
| **vptr 在对象构造的什么时候初始化？** | 构造函数执行前，编译器自动插入 vptr 初始化代码 |
| **虚函数能内联吗？** | 编译期确定类型时可以，通过基类指针调用时一般不能 |
| **构造函数能是虚函数吗？** | 不能，构造时 vptr 还没初始化完成，无法做动态绑定 |

### 第28题：纯虚函数和抽象类是什么？

> **纯虚函数 `= 0` 定义接口规范；含纯虚函数的类是抽象类，不能实例化，只用来被继承。**

#### ① 核心概念对比

| **概念** | 语法 | 能否实例化 | 能否有函数体 |
|------|------|-----------|-------------|
| **虚函数** | `virtual void f()` | ✅ 可以 | ✅ 有 |
| **纯虚函数** | `virtual void f() = 0` | ❌ 不可以 | ✅ 可以有（少见） |
| **抽象类** | 含至少一个纯虚函数的类 | ❌ 不可以 | — |

#### ② 嵌入式典型用法：设备接口抽象

```cpp
class IDevice {                                     // 抽象类：定义接口规范
public:
    virtual void init() = 0;                        // 纯虚函数：必须由子类实现
    virtual int read(uint8_t* buf, int len) = 0;
    virtual ~IDevice() {}                           // 虚析构：防止资源泄漏
};
class UARTDevice : public IDevice {
public:
    void init() override { /* 配置串口寄存器 */ }    // 实现接口
    int read(uint8_t* buf, int len) override { /* 读串口数据 */ return 0; }
};
```

#### ③ 面试重点：记住什么

- 抽象类 = 含纯虚函数的类 → 不能 `new`，只能用指针/引用指向派生类
- 纯虚函数**也可以有函数体**（`void f() = 0;` 可以在类外定义），但类仍然是抽象类
- 抽象类作为基类时，**析构函数应该声明为虚函数**
- 用途：定义接口规范，实现依赖倒置，让上层代码只依赖抽象接口

#### 面试常问追问

| 追问 | 关键回答 |
|------|---------|
| **抽象类能不能有成员变量？** | 可以，抽象类只是不能实例化，其他和普通类一样 |
| **纯虚函数可以有函数体吗？** | 可以，但类仍然是抽象类，子类仍必须重写 |
| **抽象类和接口的区别？** | C++ 没有 `interface` 关键字，用纯虚函数类模拟接口 |
| **什么时候用抽象类？** | 多个子类有统一接口、需要运行时多态时使用 |

### 第29题：为什么析构函数通常要声明为虚函数？

> **基类指针 `delete` 派生类对象时，虚析构确保派生类资源被正确释放。**

#### ① 问题演示：非虚析构导致资源泄漏

```cpp
class Base {
public:
    ~Base() { cout << "Base dtor" << endl; }        // 非虚析构
};
class Derived : public Base {
    int* data;
public:
    Derived() { data = new int[100]; }              // 派生类申请了堆内存
    ~Derived() { delete[] data; cout << "Derived dtor" << endl; }
};
Base* p = new Derived();
delete p;    // ❌ 只调用 Base::~Base()，Derived 的 data 泄漏！
```

#### ② 虚析构 vs 非虚析构对比

| **场景** | 非虚析构 | 虚析构（`virtual ~Base()`） |
|------|---------|--------------------------|
| **`Base* p = new Derived(); delete p;`** | ❌ 只调用 Base 析构 | ✅ 先调用 Derived 析构，再调用 Base 析构 |
| **`Derived d;` 局部对象** | ✅ 正常析构 | ✅ 正常析构 |
| **资源释放** | 派生类资源泄漏 | 完整释放 |

#### ③ 什么时候需要虚析构，什么时候不需要

```text
需要虚析构：                          不需要虚析构：
├── 作为多态基类使用                   ├── 不会被继承的类
├── 可能通过基类指针 delete 派生类       ├── 不通过基类指针删除派生类对象
└── 有虚函数的类                       └── 纯值类型 / POD 类型
```

#### ④ 一句话记忆规则

> **有虚函数 → 就给虚析构**。如果一个类有虚函数（说明它要被多态使用），那它的析构函数大概率也应该声明为 `virtual`。

#### 面试常问追问

| 追问 | 关键回答 |
|------|---------|
| **虚析构的代价是什么？** | vtable 多一个析构函数入口，对象多一个 vptr，开销很小 |
| **纯虚析构可以吗？** | 可以，但必须在类外提供函数体 `Base::~Base() {}` |
| **智能指针还需要虚析构吗？** | `shared_ptr` 会记住类型信息，但最佳实践仍然建议给虚析构 |
| **STL 容器里存基类指针需要虚析构吗？** | 容器存的是对象本身不涉及，但如果存指针并手动删除就需要 |

### 第30题：什么是菱形继承？如何解决？

> **菱形继承导致基类数据重复，用虚继承解决，确保只保留一份基类成员。**

#### ① 菱形继承结构图

```text
        ┌──────────┐
        │   A      │  ← 顶层基类（如：Animal）
        └────┬─────┘
       ┌─────┴─────┐
       ▼           ▼
  ┌────────┐  ┌────────┐
  │   B    │  │   C    │  ← 中间派生类（如：Dog, Bird）
  └────┬───┘  └────┬───┘
       └─────┬─────┘
             ▼
       ┌──────────┐
       │    D     │  ← 最终派生类（如：FlyingDog）
       └──────────┘

问题：D 中有两份 A 的成员数据 → 二义性 + 浪费内存
```

#### ② 问题演示与解决

```cpp
class A { public: int val = 1; };
class B : public A {};           // B 有一份 A::val
class C : public A {};           // C 有一份 A::val
class D : public B, public C {}; // D 有两份 A::val → 二义性！

// d.val = 1;  ❌ 编译报错：是 B::val 还是 C::val？
// d.B::val 和 d.C::val 是两个不同的变量，地址不同
```

#### ③ 解决方案：虚继承

```cpp
class A { public: int val = 1; };
class B : virtual public A {};   // 虚继承：共享同一份 A
class C : virtual public A {};   // 虚继承：共享同一份 A
class D : public B, public C {}; // ✅ 只有一份 A::val，无二义性
```

#### ④ 虚继承的代价与注意事项

| **方面** | 说明 |
|------|------|
| **内存开销** | 每个虚继承类多一个虚基类指针（vbptr），用于定位共享的虚基类 |
| **构造顺序** | 虚基类的构造由最底层派生类负责，中间类的虚基类构造列表被忽略 |
| **性能** | 访问虚基类成员需要通过 vbptr 间接寻址，略慢 |
| **建议** | 尽量在设计时避免菱形继承，实在需要再用虚继承 |

#### 面试常问追问

| 追问 | 关键回答 |
|------|---------|
| **虚继承的内存布局是怎样的？** | 通过 vbptr 找到虚基类的偏移量，虚基类放在对象末尾 |
| **虚基类构造函数谁负责调用？** | 最底层派生类（D）直接调用虚基类（A）的构造函数 |
| **C++ 有 `interface` 关键字吗？** | 没有，用纯虚函数类模拟，但要注意菱形继承问题 |
| **工程中菱形继承常见吗？** | 不常见，应尽量用组合代替多重继承 |

### 第31题：深拷贝和浅拷贝有什么区别？

> **浅拷贝只复制指针值（共享资源），深拷贝复制指针指向的内容（独立资源）。**

#### ① 核心区别对比表

| **特性** | 浅拷贝 | 深拷贝 |
|------|--------|--------|
| **复制内容** | 指针值（地址） | 指针指向的数据 |
| **两个对象** | 共享同一块堆内存 | 各自拥有独立堆内存 |
| **默认行为** | 编译器默认生成的就是浅拷贝 | 需要手动实现 |
| **析构问题** | 两个对象析构同一块内存 → **双重释放** | 各自释放自己的内存 → ✅ 安全 |

#### ② 问题演示

```cpp
class Buffer {
    int* data;
public:
    Buffer(int n) { data = new int[n]; }             // 构造：申请堆内存
    ~Buffer() { delete[] data; }                      // 析构：释放堆内存
    // 默认拷贝构造 = 浅拷贝：两个对象的 data 指向同一块内存
};
Buffer a(10);
Buffer b = a;  // 浅拷贝 → b.data == a.data
// a 析构后 b.data 变成悬空指针，b 析构时 → 重复释放 💥
```

#### ③ 深拷贝实现

```cpp
class Buffer {
    int* data; int size;
public:
    Buffer(int n) : size(n) { data = new int[n]; }          // 构造
    ~Buffer() { delete[] data; }                             // 析构
    Buffer(const Buffer& other) : size(other.size) {        // 深拷贝构造
        data = new int[size];                                // 申请新内存
        memcpy(data, other.data, size * sizeof(int));        // 复制内容
    }
    Buffer& operator=(const Buffer& other) {                // 深拷贝赋值
        if (this != &other) {
            delete[] data;
            size = other.size;
            data = new int[size];
            memcpy(data, other.data, size * sizeof(int));
        }
        return *this;
    }
};
```

#### ④ 记忆口诀

```text
浅拷贝 = 复印地址 → 两个对象共享一份资源 → 双重释放
深拷贝 = 复印内容 → 两个对象各自独立     → 安全
```

#### 面试常问追问

| 追问 | 关键回答 |
|------|---------|
| **编译器默认生成什么拷贝？** | 浅拷贝（逐成员复制） |
| **哪些类必须手动实现深拷贝？** | 管理堆内存、文件句柄、锁等资源的类 |
| **三/五法则是什么？** | 自定义了析构/拷贝/移动之一，通常需要定义其余几个 |
| **用智能指针还需要深拷贝吗？** | `unique_ptr` 不可拷贝，`shared_ptr` 共享所有权，按需选择 |

### 第32题：智能指针有哪些？各自的作用是什么？

> **`unique_ptr` 独占所有权、`shared_ptr` 共享所有权、`weak_ptr` 弱引用打破循环。**

#### ① 三种智能指针对比表

| **特性** | `unique_ptr` | `shared_ptr` | `weak_ptr` |
|------|-------------|-------------|------------|
| **所有权** | 独占 | 共享（引用计数） | 不拥有（弱引用） |
| **能否拷贝** | ❌ 不能 | ✅ 能 | ✅ 能（不增加计数） |
| **能否移动** | ✅ `std::move` | ✅ | — |
| **引用计数** | 无 | 有（强引用） | 有（弱引用，不影响释放） |
| **开销** | 极小（等同裸指针） | 控制块 + 原子计数 | 同 shared_ptr 的控制块 |
| **典型场景** | 资源独占管理 | 多模块共享对象 | 打破循环引用、缓存观察 |

#### ② 使用示例

```cpp
// unique_ptr：独占，离开作用域自动释放
auto p1 = std::make_unique<int>(42);   // 创建独占指针
// auto p2 = p1;                       // ❌ 编译报错，不能拷贝
auto p3 = std::move(p1);              // ✅ 转移所有权，p1 变空

// shared_ptr：共享，引用计数归零时释放
auto s1 = std::make_shared<int>(42);   // 计数 = 1
auto s2 = s1;                          // 计数 = 2
s1.reset();                            // 计数 = 1，对象仍存活

// weak_ptr：观察但不持有
std::weak_ptr<int> w = s2;             // 不增加强引用计数
if (auto sp = w.lock()) {              // lock() 尝试获取 shared_ptr
    cout << *sp;                       // 对象存在才访问
}
```

#### ③ 循环引用问题与解决

```text
问题：A.shared_ptr → B，B.shared_ptr → A
      引用计数永远 ≥ 1 → 内存泄漏 💥

解决：把其中一个改成 weak_ptr → 不增加强引用计数 → 引用计数归零 → 正常释放 ✅
```

#### ④ 嵌入式使用建议

| **场景** | 推荐 |
|------|------|
| **资源独占（驱动对象、状态机）** | `unique_ptr` |
| **多模块共享（共享缓冲区、协议栈）** | `shared_ptr` |
| **观察者/回调/反向引用** | `weak_ptr` |
| **内存极紧张的 MCU** | 慎用 `shared_ptr`（控制块开销），优先考虑栈对象或 `unique_ptr` |

#### 面试常问追问

| 追问 | 关键回答 |
|------|---------|
| **`shared_ptr` 线程安全吗？** | 引用计数增减是原子操作安全的，但对象本身访问不安全 |
| **`make_shared` 比直接 `new` 好在哪？** | 一次内存分配（对象+控制块），效率更高 |
| **`unique_ptr` 适合放容器里吗？** | 适合，用 `std::move` 放入容器 |
| **`weak_ptr` 怎么判断对象是否还活着？** | 调用 `lock()`，返回空 `shared_ptr` 表示已释放 |

### 第33题：左值和右值有什么区别？右值引用是什么？

> **左值有持久地址可取地址，右值是临时值不可取地址；右值引用 `T&&` 绑定右值，为移动语义服务。**

#### ① 左值 vs 右值速查表

| **特性** | 左值（lvalue） | 右值（rvalue） |
|------|---------------|---------------|
| **能否取地址 `&`** | ✅ 可以 | ❌ 不行 |
| **生命周期** | 持续存在（语句结束后仍在） | 临时的（语句结束后销毁） |
| **典型例子** | 变量、`*p`、`a[i]`、返回引用的函数 | 字面量 `42`、临时对象、返回值的函数 |
| **能绑定到** | 左值引用 `T&` | 右值引用 `T&&` |

#### ② 引用类型速记

```cpp
int  a = 10;        // a 是左值
int&  r1 = a;       // ✅ 左值引用绑定左值
// int& r2 = 42;    // ❌ 左值引用不能绑定右值
int&& r3 = 42;      // ✅ 右值引用绑定右值
// int&& r4 = a;    // ❌ 右值引用不能绑定左值（除非 std::move）
int&& r5 = std::move(a);  // ✅ std::move 将左值转为右值引用
```

#### ③ 为什么需要右值引用？

```text
问题场景：
  拷贝一个临时对象 → 申请新内存 → 复制内容 → 析构临时对象
  太浪费了！反正临时对象马上要销毁，直接"偷"它的资源不好吗？

右值引用的作用：
  绑定即将销毁的对象 → 告诉编译器"这个对象可以被移动"
  → 调用移动构造/移动赋值 → 直接转移资源，无需深拷贝
```

#### 面试常问追问

| 追问 | 关键回答 |
|------|---------|
| **`std::move` 做了什么？** | 不移动任何数据，只是把左值强制转为右值引用 |
| **右值引用本身是左值还是右值？** | 有名字的右值引用变量是**左值**（可以取地址） |
| **完美转发是什么？** | `std::forward` 保持参数原始值类别，配合万能引用 `T&&` 使用 |
| **`const T&` 能绑定右值吗？** | 能，但不能修改，也没法触发移动语义 |

### 第34题：移动语义是什么？解决了什么问题？

> **移动语义把资源所有权转移而非复制，避免深拷贝的开销，尤其适合管理堆内存、大缓冲区等资源。**

#### ① 拷贝 vs 移动对比

| **操作** | 拷贝构造 | 移动构造 |
|------|---------|---------|
| **做了什么** | 申请新内存 + 复制内容 | 直接拿走原对象的指针 |
| **原对象** | 不变，仍可正常使用 | 被掏空，处于可析构/可赋值状态 |
| **速度** | 慢（深拷贝） | 快（指针赋值） |
| **适用对象** | 任何对象 | 右值（临时对象或 `std::move` 后的对象） |

#### ② 移动构造函数实现

```cpp
class Buffer {
    int* data; int size;
public:
    // 移动构造：直接偷走资源
    Buffer(Buffer&& other) noexcept                // 右值引用参数
        : data(other.data), size(other.size) {     // 接管指针
        other.data = nullptr;                      // 原对象置空，防止重复释放
        other.size = 0;
    }
    // 移动赋值
    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data;                         // 释放自己的旧资源
            data = other.data;                     // 接管
            size = other.size;
            other.data = nullptr;                  // 原对象置空
            other.size = 0;
        }
        return *this;
    }
};
```

#### ③ 移动语义解决的核心问题

```text
传统拷贝链路：
  函数返回临时对象 → 拷贝构造新对象 → 析构临时对象
  时间：O(n) 深拷贝

移动语义链路：
  函数返回临时对象 → 移动构造新对象（指针赋值）→ 析构空壳临时对象
  时间：O(1) 指针操作
```

#### ④ 移动后对象的状态

> 移动后的原对象处于**合法但未指定状态**：可以析构、可以赋值，但不要读取其内容。

#### 面试常问追问

| 追问 | 关键回答 |
|------|---------|
| **`noexcept` 为什么重要？** | STL 容器在扩容时优先选择 `noexcept` 的移动构造 |
| **移动语义对 `vector` 有什么影响？** | 扩容时搬移元素用移动而非拷贝，性能大幅提升 |
| **嵌入式什么时候用移动语义？** | 大缓冲区、图像、点云等资源的传递和返回 |
| **没有移动语义会怎样？** | 临时对象只能被拷贝，浪费时间和内存 |

### 第35题：拷贝构造函数和赋值运算符有什么区别？

> **拷贝构造是创建新对象时的初始化；赋值运算符是已有对象之间的赋值。关键区分：看目标对象是否已经存在。**

#### ① 核心区别对比表

| **特性** | 拷贝构造函数 | 赋值运算符 |
|------|------------|-----------|
| **触发时机** | 用已有对象**创建新对象** | 两个**已存在**对象之间的赋值 |
| **函数签名** | `T(const T& other)` | `T& operator=(const T& other)` |
| **目标对象** | 刚创建，无旧资源 | 已存在，可能持有旧资源 |
| **是否需要释放旧资源** | ❌ 不需要 | ✅ 需要先释放再拷贝 |
| **是否需要自赋值检查** | ❌ 不需要 | ✅ 需要 `if (this != &other)` |

#### ② 触发场景对比

```cpp
Buffer a(10);
Buffer b(a);          // ① 拷贝构造：用 a 创建新对象 b
Buffer c = a;         // ② 拷贝构造：看似赋值，实际是初始化新对象
c = a;                // ③ 赋值运算符：c 和 a 都已存在
```

#### ③ 完整实现示例

```cpp
class Buffer {
    int* data; int size;
public:
    Buffer(int n) : size(n) { data = new int[n]; }
    ~Buffer() { delete[] data; }

    // 拷贝构造：新对象初始化
    Buffer(const Buffer& other) : size(other.size) {
        data = new int[size];                                  // 申请新内存
        memcpy(data, other.data, size * sizeof(int));          // 复制内容
    }

    // 赋值运算符：已有对象赋值
    Buffer& operator=(const Buffer& other) {
        if (this == &other) return *this;                      // ① 自赋值检查
        delete[] data;                                         // ② 释放旧资源
        size = other.size;
        data = new int[size];                                  // ③ 申请新内存
        memcpy(data, other.data, size * sizeof(int));          // ④ 复制内容
        return *this;
    }
};
```

#### ④ 记忆口诀

```text
拷贝构造 = 造新娃（目标对象不存在，直接初始化）
赋值运算 = 改旧娃（目标对象已存在，先清空再拷贝）
```

#### 面试常问追问

| 追问 | 关键回答 |
|------|---------|
| **`Buffer c = a` 调用哪个？** | 拷贝构造（因为 c 是新创建的） |
| **赋值运算符为什么要返回 `*this`？** | 支持链式赋值 `a = b = c` |
| **赋值运算符为什么必须检查自赋值？** | 防止 `delete[] data` 后再 `memcpy(data, ...)` 读已释放内存 |
| **三/五法则是什么？** | 需要自定义析构/拷贝/移动之一，通常需要定义其余几个 |

### 第36题：C++ 中 struct 和 class 的默认访问权限有什么不同？

> **struct 默认 public，class 默认 private，除此之外两者几乎等价。**

#### ① 默认访问权限对比

| **特性** | struct | class |
|------|--------|-------|
| **成员默认访问权限** | **public** | **private** |
| **默认继承方式** | **public 继承** | **private 继承** |

```cpp
struct S { int x; };       // x 默认 public

struct Base {};

class  D2 : Base {};        // 默认 private 继承
```

#### ③ 工程习惯

- **struct**：通常用于纯数据聚合（配置结构体、通信报文、坐标点等），行为简单
- **class**：通常用于有封装、有行为、有明确接口的对象

| **struct 可以有虚函数吗？** | 可以，和 class 能力完全一样 |
| **两者内存布局一样吗？** | 默认情况内存布局一致，都可能有对齐填充 |

### 第37题：函数重载和函数重写有什么区别？

> **重载是同作用域同名不同参数，编译期多态；重写是继承中覆盖虚函数，运行时多态。**

#### ① 核心区别对比

| **特性** | 函数重载（Overload） | 函数重写（Override） |
|------|---------------------|---------------------|
| **作用域** | 同一类/作用域内 | 子类覆盖基类虚函数 |
| **参数要求** | 参数列表必须不同 | 参数列表必须一致 |
| **是否需要 virtual** | 不需要 | 基类函数必须是 virtual |
| **绑定时机** | 编译期（静态多态） | 运行期（动态多态） |
| **返回值** | 可以不同 | 通常必须一致（协变除外） |

#### ② 代码示例

```cpp
// 重载：同一类中，同名不同参数
class Math {
public:
    int add(int a, int b) { return a + b; }           // 版本1
    double add(double a, double b) { return a + b; }  // 版本2
};

// 重写：子类覆盖基类虚函数
class Base {
public:
    virtual void speak() { /* 基类版本 */ }
};
class Child : public Base {
public:
    void speak() override { /* 子类版本 */ }  // override 检查签名匹配
};
```

#### ③ 还有个隐藏（容易混淆）

- **隐藏**：子类定义同名函数，参数可以不同，会把基类同名函数"藏起来"
- 区分口诀：**重载看参数，重写看虚函数，隐藏看名字查找**
- 想保留基类版本可用 using Base::func;

#### ④ 面试常问追问

| 追问 | 要点 |
|------|------|
| **重载能靠返回值区分吗？** | 不能，只看参数列表 |
| **重写时忘了加 virtual 会怎样？** | 变成隐藏而非重写，没有多态效果 |
| **override 关键字有什么用？** | 让编译器检查是否真的覆盖了基类虚函数 |
| **重载发生在编译期还是运行期？** | 编译期，是静态绑定 |

### 第38题：什么是函数模板和类模板？

> **模板把类型当参数，编译期根据实际类型生成对应代码，实现泛型编程。**

#### ① 函数模板 vs 类模板

| **特性** | 函数模板 | 类模板 |
|------|---------|--------|
| **用途** | 通用算法/工具函数 | 通用容器/工具类 |
| **实例化方式** | 自动推导或显式指定 | 必须显式指定模板参数 |
| **典型例子** | `std::sort`、`std::max` | `vector<T>`、`map<K,V>`、`unique_ptr<T>` |

#### ② 代码示例

```cpp
// 函数模板：编译器根据调用自动推导 T
template<typename T>
T myMax(T a, T b) { return (a > b) ? a : b; }

// 类模板：使用时必须指定类型
template<typename T>
class Box {
    T item;
public:
    void set(T val) { item = val; }
    T get() { return item; }
};

// 使用
int m = myMax(3, 5);       // T 推导为 int
Box<double> b; b.set(3.14); // 显式指定 double
```

#### ③ 模板的工作机制

```text
源代码中的模板定义
        ↓
  编译器遇到模板调用
        ↓
  根据实际类型"实例化"生成具体代码  ← 模板实例化
        ↓
  生成的代码参与正常编译链接
```

- 模板错误通常在**实例化时**才暴露，报错信息可能很长
- 不同类型实例化会生成不同代码 → **代码膨胀**（嵌入式要注意 Flash 占用）

#### ④ 面试常问追问

| 追问 | 要点 |
|------|------|
| **模板是编译期还是运行期？** | 编译期，实例化发生在编译阶段 |
| **为什么模板定义通常放头文件？** | 模板实例化需要看到完整定义，链接时才生成 |
| **模板有什么缺点？** | 代码膨胀、编译慢、错误信息难读 |
| **嵌入式用模板要注意什么？** | 控制实例化类型数量，避免 Flash 暴增 |

### 第39题：C++ 中的异常处理机制是怎样的？

> **try 检测代码块 → throw 抛出异常对象 → catch 捕获并处理，三层配合。**

#### ① 三要素

| **关键字** | 作用 |
|--------|------|
| **ry** | 包裹可能出错的代码 |
| **throw** | 抛出异常对象，中断正常流程 |
| **catch** | 捕获匹配类型的异常并处理 |

#### ② 代码示例

```cpp
try {
    int* p = new int[100];     // 可能抛出 std::bad_alloc
    if (p == nullptr) throw "分配失败"; // 手动抛异常
    delete[] p;
} catch (const std::bad_alloc& e) {   // 捕获特定类型
    // 处理内存分配失败
} catch (...) {                         // 捕获所有异常
    // 兜底处理
}
```

#### ③ 异常处理流程图

```text
正常执行 → 遇到 throw
     ↓
  沿调用栈向上查找匹配的 catch
     ↓
  找到 → 执行 catch 块，栈展开（局部对象自动析构）
  没找到 → 调用 std::terminate，程序终止
```

#### ④ 嵌入式注意事项

- 很多嵌入式项目**关闭异常**（-fno-exceptions），因为异常增加代码体积和运行时开销
- 不使用异常时，用**错误码返回**或 optional/expected 替代
- C++ 标准保证：异常抛出时会正确调用已构造对象的析构函数（栈展开）

#### ⑤ 面试常问追问

| 追问 | 要点 |
|------|------|
| **嵌入式一般用异常吗？** | 通常不用，用错误码或 optional 替代 |
| **catch(...) 是什么？** | 捕获所有类型的异常 |
| **throw 和 return 有什么区别？** | throw 沿调用栈向上跳，return 正常返回 |
| **析构函数里能抛异常吗？** | 绝对不要，可能导致 terminate |

### 第40题：new 失败时会发生什么？

> **默认抛出 std::bad_alloc 异常；使用 nothrow 版本则返回 nullptr。**

#### ① 两种行为

| **场景** | 行为 | 处理方式 |
|------|------|---------|
| new（默认） | 抛出 std::bad_alloc | try-catch 捕获 |
| new(std::nothrow) | 返回 nullptr | 判断指针是否为空 |

#### ② 代码示例

```cpp
// 默认方式：失败抛异常
try {
    int* p = new int[1000000000]; // 内存不够，抛 bad_alloc
} catch (const std::bad_alloc& e) {
    // 处理分配失败
}

// nothrow 方式：失败返回空
int* q = new(std::nothrow) int[1000000000];
if (q == nullptr) {
    // 处理分配失败
}
```

#### ③ 嵌入式建议

- 嵌入式中如果关闭了异常（-fno-exceptions），默认 new 失败会直接调用 std::terminate
- 建议使用 **nothrow 版本** 或自定义 operator new 来处理分配失败
- 最佳实践：**尽量避免动态分配**，优先用静态分配或内存池

#### ④ 面试常问追问

| 追问 | 要点 |
|------|------|
| **malloc 失败返回什么？** | 返回 NULL（不抛异常） |
| **new 和 malloc 失败处理的区别？** | new 默认抛异常，malloc 返回 NULL |
| 怎么让 new 不抛异常？ | 用 new(std::nothrow) 版本 |
| **嵌入式怎么处理 new 失败？** | 关闭异常 + nothrow，或自定义 operator new |

### 第41题：unordered_map 和 map 有什么区别？

> **map 基于红黑树有序，O(log n)；unordered_map 基于哈希表无序，平均 O(1)。**

#### ① 核心对比

| **特性** | map | unordered_map |
|------|-----|---------------|
| **底层结构** | **红黑树** | **哈希表** |
| **元素顺序** | **有序**（按 key 排序） | **无序** |
| **查找复杂度** | O(log n) | 平均 O(1)，最坏 O(n) |
| **插入复杂度** | O(log n) | 平均 O(1) |
| **内存占用** | 较少 | 较多（桶+链表/数组） |
| **适用场景** | 需要有序遍历 | 快速查找、不要求顺序 |

#### ② 选择建议

```text
需要按 key 有序遍历？    → map
需要频繁查找、不关心顺序？ → unordered_map
key 类型没有哈希函数？     → map
嵌入式内存敏感？          → map（哈希表有额外开销）
```

#### ③ 面试常问追问

| 追问 | 要点 |
|------|------|
| **unordered_map 最坏复杂度？** | O(n)，哈希冲突严重时退化 |
| **怎么减少哈希冲突？** | 好的哈希函数 + 合理的负载因子 |
| **map 能用自定义比较器吗？** | 能，模板第三个参数指定 |
| **嵌入式更适合用哪个？** | 通常 map，哈希表内存开销大 |

### 第42题：vector 和 list 有什么区别？

> **vector 连续内存随机访问快，list 双向链表中间插入删除快。**

#### ① 核心对比

| **特性** | vector | list |
|------|--------|------|
| **底层结构** | **连续数组** | **双向链表** |
| **随机访问** | **O(1)**，支持 [] | **O(n)**，需遍历 |
| **尾部插入** | 平均 O(1) | O(1) |
| **中间插入/删除** | O(n)，需移动元素 | O(1)，改指针即可 |
| **缓存友好性** | **好**（连续内存） | 差（节点分散） |
| **内存占用** | 紧凑 | 每个节点有额外指针开销 |

#### ② 性能直觉

```text
vector: [1][2][3][4][5]  ← 连续存储，CPU 缓存友好
          ↕ 快速随机访问，但中间插入要挪后面所有元素

list:   [1]⇄[2]⇄[3]⇄[4]⇄[5]  ← 节点分散，指针连接
          ↕ 中间插入快（改指针），但随机访问要一个个走
```

#### ③ 工程选择

- **默认用 vector**，缓存局部性在实际项目中优势很大
- 频繁在**中间插入/删除**且不需要随机访问 → 考虑 list
- 嵌入式中 vector 可用 `reserve` 预分配避免扩容；list 的节点碎片化可能影响性能

#### ④ 面试常问追问

| 追问 | 要点 |
|------|------|
| **vector 扩容策略？** | 通常 1.5x 或 2x，会重新分配并搬移 |
| **list 可以随机访问吗？** | 不支持 []，需要从头/尾遍历 |
| **嵌入式推荐用哪个？** | 通常 vector + reserve，或固定大小数组 |
| **deque 和它们的区别？** | 分段连续，支持头尾 O(1) 插入 |

### 第43题：迭代器失效是怎么回事？

> **容器内部结构变化后，原来持有的迭代器可能指向非法内存，再使用就是未定义行为。**

#### ① 常见失效场景

| **容器** | 操作 | 后果 |
|------|------|------|
| **vector** | push_back 导致扩容 | **所有迭代器失效** |
| **vector** | 中间 insert/erase | **被操作位置及之后的迭代器失效** |
| **list** | erase 当前迭代器 | 仅当前迭代器失效，其他不受影响 |
| **map** | erase 当前迭代器 | 仅当前迭代器失效 |
| **unordered_map** | rehash 后 | **所有迭代器失效** |

#### ② 代码示例

```cpp
vector<int> v = {1, 2, 3, 4, 5};
auto it = v.begin() + 2;        // 指向 3
v.push_back(6);                  // 如果触发扩容，it 已失效！
// *it;                          // ← 未定义行为，可能崩溃

// 安全删除的写法
for (auto it = v.begin(); it != v.end(); ) {
    if (*it == 3) it = v.erase(it); // erase 返回下一个有效迭代器
    else ++it;
}
```

#### ③ 失效流程图

```text
vector 扩容过程：
旧内存: [1][2][3][4][5]  ← it 指向这里
               ↓ push_back 触发扩容
新内存: [1][2][3][4][5][6]  ← 数据搬过来了
旧内存: [?][?][?][?][?]  ← 已释放，it 悬空！
```

#### ④ 面试常问追问

| 追问 | 要点 |
|------|------|
| **怎么安全删除 vector 元素？** | 用 it = v.erase(it) 接收返回值 |
| **erase 后 it 指向哪？** | 指向被删元素的下一个位置 |
| **怎么避免 vector 迭代器失效？** | 用 reserve 预分配，或用下标代替迭代器 |
| **map 的迭代器什么时候失效？** | 只有 erase 的那个失效，其他不受影响 |

### 第44题：Lambda 表达式的捕获方式有哪些？

> **[] 指定捕获外部变量的方式——值捕获拷贝副本，引用捕获直接引用。**

#### ① 捕获方式一览

| **捕获语法** | 含义 |
|---------|------|
| **[]** | 不捕获任何外部变量 |
| **[x]** | 值捕获 x（拷贝） |
| **[&x]** | 引用捕获 x（可修改原值） |
| **[=]** | 默认值捕获所有用到的外部变量 |
| **[&]** | 默认引用捕获所有用到的外部变量 |
| **[=, &x]** | 默认值捕获，但 x 用引用捕获 |
| **[&, x]** | 默认引用捕获，但 x 用值捕获 |
| **[this]** | 捕获当前对象指针 |
| **[x = expr]** | 初始化捕获（C++14），可以移动捕获 |

#### ② 代码示例

```cpp
int a = 1, b = 2;

auto f1 = [a]()  { return a; };    // 值捕获，a 是副本，不能改
auto f2 = [&b]() { b = 10; };      // 引用捕获，可以修改原值
auto f3 = [=]()  { return a + b; };// 所有用到的按值捕获
auto f4 = [&]()  { b = a + b; };   // 所有用到的按引用捕获
```

#### ③ 注意事项

- 值捕获的变量默认 **const**，想修改要加 `mutable`：`[x]() mutable { x++; }`
- 引用捕获要注意**生命周期**：lambda 可能比被捕获变量活得久 → 悬空引用
- 嵌入式中按值捕获大对象会**拷贝开销**，按引用捕获更高效但要注意安全

#### ④ 面试常问追问

| 追问 | 要点 |
|------|------|
| **值捕获能修改原变量吗？** | 不能，修改的是副本 |
| **[=] 捕获了什么？** | 所有 lambda 体中用到的局部变量的副本 |
| **引用捕获有什么风险？** | 被捕获变量销毁后 lambda 引用悬空 |
| **mutable 是干什么的？** | 允许修改值捕获的变量副本 |

### 第45题：static_cast、dynamic_cast、reinterpret_cast、const_cast 有什么区别？

> **四种显式类型转换各有分工——static_cast 最常用，dynamic_cast 运行期安全检查，reinterpret_cast 最危险，const_cast 去 const。**

#### ① 四种 cast 对比

| **转换类型** | 用途 | 安全性 | 检查时机 |
|---------|------|--------|---------|
| **static_cast** | 编译期可确定的类型转换 | 相对安全 | 编译期 |
| **dynamic_cast** | 继承体系中的向下转换 | **运行期检查**，失败返回 nullptr | 运行期 |
| **reinterpret_cast** | 底层位模式重新解释 | **最不安全** | 无检查 |
| **const_cast** | 添加或去除 const/volatile | 去 const 后修改原值是 UB | 编译期 |

#### ② 代码示例

```cpp
// static_cast：最常用，编译期转换
double d = 3.14;
int i = static_cast<int>(d);        // double → int，截断

// dynamic_cast：向下转型，运行期检查（需要虚函数）
Base* base = new Derived();
Derived* d2 = dynamic_cast<Derived*>(base); // 成功返回指针，失败返回 nullptr

// reinterpret_cast：强制重新解释位模式
int* p = &i;
uintptr_t addr = reinterpret_cast<uintptr_t>(p); // 指针 → 整数地址

// const_cast：去掉 const（危险！）
const int ci = 10;
int* p2 = const_cast<int*>(&ci);  // 去 const，但修改 ci 是未定义行为
```

#### ③ 嵌入式常用场景

| **场景** | 推荐 cast |
|------|----------|
| **整数/浮点互转** | static_cast |
| **基类指针转派生类指针** | dynamic_cast |
| **硬件寄存器地址转换** | `reinterpret_cast` |
| **调用不规范的旧接口** | const_cast（慎用） |

#### ④ 面试常问追问

| 追问 | 要点 |
|------|------|
| **为什么不用 C 风格强转？** | C 风格可能组合多种 cast，不明确，难排查 |
| **dynamic_cast 的条件？** | 基类必须有虚函数（多态类型） |
| **reinterpret_cast 能干什么？** | 指针↔整数、不同类型指针互转，嵌入式用于寄存器操作 |
| **去 const 后修改一定出错吗？** | 是未定义行为，原变量可能在只读段 |

### 第46题：C++ 模板的作用和工作机制是什么？

> **模板把类型当参数，编译期自动生成不同类型的具体代码，实现零运行时开销的泛型编程。**

#### ① 模板分类

| **类型** | 用途 | 典型例子 |
|------|------|---------|
| **函数模板** | 通用算法/工具函数 | std::sort, std::swap |
| **类模板** | 通用容器/工具类 | `vector<T>`、`unique_ptr<T>` |
| **变参模板** | 接受任意数量参数（C++11） | std::tuple, 日志格式化 |

#### ② 工作机制

```cpp
template<typename T>       ← 模板定义（蓝图）
T add(T a, T b) { ... }

add(1, 2);                 ← 调用点，T 推导为 int
add(1.0, 2.0);             ← 调用点，T 推导为 double

编译器自动生成：
int add(int, int);         ← 模板实例化
double add(double, double);
```

#### ③ 代码示例

```cpp
// 函数模板：自动推导
template<typename T>
T getMax(T a, T b) { return (a > b) ? a : b; }

// 类模板：使用时指定类型
template<typename T, int N>
class Array {
    T data[N];              // 编译期确定大小
public:
    T& operator[](int i) { return data[i]; }
    int size() const { return N; }
};

Array<int, 10> arr;         // 10个int的数组，零动态分配
```

#### ④ 嵌入式注意事项

- **代码膨胀**：每种类型实例化一份代码 → Flash 占用增加
- **控制策略**：限制实例化的类型数量，或用 -Os 优化
- **优势**：编译期多态，零运行时开销，适合资源受限场景

#### ⑤ 面试常问追问

| 追问 | 要点 |
|------|------|
| **模板和虚函数多态的区别？** | 模板编译期多态，虚函数运行期多态 |
| **为什么模板定义要放头文件？** | 实例化时需要看到完整定义 |
| **模板特化是什么？** | 为特定类型提供专门实现 |
| **嵌入式用模板的利弊？** | 利：零开销抽象；弊：代码膨胀 |

### 第47题：RAII 是什么？

> **Resource Acquisition Is Initialization——把资源生命周期绑定到对象生命周期，构造获取、析构释放，自动管理资源。**

#### ① RAII 核心思想

```text
对象构造 → 获取资源（内存/锁/文件句柄/设备...）
    ↓
正常使用
    ↓
对象离开作用域 → 析构函数自动释放资源  ← 不管怎么离开都保证释放
```

#### ② 典型 RAII 对象

| **RAII 对象** | 管理的资源 |
|-----------|-----------|
| **unique_ptr / shared_ptr** | 动态内存 |
| **lock_guard / unique_lock** | 互斥锁 |
| **stream** | 文件句柄 |
| **自定义类** | 串口/DMA 缓冲区/硬件句柄 |

#### ③ 代码示例

```cpp
void safeFunc() {
    std::lock_guard<std::mutex> lock(mtx);  // 构造时加锁
    // ... 临界区操作 ...
    if (error) return;   // 提前 return 也会自动解锁！
}   // 离开作用域 → 析构 → 自动解锁

// 对比手动管理（容易遗漏）：
void unsafeFunc() {
    mtx.lock();
    if (error) return;   // ← 忘了解锁！死锁！
    mtx.unlock();
}
```

#### ④ 嵌入式应用

- 用 RAII 管理**互斥锁**：避免提前 return/异常导致死锁
- 用 RAII 管理**设备句柄**：构造时打开，析构时关闭
- 用 RAII 管理**DMA 缓冲区**：析构时释放，避免内存泄漏
- 即使不开异常，RAII 也能防止"提前 return 忘记清理"的问题

#### ⑤ 面试常问追问

| 追问 | 要点 |
|------|------|
| **RAII 和普通手动释放比有什么优势？** | 保证提前 return/异常时也能释放资源 |
| **智能指针是 RAII 吗？** | 是，最典型的 RAII 实现 |
| **嵌入式不用异常还需要 RAII 吗？** | 需要，防止提前 return 遗漏释放 |
| **RAII 能管理哪些资源？** | 内存、锁、文件、网络、硬件句柄等 |

### 第48题：单例模式是什么？有什么优缺点？

> **保证一个类只有一个实例，提供全局访问点，适合日志/配置/硬件管理器等全局唯一资源。**

#### ① 核心结构

```text
                    ┌─────────────┐
 多处代码 ─────────→│  单例类       │
                    │ getInstance()│──→ 唯一实例
 客户端A ─────────→│             │
                    └─────────────┘
 客户端B ─────────→  （始终返回同一个对象）
```

#### ② 线程安全的写法（C++11 推荐）

```cpp
class Logger {
    Logger() {}                              // 私有构造
public:
    Logger(const Logger&) = delete;          // 禁止拷贝
    Logger& operator=(const Logger&) = delete; // 禁止赋值

    static Logger& getInstance() {
        static Logger instance;              // C++11 保证线程安全初始化
        return instance;
    }

    void log(const char* msg) { /* ... */ }
};
```

#### ③ 优缺点

| **优点** | 缺点 |
|------|------|
| **全局唯一，避免重复创建** | 引入全局状态，增加耦合 |
| **延迟初始化，按需创建** | 不利于单元测试 |
| **使用方便，访问简单** | 隐藏依赖关系，难以追踪 |
| **线程安全（C++11 局部静态）** | 生命周期管理复杂 |

#### ④ 面试常问追问

| 追问 | 要点 |
|------|------|
| **C++11 为什么局部 static 线程安全？** | 标准规定函数内 static 变量初始化只执行一次 |
| **单例的析构顺序问题？** | 程序退出时析构顺序不确定，可能出问题 |
| **单例和全局变量的区别？** | 单例有封装、可延迟初始化、可控制访问 |
| **嵌入式适合用单例吗？** | 适合管理全局唯一硬件资源，但不能滥用 |

### 第49题：STL 容器是线程安全的吗？

> **不是！多线程同时读写 STL 容器必须外部加锁，只读不写才安全。**

#### ① 安全性规则

| **场景** | 是否安全 |
|------|---------|
| **多线程**只读**同一个容器** | ✅ 安全 |
| **一个线程写，其他线程读** | ❌ **不安全**，需加锁 |
| **多线程同时写** | ❌ **不安全**，需加锁 |
| **不同线程操作不同容器** | ✅ 安全 |

#### ② 常见危险场景

| **容器** | 危险操作 | 后果 |
|------|---------|------|
| **vector** | 多线程 push_back | 数据竞争、迭代器失效 |
| **unordered_map** | 多线程 insert | rehash 导致迭代器全部失效 |
| **map** | 一个线程 erase，一个线程遍历 | 访问已删除节点 |

#### ③ 嵌入式常用同步方案

```cpp
// 方案1：互斥锁保护
std::mutex mtx;
void safePush(vector<int>& v, int val) {
    std::lock_guard<std::mutex> lock(mtx);  // 加锁
    v.push_back(val);
}   // 自动解锁

// 方案2：生产者-消费者队列（减少锁竞争）
// 方案3：双缓冲（一个读一个写，交替切换）
// 方案4：消息传递（无共享数据）
```

#### ④ 面试常问追问

| 追问 | 要点 |
|------|------|
| **map 的 operator[] 线程安全吗？** | 不安全，可能同时触发插入 |
| **怎么让 STL 容器线程安全？** | 外部加锁或用线程安全队列 |
| **嵌入式实时任务能用互斥锁吗？** | 可以，但要注意优先级反转和锁持有时间 |
| **有线程安全的容器库吗？** | 有，如 TBB concurrent_queue |

### 第50题：运算符重载有什么作用？需要注意什么？

> **让自定义类型像内置类型一样使用运算符，提升可读性，但必须符合直觉。**

#### ① 常见可重载运算符

| **运算符** | 典型用途 | 示例 |
|--------|---------|------|
| **+ - * /** | 数学运算 | 复数、向量、矩阵运算 |
| **== < >** | 比较 | 排序、查找 |
| **[]** | 下标访问 | 自定义容器 |
| **()** | 函数调用仿函数 | 排序比较器、策略对象 |
| **<< >>** | 流输入输出 | 打印、序列化 |
| **= * ->** | 赋值/解引用/成员访问 | 智能指针、迭代器 |

#### ② 代码示例

```cpp
struct Vec2 {
    float x, y;
    Vec2 operator+(const Vec2& o) const {  // 重载 +
        return {x + o.x, y + o.y};         // 返回新对象，不修改自身
    }
    bool operator==(const Vec2& o) const { // 重载 ==
        return x == o.x && y == o.y;
    }
};

Vec2 a{1,2}, b{3,4};
Vec2 c = a + b;   // 自然的语法，可读性好
```

#### ③ 注意事项

| **原则** | 说明 |
|------|------|
| **符合直觉** | + 不应该修改原对象，== 应该表示等价 |
| **成对重载** | 重载了 == 最好也重载 !=；重载了 < 考虑 > |
| **注意隐藏开销** | 不要让 + 内部偷偷做内存分配、大量拷贝 |
| **不能发明新运算符** | 只能重载已有的运算符 |
| **部分运算符不能重载** | :: . .* ?: sizeof 等 |

#### ④ 面试常问追问

| 追问 | 要点 |
|------|------|
| **哪些运算符不能重载？** | :: . .* ?: sizeof 等 |
| **运算符重载是运行期还是编译期？** | 编译期，本质是函数调用 |
| **重载 + 应该返回什么？** | 返回新对象，不修改 `this` |
| **嵌入式用运算符重载要注意什么？** | 不要隐藏动态分配和临时对象开销 |
