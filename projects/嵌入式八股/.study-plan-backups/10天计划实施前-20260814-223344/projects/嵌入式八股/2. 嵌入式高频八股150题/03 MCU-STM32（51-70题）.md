### 第51题：STM32 启动流程大致是什么？

> **上电 → 读向量表取栈顶&复位入口 → 执行 Reset_Handler 做底层初始化 → 跳进 main()**

#### ① 上电/复位后，CPU 先读「中断向量表」

向量表在 Flash 的最开头（通常是 0x08000000）：

| 位置        | 内容                     | 作用             |
| --------- | ---------------------- | -------------- |
| 第1个字（4字节） | **初始栈顶地址**             | 加载到 MSP（主堆栈指针） |
| 第2个字（4字节） | **Reset_Handler 入口地址** | CPU 跳过去执行      |

#### ② Reset_Handler 做底层初始化

```text
1. 设置运行环境
2. .data 段：从 Flash 拷贝到 RAM（全局变量有初值的原因）
3. .bss 段：清零（未初始化全局变量默认为 0 的原因）
4. 调用 SystemInit() 配系统时钟
5. 进入 C 运行环境，调用 main()
```

#### ③ 关键文件关系

| 文件 | 作用 |
|------|------|
| 启动文件 startup_xxx.s | 汇编，定义向量表和 Reset_Handler |
| 链接脚本 .ld/.sct | 决定 .data/.bss/堆/栈放在哪 |
| SystemInit() | 配 HSE/PLL/SYSCLK 等时钟 |

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **全局变量为什么有初值？** | .data 段在 Flash 存了初始值，启动时由 Reset_Handler 拷贝到 RAM |
| **未初始化全局变量为什么默认是 0？** | 启动文件把 .bss 段清零了 |
| **栈空间哪来的？** | 向量表第一个字就是初始栈顶地址，启动时加载到 MSP |

### 第52题：Bootloader 有什么作用？

> **Bootloader 是上电后最先跑的小程序，决定是升级固件还是跳进应用程序。**

#### ① Bootloader 工作流程

```text
上电
  |
  v
Bootloader 启动
  |
  +-- 检查升级标志/通信命令
  |     |
  |     +-- 需要升级 --> 通过串口/CAN/USB接收新固件 --> 写入Flash --> 重启
  |     |
  |     +-- 不需要升级 --> 校验应用程序合法性
  |                          |
  |                          +-- 合法 --> 设置MSP、VTOR --> 跳转APP
  |                          |
  |                          +-- 非法 --> 等待升级或报错
```

#### ② 跳转应用前的关键操作

| 操作 | 说明 |
|------|------|
| 设置 MSP | 把 APP 的栈顶地址加载到主栈指针 |
| 设置 VTOR | 向量表偏移寄存器，指向 APP 的向量表 |
| 关/重配中断 | 避免跳转后中断还在 Bootloader 的处理函数 |
| 校验固件 | 检查 CRC/MD5 或特定标志位 |

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **为什么跳转前要设 VTOR？** | 不设的话中断向量表还指向 Bootloader 区域，APP 的中断无法正确响应 |
| **Bootloader 和 APP 怎么通信？** | 共享 Flash 中的标志位、备份寄存器、或 RAM 中的通信区 |
| **IAP 是什么？** | In-Application Programming，应用内编程，本质就是 Bootloader 在线升级 |

### 第53题：什么是中断？

> **中断是 CPU 被突发事件打断去处理，处理完再回来接着干。**

#### ① 中断的核心机制

```text
正常执行  ──> 事件发生（串口收数据/定时器溢出/按键）
                    |
                    v
              CPU 保存现场（压栈 PC/LR/xPSR 等）
                    |
                    v
              跳转到中断服务函数（ISR）执行
                    |
                    v
              ISR 清标志、处理事件
                    |
                    v
              恢复现场（出栈），继续原程序
```

#### ② 中断 vs 轮询

| 对比项 | 中断 | 轮询 |
|--------|------|------|
| 响应方式 | 事件驱动，被动响应 | CPU 主动反复检查 |
| CPU 占用 | 空闲时不占 CPU | 一直占用 |
| 实时性 | 高（可嵌套优先级） | 低（取决于轮询周期） |
| 复杂度 | 需要处理现场保存/恢复 | 简单直接 |

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **中断服务函数要注意什么？** | 短小、快速、确定——只做清标志+存数据+发通知，复杂逻辑交给主循环 |
| **中断嵌套怎么实现？** | NVIC 的抢占优先级机制，高优先级可以打断低优先级 |
| **中断延迟是什么？** | 从事件发生到 ISR 开始执行的时间，包括压栈、优先级判断等 |

### 第54题：异常和中断有什么区别？

> **异常是更大的概念，中断只是异常的一种——异常包括中断、系统异常和错误，在 Cortex-M 里被统一管理。**

#### ① Cortex-M 异常分类

| 类型 | 示例 | 说明 |
|------|------|------|
| 系统异常 | Reset, NMI, HardFault, MemManage, BusFault, UsageFault | CPU 内部，不可屏蔽或严重错误 |
| 系统异常 | SVCall, PendSV, SysTick | 系统服务/RTOS 相关 |
| 外部中断 IRQ | USART_IRQn, TIM_IRQn, DMA_IRQn 等 | 外设触发，可配置优先级 |

#### ② 关键区别

| 对比项 | 异常 | 中断 |
|--------|------|------|
| 范围 | 更广，包含系统异常+IRQ | 通常指外设 IRQ |
| 来源 | CPU 内部 + 外部 | 通常外部外设 |
| 编号 | 0~15 是系统异常 | 16+ 是外部中断 |
| 管理 | 统一由 NVIC 管理 | NVIC 管理的一部分 |

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **HardFault 是中断还是异常？** | 是系统异常，不属于外设中断 |
| **SysTick 是什么类型的异常？** | 系统异常（编号 15），FreeRTOS 用它做调度心跳 |
| **PendSV 在 RTOS 中起什么作用？** | 用于任务切换，优先级设为最低，保证在其他 ISR 结束后才切换 |

### 第55题：NVIC 是什么？

> **NVIC 是 Cortex-M 内核里专门管中断的"大管家"——谁可以中断、谁优先、能不能打断别人，全由它说了算。**

#### ① NVIC 管理的要素

| 要素 | 说明 |
|------|------|
| 使能/禁止 | 每个 IRQ 可以独立开关 |
| 优先级 | 抢占优先级 + 响应（子）优先级 |
| 挂起/清除 | 可以软件触发或清除中断挂起 |
| 嵌套 | 高抢占优先级可以打断低优先级 |

#### ② 优先级分组（STM32 常见）

| 分组 | 抢占位 | 响应位 | 含义 |
|------|--------|--------|------|
| Group 0 | 0 位 | 4 位 | 不能嵌套，只有响应优先级 |
| Group 2 | 2 位 | 2 位 | 4 级抢占 × 4 级响应 |
| Group 4 | 4 位 | 0 位 | 16 级抢占，无响应优先级 |

数值越小优先级越高。

#### ③ FreeRTOS 注意事项

```text
configMAX_SYSCALL_INTERRUPT_PRIORITY = 5（举例）

优先级 >= 5 的中断：可以安全调用 FreeRTOS API（xQueueSendFromISR 等）
优先级 < 5 的中断：不能调用 FreeRTOS API，不受 RTOS 管理
```

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **抢占和响应优先级有什么区别？** | 抢占决定能不能打断别人；响应决定同抢同时谁先执行 |
| **数值越小优先级越高吗？** | 是的，0 是最高优先级 |
| **为什么 FreeRTOS 要限制中断优先级？** | 防止高优先级中断破坏 RTOS 临界区，导致内核数据结构被破坏 |

### 第56题：SysTick 在嵌入式系统中有什么作用？

> **SysTick 是 Cortex-M 内核自带的 24 位倒计数定时器，产生固定周期节拍中断——裸机中用于计时和延时，RTOS 中作为调度心跳。**

#### ① SysTick 基本参数

| 参数 | 说明 |
|------|------|
| 位宽 | 24 位倒计数 |
| 时钟源 | AHB/8 或 AHB（系统时钟） |
| 最大计数 | 2^24 = 16,777,215 |
| 自动重载 | 到 0 时自动加载重载值并触发中断 |

#### ② 两种用途

| 场景 | 作用 |
|------|------|
| 裸机 | 提供 ms/us 级延时和计时基准（HAL_Delay 就是用它） |
| RTOS | 提供系统 tick，驱动任务调度、延时、超时检测 |

#### ③ FreeRTOS 中的角色

```text
SysTick 中断
    |
    v
xTaskIncrementTick()
    |
    +-- 更新系统 tick 计数
    +-- 检查延时任务是否到期
    +-- 必要时触发 PendSV 进行任务切换
```

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **SysTick 是外设吗？** | 不是，它是 Cortex-M 内核的一部分，所有 Cortex-M 芯片都有 |
| **HAL_Delay 为什么不准？** | 它基于 SysTick 中断计数，中断延迟和优先级会影响精度 |
| **FreeRTOS 的 configTICK_RATE_HZ 是什么？** | SysTick 中断频率，设为 1000 则 1ms 一个 tick |

### 第57题：中断服务函数设计时需要注意什么？

> **ISR 核心原则：短小、快速、确定——只做清标志、存数据、发通知，复杂逻辑交给主循环或任务。**

#### ① ISR 中应该做的

| 操作 | 说明 |
|------|------|
| 清中断标志 | 不清标志会反复进入中断 |
| 读取数据 | 如读 UART DR、ADC 数据寄存器 |
| 存入缓冲区 | 写环形缓冲区或队列 |
| 发通知 | 置标志位 / xSemaphoreGiveFromISR |

#### ② ISR 中不应该做的

| 操作 | 原因 |
|------|------|
| printf | 可能死锁，耗时长 |
| 复杂运算 | 占用 ISR 时间，影响实时性 |
| while 等待 | 阻塞 ISR，可能死锁 |
| 动态内存分配 | malloc 不是可重入的 |

#### ③ 代码示例

```c
void USART1_IRQHandler(void) {
    if (USART_GetITStatus(USART1, USART_IT_RXNE)) {
        uint8_t ch = USART_ReceiveData(USART1);  // 读数据
        ring_buf_put(&rx_buf, ch);               // 存缓冲区
        USART_ClearITPendingBit(USART1, USART_IT_RXNE); // 清标志
    }
}
```

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **ISR 里能用延时函数吗？** | 不能，会阻塞 ISR，且可能错过其他中断 |
| **中断里怎么通知任务？** | 用 xSemaphoreGiveFromISR 或 xQueueSendFromISR |
| **不清中断标志会怎样？** | 退出 ISR 后立刻再次进入，形成"中断风暴" |

### 第58题：中断和轮询有什么区别？

> **轮询是 CPU 主动反复检查，中断是事件主动通知 CPU——核心区别在于"谁发起"。**

#### ① 对比表

| 对比项 | 中断 | 轮询 |
|--------|------|------|
| 触发方式 | 外设/事件主动通知 CPU | CPU 主动反复查询 |
| CPU 利用率 | 高（空闲时可做其他事） | 低（一直查询浪费 CPU） |
| 实时性 | 高（可配置优先级嵌套） | 低（取决于轮询周期） |
| 实现复杂度 | 较高（需处理现场保存） | 简单 |
| 适用场景 | 随机事件、实时响应 | 状态机循环、简单场景 |

#### ② 实际选择建议

| 场景 | 推荐方式 |
|------|----------|
| 串口接收 | 中断 + DMA |
| 按键检测 | 中断 或 定时器轮询消抖 |
| 忙等待状态 | 超时轮询（避免死等） |
| 低功耗唤醒 | 中断唤醒 |

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **什么时候用轮询比中断好？** | 事件频率极高且可预测时，轮询开销反而更小（如 SPI 高速传输） |
| **中断太多会怎样？** | 频繁上下文切换，CPU 开销大，可能导致低优先级中断饥饿 |
| **裸机主循环叫什么？** | 前后台系统：中断叫前台，主循环 while(1) 叫后台 |

### 第59题：DMA 是什么？有什么作用？

> **DMA 能在外设和内存之间自动搬运数据而不占用 CPU，CPU 只负责配置，搬完后 DMA 发中断通知。**

#### ① DMA 核心概念

| 项目 | 说明 |
|------|------|
| 全称 | Direct Memory Access，直接存储器访问 |
| 工作方式 | 硬件自动搬运，CPU 不参与逐字节传输 |
| 触发源 | 外设请求（UART RX/TX、ADC、SPI 等） |
| 传输方向 | 外设→内存、内存→外设、内存→内存 |
| 完成通知 | DMA 传输完成中断 |

#### ② DMA vs CPU 搬运

| 对比项 | CPU 搬运 | DMA 搬运 |
|--------|----------|----------|
| CPU 占用 | 每个字节都要 CPU 参与 | 只需配置一次，自动搬运 |
| 速度 | 受 CPU 主频和总线仲裁限制 | 可达总线最大带宽 |
| 适用场景 | 少量数据 | 大量连续数据（串口、ADC、音频） |

#### ③ 典型应用

```text
UART 接收：
  UART DR --DMA--> 内存缓冲区（不经过 CPU）
  传输完成 --> DMA 中断通知 CPU 处理

ADC 连续采样：
  ADC DR --DMA--> 采样数组（自动填充）
  采满 N 个 --> DMA 中断通知 CPU
```

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **DMA 和 CPU 会抢总线吗？** | 会，有总线仲裁机制，通常 DMA 优先级更高 |
| **DMA 传输方向有哪些？** | 外设→内存、内存→外设、内存→内存（M2M） |
| **DMA 需要配置哪些参数？** | 源地址、目标地址、传输长度、传输方向、触发源、循环/单次模式 |

### 第60题：UART DMA 接收不定长数据通常怎么做？

> **DMA 持续搬运，IDLE 空闲中断判断"一帧结束"，通过 DMA 剩余计数算出实际收到多少字节。**

#### ① 核心思路

```text
UART RX --DMA--> 内存缓冲区（循环模式，持续接收）
    |
    +-- 每收到一个字节，DMA 计数器自动减 1
    |
    +-- 总线空闲（IDLE 中断）时：
        实际收到 = 缓冲区大小 - DMA 剩余计数
```

#### ② 实现步骤

| 步骤 | 操作 |
|------|------|
| 1 | 配置 UART DMA 接收，缓冲区设为最大预期长度 |
| 2 | 使能 UART IDLE 空闲中断 |
| 3 | DMA 循环模式持续接收，不关闭 DMA |
| 4 | IDLE 中断触发时，读 DMA 剩余计数 |
| 5 | 计算实际长度 = 缓冲区大小 - 剩余计数 |
| 6 | 处理数据，重置 DMA 计数器 |

#### ③ 关键代码片段

```c
void USART1_IRQHandler(void) {
    if (USART_GetITStatus(USART1, USART_IT_IDLE)) {
        USART1->SR; USART1->DR;  // 清 IDLE 标志
        uint16_t remain = DMA_GetCurrDataCounter(DMA1_Channel5);
        uint16_t len = RX_BUF_SIZE - remain;  // 实际长度
        process_data(rx_buf, len);            // 处理
        DMA_SetCurrDataCounter(DMA1_Channel5, RX_BUF_SIZE); // 重置
    }
}
```

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **为什么用 IDLE 而不是按字节中断？** | 高波特率下逐字节中断开销太大，IDLE 只在帧结束时触发一次 |
| **DMA 单次和循环模式有什么区别？** | 单次搬完停止；循环模式自动从头开始，适合持续接收 |
| **缓冲区满了怎么办？** | 可以双缓冲，或在 IDLE 中断后立即处理并重置 |

### 第61题：环形缓冲区是什么？适合什么场景？

> **环形缓冲区是一块固定大小数组，通过读写指针循环移动实现先进先出，解耦生产者和消费者。**

#### ① 数据结构

```text
      写指针 (head)
         |
   [  A  |  B  |  C  |     |     ]
                   |
                读指针 (tail)

写入：data[head++] = value;  head %= SIZE;
读取：value = data[tail++];  tail %= SIZE;
满：  (head + 1) % SIZE == tail
空：  head == tail
```

#### ② 关键特性

| 特性 | 说明 |
|------|------|
| 固定大小 | 不会动态扩容，内存可控 |
| O(1) 读写 | 只移动指针，无拷贝 |
| 生产者-消费者 | 一个写一个读，天然解耦 |
| 无锁条件 | 单生产者单消费者时不需要锁 |

#### ③ 典型应用场景

| 场景 | 说明 |
|------|------|
| 串口接收 | ISR 写入，主循环读出解析 |
| 日志缓冲 | 高频写入，低频批量输出 |
| 音频流 | 持续填充，持续播放 |
| 传感器数据 | 采集中断写，任务读处理 |

#### ④ 和普通数组/链表对比

| 对比项 | 环形缓冲区 | 普通数组 | 链表 |
|--------|-----------|----------|------|
| 内存 | 固定，预分配 | 固定 | 动态分配 |
| 读写效率 | O(1) | 头部删除 O(n) | O(1) |
| 碎片 | 无 | 无 | 可能有 |
| 适用 | 流式数据 | 随机访问 | 频繁增删 |

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **怎么判断满和空？** | 留一个空位：满=(head+1)%SIZE==tail，空=head==tail |
| **多线程安全吗？** | 单写单读是安全的（原子操作指针）；多写多读需要加锁 |
| **和 FreeRTOS 队列有什么区别？** | 队列自带信号量通知和阻塞机制，环形缓冲区更底层更轻量 |

### 第62题：看门狗的工作原理是什么？

> **看门狗是必须定期喂的硬件定时器，超时没喂就自动复位，本质是程序跑飞时的自动恢复机制。**

#### ① 工作原理

```text
程序启动 --> 初始化看门狗，设超时时间
    |
    v
正常运行中定期"喂狗"（重置计数器）
    |
    +-- 程序正常 --> 一直在喂 --> 不会复位
    |
    +-- 程序跑飞/死锁 --> 没人喂 --> 计数器溢出 --> 硬件自动复位
```

#### ② STM32 看门狗类型

| 类型 | 时钟源 | 超时范围 | 特点 |
|------|--------|----------|------|
| IWDG（独立看门狗） | LSI ~40kHz | ms~s 级 | 独立于主时钟，更可靠 |
| WWDG（窗口看门狗） | APB1 时钟 | μs~ms 级 | 必须在窗口期内喂，太早太晚都复位 |

#### ③ 喂狗注意事项

| 要点 | 说明 |
|------|------|
| 喂狗位置 | 主循环中确认所有任务正常后再喂 |
| 不要在 ISR 中喂 | ISR 正常不代表主循环正常 |
| 超时时间 | 要大于主循环最大周期，留余量 |
| IWDG vs WWDG | IWDG 防卡死，WWDG 防跑飞（窗口约束） |

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **IWDG 和 WWDG 有什么区别？** | IWDG 超时就复位；WWDG 必须在窗口期内喂，太早太晚都复位 |
| **为什么不要在中断里喂狗？** | 主循环卡死了中断可能还在跑，喂狗后看不出来 |
| **FreeRTOS 项目怎么看门狗？** | 每个任务报告状态，空闲任务统一喂狗，某个任务卡死则不喂 |

### 第63题：Flash 写入和掉电保护要注意什么？

> **Flash 必须先擦后写、按页擦除、有寿命限制；掉电保护核心是防写一半断电导致数据损坏。**

#### ① Flash 基本特性

| 特性 | STM32 内部 Flash | EEPROM |
|------|-------------------|--------|
| 擦除单位 | 页（1KB/2KB） | 字节 |
| 写入单位 | 半字/字 | 字节 |
| 擦除值 | 0xFF | 0xFF |
| 寿命 | 1万~10万次 | 100万次+ |
| 速度 | 擦除慢（ms 级） | 快（μs 级） |

#### ② 掉电保护策略

```text
方案一：双区备份
  区A 写完 --> 标记区A有效 --> 区B 备份
  掉电恢复时：检查标记，用有效区的数据

方案二：日志追加
  每次写新记录追加到下一位置
  掉电后从最后一条有效记录恢复
```

#### ③ 工程注意事项

| 要点 | 说明 |
|------|------|
| 先擦后写 | Flash 只能 1→0 写，必须先擦成 0xFF |
| 写入时不能读 | 写 Flash 期间 CPU 不能从 Flash 取指（需要 RAM 中执行） |
| 对齐要求 | 按字/半字写入，地址要对齐 |
| 寿命管理 | 频繁写入场景用磨损均衡 |

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **为什么写 Flash 时要关中断？** | 写 Flash 期间不能从 Flash 取指，ISR 可能触发取指导致 HardFault |
| **EEPROM 和 Flash 哪个适合存配置？** | EEPROM 更适合（字节擦写、寿命长），Flash 适合存固件 |
| **磨损均衡是什么？** | 分散写入不同位置，避免某一页过早达到擦写寿命 |

### 第64题：GPIO 常见工作模式有哪些？

> **GPIO 分输入、输出、复用、模拟四大类，核心看引脚接什么外设做什么用来选模式。**

#### ① GPIO 模式分类

| 模式 | 方向 | 典型用途 |
|------|------|----------|
| 浮空输入 | 输入 | 外部信号检测，无内部上下拉 |
| 上拉输入 | 输入 | 按键检测（默认高电平） |
| 下拉输入 | 输入 | 按键检测（默认低电平） |
| 模拟输入 | 输入 | ADC 采样 |
| 推挽输出 | 输出 | 驱动 LED、控制电平 |
| 开漏输出 | 输出 | I2C、电平转换、线与逻辑 |
| 复用推挽 | 输出 | USART TX、SPI MOSI |
| 复用开漏 | 输出 | I2C SCL/SDA |

#### ② 推挽 vs 开漏

| 对比项 | 推挽 | 开漏 |
|--------|------|------|
| 输出高 | 主动输出 VCC | 需要上拉电阻 |
| 输出低 | 主动拉 GND | 主动拉 GND |
| 线与 | 不支持 | 支持（I2C 必须） |
| 电平转换 | 不支持 | 支持（上拉到不同电压） |

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **浮空输入和上拉输入有什么区别？** | 浮空无上下拉，引脚悬空时电平不确定；上拉默认高电平 |
| **GPIO 输出速度是什么？** | 翻转速率，高速适合高频信号（SPI/I2C），低速省功耗 |
| **为什么 ADC 引脚要设为模拟输入？** | 避免数字输入的施密特触发器干扰模拟信号 |

### 第65题：ADC 分辨率和采样时间是什么意思？

> **分辨率决定能把电压分成多少份，采样时间决定给电容充多久电，两者共同影响精度。**

#### ① 分辨率

| 分辨率 | 量化级数 | 1LSB（3.3V 参考） | 适用场景 |
|--------|----------|-------------------|----------|
| 12 位 | 4096 | 0.8mV | 通用精度 |
| 10 位 | 1024 | 3.2mV | 一般精度 |
| 8 位 | 256 | 12.9mV | 低精度高速 |

#### ② 采样时间

```text
总转换时间 = 采样时间 + 12.5 个 ADC 时钟周期（12位）

采样时间可配置：1.5/7.5/13.5/28.5/41.5/55.5/71.5/239.5 个周期
```

| 采样时间 | 适用场景 |
|----------|----------|
| 短（1.5~7.5） | 高速采样，信号源阻抗低 |
| 长（55.5~239.5） | 高精度，信号源阻抗高（需要更长充电时间） |

#### ③ 提高精度的方法

| 方法 | 说明 |
|------|------|
| 增加采样时间 | 给内部电容更长充电时间 |
| 多次采样取平均 | 减小随机噪声影响 |
| 使用外部参考源 | 比内部参考更稳定 |
| 硬件滤波 | RC 低通滤波消除高频噪声 |

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **ADC 精度和分辨率是一回事吗？** | 不是，分辨率是量化级数，精度还包括偏移、增益、噪声等误差 |
| **为什么采样时间要和信号源阻抗匹配？** | 阻抗高充电慢，采样时间不够电容没充满，读数偏低 |
| **STM32 ADC 是 SAR 型吗？** | 是的，逐次逼近型，内部有一个 DAC 做二分查找 |

### 第66题：PWM 是什么？定时器如何产生 PWM？

> **PWM 通过改变固定周期内高电平占比来等效控制输出平均能量，频率固定靠比例说话。**

#### ① PWM 基本概念

```text
ARR = 999（自动重装载值）
CCR = 700（比较值）

CNT:  0  1  2 ... 699  700  701 ... 999  0  1 ...
OUT:  ──────────────┐                   ┌──────
高电平               └───────────────────┘
                     CCR=700             ARR=999
占空比 = CCR / (ARR+1) = 700/1000 = 70%
```

#### ② 定时器产生 PWM 的关键寄存器

| 寄存器 | 作用 |
|--------|------|
| PSC | 预分频，决定计数频率 |
| ARR | 自动重装载，决定 PWM 周期 |
| CCR | 比较值，决定占空比 |
| CCER | 输出极性（有效高/有效低） |

#### ③ 频率和占空比计算

```text
PWM 频率 = 定时器时钟 / (PSC + 1) / (ARR + 1)
占空比 = CCR / (ARR + 1) × 100%
```

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **PWM 频率怎么选？** | LED >100Hz 避免闪烁，电机看驱动器要求，舵机 50Hz |
| **怎么改占空比？** | 运行时直接改 CCR 值，下一个周期生效 |
| **PWM 和 DAC 输出有什么区别？** | PWM 是数字信号等效模拟，需要 RC 滤波才是真模拟；DAC 直接输出模拟电压 |

### 第67题：STM32 时钟树为什么重要？

> **时钟树是 STM32 的心脏节拍，内核总线外设都靠它驱动，配错时钟外设全部异常。**

#### ① 时钟树主要结构

```text
HSE(外部晶振) ──┐
                ├──> PLL ──> SYSCLK(最高168MHz)
HSI(内部RC)  ──┘                    |
                                    v
                               AHB 分频 ──> HCLK(内核/内存)
                                    |
                               APB1 分频 ──> PCLK1(低速外设, max 42MHz)
                                    |
                               APB2 分频 ──> PCLK2(高速外设, max 84MHz)
```

#### ② 常见外设时钟依赖

| 外设 | 时钟来源 | 配错的后果 |
|------|----------|------------|
| UART | APBx | 波特率错误，乱码 |
| 定时器 | APBx×2 或 APBx | 定时不准 |
| ADC | APB2 | 采样率错误 |
| SPI | APBx | 通信速率错误 |
| USB | 48MHz 专用 | 无法枚举 |

#### ③ 工程检查要点

| 检查项 | 说明 |
|--------|------|
| HSE 是否起振 | 晶振是否正常工作 |
| PLL 配置 | 倍频系数是否正确 |
| APB 分频 | 是否影响外设时钟 |
| 外设时钟是否使能 | RCC_APBxPeriphClockCmd() |

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **HSE 和 HSI 有什么区别？** | HSE 外部晶振精度高；HSI 内部 RC 精度低但不需外部元件 |
| **APB1 和 APB2 分别挂什么外设？** | APB1 挂低速（UART2/3、TIM2-7、I2C）；APB2 挂高速（UART1、SPI1、TIM1、ADC） |
| **为什么定时器时钟可能是 APBx 的 2 倍？** | 当 APBx 分频系数 >1 时，定时器时钟自动 ×2 |

### 第68题：HAL 库开发和寄存器开发有什么区别？

> **HAL 库是封装好的 API 开发快但层厚，寄存器直接操控效率高但门槛高，工程上混合使用。**

#### ① 对比表

| 对比项 | HAL 库 | 寄存器开发 |
|--------|--------|------------|
| 开发效率 | 高，API 封装好 | 低，需查手册 |
| 代码体积 | 较大（通用性开销） | 最小 |
| 执行效率 | 有封装层开销 | 最直接 |
| 可移植性 | 强（跨 STM32 系列） | 弱（依赖具体寄存器） |
| 调试难度 | 不够直观 | 清楚知道每一步操作 |
| 学习门槛 | 低 | 高 |

#### ② 工程实践建议

| 场景 | 推荐方式 |
|------|----------|
| 快速原型开发 | HAL 库 |
| 常规外设配置 | HAL 库 |
| 性能敏感代码 | 寄存器 |
| 时序严格场景 | 寄存器 |
| 排查底层问题 | 寄存器（看懂 HAL 背后逻辑） |

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **HAL 库为什么效率低？** | 为了通用性做了大量参数检查和分支判断，函数调用层级深 |
| **LL 库是什么？** | Low-Layer 库，比 HAL 更轻量，接近寄存器但保留一定封装 |
| **标准库和 HAL 库有什么区别？** | 标准库（StdPeriph）更轻量直接，HAL 是 ST 后来推的统一抽象层 |

### 第69题：MCU 低功耗设计通常从哪些方面考虑？

> **低功耗从选模式、关外设、控 GPIO、减唤醒四个层面入手，功耗往往来自外围电路。**

#### ① STM32 低功耗模式

| 模式 | 功耗 | 唤醒源 | 唤醒时间 |
|------|------|--------|----------|
| Sleep | 最高（只停 CPU） | 任意中断 | 即时 |
| Stop | 低（关 HSI/HSE） | EXTI 中断 | μs~ms |
| Standby | 最低（类似复位） | WKUP 引脚/RTC/看门狗 | ms 级 |

#### ② 功耗优化清单

| 层面 | 措施 |
|------|------|
| **时钟** | 关闭不用的外设时钟，降低主频 |
| **外设** | ADC/SPI/I2C 不用时关闭，DMA 停止 |
| **GPIO** | 未用引脚配置为输出低电平或模拟输入，避免悬空 |
| **外围电路** | 传感器/模块断电或进低功耗模式 |
| **软件** | 减少轮询，用中断唤醒，空闲进 Stop/Standby |

#### ③ 常见坑

| 问题 | 原因 |
|------|------|
| 功耗比预期高 | GPIO 悬空导致漏电 |
| 低功耗模式进不去 | 某个外设还在运行 |
| 唤醒后异常 | 时钟未恢复，外设未重新初始化 |

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **Stop 和 Standby 有什么区别？** | Stop 保留 RAM 和寄存器，唤醒后继续执行；Standby 类似复位，从头开始 |
| **怎么测量功耗？** | 串联电流表测电流，或用开发板上的电流测量接口 |
| **RTC 在低功耗模式下能用吗？** | 可以，RTC 用 LSE（32.768kHz）独立工作，Standby 模式下也能唤醒 |

### 第70题：HardFault 一般如何排查？

> **HardFault 排查核心是保现场、查 PC、读 CFSR 定位错误类型，结合 map 文件找代码行。**

#### ① 常见触发原因

| 原因 | 说明 |
|------|------|
| 空指针访问 | 读写地址 0x00000000 附近 |
| 数组越界 | 写到非法内存区域 |
| 栈溢出 | 局部变量或嵌套过深 |
| 未对齐访问 | 非对齐地址读写多字节数据 |
| 非法函数指针 | 跳转到无效地址 |
| 外设地址错误 | 访问未映射的寄存器地址 |

#### ② 排查流程

```text
① 保现场：别在 HardFault_Handler 里 while(1)，先存关键寄存器
    |
    v
② 查 PC：崩在哪个地址？反汇编/map 文件查对应代码行
    |
    v
③ 查 CFSR：判断错误类型
    - BFARVALID -> 总线错误，读 BFAR 得到非法地址
    - MMARVALID -> 内存管理错误
    - UNSTKERR / INVSTATE -> 栈/状态异常
    |
    v
④ 查 LR：判断是从哪个函数进来的
    |
    v
⑤ 结合 map 文件 + 反汇编定位具体代码
```

#### ③ CFSR 关键位速查

| 位 | 含义 | 排查方向 |
|----|------|----------|
| IACCVIOL | 指令访问违规 | 跳转到非法地址 |
| DACCVIOL | 数据访问违规 | 空指针或越界读写 |
| BFARVALID | BFAR 有效 | 读 BFAR 得到非法地址 |
| UNSTKERR | 出栈错误 | 栈被破坏 |
| INVSTATE | 无效状态 | Thumb 模式异常 |

#### ④ 保留现场代码示例

```c
void HardFault_Handler(void) {
    __asm volatile (
        "TST LR, #4       \n"   // 判断用 MSP 还是 PSP
        "ITE EQ           \n"
        "MRSEQ R0, MSP    \n"
        "MRSNE R0, PSP    \n"
        "B hard_fault_handler_c \n"
    );
}

void hard_fault_handler_c(uint32_t *stack) {
    volatile uint32_t pc  = stack[6];   // PC = 崩溃地址
    volatile uint32_t lr  = stack[5];   // LR = 返回地址
    volatile uint32_t cfsr = SCB->CFSR; // 错误状态
    while(1);  // 断点停在这里，用调试器查看
}
```

#### ⑤ 工程预防措施

| 措施 | 说明 |
|------|------|
| 保留 map 文件 | 符号地址到代码行映射 |
| 栈水位监控 | FreeRTOS 用 uxTaskGetStackHighWaterMark |
| 打开调试信息 | 编译加 -g 保留符号表 |
| MPU 保护 | 配置内存保护单元拦截非法访问 |

#### 面试常问追问

| 追问 | 回答 |
|------|------|
| **CFSR 和 HFSR 有什么区别？** | CFSR 是具体故障状态（总线/内存/用法），HFSR 是 HardFault 总标志 |
| **BFAR 是什么？** | Bus Fault Address Register，记录导致总线错误的非法地址 |
| **FreeRTOS 项目 HardFault 最常见原因？** | 任务栈溢出、中断优先级配置错误（低于 configMAX_SYSCALL_INTERRUPT_PRIORITY） |
