## 2.1 C和C++区别

### 2.1.1 设计目标的不同

|语言|C|C++|
|---|---|---|
|设计目标|面向过程，贴近硬件，追求效率|在高效基础上，支持大规模工程和抽象|

### 2.1.2 编程范式差异（核心区别）

- C 以过程式编程为主，也可通过结构体和函数指针进行模块化设计。
- C++ 是多范式语言，除过程式外还原生支持面向对象、泛型、函数式风格和编译期编程。

### 2.1.3 抽象能力对比

|能力|C|C++|
|---|---|---|
|封装|手动模拟|原生支持|
|继承|不支持|支持|
|多态|不支持|支持|
|泛型|宏|模板|

### 2.1.4 内存与资源管理

- C 通常使用 `malloc/free` 及显式清理函数管理资源。
- C++ 提供构造/析构、RAII、智能指针和标准容器，使资源生命周期可与对象绑定。

### 2.1.5 类型安全

- 两种语言都有静态类型检查；C++ 在重载、引用、模板、`enum class` 和显式转换等方面提供了更丰富的类型约束。

### 2.1.6 标准库能力

|项目|C|C++|
|---|---|---|
|容器|无|vector / map|
|算法|少|丰富|
|字符串|char*|std::string|

### 2.1.7 代码规模与维护性

- C 接口直接、运行时模型简单；大型项目通常依赖严格的模块规范和人工资源管理。
- C++ 的类、命名空间、模板与 RAII 有利于组织大型工程，但也增加了语言复杂度。

### 2.1.8 性能对比

- 两者都可生成高效本地代码。C++ 的零开销抽象通常不会引入额外运行时成本，但动态分派、异常或不恰当的抽象仍可能产生开销；应以测量结果为准。

### 2.1.9 为什么有了 C 还要 C++（总结）

C++ 在保留底层控制和性能能力的同时，增加了类、模板、标准容器、RAII 等抽象机制，用来降低复杂系统的维护成本。它不是所有场景下对 C 的替代；内核、极小型 MCU、ABI 边界等仍常使用 C。

### 2.1.10 实际使用建议（工程视角）

|场景|推荐|
|---|---|
|驱动 / 内核|C|
|嵌入式应用|C / C++|
|大型软件|C++|

## 2.2 C++的三大特性（有些会问四大特性）

C++ 的设计理念是 **面向对象编程**，并且继承了 C 语言的过程化编程特性。C++ 通过引入很多新特性，使得程序员可以灵活地开发高效、可维护和可扩展的应用程序。C++ 的核心特性通常被总结为 **三大特性** 或 **四大特性**。

### 2.2.1 三大特性（经典的三个特性）

**封装（Encapsulation）**

- **定义**：封装是指将数据和操作数据的函数捆绑在一起，并将对象的内部实现细节隐藏起来，外部只能通过公开的接口访问对象。
- **作用**：通过封装，我们可以控制对数据的访问权限，增强程序的安全性和可靠性，防止外部无意或恶意的篡改数据。
- **实现方式**：使用 class 来定义对象，通过 **访问修饰符**（public、private、protected）控制数据成员和成员函数的访问。

```cpp
class MyClass {
private:
    int data;  // 私有成员，外部无法直接访问

public:
    void setData(int value) { data = value; }  // 公共成员函数，用来访问和修改私有数据
    int getData() { return data; }
};
```

**继承（Inheritance）**

- **定义**：继承是指一个类从另一个类派生出来，派生类继承基类的成员（属性和方法）。通过继承，我们可以重用已有类的代码，并且通过扩展或修改基类的功能来创建新的类。
- **作用**：继承允许程序员创建层次结构化的类，实现代码的复用，减少冗余代码。
- **实现方式**：通过使用 class 关键字和访问修饰符来实现继承关系。

```cpp
class Base {
public:
    void show() { std::cout << "Base class" << std::endl; }
};

class Derived : public Base {  // Derived 继承自 Base
public:
    void display() { std::cout << "Derived class" << std::endl; }
};
```

**多态（Polymorphism）**

- **定义**：多态性是指同一个操作作用于不同的对象时，可以有不同的表现形式。C++ 中的多态分为 **编译时多态**（如函数重载、运算符重载）和 **运行时多态**（如通过虚函数实现）。
- **作用**：通过多态，程序可以更加灵活地扩展和维护，并能够动态选择合适的操作。
- **实现方式**：通过虚函数（virtual）实现运行时多态，或者通过函数重载和运算符重载实现编译时多态。

```cpp
class Base {
public:
    virtual void display() {
        std::cout << "Base display" << std::endl;
    }
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    void display() override {
        std::cout << "Derived display" << std::endl;
    }
};

int main() {
    Base* basePtr = new Derived();
    basePtr->display();  // 动态绑定，调用 Derived 的 display()
    delete basePtr;
}
```

### 2.2.2 四大特性（增加了一个特性）

除了上述三大特性外，C++ 还有一个非常重要的特性 —— **抽象（Abstraction）**，因此，C++ 被称为拥有 **四大特性**。

**抽象（Abstraction）**

- **定义**：抽象是指通过定义接口或抽象类，隐藏对象的复杂性，仅暴露出必要的功能和行为。它是面向对象设计的核心特性之一，确保用户只需要关心对象的行为，而不需要了解其具体实现。
- **作用**：抽象有助于减少系统的复杂性，并使得代码更加模块化和可扩展。通过抽象，可以为子类提供通用的接口，从而让代码更加灵活和易于维护。
- **实现方式**：通过定义 **抽象类**（包含纯虚函数）来实现抽象。

```cpp
class Shape {
public:
    virtual void draw() = 0;  // 纯虚函数，表示抽象
};

class Circle : public Shape {
public:
    void draw() override {
        std::cout << "Drawing Circle" << std::endl;
    }
};

class Square : public Shape {
public:
    void draw() override {
        std::cout << "Drawing Square" << std::endl;
    }
};
```

在上述代码中，Shape 是一个抽象类，draw 函数是一个纯虚函数（= 0），每个派生类都需要实现 draw 方法。

### 2.2.3 总结

**三大特性**

- **封装**：隐藏对象的内部实现，只提供必要的接口。
- **继承**：通过继承机制重用已有类的功能，并扩展新的功能。
- **多态**：同一操作作用于不同类型的对象时，表现出不同的行为。
- **抽象（四大特性中的一种）**：通过抽象类和接口隐藏实现细节，只暴露对象的必要行为和功能。

## 2.3 继承是什么？

### 2.3.1 继承的定义

**继承（Inheritance）是面向对象编程（OOP）的核心特性之一，指派生类（子类）可以复用基类（父类）的成员（属性和方法）**，并可以扩展或修改其行为。

- 继承体现“**是一个**”关系（is-a）
- 提高代码复用性和可维护性

### 2.3.2 继承的基本语法

```cpp
class Base {
public:
    void func() {}
};

class Derived : public Base {
public:
    void newFunc() {}
};
```

- Derived 继承 Base 的 func()
- Derived 可扩展新的成员 newFunc()

### 2.3.3 继承方式（访问控制）

|继承方式|基类 public 成员|基类 protected 成员|基类 private 成员|
|---|---|---|---|
|public 继承|public|protected|派生类不能直接访问，但基类子对象中仍存在|
|protected 继承|protected|protected|派生类不能直接访问，但基类子对象中仍存在|
|private 继承|private|private|派生类不能直接访问，但基类子对象中仍存在|

### 2.3.4 继承的作用（重点）

1. **代码复用**：派生类无需重新实现基类功能
2. **可扩展性**：在基类基础上增加新功能
3. **支持多态**：运行时可通过基类接口操作不同派生类对象

### 2.3.5 继承与多态的关系

- 继承是实现多态的基础
- 虚函数 + 继承 → 运行时多态

```cpp
class Base {
public:
    virtual void func() { cout << "Base\n"; }
};

class Derived : public Base {
public:
    void func() override { cout << "Derived\n"; }
};

Base* p = new Derived();
p->func();   // 输出 Derived
```

### 2.3.6 面试高频总结句

> 继承是派生类获取基类成员和行为的机制，用于代码复用、扩展和多态实现。
> 继承让子类“拥有”父类特性，并可在此基础上扩展或修改行为。

## 2.4 C++编译时和C有什么不同，在C++中怎么用C？

### 2.4.1 C++ 编译时与 C 的不同

|特性|C|C++|
|---|---|---|
|编译方式|基于函数|基于类和函数|
|函数重载|不支持|支持|
|名字修饰（Name Mangling）|无|支持（用于函数重载和模板）|
|类型检查|弱|强（更严格）|
|内存管理|手动 malloc/free|手动 + new/delete + RAII|
|面向对象|不支持|支持类、继承、多态|
|默认函数参数|不支持|支持|
|内联函数|宏或 inline|inline 关键字更完善|

### 2.4.2 C++ 编译时机制

- **名字修饰**：同名函数参数不同，编译器通过修饰区分
- **模板实例化**：编译期生成对应代码
- **类型安全检查更严格**：防止隐式转换错误
- **内联函数和 constexpr**：更多编译期优化可能

### 2.4.3 在 C++ 中使用 C 代码

**（1）直接包含 C 头文件**

```cpp
#include <stdio.h>
#include <stdlib.h>
```

- C++ 在不牺牲性能的前提下，提高：
    - 可维护性
    - 可扩展性
    - 抽象能力
- C 库头文件可直接使用
- 注意 **函数名链接** 问题

**（2）防止名字修饰（Name Mangling）**

- C++ 默认函数名会修饰，C 编译器不识别
- 用 extern "C" 指定 C 链接方式

```cpp
extern "C" {
    #include "my_c_lib.h"
    void c_func(int x);
}
```

- 编译器按 C 方式处理函数名，避免链接错误

### 2.4.4 C++ 调用 C 的注意事项

1. 头文件用 `extern "C"` 包裹
2. **不能直接用 C++ 特性**（如类、重载、模板）在 C 里
3. **数据类型匹配**：避免 `bool`、引用等 C++ 特性与 C 不兼容

### 2.4.5 面试高频总结句

> C++ 大体兼容 C，但并非严格意义上的 C 超集；C 代码在 C++ 中通常通过 `extern "C"` 保证链接兼容。

C++ 编译时比 C 更严格、更复杂，支持名字修饰和模板实例化；C 代码在 C++ 中通过 extern "C" 使用，保证链接兼容。

## 2.5 结构体（struct）和类（class）的区别

### 2.5.1 默认访问权限

**示例**：

```cpp
struct S {
    int a;  // 默认 public
};

class C {
    int b;  // 默认 private
};
```

- S.a 可以在外部直接访问
- C.b 需要通过公有成员函数访问，否则编译报错

|类型|成员变量/成员函数默认访问权限|
|---|---|
|struct|public|
|class|private|

### 2.5.2 默认继承权限

**示例**：

```cpp
struct Base {};
struct Derived1 : Base {};  // public 继承
class Derived2 : Base {};   // private 继承
```

|类型|struct|class|
|---|---|---|
|默认继承权限|public|private|

### 2.5.3 使用习惯

- struct
    - 常用于 **仅包含数据的类型**（类似 C 语言结构体）
    - 成员一般都公开，方便直接访问
    - 在嵌入式开发中经常用来表示寄存器映射或数据包结构

### 2.5.4 其他注意点

- **C++ 中的 struct 与 class 功能上几乎等价**，除了默认访问权限和默认继承权限
- **C 语言只有 struct**，没有 class，也不支持面向对象特性
- **嵌入式开发中**：struct 更常用在硬件寄存器或通信协议定义中，class 用于实现复杂控制逻辑

### 2.5.5 总结

|特性|struct|class|
|---|---|---|
|默认成员访问权限|public|private|
|默认继承权限|public|private|
|面向对象特性|支持（C++）|支持（C++）|
|使用场景|数据封装简单、寄存器映射|封装复杂逻辑、继承、多态|

## 2.6 public、protected、private 的访问控制区别？

### 2.6.1 public 访问控制

- **含义**：public 成员可以在任何地方被访问，包括类外部的任何代码。
- **常用场景**：当你希望某个成员（变量或函数）可以被类的外部自由访问和修改时，使用 public。

**示例**：

**C 语言**

```cpp
class MyClass {
public:
    int x;  // public 成员变量

    void print() {  // public 成员函数
        std::cout << "Value: " << x << std::endl;
    }
};

int main() {
    MyClass obj;
    obj.x = 10;  // 直接访问 public 成员
    obj.print();  // 直接调用 public 函数
    return 0;
}
```

- **优点**：灵活、容易访问，适用于外部需要频繁访问的成员。
- **缺点**：如果设计不当，可能会让对象的状态暴露给外部，影响封装性和数据安全性。

### 2.6.2 protected 访问控制

- **含义**：protected 成员只能在类内部和派生类中访问，但不能在类外部直接访问。
- **常用场景**：当你希望成员变量或成员函数在基类和派生类中可访问，但不希望外部直接访问时，使用 protected。

**示例**：

```cpp
class Base {
protected:
    int x;  // protected 成员变量
};

class Derived : public Base {
public:
    void setX(int value) {
        x = value;  // 在派生类中可以访问基类的 protected 成员
    }
};

int main() {
    Base obj;
    // obj.x = 10;  // 错误：无法访问 protected 成员
    Derived derived;
    derived.setX(10);  // 可以通过派生类访问
    return 0;
}
```

- **优点**：允许派生类继承父类的成员，并且提供一定的保护，不允许外部随意访问。
- **缺点**：限制了对成员的访问，可能不方便在某些场景下进行直接访问。

### 2.6.3 private 访问控制

- **含义**：private 成员只能在类的内部访问，不能在外部代码中直接访问。派生类也不能直接访问基类的 private 成员，除非通过公共接口访问。
- **常用场景**：当你希望类的成员变量和函数完全隐藏，封装在类内部时，使用 private。

**示例**：

```cpp
int main() {
    MyClass obj;
    // obj.x = 10;  // 错误：无法直接访问 private 成员
    obj.setX(10);  // 使用公共函数间接访问
    std::cout << obj.getX() << std::endl;
    return 0;
}
```

- **优点**：完全封装类的实现细节，保护对象的内部状态，避免外部直接修改，增强了数据的安全性。
- **缺点**：不能直接访问数据，必须通过公有接口访问，可能导致代码冗长。

### 2.6.4 对比

|访问控制|类外访问|派生类访问|类内访问|常用场景|
|---|---|---|---|---|
|public|可访问|可访问|可访问|当你希望外部可以自由访问类的成员时使用|
|protected|不可访问|可访问|可访问|当你希望派生类能访问基类成员，但外部不可访问|
|private|不可访问|不可访问|可访问|当你希望完全隐藏类的实现细节时使用|

### 2.6.5 访问控制的应用

- public：公开方法和数据成员，通常用于与外界交互时，例如接口函数。
- protected：用于父类与子类之间的继承关系，但不允许外部随意访问，常用于那些需要在子类中修改的成员。
- private：完全隐藏类的实现细节，只允许类内部访问，确保类的封装性和数据安全性。

### 2.6.6 实际应用场景

- **封装性和数据安全**：通常，我们将类的成员声明为 private，并通过公有（public）的 getter 和 setter 方法来控制对成员的访问，从而确保数据不被随意修改。

```cpp
class BankAccount {
private:
    double balance;  // 保护账户余额

public:
    void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    double getBalance() {
        return balance;
    }
};
```

- **继承和扩展性**：当我们设计继承体系时，可以将一些方法或数据成员声明为 protected，使得派生类能够继承和修改这些成员，而外部无法直接访问。

```cpp
class Shape {
protected:
    double area;
public:
    virtual void calculateArea() = 0;  // 纯虚函数
};

class Rectangle : public Shape {
public:
    void calculateArea() override {
        area = 10 * 5;  // 计算面积
    }
};
```

### 2.6.7 总结

- public：允许类外部直接访问成员。
- protected：允许类外部无法直接访问，但可以在派生类中访问。
- private：完全封装成员，仅允许类内部访问。

## 2.7 常量成员函数

### 2.7.1 定义

**常量成员函数（const member function）** 是在成员函数后加 `const` 的函数，表示不能直接修改对象的非 `mutable` 数据成员。

```cpp
class A {
    int x;
public:
    int getX() const { return x; }  // 常量成员函数
};
```

- const 成员函数不能直接修改非 `mutable` 数据成员
- 可以被 **const 对象** 调用

### 2.7.2 语法与特点

```cpp
返回类型 函数名(参数) const;
```

特点：

1. **`this` 指针视为指向 const 对象**
    - A* const this → const A* const this
    - 不能修改成员变量或调用非 const 函数
2. **可以被 const 对象调用**
    - 非 const 成员函数不能被 const 对象调用

### 2.7.3 示例

```cpp
class A {
    int x;
public:
    A(int val) : x(val) {}
    int getX() const { return x; }    // const 成员函数
    void setX(int val) { x = val; }   // 非 const 成员函数
};

int main() {
    const A a(10);
    a.getX();  // OK
    // a.setX(20);  // 错误，不能调用非 const 函数
}
```

### 2.7.4 用途

1. **保证成员函数不修改对象**
2. **支持 const 对象或 const 引用调用**
3. **提高代码安全性和可读性**

### 2.7.5 注意事项

1. 常量成员函数 **不能修改普通成员变量**
2. 可以修改 mutable 修饰的成员
3. 常量成员函数 **可以调用其他 const 成员函数**

```cpp
class A {
    mutable int cache; // 可在 const 函数中修改
public:
    int getCache() const { return ++cache; }
};
```

### 2.7.6 面试高频总结句

> const 成员函数不能直接修改非 `mutable` 数据成员，并且可被 const 对象调用；它提供的是接口层面的只读承诺。

## 2.8 new和malloc的区别

### 2.8.1 语言层级不同

|对比项|malloc|new|
|---|---|---|
|所属语言|C|C++|
|是否关键字|否（函数）|是（运算符）|

### 2.8.2 返回类型不同（重要）

- malloc 返回 void*，需要强制类型转换
- new 返回具体类型指针，无需转换

```c
int *p = (int *)malloc(sizeof(int));
```

```cpp
int *p = new int;
```

### 2.8.3 是否调用构造/析构函数（核心区别）

|项目|malloc|new|
|---|---|---|
|构造函数|不调用|调用|
|析构函数|不调用|delete 时调用|

### 2.8.4 内存初始化行为

**C++**

- malloc：不初始化
- new：
    - 基本类型：不初始化（new int）
    - 带括号：初始化（new int()）
    - 对象：调用构造函数

### 2.8.5 释放方式不同（必须配对）

|分配|释放|
|---|---|
|malloc|free|
|new|delete|
|new[]|delete[]|

### 2.8.6 失败处理方式

- malloc：返回 NULL
- new：抛出异常（std::bad_alloc）

```cpp
int *p = new(std::nothrow) int;
```

- 支持面向对象

### 2.8.7 分配机制不同

- malloc：
    - 只负责分配内存
    - 不关心类型
- new：
    - 分配内存 + 类型构造
    - 类型安全

### 2.8.8 使用场景建议

|场景|建议|
|---|---|
|C 项目|malloc|
|C++ 项目|new / 智能指针|
|对象管理|new|
|嵌入式实时系统|谨慎使用两者|

### 2.8.9 注意点

- malloc + free
- new + delete
- new[] + delete[]
- 数据与行为封装在类中
- malloc 只分配内存，new 分配内存并构造对象；在 C++ 中应优先使用 new（或智能指针）。

## 2.9 C++ 中 enum class 与传统 enum 的区别？（状态机可能会用）

**C++11 **引入了 enum class，为传统的 enum 提供了更强的类型安全和作用域控制。它们的主要区别在于作用域、类型安全和可扩展性等方面。

### 2.9.1 作用域（Scope）

```cpp
enum Color { Red, Green, Blue };

Color c = Red;  // 无需作用域访问
// 但是如果有另一个枚举也定义了 Red，就会发生冲突
```

- enum class：enum class 定义的枚举常量被严格限制在枚举类型的作用域内，必须通过类型名来访问，避免了名称冲突。
- **示例**：

```cpp
enum class Color { Red, Green, Blue };

Color c = Color::Red;  // 需要通过作用域访问
// 不会与其他枚举类型中的 Red 冲突
```

### 2.9.2 类型安全（Type Safety）

- **传统 `enum`**：传统的 enum 会自动将枚举值转换为整型（int），这可能导致隐式类型转换，从而发生潜在的错误。
- **示例**：

```cpp
enum Color { Red, Green, Blue };

Color c = Red;
int x = c;  // 可以隐式转换为 int，可能会引起逻辑错误
```

- enum class：enum class 是 **强类型枚举**，不允许隐式转换为整型或其他类型，提供了更强的类型安全性。
- **示例**：

```cpp
enum class Color { Red, Green, Blue };

Color c = Color::Red;
int x = c;  // 编译错误：不能隐式转换为 int
```

### 2.9.3 默认值（Underlying Type）

- **传统 `enum`**：传统 enum 的枚举值通常自动从 0 开始，枚举值的底层类型通常是 int。但可以显式指定底层类型。
- **示例**：

```cpp
enum Color { Red = 1, Green, Blue };  // 默认 1, 2, 3
```

- enum class：enum class 的底层类型是 **默认的整数类型**（通常是 int），但是你可以显式指定底层类型，并且枚举值的默认值也从 0 开始。
- **示例**：

```cpp
enum class Color : uint8_t { Red = 1, Green, Blue };  // 显式指定底层类型为 uint8_t
```

### 2.9.4 与整数的交互

- **传统 **enum：可以直接与整数进行比较或赋值操作。
- **示例**：

```cpp
enum Color { Red = 1, Green, Blue };

Color c = Green;
if (c == 2) {  // 可以直接比较
    // do something
}
```

- enum class：enum class 的枚举值不能直接与整数进行比较或赋值操作，必须显式转换为底层类型。
- **示例**：

```cpp
enum class Color { Red = 1, Green, Blue };

Color c = Color::Green;
// if (c == 2) {  // 编译错误，不能直接比较
if (static_cast<int>(c) == 2) {  // 显式转换
    // do something
}
```

### 2.9.5 枚举值的使用场景

- **传统 `enum`**：传统 enum 更适合用于那些不需要强类型保护的场景，或者枚举值本身有明确的数值含义。
- enum class：enum class 适用于需要更严格类型检查和作用域控制的场景，特别是在大型项目或库开发中，能够有效避免命名冲突和隐式类型转换问题。

### 2.9.6 总结对比

|特性|传统 enum|enum class|
|---|---|---|
|作用域|无作用域限制，枚举值暴露在全局作用域|有作用域，需通过类型名访问|
|类型安全|不提供类型安全，允许隐式转换|强类型，不允许隐式转换|
|底层类型|默认是 int，但可以显式指定|默认是 int，可以显式指定底层类型|
|与整数的交互|可以与整数直接比较|必须显式转换为底层类型后比较|
|适用场景|简单的枚举，或者枚举值本身是数字|需要更强封装和类型安全的场景|

### 2.9.7 使用建议

- **使用传统 **enum：
    - 当枚举值是一些固定的数字，且不需要严格的类型保护时，使用传统的 enum 更为简洁。

## 2.10 编译的四个过程

C++ 编译过程通常分为四个主要阶段：**预处理阶段、编译阶段、汇编阶段和链接阶段**。每个阶段都有其特定的任务和作用，确保源代码能够成功编译为可执行程序。

### 2.10.1 预处理阶段

预处理阶段主要处理代码中的**预处理指令**（以 # 开头），它是整个编译过程的第一步。主要工作包括以下几个方面：

- **文件包含**（#include）：预处理器会将 #include 指令中的头文件内容插入到源代码中。在这个阶段，预处理器会将所有的头文件（如 .h 或 .hpp 文件）替换成它们实际的内容。例如：#include <iostream> 会被替换成 iostream 文件的完整内容。
- **宏定义**（#define）：预处理器会将所有的宏定义（#define）替换成它们所定义的内容。
- **条件编译**（#if、#ifdef、#else、#endif 等）：预处理器会根据条件编译指令，决定哪些代码需要被编译，哪些则被忽略。
- **删除注释**：在预处理阶段，源代码中的注释（如 // 或 /* */）会被移除，因为它们不需要出现在编译后的代码中。

### 2.10.2 编译阶段

编译阶段是源代码被**转化为汇编代码**的过程。这个阶段主要包括以下几个步骤：

- **语法分析：**编译器会检查源代码的语法是否正确。语法分析会确保代码符合 C++ 语法规则，例如括号匹配、表达式格式等。
- **语义分析：**编译器检查代码的语义是否正确。语义分析确保变量、函数等的使用是合理的，如类型匹配、变量初始化等。
- **优化：**编译器会尝试优化代码，提高其执行效率。这包括移除冗余代码、合并相似的表达式、进行常量折叠等优化。
- **生成汇编代码：**在编译阶段的最后，编译器将源代码转换为汇编语言代码。生成的汇编文件通常具有 .s 扩展名，表示汇编代码。该汇编代码为机器代码生成做准备。

### 2.10.3 汇编阶段

在汇编阶段，编译器生成的汇编代码会被汇编器**转化为机器语言（即二进制代码）**。此阶段主要包括以下内容：

- **汇编：**汇编器将 .s 文件中的汇编语言代码转换为机器指令（即机器码）。每条汇编指令都对应一条机器指令，这些机器指令可以直接被计算机执行。
- **生成目标文件：**汇编器输出的文件是目标文件（通常是 .o 或 .obj 扩展名），它包含了编译后的机器码，但是还没有完全链接成可执行文件。目标文件可能会缺少一些外部符号的定义（例如其他源文件中的函数或变量）。

### 2.10.4 链接阶段

链接阶段是整个编译过程的最后一步，它将**所有的目标文件和库文件组合在一起，生成最终的可执行文件**。链接阶段包括以下内容：

- **符号解析：**链接器会查找目标文件中的符号（如函数、变量等），将它们与其他目标文件或库中的符号进行匹配，确保所有的函数和变量都能正确地连接。
- **重定位：**链接器会处理代码中相对地址的修正，**将所有符号的引用地址更新为实际的内存地址**。这是因为每个目标文件的符号地址都是相对的，链接器需要确保这些符号引用正确。
- **库文件链接：**链接器还会将程序所依赖的库（如静态库 .a 或 .lib 文件）**链接到最终的可执行文件中**。

```cpp
std::unique_ptr
```

- **生成可执行文件：**最终，链接器将所有的目标文件和库文件合并，生成一个完整的**可执行文件**（通常是 .exe、.out 或 .elf 文件），程序可以通过操作系统来运行。

### 2.10.5 总结

C++ 编译的四个过程：

1. **预处理阶段：** 处理预处理指令（文件包含、宏定义、条件编译等），生成预处理后的源文件。.i
2. **编译阶段：** 进行语法分析、语义分析、优化，生成汇编代码。.s
3. **汇编阶段：** 将汇编代码转化为机器码，生成目标文件（.o 或 .obj）。
4. **链接阶段：** 进行符号解析、重定位，合并目标文件和库，生成最终的可执行文件。

## 2.11 左值引用、右值引用

### 2.11.1 定义

**引用（Reference）** 是 C++ 提供的对已有变量的别名。
根据绑定对象的类型，分为：

1. **左值引用（lvalue reference）**
    - 非 `const` 左值引用绑定到类型兼容的左值；`const T&` 还可绑定右值并延长某些临时对象的生命期
    - 声明方式：T&

2. **右值引用（rvalue reference）**
    - 绑定到 **临时对象或将亡对象**（右值）
    - 声明方式：T&&
    - 支持 **移动语义** 和 **完美转发**

### 2.11.2 左值引用

```cpp
int a = 10;
int& ref = a; // 左值引用，ref 是 a 的别名
ref = 20;     // a 也变为 20
```

- 非 `const T&` 通常绑定到可修改左值；`const T&` 可以绑定临时对象
- 常用于函数参数传递和返回已存在对象的别名；引用本身不是“返回值优化”或 RAII 机制

```cpp
void foo(const std::string& s); // 避免拷贝
```

### 2.11.3 右值引用

```cpp
int&& rref = 10; // 右值引用绑定临时对象
rref += 5;       // 可以修改临时对象
```

- **主要用途**：移动语义、资源转移
- 典型场景：

**移动示例**

```cpp
std::vector<int> v1 = {1,2,3};
std::vector<int> v2 = std::move(v1); // 允许从 v1 移动构造 v2
```

- `std::move` 本身只做类型转换，不移动任何资源；是随后选中的移动构造/赋值函数决定如何处理源对象。

- 支持函数参数 **完美转发**：

```cpp
template<typename T>
void wrapper(T&& arg) {
    func(std::forward<T>(arg));
}
```

### 2.11.4 左值引用 vs 右值引用

|特性|左值引用（Lvalue Reference）|右值引用（Rvalue Reference）|
|---|---|---|
|定义语法|`T& a = x;`|`T&& a = T();`|
|可绑定对象|`T&` 绑定左值；`const T&` 也可绑定右值|`T&&` 通常绑定右值；模板推导中的 `T&&` 还可能是转发引用|
|修改原对象|可以通过引用修改原对象|可以通过引用修改临时对象，但临时对象寿命会延长|
|主要用途|传递参数、返回对象、避免拷贝|移动语义、完美转发、优化性能|
|生命周期管理|不改变原对象生命周期|可延长右值对象生命周期以便安全使用|

### 2.11.5 总结

> 左值引用通常表示已存在对象的别名；右值引用可用于移动语义，模板推导语境中的转发引用可配合 `std::forward` 保留值类别。
> 左值引用 = 别名，右值引用 = 可转移资源的临时对象。

## 2.12 简述C++有几种传值方式之间的区别

### 2.12.1 值传递（Pass by Value）

```cpp
void func(int x);
```

- **实参拷贝一份给形参**

```c
malloc / free
```

- 函数内修改不影响实参
- 会产生拷贝开销

适用场景：

- 基本类型
- 小对象

### 2.12.2 指针传递（Pass by Pointer）

```cpp
void func(int *p);
```

- 传递的是**地址的副本**
- 可通过指针修改实参
- 需显式解引用

特点：

- 可能为 nullptr
- 易出错
- 易出错，但语义清晰（C 风格）

### 2.12.3 引用传递（Pass by Reference）

```cpp
void func(int &x);
```

- 形参是实参的**别名**
- 无拷贝、无空引用
- 调用方式更自然

工程中**最常用**

### 2.12.4 常量引用传递（重点推荐）

```cpp
void func(const MyClass &obj);
```

- 不拷贝对象
- 防止修改
- 支持临时对象

适用：

- 大对象
- 接口参数设计

### 2.12.5 右值引用传递（C++11 及以后）

```cpp
void func(MyClass &&obj);
```

- 绑定临时对象
- 支持**移动语义**
- 减少拷贝

常用于：

- 构造函数
- 容器、资源管理类

### 2.12.6 各种方式对比总结

|方式|是否拷贝|能否修改实参|是否可为空|
|---|---|---|---|
|值传递|是|否|否|
|指针传递|否|是|是|
|引用传递|否|是|否|
|const 引用|否|否|否|
|右值引用|否|是|否|

**常见考点**

- C 与 C++ 传参方式区别
- 为什么推荐 const &
- 引用与指针的本质区别
- **C++ 在值传递基础上引入引用与右值引用，实现高效、安全、语义清晰的参数传递机制**

## 2.13 typedef 与 using 的区别？

### 2.13.1 基本用法

- typedef：typedef 用于为现有类型创建一个新的别名。
- **示例**：

```cpp
typedef int Integer;  // int 类型的别名 Integer
Integer x = 10;       // 使用别名
```

- using：using 也用于创建类型别名，但语法更加直观。
- **示例**：

```cpp
using Integer = int;  // int 类型的别名 Integer
Integer x = 10;       // 使用别名
```

### 2.13.2 语法差异

- typedef：typedef 的语法相对繁琐。它通常把类型放在别名后面。

```cpp
typedef existing_type alias_name;  // 语法：typedef <类型> <别名>
```

- using：using 的语法更直观，把别名放在等号左边，类型放在等号右边。

```cpp
using alias_name = existing_type;  // 语法：using <别名> = <类型>
```

### 2.13.3 模板别名（typedef 和 using 的差异）

- typedef：在为模板类型定义别名时，typedef 的语法比较复杂，特别是模板类型参数较为复杂时。
- **示例**：

```cpp
typedef std::vector<int> IntVector;  // 定义 vector<int> 的别名
```

- using：using 更加简洁，尤其是定义模板别名时，更加直观。
- **示例**：

```cpp
using IntVector = std::vector<int>;  // 定义 vector<int> 的别名
```

- **模板别名的复杂情况**：
  在模板别名中，using 提供了比 typedef 更简洁的语法。
- **typedef 示例**：

```cpp
typedef std::map<int, std::vector<int>> MapType;  // 复杂模板别名
```

- **using 示例**：

```cpp
using MapType = std::map<int, std::vector<int>>;  // 更简洁
```

### 2.13.4 别名模板（模板别名）

using 提供了对模板类型别名的支持，而 typedef 不支持别名模板，必须通过 typedef 和模板的嵌套结合实现。using 使得模板别名更加简单易读。

- **using 允许定义别名模板**：

```cpp
template <typename T>
using Vec = std::vector<T>;  // 别名模板
```

- 你可以通过 Vec<int> 来代替 std::vector<int>，这使得模板的使用更加简洁。
- **typedef 不支持别名模板**：
  如果你想为模板类型使用 typedef，必须使用复杂的嵌套 typedef。

```cpp
template <typename T>
struct Vec {
    typedef std::vector<T> type;  // 不如 using 简洁
};
```

### 2.13.5 可读性与可维护性

- typedef：对于复杂的类型别名，typedef 会显得较为冗长和不直观，尤其是嵌套模板类型别名时。
- **示例**：

```cpp
typedef std::map<int, std::vector<std::string>> ComplexType;
```

- using：using 提供了更直观的方式来定义类型别名，尤其在模板别名时，语法清晰且易于理解。
- **示例**：

```cpp
using ComplexType = std::map<int, std::vector<std::string>>;
```

### 2.13.6 typedef 和 using 的选择

- **使用 `typedef` 的场景**：typedef 是旧版本 C++ 的标准，因此，早期的 C++ 代码和许多库仍使用 typedef。如果需要支持 C++98 或编写旧版代码，可以使用 typedef。
- **使用 `using` 的场景**：对于现代 C++（C++11 及之后），通常更推荐 using，因为语法简洁直观，并支持模板别名。

### 2.13.7 总结对比

|特性|typedef|using|
|---|---|---|
|语法|typedef <类型> <别名>|using <别名> = <类型>|
|模板别名|不支持模板别名，必须嵌套定义|支持模板别名，语法简洁直观|
|可读性|在复杂类型别名时不如 using 直观|更加简洁，尤其是在模板类型别名时|
|使用场景|兼容旧版本代码，必须支持 C++98|推荐在现代 C++ 中使用|
|支持的特性|不支持别名模板|支持别名模板，模板参数别名更简洁|

### 2.13.8 使用建议

- **现代 C++ 中，推荐使用 **using 来定义类型别名，尤其是在处理模板别名时，using 的语法更直观。
- typedef 主要用于向后兼容旧代码，或者在某些特定情况下（如 typedef 需要用于 C++98 标准中）。

## 2.14 什么是野指针和悬挂指针？

### 2.14.1 野指针（Wild Pointer）

**定义：**
**未初始化或指向不确定地址的指针**。

```c
int *p;   // 野指针
```

- **产生原因：** 定义后未初始化；指针被随意赋值
- **危害：** 解引用导致不可预期行为；可能破坏任意内存

**避免方法：**

```c
int *p = NULL;
```

### 2.14.2 悬挂指针（Dangling Pointer）

**定义：**
**指向已被释放或已失效内存的指针**。

```c
int *p = malloc(sizeof(int));
free(p);
// p 仍指向原地址 → 悬挂指针
```

- **产生原因：** free 后继续使用；返回局部变量地址；指向生命周期已结束的对象
- **危害：** 访问非法内存；难以复现的随机错误

**避免方法：**

```c
free(p);
p = NULL;
```

### 2.14.3 核心区别对比（高频）

|对比项|野指针|悬挂指针|
|---|---|---|
|是否初始化|否|是|
|指向地址|随机|曾经合法|
|产生阶段|定义时|释放或失效后|
|危险程度|极高|极高|

### 2.14.4 常见错误示例

**返回局部变量地址（悬挂指针）**

```c
int* func() {
    int a = 10;
    return &a;
}
```

### 2.14.5 注意点

- 指针定义即初始化
- 释放后立即置 NULL
- 使用工具检测（ASan、Valgrind）
- C++ 中使用智能指针

## 2.15 内置类型的默认初始化和类成员的默认初始化区别？

### 2.15.1 内置类型的默认初始化

- **定义**：内置类型（如 int, char, double, 等）在局部变量声明时 **不会自动初始化**，它们的初始值是不确定的（即未定义的）。如果在全局或静态作用域中声明，内置类型的变量会被自动初始化为零（0）。
- **局部变量**：
  局部的内置类型变量 **不会被初始化**，其值是未定义的。

```cpp
void function() {
    int x;  // x 的值不确定
}
```

- **全局/静态变量**：
  全局或静态变量会 **自动初始化为零**。

```cpp
int x;  // 全局变量，x 默认值是 0
```

### 2.15.2 类成员的默认初始化

- **定义**：类的成员变量在创建对象时有不同的初始化规则。成员变量的默认初始化行为取决于它们的作用域（成员是否有初始值，构造函数的作用等）。
- **类成员的自动初始化**：
  如果成员变量没有显式的初始化，那么它的值是 **未定义的**（对于普通成员变量而言）。但是，可以通过 **构造函数的初始化列表** 或 **默认成员初始化** 来指定默认值。
    - **默认成员初始化**：C++11 引入了默认成员初始化。通过为类的成员提供一个初始值，使得每次创建对象时，成员会有一个明确的初始值。

```cpp
struct DefaultInit {
    int x = 10;
    double y = 3.14;
};

DefaultInit obj;
std::cout << obj.x << ", " << obj.y << std::endl;  // 输出 10 和 3.14
```

- **构造函数初始化列表**：你也可以在构造函数中使用初始化列表来初始化成员变量。

```cpp
class MyClass {
public:
    int x;
    double y;

    MyClass(int a, double b) : x(a), y(b) {}  // 通过构造函数初始化
};

MyClass obj(5, 7.6);
std::cout << obj.x << ", " << obj.y << std::endl;  // 输出 5 和 7.6
```

### 2.15.3 区别总结

- **对于内置类型**：尽量避免依赖于未初始化的内置类型变量，尤其是在局部变量中，应始终显式初始化变量。
- **对于类成员**：推荐使用 **默认成员初始化**，确保每个成员有明确的初始值，从而减少出现未定义行为的风险。

|特性|内置类型|类成员|
|---|---|---|
|默认初始化|局部内置类型变量没有默认初始化，值不确定；全局/静态变量默认初始化为 0|如果没有显式初始化，类成员的值未定义，可以通过构造函数或默认成员初始化指定默认值|
|初始化行为|未定义的行为；必须显式初始化才能保证可预测的结果|可以通过构造函数、默认成员初始化来明确指定初始值|
|自动赋值|不会自动赋予一个合理的初值，可能导致程序错误|可以为成员变量提供默认值，避免未初始化的问题|

## 2.16 内联函数

### 2.16.1 什么是内联函数（Inline Function）

**定义：**
内联函数是指在编译阶段，**将函数调用处直接展开为函数体代码**，从而避免函数调用开销。

```cpp
inline int add(int a, int b) {
    return a + b;
}
```

### 2.16.2 为什么使用内联函数

**（1）减少函数调用开销**

- 省去压栈、跳转、返回等操作
- 适合短小、频繁调用的函数

**（2）提高执行效率**

- 尤其在性能敏感代码中
- 常用于嵌入式和底层库

**（3）比宏更安全（重点）**

|对比|宏|内联函数|
|---|---|---|
|类型检查|无|有|
|作用域|无|有|
|调试友好|差|好|

### 2.16.3 内联函数的工作机制

- inline 是 **对编译器的建议**
- 编译器可选择忽略
- 真正是否内联由编译器决定

### 2.16.4 常见使用场景

- 访问器函数（getter/setter）
- 短小工具函数
- 模板函数（通常内联）

### 2.16.5 使用内联函数的注意事项（必考）

**（1）函数不宜过大**

- 函数体大反而增加代码体积
- 可能导致指令缓存压力

**（2）不适合复杂逻辑**

- 循环多
- 递归函数
- 虚函数（运行期多态）

**（3）内联函数通常放在头文件**

- 编译期展开
- 多文件可见

**（4）递归函数不能内联**

- 无法在编译期确定展开次数

### 2.16.6 C 与 C++ 中的区别

- C：通过 static inline
- C++：直接 inline

```c
static inline int add(int a, int b) {
    return a + b;
}
```

## 2.17 nullptr、NULL 与 0 的区别？

在 C++ 中，nullptr、NULL 和 0 都可以用来表示 **空指针**，但它们的使用方式和语义存在差异。下面将详细说明它们之间的区别。

### 2.17.1 nullptr

- **定义**：`nullptr` 是 C++11 引入的空指针字面量，类型为 `std::nullptr_t`，可转换为任意指针或成员指针类型。
- **特点**：
    - **类型安全**：nullptr 是专门为指针类型设计的，编译器能够根据上下文确定它是指针类型，因此避免了与整数类型的混淆。
    - **明确性**：它明确表示指针没有指向任何对象。
- **示例**：

```cpp
int* ptr = nullptr;  // 明确指针为空
if (ptr == nullptr) {
    std::cout << "Pointer is null" << std::endl;
}
```

- **注意**：`nullptr` 不能隐式转换为普通整数；可与指针比较，也可转换为任意指针或成员指针类型。

### 2.17.2 NULL

- **定义**：`NULL` 是实现定义的宏；在 C++ 中通常展开为整型空指针常量（如 `0` 或 `0L`），不应假定为 `((void*)0)`。
- **特点**：
    - **类型不安全**：`NULL` 是宏，在 C++ 中通常是整型空指针常量，重载解析时可能被当作整数。
    - **历史遗留问题**：NULL 在 C++ 中是为了与 C 兼容而保留下来的，虽然它仍然有效，但不如 nullptr 安全。
- **示例**：

```cpp
int* ptr = NULL;  // 使用 NULL 来表示空指针
if (ptr == NULL) {
    std::cout << "Pointer is null" << std::endl;
}
```

- **注意**：不要依赖 `NULL` 的具体宏展开；它可能与整数重载混淆。

### 2.17.3 0

- **定义**：在 C++ 中，0 可以作为空指针常量使用，表示指针不指向任何有效地址。
- **特点**：
    - **类型不安全**：0 是一个整数常量，编译器允许它与指针进行比较或赋值，这可能导致潜在的类型不安全问题。
    - **历史遗留问题**：在 C++ 中，0 可以隐式地转换为空指针，虽然它在很多旧代码中使用，但它不是专门为指针设计的。
- **示例**：

```cpp
int* ptr = 0;  // 使用 0 表示空指针
if (ptr == 0) {
    std::cout << "Pointer is null" << std::endl;
}
```

- **注意**：
    - 使用 0 来表示空指针时，不如 nullptr 语义明确，且可能会与其他整数混淆，因此不推荐使用。

### 2.17.4 总结

- **优先使用 `nullptr`**：在现代 C++ 编程中，推荐使用 `nullptr`，它是专为指针语义设计的，能够避免与整数混淆。
- **避免使用 `NULL` 和 `0` 表示空指针**：虽然它们在 C++ 中仍然有效，但不具备 nullptr 的类型安全性；新代码通常推荐使用 `nullptr`。

|特性|nullptr|NULL|0|
|---|---|---|---|
|类型|`std::nullptr_t`，专为指针语义设计|实现定义的宏，C++ 中通常为整型空指针常量|整数常量，可以隐式转换为指针|
|与指针的兼容性|可转换为任意指针或成员指针类型|可以与指针类型比较，但可能与整数混淆|可以与指针类型比较，但可能与整数混淆|
|类型安全|高，避免与整数等其他类型混淆|低，可能与整数混淆，容易产生错误|低，整数常量可能会产生隐式转换错误|
|推荐使用场景|在 C++11 及之后推荐用于空指针|兼容旧代码|可用但不推荐，新代码使用 `nullptr`|

## 2.18 构造函数、析构函数的作用和调用顺序？

### 2.18.1 构造函数

**作用：**

构造函数是类的一种特殊成员函数，它在创建对象时自动调用，用于初始化对象的成员变量或进行资源分配等操作。构造函数有两个主要功能：

- **初始化对象**：为对象的成员变量赋初值。
- **资源分配**：如果对象涉及动态内存或资源管理（如文件、网络连接等），构造函数可以用于分配和初始化这些资源。

**特点：**

- **自动调用**：构造函数在对象创建时自动被调用，无需显式调用。
- **没有返回值**：构造函数没有返回类型（即使是 void 也不能指定）。
- **函数名与类名相同**：构造函数的名称与类名完全相同。

**调用时机：**

构造函数在以下情况下被自动调用：

- 当一个对象被创建时（无论是栈对象还是堆对象）。
- 当对象的某个成员初始化时（通过构造函数初始化列表）。
- **构造函数类型：** **默认构造函数**：不带参数的构造函数。

```cpp
class MyClass {
public:
    MyClass() { // 默认构造函数
        // 初始化成员变量
    }
};
```

- **参数化构造函数**：带有参数的构造函数，用来根据传入的参数进行初始化。

```cpp
class MyClass {
public:
    MyClass(int a) { // 参数化构造函数
        // 使用参数 a 初始化成员变量
    }
};
```

- **拷贝构造函数**：当一个对象通过复制构造另一个对象时，调用拷贝构造函数。

```cpp
class MyClass {
public:
    MyClass(const MyClass& other);  // 拷贝构造函数声明
};
```

- **移动构造函数**：用于将一个右值对象的资源“移动”到当前对象，避免不必要的深拷贝，提高性能（常见于临时对象、函数返回值等场景）。

```cpp
class MyClass {
public:
    MyClass(MyClass&& other) { // 移动构造函数
        // 将 other 的资源转移到当前对象
        data = other.data;

        // 将 other 的资源置空，避免重复释放
        other.data = nullptr;
    }

private:
    int* data;
};
```

### 2.18.2 析构函数

**作用：**

析构函数是类的另一种特殊成员函数，它在对象生命周期结束时自动调用，用于清理资源。主要功能：

- **资源释放**：释放动态分配的内存、关闭文件、释放网络连接等。
- **对象销毁时的清理工作**：进行清理操作以避免资源泄漏或其他潜在问题。

**特点：**

- **自动调用**：析构函数在对象销毁时自动调用，无需显式调用。
- **没有返回值和参数**：析构函数没有返回类型，且不接受任何参数。
- **函数名与类名相同，但前面有一个波浪符（`~`）**：

```cpp
~MyClass() {
    // 释放资源
}
```

**调用时机：**

析构函数在以下情况下自动调用：

- 当栈对象超出作用域时，析构函数被调用（自动销毁）。
- 当动态分配的对象通过 delete 删除时，析构函数被调用。

### 2.18.3 构造函数和析构函数的调用顺序

**构造函数调用顺序：**

1. **基类构造函数**：如果类继承自其他类，基类构造函数先于派生类自己的成员和构造函数体执行。
    - **先基类后派生类**：在构造派生类对象时，首先会调用基类构造函数，随后调用派生类构造函数。

```cpp
class Base {
public:
    Base() {
        std::cout << "Base constructor" << std::endl;
    }
};

class Derived : public Base {
public:
    Derived() {
        std::cout << "Derived constructor" << std::endl;
    }
};
```

2. **成员变量的构造**：基类构造完成后，派生类成员按声明顺序初始化。

补充说明：当创建派生类对象时，先构造虚基类（如有），再构造直接基类，然后按成员在类中声明的顺序初始化派生类成员，最后执行派生类构造函数体。初始化顺序与初始化列表中的书写顺序无关。

3. **派生类构造函数体**：最后执行派生类构造函数体。

**析构函数调用顺序：**

1. **派生类析构函数**：当对象销毁时，析构过程从派生类开始，首先调用派生类的析构函数。
2. **基类析构函数**：在派生类析构函数执行完毕后，再调用基类的析构函数。
    - **先派生类后基类**：析构过程从派生类的析构函数开始，最后调用基类的析构函数。

```cpp
class Base {
public:
    virtual ~Base() {
        std::cout << "Base destructor" << std::endl;
    }
};

class Derived : public Base {
public:
    ~Derived() {
        std::cout << "Derived destructor" << std::endl;
    }
};
```

### 2.18.4 总结

- **构造函数**：在构造函数中负责初始化资源，保证对象在使用之前是处于有效状态。
- **析构函数**：在析构函数中释放资源，确保没有内存泄漏和资源丢失。

|特性|构造函数|析构函数|
|---|---|---|
|调用时机|创建对象时自动调用|销毁对象时自动调用|
|返回类型|无返回类型|无返回类型|
|参数|可以带参数|无参数|
|调用顺序|虚基类（如有）→ 直接基类 → 成员变量 → 派生类构造函数体|派生类析构函数体 → 成员逆序析构 → 直接基类逆序析构 → 虚基类析构|
|目的|初始化对象，分配资源|清理资源，销毁对象|

## 2.19 拷贝构造函数、移动构造函数的区别？

### 2.19.1 拷贝构造函数

**作用：**

拷贝构造函数用于 **通过已有对象创建新对象**，通常用于：

- 创建一个新的对象，且该对象是已有对象的副本。
- 将一个对象作为函数参数传递或从函数返回。

**定义：**

拷贝构造函数的定义通常如下：

```cpp
ClassName(const ClassName& other);  // 拷贝构造函数
```

- **调用时机：** 用同类型左值初始化新对象、按值传参或按值返回且拷贝未被省略时。RVO/拷贝消除发生时不会调用拷贝构造函数。

**行为：**

拷贝构造函数会 **逐个复制** 被拷贝对象的成员变量。对于动态分配的资源（如指针），如果不进行特殊处理（如深拷贝），可能会导致 **浅拷贝** 问题，从而引发资源共享和内存泄漏等问题。

**示例：**

```cpp
class MyClass {
public:
    int x;
    MyClass(int val) : x(val) {}  // 构造函数
    MyClass(const MyClass& other) {  // 拷贝构造函数
        x = other.x;  // 按值拷贝
    }
};

MyClass obj1(10);
MyClass obj2 = obj1;  // 调用拷贝构造函数
```

### 2.19.2 移动构造函数

**作用：**

移动构造函数用于 **通过右值引用创建新对象**，它允许资源的“转移”而不是复制。移动构造通常用于 **避免不必要的内存开销**，尤其是当对象包含动态分配的资源时。它通过转移资源所有权来提高效率。

**定义：**

移动构造函数的定义通常如下：

```cpp
ClassName(ClassName&& other);  // 移动构造函数
```

- **调用时机：** 用同类型右值初始化新对象，或容器搬移元素等需要从右值构造且拷贝未被省略时。仅“传给右值引用形参”本身不会构造新对象；RVO 发生时也不会调用移动构造函数。

**行为：**

- 移动构造函数可转移资源所有权，也可能选择逐成员移动/拷贝。移动后的源对象必须仍然可析构、可按类约定赋值；其精确值常为“有效但未指定”，不要一概假定必然为空。
- 对于动态资源，通常通过将指针从源对象转移到新对象，避免了额外的内存分配和拷贝操作。

**示例：**

```cpp
class Buffer {
public:
    int *data;
    explicit Buffer(int value) : data(new int(value)) {}
    Buffer(Buffer&& other) noexcept : data(other.data) {
        other.data = nullptr;
    }
    ~Buffer() { delete data; }
};

Buffer a(1);
Buffer b(std::move(a));  // 转移资源
```

### 2.19.3 拷贝构造函数与移动构造函数的主要区别

|特性|拷贝构造函数|移动构造函数|
|---|---|---|
|作用|创建对象的副本|通过转移资源创建新对象，避免不必要的复制|
|调用时机|由左值初始化、按值传参/返回且未消除拷贝时|由右值初始化、容器搬移且未消除构造时|
|资源处理|复制资源（可能导致浅拷贝问题）|转移资源所有权，避免重复的资源复制|
|性能|可能涉及不必要的内存分配和资源复制|提高效率，减少不必要的资源复制和内存开销|
|资源状态|源对象保持原有语义状态|源对象仍有效但状态通常未指定，必须可安全析构和重新赋值|
|定义|`MyClass(const MyClass& other)`|`MyClass(MyClass&& other)`|

### 2.19.4 总结

- **拷贝构造函数**：用于创建现有对象的副本，逐个拷贝成员变量。适用于对象需要被完全复制的场景。
- **移动构造函数**：用于通过右值引用转移资源，避免不必要的内存开销。适用于动态资源管理，能提高性能，尤其在现代 C++ 标准库中广泛使用。

在处理动态内存、文件句柄或其他资源时，**移动构造函数** 可以显著提高性能，而 **拷贝构造函数** 适用于需要完整副本的场景。

## 2.20 智能指针及如何解决内存泄漏？

智能指针是 C++ 中用于**自动管理动态内存**的工具，通过对象生命周期绑定资源释放，从根本上减少内存泄漏问题。

### 2.20.1 什么是智能指针

**定义：**
智能指针是一个**类模板**，行为像指针，但在对象生命周期结束时**自动释放所管理的内存**。

```cpp
std::unique_ptr<int> p(new int(10));
```

- **核心思想：** RAII（资源获取即初始化）；析构函数中自动释放资源

### 2.20.2 智能指针如何解决内存泄漏

**传统问题**

```cpp
int *p = new int;
// 可能忘记 delete
```

**智能指针方式**

```cpp
std::unique_ptr<int> p(new int(10));
// 自动 delete
```

- 超出作用域自动释放
- 即使异常抛出也能正确释放

### 2.20.3 常见智能指针类型（重点）

**（1）std::unique_ptr**

- 独占所有权
- 不可拷贝，可移动
- 最常用、最安全

```cpp
std::unique_ptr<int> p = std::make_unique<int>(10);
```

**（2）std::shared_ptr**

- 共享所有权
- 引用计数
- 最后一个释放时 delete

```cpp
std::shared_ptr<int> p1 = std::make_shared<int>(10);
```

**（3）std::weak_ptr**

- 不拥有资源
- 解决 shared_ptr 循环引用

```cpp
std::weak_ptr<int> wp;
```

### 2.20.4 智能指针与内存泄漏的关系

|场景|unique_ptr|shared_ptr 正常使用|shared_ptr 循环引用|
|---|---|---|---|
|是否泄漏|不泄漏|不泄漏|会泄漏|

### 2.20.5 为什么推荐使用智能指针

- 自动释放，避免忘记 delete
- 异常安全
- 代码更简洁
- 明确资源所有权

### 2.20.6 使用智能指针的注意点

**（1）不要混用裸指针管理同一资源**

```cpp
int *p = new int;
std::unique_ptr<int> up1(p);
// std::unique_ptr<int> up2(p);  // 错误：两个所有者会导致重复释放
```

- 将新分配的裸指针立即交给唯一一个智能指针是合法的；风险在于为同一裸指针创建多个独立所有者，或再手动 `delete p`。

**（2）优先使用 make_unique / make_shared**

- 更安全
- 防止资源泄漏
- `std::make_unique` 从 C++14 开始提供，`std::make_shared` 从 C++11 开始提供。

**（3）注意 shared_ptr 循环引用**

- 使用 weak_ptr 解决

### 2.20.7 嵌入式与性能考虑

- 有一定额外开销
- `unique_ptr` 通常是零或极低开销；`shared_ptr` 需要控制块、引用计数，且可能涉及原子操作。
- 在极端资源受限 MCU 上应根据动态内存策略和实时约束选用，不应将所有智能指针一概禁用。
- 适合嵌入式 Linux / 上位机

### 2.20.8 面试一句话总结

> 智能指针通过 RAII 机制自动管理内存，显著降低内存泄漏风险，是现代 C++ 的推荐用法。

## 2.21 构造函数中的初始化列表与赋值的区别

在 C++ 中，构造函数有两种方式来初始化成员变量：**初始化列表** 和 **赋值**。这两者虽然在效果上可能相似，但它们在性能、语法和行为上有一些重要的区别。

### 2.21.1 初始化列表

**定义：**

初始化列表是构造函数的一部分，它在构造函数体之前被调用，用于直接初始化类的成员变量。初始化列表的语法如下：

```cpp
ClassName(Type1 param1, Type2 param2) : member1(value1), member2(value2) {
    // 构造函数体
}
```

**工作原理：**

- **直接初始化**：初始化列表在对象创建时直接对成员变量进行初始化。这意味着，成员变量的值在构造函数体执行之前就已经确定。
- **顺序**：初始化列表的成员变量初始化顺序是根据声明顺序，而不是初始化列表中列出成员的顺序。

**优点：**

- **效率更高**：对于复杂类型（如类类型、动态分配的资源等），初始化列表避免了先默认构造后再赋值的多余操作，直接对成员进行初始化。
- **适用于常量和引用成员**：常量成员变量（const）和引用成员（&）必须通过初始化列表进行初始化，因为它们无法在构造函数体中重新赋值。

**示例：**

```cpp
class MyClass {
public:
    int x;
    const int y;
    MyClass(int val) : x(val), y(val) {}  // 使用初始化列表
};
```

- y 必须在初始化列表中初始化，因为它是常量。

### 2.21.2 赋值（在构造函数体内）

**定义：**

赋值是在构造函数体内将值赋给成员变量。它的语法如下：

```cpp
ClassName(Type1 param1, Type2 param2) {
    member1 = value1;  // 赋值操作
    member2 = value2;
}
```

**工作原理：**

- **默认构造后赋值**：成员变量首先会通过默认构造函数进行初始化，然后在构造函数体内赋值。对于基础数据类型，赋值操作可能并不会引发问题，但对于类类型的成员变量，首先调用默认构造函数，然后执行赋值，这可能导致不必要的临时对象创建，效率较低。
- **顺序**：赋值的顺序与成员声明的顺序无关，而是按照代码中赋值的顺序执行。

**缺点：**

- **效率较低**：对于非基础类型（如类类型、字符串、容器等），首先调用默认构造函数进行初始化，然后再进行赋值，可能涉及不必要的资源分配、拷贝或移动操作。
- **不适用于常量和引用成员**：常量成员变量和引用成员变量不能在构造函数体内进行赋值，因为它们必须在初始化时就被赋值。

**示例：**

```cpp
class MyClass {
public:
    int x;
    const int y;
    MyClass(int val) {
        x = val;  // 赋值
        y = val;  // 错误，y 是常量成员，不能在构造函数体内赋值
    }
};
```

- 上面的代码会导致编译错误，因为 y 是常量成员，必须通过初始化列表初始化，而不是赋值。

### 2.21.3 初始化列表与赋值的区别

|特性|初始化列表|赋值|
|---|---|---|
|工作原理|在构造函数体执行之前，直接初始化成员变量|先调用默认构造函数初始化，再进行赋值操作|
|性能|更高效，特别是对于类类型、引用、常量成员|效率较低，因为需要先默认构造，再赋值|
|适用场景|推荐用于所有成员，尤其是常量成员、引用成员|不推荐用于常量成员或引用成员，适用于基础类型|
|初始化顺序|按照声明顺序初始化成员变量|按照赋值语句的顺序赋值|
|对常量和引用的支持|可以初始化常量成员和引用成员|不能赋值常量成员和引用成员|

### 2.21.4 何时使用初始化列表与赋值

- **使用初始化列表**：
    - 对于 **常量成员** (const) 或 **引用成员** (&)，必须在初始化列表中初始化。
    - 对于 **类类型成员**，使用初始化列表可以避免先默认构造后再赋值的效率损失。
    - 在需要 **避免额外的拷贝或移动操作**（尤其是对于有昂贵复制构造函数的类类型成员）时，应使用初始化列表。
- **使用赋值**：
    - 对于 **简单类型成员**（如 int, double 等），在性能上差别不大，可以使用赋值。
    - 如果成员没有提供默认构造函数，且可以直接赋值，赋值也可以是一个可行的选择。

### 2.21.5 总结

因此，在 **现代 C++ 编程** 中，通常推荐使用 **初始化列表** 来初始化成员，尤其是对于 **常量** 和 **类类型** 成员，以确保更高效且更安全的初始化。

|特性|初始化列表|赋值|
|---|---|---|
|效率|较高，直接初始化成员|较低，需要先默认构造再赋值|
|适用范围|推荐用于所有成员，尤其是类类型、常量、引用成员|适用于基础数据类型，但不推荐用于常量成员|
|对常量和引用的支持|支持，常量成员和引用成员必须通过初始化列表初始化|不支持，常量成员和引用成员不能赋值|

## 2.22 虚函数与纯虚函数的原理是什么？

### 2.22.1 虚函数（Virtual Function）

**定义：**
虚函数是使用 virtual 关键字声明的成员函数，用于实现 **运行时多态**。

```cpp
class Base {
public:
    virtual void func() {
        // 有默认实现
    }
};
```

### 2.22.2 虚函数的特点

- 通过 **基类指针 / 引用** 调用
- 实际执行派生类重写的函数
- 基类可提供默认实现
- 依赖 **虚函数表（vtable）**

### 2.22.3 纯虚函数（Pure Virtual Function）

**定义：**
纯虚函数是在虚函数声明后加 `= 0`，用于使该类成为抽象类并约束派生类接口。纯虚函数仍然可以在类外提供定义，只是不能因此让基类变为可实例化类型。

```cpp
class Base {
public:
    virtual void func() = 0;
};
```

### 2.22.4 抽象类（Abstract Class）

- **包含至少一个纯虚函数的类**
- **不能实例化对象**
- 只能作为基类使用

### 2.22.5 虚函数与纯虚函数的区别（重点）

|对比项|虚函数|纯虚函数|
|---|---|---|
|是否有实现|可以有默认实现|可以在类外定义，但仍保持“纯”属性|
|是否必须重写|否|具体派生类必须覆盖所有继承的纯虚函数|
|所在类是否可实例化|若无其他纯虚函数则可以|包含它的类不可实例化|
|主要用途|提供默认行为|定义接口|

### 2.22.6 纯虚函数的作用

- 强制派生类实现接口
- 实现接口规范
- 支持多态设计

### 2.22.7 虚析构函数（必考）

```cpp
class Base {
public:
    virtual ~Base() {}
};
```

- 防止通过基类指针 delete 派生类对象时资源泄漏
- 基类作为接口类时 **析构函数必须是 virtual**

### 2.22.8 虚函数的底层原理（简述）

- 每个含虚函数的类有一张 **虚函数表**
- 对象中保存 vptr 指向 vtable
- 运行时通过 vtable 查找函数地址

### 2.22.9 常见误区

- 构造函数不能是虚函数
- 静态成员函数不能是虚函数
- 内联函数可为虚函数，但多态时不会内联

### 2.22.10 面试高频总结句

> 虚函数用于实现运行时多态，纯虚函数用于定义接口，包含纯虚函数的类称为抽象类，不能实例化。
> 虚函数给默认行为，纯虚函数定行为规范。

## 2.23 纯虚函数与抽象类的区别？

### 2.23.1 纯虚函数（Pure Virtual Function）

**定义：**

纯虚函数是在声明末尾写 `= 0` 的虚函数。它使所在类成为抽象类；要让派生类成为具体类，派生类必须为所有继承的纯虚函数提供最终覆盖。纯虚函数本身可以另行提供定义。

- **作用：** 纯虚函数定义接口约束；如果派生类没有覆盖所有纯虚函数，它仍是抽象类。

**示例：**

```cpp
class Shape {
public:
    virtual void draw() = 0;  // 纯虚函数
};

class Circle : public Shape {
public:
    void draw() override {  // 必须实现纯虚函数
        std::cout << "Drawing a Circle" << std::endl;
    }
};
```

- draw() 是一个纯虚函数，它在 Shape 类中没有实现，必须由派生类（如 Circle）提供实现。
- **特点：** 一个类可以有一个或多个纯虚函数；包含或继承未覆盖纯虚函数的类是**抽象类**。纯虚析构函数必须提供函数定义。

### 2.23.2 抽象类（Abstract Class）

**定义：**

抽象类是包含或继承了尚未被最终覆盖的纯虚函数的类。抽象类无法直接实例化，可以作为基类派生其他类。

- **作用：** 抽象类可用于定义接口约束，也可提供共享实现。派生类只有在覆盖所有尚未实现的纯虚函数后才能实例化；否则它仍是抽象类。

**示例：**

```cpp
class Shape {
public:
    virtual void draw() = 0;  // 纯虚函数
    void move() {  // 非纯虚函数
        std::cout << "Moving Shape" << std::endl;
    }
};

class Circle : public Shape {
public:
    void draw() override {
        std::cout << "Drawing a Circle" << std::endl;
    }
};
```

- Shape 类是一个抽象类，因为它包含纯虚函数 draw()。
- Circle 类继承自 Shape，并实现了纯虚函数 draw()，因此可以实例化。
- **特点：** 抽象类可以包含纯虚函数、普通成员函数和数据成员。它不能直接实例化，但可作为基类，并为派生类提供共享代码。

### 2.23.3 纯虚函数与抽象类的主要区别

|特性|纯虚函数|抽象类|
|---|---|---|
|定义|声明末尾带 `= 0` 的虚函数|包含或继承了未覆盖纯虚函数的类|
|是否可以实例化|函数不涉及“实例化”|抽象类不能实例化|
|是否要求派生类实现|具体派生类必须提供最终覆盖|未覆盖全部纯虚函数的派生类仍为抽象类|
|是否能提供定义|可以在类外提供定义|可以包含纯虚函数、普通成员函数和数据成员|
|例子|`virtual void func() = 0;`|`class Abstract { virtual void func() = 0; };`|

### 2.23.4 总结

- **纯虚函数**：定义接口约束；可以另行提供定义，但具体派生类仍需覆盖。
- **抽象类**：包含至少一个纯虚函数的类。抽象类不能实例化，可以包含纯虚函数和普通成员函数，用于提供部分实现或共享代码。

**纯虚函数** 是 **抽象类** 的组成部分，而 **抽象类** 是为了给派生类提供接口约束和可选的实现代码。在 C++ 中，抽象类和纯虚函数用于实现 **多态性** 和 **接口设计**。

## 2.24 单继承和多继承的区别？

### 2.24.1 单继承

**定义：**

单继承指的是一个类只能继承自一个基类，子类与基类之间存在单一的继承关系。

**特点：**

- **简化关系**：由于只有一个父类，继承关系相对简单，类之间的层次结构清晰明了。
- **易于维护**：维护继承关系时，问题的定位比较简单，不容易出现复杂的继承冲突。
- **多态性**：单继承同样支持多态机制，可以通过基类指针或引用来操作派生类对象。

**示例：**

```cpp
class Animal {
public:
    void eat() { std::cout << "Animal eating" << std::endl; }
};

class Dog : public Animal {
public:
    void bark() { std::cout << "Dog barking" << std::endl; }
};
```

在上面的示例中，Dog 类通过单继承继承了 Animal 类。

### 2.24.2 多继承

**定义：**

多继承是指一个类可以同时继承多个基类，从而拥有多个父类的特性。

**特点：**

- **复杂性增加**：由于一个类可以继承多个父类，继承关系可能变得复杂，容易出现冲突或意外行为。
- **潜在的命名冲突**：如果多个基类中有相同的成员（如函数、变量等），则需要在子类中处理这种冲突，通常通过**作用域解析符**来解决。
- **继承路径问题**：如果多个基类存在继承关系，则可能会出现**菱形继承问题**（钻石问题），即子类通过不同路径继承自同一个基类，从而导致冗余的父类实例。
- **多态性**：同样支持多态机制，但是处理多继承时需要注意虚拟继承。

**示例：**

```cpp
class Animal {
public:
    virtual ~Animal() = default;
};

class Pet {
public:
    virtual ~Pet() = default;
};

class Dog : public Animal, public Pet {
public:
    void bark() { std::cout << "Dog barking" << std::endl; }
};
```

在上面的示例中，Dog 类通过多继承同时继承了 Animal 和 Pet 类。

**菱形继承问题（钻石问题）：**

多继承的一大问题是**菱形继承**，即某个类通过两条路径继承了同一个基类，导致该基类出现冗余实例。

```cpp
class A {
public:
    void func() { std::cout << "A func" << std::endl; }
};

class B : public A { };

class C : public A { };

class D : public B, public C { };
```

在这个例子中，D 类继承自 B 和 C，而 B 和 C 都继承自 A。如果没有特别处理，D 类会有两个 A 的实例，这可能导致不确定的行为。

为了避免菱形继承问题，C++ 提供了 **虚拟继承**，它确保基类 A 只有一个实例。

```cpp
class B : virtual public A { };
class C : virtual public A { };
```

### 2.24.3 单继承与多继承的主要区别

|特性|继承层级|继承关系|菱形继承问题|
|---|---|---|---|
|单继承|只能从一个基类继承|简单、清晰，通常没有命名冲突问题|无菱形继承问题|
|多继承|可以从多个基类继承|继承关系复杂，容易产生命名冲突或冗余|可能出现菱形继承问题（通过虚拟继承解决）|

### 2.24.4 优缺点比较

|特性|优点|缺点|适用场景|
|---|---|---|---|
|单继承|简单清晰，易于理解和维护|继承关系简单，可能无法满足某些复杂需求|适用于较简单的类层次结构|
|多继承|可以同时继承多个类，复用多个父类的功能|继承关系复杂，容易产生命名冲突和冗余|适用于需要复用多个类功能的复杂系统|

### 2.24.5 总结

- **单继承**：一个类继承自单个基类，继承关系简单，易于理解和维护，适用于类层次关系清晰的场景。
- **多继承**：一个类继承自多个基类，允许复用多个类的功能，但会增加复杂性，可能导致命名冲突和菱形继承问题。在现代 C++ 中，通常建议使用 **接口** 或 **组合** 来避免多继承的复杂性，尽量减少多继承的使用。

在实际开发中，多继承虽然强大，但容易带来不可预测的复杂问题，因此建议尽量优先使用单继承，并在必要时使用 **虚拟继承** 或 **接口** 来处理多继承问题。

## 2.25 多态是如何实现的（VTable）？

在 C++ 中，**多态性** 是面向对象编程（OOP）的核心特性之一，它允许程序在运行时根据对象的实际类型来决定调用哪个方法。**虚函数** 是实现多态的关键，C++ 通过 **虚函数表（VTable）** 和 **虚函数指针（VPtr）** 来实现多态性。

### 2.25.1 多态的定义

多态性是指同一操作作用于不同的对象时，能够产生不同的行为。在 C++ 中，主要有两种类型的多态：

- **编译时多态**（如函数重载、运算符重载）
- **运行时多态**（通过虚函数和继承实现）

C++ 的 **运行时多态** 是通过 **虚函数** 来实现的，虚函数使得基类和派生类的对象能够在运行时动态地决定调用哪一个函数。

### 2.25.2 虚函数与多态的关系

**虚函数的作用**

- 当我们在基类中声明一个函数为虚函数（使用 virtual 关键字），它就可以在派生类中被重写（覆盖）。
- 如果通过基类指针或引用调用虚函数，程序会根据对象的实际类型来决定调用哪个版本的函数（即派生类的重写版本，而不是基类的版本），从而实现多态。

**虚函数调用的关键：**

虚函数调用的实现依赖于 C++ 的 **虚函数表（VTable）** 机制。

### 2.25.3 VTable（虚函数表）

**什么是 VTable？**

VTable 是一个指针表，存储了类中所有虚函数的地址。每一个包含虚函数的类都会有一张虚函数表。编译器在编译时为每个类生成一个 VTable，存储了该类所有虚函数的地址（即函数指针）。

**VTable 的工作原理**

- 主流编译器通常为多态类生成虚函数表，表中除虚函数入口外还可含 RTTI、偏移或析构相关条目，具体大小与格式由 ABI 决定，不能简单说与虚函数数目相同。
- 每个多态类对象通常含有一个或多个由编译器安排的虚表指针（VPtr）；多重/虚继承下布局可更复杂。C++ 标准规定的是虚调用行为，不强制使用 VTable/VPtr 这一种实现。
- 当调用虚函数时，程序会通过对象的 VPtr 查找虚函数表，然后跳转到正确的虚函数地址，从而实现动态绑定（即运行时选择函数）。

**VTable 的示意图**

假设有一个基类 Base 和一个派生类 Derived，它们都有虚函数 foo()。

```cpp
class Base {
public:
    virtual void foo() {
        std::cout << "Base foo" << std::endl;
    }
};

class Derived : public Base {
public:
    void foo() override {
        std::cout << "Derived foo" << std::endl;
    }
};
```

- **Base 类的 VTable** 可能会包含指向 Base::foo() 的函数指针。
- **Derived 类的 VTable** 会包含指向 Derived::foo() 的函数指针。

当我们通过基类指针调用 foo() 时，C++ 通过 **虚指针（VPtr）** 确定实际调用的是 Derived::foo()，而不是 Base::foo()。

### 2.25.4 VTable 和 VPtr 的实现细节

**对象中通常含有虚表指针（VPtr）**

- 在主流 ABI 中，多态类对象通常含有一个或多个指向相关 VTable 的 VPtr。
- VPtr 由编译器在对象构造过程中维护；多重继承和虚继承下可能有多个虚表指针，具体布局由 ABI 决定。

**虚函数表的构造**

- 主流编译器通常为多态类生成 VTable；派生类未覆盖某个虚函数时，相应表项会使调用落到继承的实现。
- **VTable 的内存布局**：虚表通常按类共享，并可能放在只读区域；表项、数量和位置均属于 ABI 实现细节。

**函数调用流程**

1. 对象的虚指针（VPtr）指向该对象所属类的 VTable。
2. 通过基类指针或引用调用虚函数时，程序通过 VPtr 查找虚函数表中的地址。
3. 找到相应的虚函数地址后，程序跳转并执行该函数。

### 2.25.5 示例：VTable 和 VPtr 实现多态

```cpp
#include <iostream>
using namespace std;

class Base {
public:
    virtual void foo() { cout << "Base::foo" << endl; }
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    void foo() override { cout << "Derived::foo" << endl; }
};

int main() {
    Base* b = new Derived();
    b->foo();
    delete b;
}
```

- 在此示例中，Base 类和 Derived 类都有虚函数 foo()。
- 当 b 指向 Derived 对象时，通过基类指针调用 foo()，实际调用的是 Derived 中的 foo()。
- 编译器会根据 b 对应的虚指针查找 Derived 类的虚函数表，然后调用 Derived::foo()。

### 2.25.6 总结

- C++ 标准规定虚调用的语义；VTable/VPtr 是主流 ABI 的常见实现。
- 通过基类指针或引用调用虚函数时，程序会按对象的动态类型选择最终覆盖函数，实现运行时多态。

虚函数表和虚指针使得 C++ 支持动态绑定，即在运行时确定函数的调用，这在实现多态性时非常重要。

## 2.26 虚函数表是共享的吗

### 2.26.1 定义

**虚函数表（VTable）是编译器为支持多态生成的每个类的函数指针表**，用于实现运行时动态绑定。

- 每个含虚函数的类有一张 VTable
- 对象内部存储一个指向 VTable 的指针（vptr）

### 2.26.2 是否共享

- **同一个类的所有对象共享同一张 VTable**
    - VTable 在编译期生成，存储在静态存储区
    - vptr 指向这张共享的 VTable
- **不同类（即使继承关系）**会有各自的 VTable
    - 派生类重写虚函数时，VTable 指向新的函数实现

### 2.26.3 示例说明

```cpp
class Base {
public:
    virtual void func() { std::cout << "base" << std::endl; }
};

class Derived : public Base {
public:
    void func() override { std::cout << "Derived" << std::endl; }
};

int main() {
    Base b1, b2;
    Derived d1, d2;
    // b1.vptr 和 b2.vptr 指向 Base 的 VTable
    // d1.vptr 和 d2.vptr 指向 Derived 的 VTable
}
```

- Base 类的所有对象共享 Base 的 VTable
- Derived 类的所有对象共享 Derived 的 VTable

### 2.26.4 注意事项

1. **对象 vptr 只存储指向 VTable 的指针**，每个对象占用一份指针
2. **节省内存**：不为每个对象都复制函数指针
3. **虚继承**：可能增加多张 VTable 或调整 VPtr 布局

### 2.26.5 面试高频总结句

> 同一个类的虚函数表在静态区共享，所有对象通过 vptr 指向这张共享表，实现动态绑定；不同类有不同的 VTable。
> VTable 是类共享的函数指针表，对象只存 vptr 指向它，实现多态。

## 2.27 当类成员是引用或 const 时如何初始化？

在 C++ 中，当类成员是 **引用类型** 或 **常量类型**（const）时，它们的初始化方式和普通成员变量不同。由于 **引用** 和 **常量** 必须在对象创建时初始化，因此不能通过构造函数体内的赋值来初始化它们，必须使用 **初始化列表** 来进行初始化。

### 2.27.1 引用成员的初始化

- **引用的特性：** 引用在 C++ 中是一种别名，必须在定义时绑定到一个合法的对象。；引用类型的成员变量不能被默认构造或赋值，必须在构造函数的初始化列表中进行初始化。

**初始化方式：**

引用成员必须在 **初始化列表** 中进行初始化，不能在构造函数体内赋值。

**示例：**

```cpp
class MyClass {
public:
    int& ref;  // 引用成员
    MyClass(int& r) : ref(r) {  // 使用初始化列表初始化引用成员
        // 构造函数体
    }
};
```

- ref 是一个引用成员，它必须通过构造函数的初始化列表来初始化，并且它被绑定到外部的 r 引用。
- **注意：** 引用成员必须在构造函数调用时就与某个对象绑定，不能为空引用。；引用成员无法进行 **默认初始化**，即不能在构造函数中没有提供对应的对象就进行初始化。

### 2.27.2 常量成员的初始化

- **常量的特性：** 常量成员变量（const）在初始化后，其值不能更改。；常量成员必须在对象构造时进行初始化，并且不能在构造函数体内进行赋值。

**初始化方式：**

常量成员必须通过 **初始化列表** 进行初始化。常量成员的值必须在对象创建时就确定，并且不能在构造函数体内赋值。

**示例：**

```cpp
class MyClass {
public:
    const int x;  // 常量成员
    MyClass(int val) : x(val) {  // 使用初始化列表初始化常量成员
        // 构造函数体
    }
};
```

- x 是一个常量成员，它只能通过初始化列表来初始化，且值在构造时已经被设定，无法修改。
- **注意：** 常量成员在初始化后无法修改其值，因此它必须在构造函数的初始化列表中赋初值。；如果没有在构造函数中提供初始化列表，则编译器会报错，因为常量成员不能被默认初始化。

### 2.27.3 引用和常量成员的初始化对比

|特性|初始化位置|初始化后是否可以修改|默认初始化|
|---|---|---|---|
|引用成员|必须在构造函数的初始化列表中初始化|不可以修改（引用一旦绑定后不能更改）|不允许默认初始化（必须与某个对象绑定）|
|常量成员|必须在构造函数的初始化列表中初始化|不可以修改|不允许默认初始化（必须提供初始值）|

### 2.27.4 总结

- **引用成员**：必须通过构造函数的初始化列表进行初始化，且引用的对象必须在对象构造时就已经确定。
- **常量成员**：也必须通过初始化列表进行初始化，并且其值在对象构造后不可更改。

这两个成员类型的共同点是，它们都不能通过构造函数体内的赋值来进行初始化。必须在 **初始化列表** 中赋予它们值，从而确保对象在创建时就处于有效状态。

## 2.28 虚函数可以内联吗?

### 2.28.1 先说结论（面试常用）

**虚函数在特定情况下可以内联，但在发生多态调用时不能内联。**

### 2.28.2 什么是内联的前提

函数能否内联，关键在于：

- **调用的函数地址在编译期是否确定**

### 2.28.3 虚函数为什么通常不能内联

虚函数调用一般是这样的：

```cpp
Base* p = new Derived();
p->func();   // 虚函数调用
```

- 实际调用哪个函数 **运行期才能确定**
- 通过 vptr → vtable 查找
- 编译期无法确定目标函数地址
- **无法内联展开**

### 2.28.4 虚函数可以内联的情况（重点）

**（1）通过对象调用（非多态）**

```cpp
Derived d;
d.func();    // 可以内联
```

- 对象类型确定
- 调用函数确定
- 编译器可内联

**（2）编译期可确定类型**

```cpp
Derived* p = new Derived();
p->func();   // 编译器可能内联（优化级别相关）
```

- 指针类型和对象类型一致
- 不发生多态

### 2.28.5 inline + virtual 是否冲突？

```cpp
class A {
public:
    inline virtual void func() {}
};
```

- 语法合法
- inline 只是建议
- 多态调用时仍不会内联

### 2.28.6 纯虚函数与内联

- 纯虚函数声明本身不提供可在调用点展开的函数体；若另行给出定义，该定义在满足通常条件时也可以声明为 `inline`
- 派生类的覆盖函数同样可能被内联

### 2.28.7 编译器优化角度说明

- 高优化级别（O2 / O3）
- 去虚拟化（devirtualization）
- 编译器能推断真实类型 → 可能内联

### 2.28.8 面试高频总结句

> 虚函数在发生运行时多态调用时不能内联，但在编译期能确定调用对象类型的情况下，虚函数是可以内联的。
> 是否内联不看是不是虚函数，而看能不能在编译期确定调用目标。

## 2.29 如何实现接口类？

在 C++ 中，**接口类**是一种设计惯例，不是语言单独规定的类别。它通常是一个抽象基类：用纯虚函数定义派生类需要提供的操作，并提供虚析构函数，以便通过基类指针安全销毁对象。

为了保持接口简洁，这类类通常不保存业务状态，也尽量不提供与接口无关的具体实现；但这些都是设计约定，不是 C++ 语法强制。

### 2.29.1 接口类的定义

**接口类的特点：**

- **用纯虚函数定义主要操作**：具体派生类必须覆盖尚未实现的纯虚函数。
- **自身不能实例化**：只要还有纯虚函数未被覆盖，该类就是抽象类。
- **多态**：接口类允许通过基类指针或引用来操作派生类对象，支持多态性。
- **通常有虚析构函数**：需要通过接口指针删除派生对象时，公有虚析构函数是必需的。

**接口类的语法：**

```cpp
class Interface {
public:
    virtual void method1() = 0;  // 纯虚函数
    virtual void method2() = 0;  // 纯虚函数
    virtual ~Interface() = default;  // 支持通过接口指针安全销毁
};
```

- 在这个例子中，Interface 按接口风格设计：method1() 和 method2() 是纯虚函数，析构函数则有默认实现。

**接口类的使用：**

接口类本身不能实例化，只能由其他类继承并实现其纯虚函数。

### 2.29.2 派生类实现接口类

派生类需要实现接口类中声明的所有纯虚函数，才能被实例化。

**示例：**

```cpp
class ConcreteClass : public Interface {
public:
    void method1() override {
        std::cout << "method1 implemented in ConcreteClass" << std::endl;
    }

    void method2() override {
        std::cout << "method2 implemented in ConcreteClass" << std::endl;
    }
};
```

- ConcreteClass 继承了 Interface，并实现了 method1() 和 method2()。只有这样，ConcreteClass 才能被实例化。

**接口类和多态性：**

通过基类指针或引用可以调用派生类的实现函数，从而实现多态性。

```cpp
int main() {
    ConcreteClass obj;
    Interface* interfacePtr = &obj;

    interfacePtr->method1();  // 调用 ConcreteClass 中实现的 method1
    interfacePtr->method2();  // 调用 ConcreteClass 中实现的 method2

    return 0;
}
```

- 在上面的代码中，interfacePtr 是 Interface 类型的指针，它指向 ConcreteClass 的对象。
- 使用 interfacePtr 调用 method1() 和 method2() 时，实际调用的是 ConcreteClass 中的实现函数。

### 2.29.3 接口类的设计注意事项

**虚析构函数：**

- 为了确保正确地调用派生类的析构函数，应在接口类中声明虚析构函数。
- 即使接口类不需要有任何具体实现，虚析构函数也是良好的设计实践，尤其是在通过基类指针删除派生类对象时。
- **接口类与抽象类的关系：** 接口类通常是一种只表达服务契约的抽象类；一般抽象类还可以拥有状态、普通成员函数和共享实现。二者的区分来自设计意图，而非语言对“接口类”的额外限制。

**接口的多继承：**

接口类可以通过多继承来组合多个接口，但需要特别注意避免 **菱形继承**（钻石问题）所带来的复杂性。

### 2.29.4 接口类的应用场景

接口类在许多设计模式和实际项目中都有广泛应用，尤其是在以下场景：

- **策略模式**：通过接口类定义不同的策略（例如不同的排序算法、支付方式等），然后通过不同的实现类来实现这些策略。
- **工厂模式**：通过接口类定义对象的创建接口，不同的工厂类实现该接口来创建不同类型的对象。
- **回调机制**：在回调机制中，通常定义一个接口类，回调的对象实现该接口类来处理回调逻辑。

### 2.29.5 总结

- **接口类**：是一种以纯虚函数定义契约的抽象基类设计惯例，通常不保存业务状态，并提供虚析构函数。
- **实现接口类**：派生类必须覆盖所有尚未实现的纯虚函数，才能实例化。
- **多态性**：接口类与多态性紧密相关，可以通过基类指针或引用操作派生类对象。
- **设计注意**：接口类通常需要包含虚析构函数，并且通过多继承可以组合多个接口。

接口类是实现面向对象编程中 **解耦** 和 **灵活性** 的重要工具，它让不同类能够遵循相同的接口，实现一致的行为。

## 2.30 虚析构函数为什么重要？

### 2.30.1 问题背景

在 C++ 中，如果通过 **基类指针删除派生类对象**：

```cpp
Base* p = new Derived();
delete p;  // 会发生什么？
```

- **基类析构函数非虚函数** → 通过基类指针执行 `delete` 的行为未定义
- 常见后果是派生类析构未执行、资源泄漏或程序异常

### 2.30.2 虚析构函数的作用

- 在基类析构函数前加 virtual：

```cpp
class Base {
public:
    virtual ~Base() {}
};
```

- delete 基类指针时：
    a. 通过 vptr 查找派生类析构函数
    b. 先调用派生类析构函数释放资源
    c. 再调用基类析构函数
- **确保对象完整销毁**，防止内存泄漏或资源泄漏

### 2.30.3 使用规则

1. **需要通过基类指针删除对象的多态基类** → 析构函数应为虚函数
2. **接口类 / 抽象类** → 通常使用公有虚析构；若禁止通过基类删除，也可使用受保护的非虚析构
3. **没有继承的类** → 可不虚，节省 vptr 开销

### 2.30.4 示例

```cpp
class Base {
public:
    virtual ~Base() { cout << "Base destroyed\n"; }
};

class Derived : public Base {
public:
    ~Derived() { cout << "Derived destroyed\n"; }
};

Base* p = new Derived();
delete p;
// 输出：
// Derived destroyed
// Base destroyed
```

### 2.30.5 非虚析构函数问题示例

```cpp
class Base {
public:
    ~Base() { cout << "Base destroyed\n"; }
};

class Derived : public Base {
public:
    ~Derived() { cout << "Derived destroyed\n"; }
};

Base* p = new Derived();
delete p;  // 未定义行为：不能依赖“只调用 Base 析构”这一表现
```

### 2.30.6 面试高频总结句

> 多态基类若允许通过基类指针删除对象，应提供公有虚析构函数，以保证派生类和基类部分按顺序完整销毁。

## 2.31 构造函数为什么不定义为虚函数？

### 2.31.1 构造函数的本质

- 构造函数用于 **初始化对象**，在对象创建时调用
- **对象还没完全生成**，派生类部分尚未构建

### 2.31.2 虚函数的本质

- 虚函数依赖 **虚函数表（vtable）** 和 **vptr**
- vptr 在构造函数执行时才被设置
- 调用虚函数时要通过 vptr 定位具体函数

### 2.31.3 构造函数不能是虚函数的原因（重点）

1. **对象未完全构建**
    - 在基类构造阶段，派生类部分还不存在
    - 如果构造函数是虚的，调用派生类函数无法实现
2. **vptr 未初始化**
    - vptr 在构造函数执行过程中逐级初始化
    - 构造函数调用虚函数会调用 **当前类版本**，而不是派生类版本
3. **语义上不合理**
    - 构造是创建对象，不是运行时多态行为

### 2.31.4 构造函数与多态

- 构造函数本身 **不支持多态**
- 若需要多态初始化行为：
    - 使用 **工厂函数**
    - 或 **虚函数在构造之后调用**

### 2.31.5 示例说明

```cpp
class Base {
public:
    Base() { func(); }  // func 是虚函数
    virtual void func() { cout << "Base func\n"; }
};

class Derived : public Base {
public:
    void func() override { cout << "Derived func\n"; }
};

Derived d;
// 输出：Base func
// 构造 Base 时，调用的是 Base::func，不是 Derived::func
```

### 2.31.6 面试高频总结句

> 构造函数在对象创建阶段执行，此时派生类部分尚未构建，语言规则不允许构造函数为虚函数；构造期间调用虚函数只会分派到当前正在构造的类。
> 构造函数不能是虚函数，因为它负责建立对象，而虚调用需要基于一个已经存在的对象确定动态类型。

## 2.32 虚继承解决什么问题？

**虚继承** 是 C++ 中的一种特殊继承方式，主要用于解决 **菱形继承问题**（又称 **钻石问题**）。在传统的多继承中，当多个派生类通过不同路径继承自同一个基类时，可能会导致基类的成员（如数据成员、函数等）被冗余地继承多次，进而引发一系列问题。虚继承通过确保基类只有一个实例，解决了这些冗余和冲突问题。

### 2.32.1 菱形继承问题（钻石问题）

**菱形继承结构：**

在 C++ 中，多继承通常会产生菱形结构，示例如下：

```cpp
class A {
public:
    void funcA() { std::cout << "A's func" << std::endl; }
};

class B : public A {
public:
    void funcB() { std::cout << "B's func" << std::endl; }
};

class C : public A {
public:
    void funcC() { std::cout << "C's func" << std::endl; }
};

class D : public B, public C {
public:
    void funcD() { std::cout << "D's func" << std::endl; }
};
```

- A 是基类，B 和 C 分别继承自 A，然后 D 继承自 B 和 C。
- 这就形成了一个菱形结构：D 继承了 B 和 C，而 B 和 C 都继承自 A。

**问题：**

- D 类将会拥有两个 A 类的副本：一个来自 B，一个来自 C。这就造成了同一个基类 A 的多重继承，导致 D 类有冗余的 A 的成员。
- 如果 A 类有成员变量，D 类会同时拥有两个相同的成员变量，可能引发**二义性**或**冗余问题**。

### 2.32.2 虚继承的解决方案

虚继承通过将基类的实例在继承链中共享，从而解决了菱形继承带来的冗余问题。

**虚继承语法：**

在派生类中，通过 virtual 关键字来声明虚继承，确保基类只存在一个实例。

```cpp
class A {
public:
    void funcA() { std::cout << "A's func" << std::endl; }
};

class B : virtual public A {   // 虚继承 A
public:
    void funcB() { std::cout << "B's func" << std::endl; }
};

class C : virtual public A {   // 虚继承 A
public:
    void funcC() { std::cout << "C's func" << std::endl; }
};

class D : public B, public C {
public:
    void funcD() { std::cout << "D's func" << std::endl; }
};
```

**虚继承的效果：**

- 通过 **虚继承**，B 和 C 都 **共享** A 类的一个实例，因此 D 类只会拥有一个 A 类的实例，而不是两个。
- 这种方式解决了 **冗余** 和 **二义性** 问题。

**初始化虚基类：**

由于虚继承的特殊性，**虚基类的构造函数** 需要由最底层的派生类负责调用，并且只能调用一次。

```cpp
class A {
public:
    A() { std::cout << "A's constructor" << std::endl; }
};

class B : virtual public A {
public:
    B() { std::cout << "B's constructor" << std::endl; }
};

class C : virtual public A {
public:
    C() { std::cout << "C's constructor" << std::endl; }
};

class D : public B, public C {
public:
    D() { std::cout << "D's constructor" << std::endl; }
};
```

在上面的代码中，D 类的构造函数将负责调用 A 的构造函数，并且 A 的构造函数只会被调用一次。

### 2.32.3 虚继承的优缺点

**优点：**

- **消除了冗余**：通过虚继承，确保基类 A 只有一个实例，避免了菱形继承中的冗余成员。
- **解决了二义性问题**：避免了派生类拥有多个同名的基类成员，减少了访问冲突。

**缺点：**

- **复杂性增加**：虚继承引入了额外的复杂性，需要更仔细地管理基类的初始化和构造函数调用。
- **性能损失**：虚继承需要通过虚表（VTable）进行虚函数调用，可能会导致性能上的一些损失。
- **构造函数初始化**：虚基类的构造函数由最底层的派生类来调用，这可能会导致一些不直观的初始化行为。

### 2.32.4 总结

虚继承的主要目的是解决 **菱形继承问题**，即确保通过多重继承路径继承同一基类时，基类只会有一个实例。这种方式消除了多重继承中的冗余，避免了成员变量和成员函数的二义性。虽然虚继承可以解决冗余问题，但它也增加了代码的复杂性，尤其是在初始化虚基类时，程序员需要特别注意。

## 2.33 模板（Template）

### 2.33.1 定义

**模板（Template）** 是 C++ 提供的一种**泛型编程机制**，用于编写与类型无关的函数或类，使同一份代码可处理多种数据类型。

- 分为 **函数模板** 和 **类模板**
- 编译器在实例化时生成具体类型的代码

### 2.33.2 函数模板

```cpp
template <typename T>
T add(T a, T b) {
    return a + b;
}

int main() {
    std::cout << add<int>(1, 2) << std::endl;    // 指定类型
    std::cout << add<double>(1.1, 2.2) << std::endl;
}
```

- T 为模板参数
- 支持 **多种类型调用同一函数**

### 2.33.3 类模板

```cpp
template <typename T>
class MyClass {
    T data;
public:
    MyClass(T val) : data(val) {}
    T getData() { return data; }
};

int main() {
    MyClass<int> obj1(10);
    MyClass<double> obj2(3.14);
    std::cout << obj1.getData() << ", " << obj2.getData() << std::endl;
}
```

- 同一类模板可生成不同类型对象

### 2.33.4 特点

1. **类型独立**：一次编写，多次复用
2. **编译期实例化**：不同类型生成不同代码
3. **支持函数和类模板**
4. **支持模板特化**（Partial/Full specialization）

### 2.33.5 使用场景

- 通用算法（如排序、查找）
- 容器类（如 std::vector、std::map）
- 提高代码复用性和可维护性

### 2.33.6 面试高频总结句

> 模板是 C++ 泛型编程工具，允许函数或类与类型无关，在编译期实例化生成具体类型代码，提高代码复用。
> Template = “类型参数化”，一次定义，多类型复用。

---

## 2.34 虚函数可以是模板函数吗？

### 2.34.1 先说结论

**虚函数不能是模板函数**，但可以在模板类中定义虚函数。

- **虚函数**依赖运行时多态（vtable）
- **模板函数**在编译期实例化
- 两者机制冲突 → C++ 不允许直接将函数同时标记 virtual 和 template

### 2.34.2 为什么不允许

1. **虚函数需要固定地址表（vtable）**
    - vtable 由编译器生成，函数地址固定
2. **模板函数在编译期按类型实例化**
    - 地址在编译期确定，但 vtable 要运行时绑定
- 不同类型生成不同函数版本
3. **冲突**
    - vtable 需要单一函数地址，模板函数可能有多版本
    - 无法统一放入 vtable

### 2.34.3 可行方案

**（1）模板类 + 虚函数**

```cpp
template<typename T>
class Base {
public:
    virtual void func() = 0;  // OK
};

class Derived : public Base<int> {
public:
    void func() override {}
};
```

- 虚函数是固定函数
- 模板参数用于类，而不是函数本身

**（2）模板函数 + 非虚函数**

```cpp
class A {
public:
    template<typename T>
    void func(T x) { /* ... */ }  // OK, 非虚
};
```

**（3）结合多态和模板（常用技巧）**

- 使用 **非模板基类 + 模板派生类**
- 通过基类指针实现多态
- 避免虚模板函数直接声明

```cpp
class Base {
public:
    virtual void func() = 0;
};

template<typename T>
class Derived : public Base {
public:
    void func() override { /* T相关逻辑 */ }
};
```

### 2.34.4 面试高频总结句

> 虚函数与模板函数机制冲突，虚函数需要运行时绑定，模板函数在编译期生成多版本，因此 C++ 不允许虚模板函数，但可以用模板类继承虚函数实现类似效果。

虚函数不能是模板函数，但模板类可以包含虚函数。

## 2.35 基类指针指向派生类对象调用非虚函数会发生什么？

### 2.35.1 背景

在 C++ 中，基类指针或引用指向派生类对象时，调用基类的函数时，会发生什么取决于该函数是否被声明为虚函数（virtual）。如果是虚函数，则会启用 **动态绑定** 或 **运行时多态**，根据对象的实际类型来决定调用哪个版本的函数。如果不是虚函数，则会使用 **静态绑定**，即调用基类版本的函数，无论对象的实际类型是什么。

### 2.35.2 非虚函数的行为

当基类指针指向派生类对象，并调用一个非虚函数时，**不会发生动态绑定**。程序将直接调用基类中的该函数，而不是派生类中的函数版本。无论对象的实际类型是什么，都会调用基类中对应的函数实现。

### 2.35.3 示例代码

```cpp
class Base {
public:
    void nonVirtualFunction() {
        cout << "Base non-virtual function" << endl;
    }

    virtual void virtualFunction() {
        cout << "Base virtual function" << endl;
    }
};

class Derived : public Base {
public:
    void nonVirtualFunction() {
        cout << "Derived non-virtual function" << endl;
    }

    void virtualFunction() override {
        cout << "Derived virtual function" << endl;
    }
};

int main() {
    Base* basePtr = new Derived();

    // 调用非虚函数
    basePtr->nonVirtualFunction();  // 调用 Base 的版本

    // 调用虚函数
    basePtr->virtualFunction();  // 调用 Derived 的版本

    delete basePtr;
    return 0;
}
```

### 2.35.4 输出解释

```text
Base non-virtual function
Derived virtual function
```

- nonVirtualFunction(): 虽然 basePtr 指向的是 Derived 类型的对象，但是因为 nonVirtualFunction 不是虚函数，编译器在编译时决定调用基类 Base 中的版本。所以输出是 "Base non-virtual function"。
- virtualFunction(): 因为 virtualFunction 是虚函数，程序会使用动态绑定机制，根据 basePtr 实际指向的对象类型（即 Derived）来决定调用哪个版本。此时，输出 "Derived virtual function"。

### 2.35.5 总结

- **非虚函数**：如果基类指针指向派生类对象，调用非虚函数时，程序会根据 **静态绑定** 机制直接调用基类中的该函数版本。
- **虚函数**：如果基类指针指向派生类对象，调用虚函数时，程序会根据 **动态绑定** 机制调用派生类中的函数版本。

这种行为体现了 C++ 中静态和动态绑定的区别，虚函数依赖于动态绑定，而非虚函数依赖于静态绑定。

## 2.36 explicit 的作用及用法

### 2.36.1 explicit 是什么

**定义：**
explicit 是 **C++ 关键字**，用于修饰**构造函数**（C++11 起也可用于转换运算符），用于**禁止隐式类型转换**。

### 2.36.2 为什么需要 explicit

C++ 允许 **单参数构造函数** 作为隐式转换构造函数，容易引入隐式、难察觉的错误。

```cpp
class A {
public:
    A(int x) {}
};

A a = 10;   // 隐式转换：int → A
```

### 2.36.3 explicit 的基本用法

```cpp
class A {
public:
    explicit A(int x) {}
};

A a(10);    // 正确
A a = 10;   // 错误，禁止隐式转换
```

### 2.36.4 explicit 的作用总结

- 禁止 **隐式构造**
- 提高代码可读性
- 避免意外类型转换
- 增强接口安全性

### 2.36.5 explicit 对函数传参的影响（常考）

```cpp
void func(A a);

func(10);   // 未加 explicit：合法
func(10);   // 加 explicit：非法
```

### 2.36.6 多参数构造函数的注意点

- **只有一个参数（或其他参数有默认值）** 时才可能发生隐式转换

```cpp
class B {
public:
    explicit B(int x, int y = 0) {}
};
```

### 2.36.7 C++11：explicit 修饰转换运算符

```cpp
class C {
public:
    explicit operator bool() const {
        return true;
    }
};
```

- 禁止大多数普通隐式转换，但允许在 `if`、`while`、`!`、`&&`、`||` 等“语境转换为 `bool`”的位置使用。
- 也可显式转换：

```cpp
C c;
if (c) {}                    // 合法：语境转换为 bool
if (static_cast<bool>(c)) {}
```

### 2.36.8 面试高频总结句

> explicit 用于禁止构造函数或类型转换运算符的隐式转换，防止隐式类型提升带来的潜在错误。

### 2.36.9 使用建议

- **单参数构造函数一律加 explicit**
- 除非明确需要隐式转换

### 2.36.10 一句话总结

> explicit 的核心作用是 **“不让编译器帮你偷偷转换类型”**。

## 2.37 运算符重载

C++ 允许用户自定义运算符的行为，称为 **运算符重载**。通过运算符重载，我们可以让自定义的类支持基本的运算符（如 +、-、*、[] 等）操作，使得类的对象能够像内置类型一样进行操作。

然而，运算符重载有一些基本规则和限制，确保运算符的使用和行为符合预期。下面是 C++ 运算符重载的一些基本规则和注意事项。

### 2.37.1 运算符重载的基本规则

- **不能改变运算符的优先级和结合性：** 语法解析规则仍由 C++ 语言固定。
- **不能创造新的运算符记号：** 只能重载语言已有且允许重载的运算符。`++` 和 `+=` 是已有运算符，可以为用户定义类型重载；不能自创一个新记号。重载表达式至少有一个操作数必须是类或枚举类型，不能重定义两个内置类型之间的运算。

**重载运算符必须是成员函数或非成员函数**

- 运算符重载可以定义为 **成员函数** 或 **非成员函数**，具体取决于运算符的需求。
    - **成员函数**：当运算符的第一个操作数是当前对象（this）时，运算符应该定义为成员函数。
    - **非成员函数**：如果运算符的两个操作数都是自定义类型，或者两个自定义类型之间进行运算时，运算符可以定义为非成员函数。

**不能重载某些运算符**

- 有些运算符不能被重载，如：
    - ::（作用域解析运算符）
    - .（成员访问运算符）
    - .*（成员指针运算符）
    - ?:（条件运算符）
    - sizeof（大小运算符）
    - typeid（类型信息运算符）
- **不能改变运算符的操作数数量：** 例如二元 `+` 仍只能有两个操作数。成员函数形式中左操作数由隐式 `*this` 提供，所以显式参数会少一个。

### 2.37.2 运算符重载的实现方式

- **成员函数重载** 如果运算符的第一个操作数是类的对象，可以将运算符定义为成员函数。；运算符的参数一般只有一个（第二个操作数）。

```cpp
class Complex {
public:
    int real, imag;

    Complex operator + (const Complex& other) {
        Complex temp;
        temp.real = real + other.real;
        temp.imag = imag + other.imag;
        return temp;
    }
};
```

- 在这个例子中，+ 运算符被重载为成员函数，this 指针指向调用该运算符的对象，other 是另一个操作数。
- **非成员函数重载** 如果运算符的第一个操作数不是类的成员，或者运算符需要两个自定义类型作为参数，则运算符应该定义为非成员函数。

```cpp
class Complex {
public:
    int real, imag;

    Complex(int r, int i) : real(r), imag(i) {}
};

// 非成员函数重载
Complex operator + (const Complex& c1, const Complex& c2) {
    Complex temp(c1.real + c2.real, c1.imag + c2.imag);
    return temp;
}
```

- 在这个例子中，+ 运算符被重载为非成员函数，接受两个 Complex 类型的参数并返回一个新的 Complex 对象。

### 2.37.3 常见的运算符重载示例

**加法运算符（+）重载**

```cpp
Complex operator+(const Complex& other) const {
    return Complex(real + other.real, imag + other.imag);
}
```

**输出流运算符（<<）重载**

```cpp
#include <iostream>
using namespace std;

class Complex {
public:
    int real, imag;

    Complex(int r, int i) : real(r), imag(i) {}

    // 非成员函数重载
    friend ostream& operator << (ostream& out, const Complex& c) {
        out << c.real << " + " << c.imag << "i";
        return out;
    }
};

int main() {
    Complex c1(3, 4);
    cout << c1 << endl;  // 输出 3 + 4i
    return 0;
}
```

- 在这个例子中，<< 被重载为非成员函数，并且通过友元函数 friend 使其能够访问 Complex 类的私有成员。

**自增运算符（++）重载**

```cpp
class Counter {
public:
    Counter& operator++() {
        ++value;
        return *this;
    }
private:
    int value = 0;
};
```

### 2.37.4 总结

- **运算符重载** 可以让自定义类型的对象支持与内置类型相同的操作符行为。
- 不能改变运算符的优先级、结合性，也不能创造新的运算符记号；但可为用户定义类型重载 `++`、`+=` 等已有运算符。
- 运算符重载可以通过 **成员函数** 或 **非成员函数** 实现，具体根据需要来选择。
- 重载时应遵循 **语法规则** 和 **语义一致性**，确保程序的可读性和可维护性。

## 2.38 函数重载

### 2.38.1 定义

**函数重载**是 C++ 支持的一种特性：**同一作用域内可以定义多个同名函数，但参数列表不同**。

- 参数类型、数量或顺序不同即可
- 返回值类型 **不能作为唯一区分条件**

> C 语言不支持函数重载

### 2.38.2 基本语法

```cpp
#include <iostream>
using namespace std;

// 参数类型不同
int add(int a, int b) { return a + b; }
double add(double a, double b) { return a + b; }

// 参数数量不同
int add(int a, int b, int c) { return a + b + c; }

int main() {
    cout << add(1, 2) << endl;       // 调用 int 版本
    cout << add(1.1, 2.2) << endl;   // 调用 double 版本
    cout << add(1, 2, 3) << endl;    // 调用三个参数版本
}
```

### 2.38.3 重载规则

1. **函数名相同**
2. **参数列表不同**（数量、类型、顺序）
3. **返回类型不能唯一区分**
4. 编译器根据**实参类型**选择最合适的函数

### 2.38.4 使用场景

- 同一操作对不同类型的数据实现
- 增强代码可读性和复用性
- 避免为不同类型写多个函数名

### 2.38.5 注意事项

1. **C 不支持**
2. 默认参数可能与重载冲突，需要小心
3. 避免模糊匹配引发编译错误

### 2.38.6 面试高频总结句

> 函数重载允许同名函数根据参数列表区分，C++ 支持，C 不支持，提高函数复用性和可读性。
> Function Overloading = “同名不同参”，增强代码灵活性，C++ 独有特性。

## 2.39 拷贝构造函数作用

### 2.39.1 定义

**拷贝构造函数（Copy Constructor）是用来用一个同类型对象初始化另一个对象**的构造函数。

- 形式一般为：

```cpp
ClassName(const ClassName& other);
```

- 参数通常是 **const 引用**，避免递归调用和提高效率

### 2.39.2 系统提供的默认拷贝构造函数

- 在特殊成员函数规则允许时，编译器可以隐式声明/定义拷贝构造函数，它会**逐个拷贝基类子对象和非静态数据成员**。
- 对指针成员而言，逐成员拷贝只复制指针值；但对 `std::string`、`std::vector` 等类成员，会调用其自身拷贝构造，不能将所有默认拷贝简化为“浅拷贝”。

```cpp
class A {
public:
    int x;
};

A a1;
A a2 = a1; // 默认拷贝构造函数，逐成员拷贝
```

### 2.39.3 拷贝构造函数的作用

1. **对象初始化**

```cpp
ClassName obj2 = obj1; // 用 obj1 初始化 obj2
```

2. **函数传参**（按值传递）

```cpp
void func(ClassName obj); // 调用拷贝构造函数
```

- 若实参是右值且类有可用移动构造，则可调用移动构造；拷贝消除时也可能不调用两者。

3. **函数返回值**（按值返回）

```cpp
ClassName func() {
    ClassName obj;
    return obj; // 可发生 NRVO；未消除时通常优先移动，否则拷贝
}
```

### 2.39.4 自定义拷贝构造函数用途

- 当类中包含 **动态内存、资源句柄、文件指针等非平凡成员** 时
- 默认浅拷贝可能引起 **多重释放、悬挂指针**
- 需实现 **深拷贝**，保证每个对象独立管理资源

```cpp
class MyClass {
    int* data;
public:
    MyClass(int val) { data = new int(val); }
    MyClass(const MyClass& other) { // 深拷贝
        data = new int(*(other.data));
    }
    ~MyClass() { delete data; }
};
```

### 2.39.5 注意事项

1. 拷贝构造函数的第一个参数必须是当前类类型的引用（常见为 `const T&`）；若按值传入，为了构造该形参又需要拷贝，所以这种声明不成立。
2. C++11 后可结合 **移动构造函数**优化性能

### 2.39.6 总结

> 拷贝构造函数用于用一个对象初始化另一个对象，保证对象资源正确管理，防止浅拷贝引发问题。
> 拷贝构造函数让对象“以已有对象为蓝本”创建新的独立实例。

## 2.40 深拷贝和浅拷贝

### 2.40.1 定义

- **浅拷贝（Shallow Copy）**
    - 直接按 **值复制对象的成员变量**
    - 对象中指针成员只是复制地址，多个对象指向同一块内存
- **深拷贝（Deep Copy）**
    - 不仅复制值，还 **复制指针指向的内容**
    - 每个对象拥有独立的资源

### 2.40.2 举例说明

```cpp
class Shallow {
public:
    int* data;
    Shallow(int val) { data = new int(val); }
    ~Shallow() { delete data; }
};

// 默认拷贝构造函数是浅拷贝
Shallow a(10);
Shallow b = a; // b.data = a.data 指向同一地址
```

- 修改 b.data 会影响 a.data
- 对象销毁时会出现 **重复释放** → 崩溃

```cpp
class Deep {
public:
    int* data;
    Deep(int val) { data = new int(val); }
    Deep(const Deep& other) { // 深拷贝
        data = new int(*(other.data));
    }
    ~Deep() { delete data; }
};

Deep a(10);
Deep b = a; // b.data 指向独立内存
```

- 修改 b.data 不影响 a.data
- 每个对象独立管理资源，安全

### 2.40.3 区别总结

|特性|浅拷贝|深拷贝|
|---|---|---|
|内存复制|成员值|成员值 + 指针指向内容|
|指针成员|指向同一块内存|指向独立内存|
|对象独立性|否|是|
|资源释放|可能重复释放 → 崩溃|安全|
|实现方式|原始指针逐成员拷贝时会共享指向|可自定义复制资源，或优先用标准 RAII 类让其拷贝语义自然正确|

### 2.40.4 使用场景

- **逐成员拷贝**：当各成员的拷贝语义本身正确时可直接使用，不限于基本类型。
- **独立资源副本**：对象直接拥有需复制的资源时，应明确实现拷贝语义；工程上优先使用 `std::vector`、`std::string`、智能指针等 RAII 成员，遵循 Rule of Zero。

### 2.40.5 面试高频总结句

> 浅拷贝只复制指针地址，深拷贝复制指针指向内容；深拷贝保证对象独立性，避免资源冲突。
> 浅拷贝“共享资源”，深拷贝“各自拥有”，深拷贝更安全。

## 2.41 成员函数重载 vs 非成员函数重载

在 C++ 中，**运算符重载**可以通过 **成员函数** 或 **非成员函数** 来实现。选择使用成员函数还是非成员函数取决于运算符的需求和操作数的类型。两者的主要区别在于 **函数的定义方式** 和 **操作数的处理方式**。

### 2.41.1 成员函数重载

**定义方式**

- 成员函数重载是指运算符作为类的成员函数进行重载。在这种情况下，运算符重载函数必须作为类的一部分进行定义。
- 成员函数重载的 **第一个操作数**（即 this 指针）是隐式传递的，因此不需要显式地将其作为参数传递给函数。
- **适用场景** 如果运算符的第一个操作数是类的对象，且我们希望将该运算符定义为类的一部分，通常会使用成员函数来实现运算符重载。

**例子：加法运算符重载**

```cpp
class Complex {
public:
    int real, imag;

    Complex(int r, int i) : real(r), imag(i) {}

    // 成员函数重载加法运算符
    Complex operator + (const Complex& other) {
        return Complex(real + other.real, imag + other.imag);
    }
};
```

- 在这个例子中，operator+ 是类 Complex 的成员函数，第一个操作数（this）指向当前对象，第二个操作数是 other，表示传入的另一个 Complex 对象。
- **优点：** 成员函数重载语法简洁，特别是对于需要修改当前对象的运算符（如 +=、++ 等）。；由于第一个操作数是隐式传递的，因此代码简洁。
- **缺点：** 左操作数必须是当前类（或可转换到当前类）的对象，而隐式 `this` 不参与普通用户定义转换；若需要左右操作数对称转换，通常选择非成员重载。成员函数仍可以接受不同类型的右操作数。

### 2.41.2 非成员函数重载

**定义方式**

- 非成员函数重载是指将运算符作为类外的普通函数进行定义。通常，非成员函数重载需要将两个操作数都作为参数传递给函数。
- 非成员函数可以是友元函数（friend），以便访问类的私有成员。

**适用场景**

- 非成员函数重载通常适用于以下几种情况：
    - 运算符的第一个操作数不是类的对象。
    - 需要操作不同类型的对象（例如两个自定义类型之间进行运算）。

**例子：加法运算符重载（非成员函数）**

```cpp
class Complex {
public:
    int real, imag;

    Complex(int r, int i) : real(r), imag(i) {}

    // 友元函数重载加法运算符
    friend Complex operator + (const Complex& c1, const Complex& c2) {
        return Complex(c1.real + c2.real, c1.imag + c2.imag);
    }
};
```

- 在这个例子中，operator+ 被重载为 **非成员函数**。它通过 friend 关键字声明为友元函数，可以访问 Complex 类的私有成员。
- 这里的 operator+ 接受两个操作数：c1 和 c2，它们都是 Complex 类型的对象。
- **优点：** 非成员函数可以对不同类型的对象进行操作，特别是当运算符需要处理两个不同类型的对象时。；可以设计成友元函数，从而访问类的私有成员，但不必成为类的成员函数。
- **缺点：** 需要显式传递两个操作数，因此代码相对较冗长。；不能直接访问类的私有成员，除非将其设计为友元函数。

### 2.41.3 成员函数 vs 非成员函数重载的比较

|特性|成员函数重载|非成员函数重载|
|---|---|---|
|第一个操作数|隐式通过 this 指针传递|显式作为参数传递|
|访问类的私有成员|可以直接访问类的私有成员|需要使用 friend 关键字，或通过 getter/setter 方法|
|显式形参数|比运算符的操作数数量少 1，因为左操作数是隐式 `*this`|与运算符的操作数数量一致（除语言对个别运算符的特殊规则）|
|适用场景|操作数是当前类对象时（如 +=、++）|操作数不是当前类对象时，或者需要操作两个不同类型的对象时|
|灵活性|适用于操作当前对象的情况|需要显式传递操作数，可能稍微复杂|

### 2.41.4 总结

- **成员函数重载**：适合需要修改当前对象或语言强制必须为成员的运算符；左操作数由 `*this` 提供，右操作数可以是不同类型。
- **非成员函数重载**：非成员函数重载适用于需要操作两个自定义类型的对象，或者当运算符的第一个操作数不是类对象时。它可以作为友元函数访问类的私有成员。

根据具体的应用场景和需求，选择适合的重载方式，可以提高代码的可读性、可维护性和灵活性。

## 2.42 什么时候应该重载赋值运算符？

在 C++ 中，**赋值运算符（`=`）** 是一个特殊的运算符，它用于将一个对象的值赋给另一个对象。通常情况下，编译器会自动生成一个默认的赋值运算符。然而，当类中包含 **动态分配的资源** 或 **指针成员** 时，**默认赋值运算符** 可能导致资源共享或内存泄漏等问题，因此需要 **重载赋值运算符** 来确保正确的赋值行为。

### 2.42.1 赋值运算符的默认行为

C++ 编译器会为每个类自动生成一个 **默认赋值运算符**，它执行的是 **逐位赋值**。即：

- 对象的成员逐个复制。
- 如果类包含指针成员，默认的赋值运算符会简单地复制指针的值（地址），而不会复制指针所指向的内存内容。

这种默认行为可能导致以下问题：

- **浅拷贝**：如果一个类的对象包含指针成员，默认赋值运算符会导致两个对象指向相同的内存地址，导致 **资源共享** 和 **内存泄漏**。
- **内存泄漏**：当一个对象被销毁时，指针成员指向的内存空间可能没有正确释放。

因此，当类涉及到动态分配的内存或其他资源时，应该 **重载赋值运算符** 来确保正确的 **深拷贝** 行为。

### 2.42.2 什么时候需要重载赋值运算符

**类包含动态分配的内存（指针成员）**

当类包含 **指针成员**，且这些指针指向动态分配的内存时，使用默认赋值运算符会导致指针共享相同的内存地址。这可能导致 **双重释放** 等问题，因此需要重载赋值运算符，确保每个对象都拥有自己的副本。

**类包含资源管理（如文件句柄、网络连接等）**

如果类包含 **文件句柄**、**数据库连接** 或其他资源，默认赋值运算符可能导致资源的重复管理或意外释放。这时，需要重载赋值运算符，确保每个对象拥有独立的资源管理。

**当类对象的成员可能需要进行深拷贝时**

如果类的成员是其他类的对象，或者包含动态分配的内存，赋值时需要确保通过 **深拷贝** 复制资源，而不是简单的浅拷贝。

### 2.42.3 重载赋值运算符的实现

重载赋值运算符时，必须遵循一些规则，确保赋值操作的正确性，特别是 **自我赋值**（即 a = a）的情况。

**赋值运算符的基本实现**

```cpp
class MyClass {
public:
    // 构造函数
    explicit MyClass(int value) : data(new int(value)) {}

    // 析构函数
    ~MyClass() {
        delete data;
    }

    // 赋值运算符重载
    MyClass& operator=(const MyClass& other) {
        if (this == &other)  // 自我赋值检查
            return *this;

        // 释放当前资源
        delete data;

        // 分配新内存并复制数据
        data = new int(*other.data);

        return *this;  // 返回 *this 以支持链式赋值
    }

    // 用于输出数据的成员函数
    void print() const {
        std::cout << *data << std::endl;
    }

private:
    int* data;
};
```

**关键点解释**

- **自我赋值检查**：首先检查 this == &other，以确保对象没有自我赋值。如果是自我赋值，直接返回当前对象。
- **释放原有资源**：在进行新的内存分配前，首先释放原有的内存或资源，防止内存泄漏。
- **深拷贝**：通过动态分配内存并复制数据，实现深拷贝行为。
- **返回 \*this**：返回当前对象的引用，以支持链式赋值（例如：a = b = c）。

**复制构造函数与赋值运算符的关系**

复制构造函数和赋值运算符常常一起重载。复制构造函数用于对象初始化时的深拷贝，而赋值运算符用于已有对象之间的深拷贝。

- 复制构造函数：用于构造一个新对象时，将一个现有对象的状态复制到新对象中。
- 赋值运算符：用于将一个已存在的对象赋值给另一个已存在的对象。

```cpp
// 复制构造函数
MyClass(const MyClass& other) {
    data = new int(*other.data);
}
```

### 2.42.4 赋值运算符重载的常见错误

**没有检查自我赋值**

没有检查 this == &other 可能会导致对象自我赋值时的错误行为。

**没有释放旧资源**

没有正确释放当前对象的资源，可能会导致内存泄漏。

**返回类型不对**

赋值运算符应返回 *this，如果返回其他类型（如 void），将无法支持链式赋值。

**遗漏深拷贝**

如果没有进行深拷贝，可能会导致多个对象共享同一块内存，造成资源冲突或多次释放。

### 2.42.5 总结

- **应该重载赋值运算符的情况：** 类包含动态分配的内存（如指针成员）。；类包含需要管理的资源（如文件句柄、网络连接等）。；类成员需要深拷贝时。

通过重载赋值运算符，程序员可以控制对象的赋值行为，避免内存泄漏、资源共享和不当的资源管理，确保类的对象能正确管理其动态资源。

## 2.43 前置 ++ 和后置 ++ 重载的区别

在 C++ 中，**前置 `++` 和后置 `++` 都是自增运算符**。这两个运算符的作用是相同的：将变量的值增加 1。然而，它们在重载时有一些细微的区别，特别是在实现上。前置和后置自增的主要区别在于它们的返回值和实现方式。

```cpp
++a;
```

**前置自增重载实现**

前置 ++ 运算符的重载定义通常很简单，直接在对象上进行自增，并返回对象本身。

```cpp
class Counter {
private:
    int value;
public:
    Counter(int val) : value(val) {}

    // 前置自增运算符重载
    Counter& operator++() {
        ++value;  // 先自增
        return *this;  // 返回自增后的对象
    }

    void print() const {
        std::cout << value << std::endl;
    }
};
```

- 在前置自增中，operator++ 返回 *this，即当前对象的引用。
- **特点：** **返回值**：返回对象自身的引用，可以支持链式操作（例如：a = ++b;）。；**实现**：直接修改对象，并返回自增后的对象。

### 2.43.1 前置自增 ++

前置自增运算符在 **操作数之前**进行自增，即 ++a 会先对 a 进行自增操作，然后返回自增后的值。

**语法：**

```cpp
++a;
```

**前置自增重载实现**

前置 ++ 运算符的重载定义通常很简单，直接在对象上进行自增，并返回对象本身。

```cpp
class Counter {
public:
    Counter(int val) : value(val) {}
    Counter& operator++() {
        ++value;
        return *this;
    }
private:
    int value;
};
```

- 在前置自增中，operator++ 返回 *this，即当前对象的引用。

### 2.43.2 后置自增 ++

后置自增运算符在 **操作数之后**进行自增，即 a++ 会先返回原来的值，然后再对 a 进行自增。

**语法：**

```cpp
a++;
```

**后置自增重载实现**

后置 ++ 运算符的重载比前置 ++ 更复杂，通常需要保存当前对象的副本，然后自增对象的值，最后返回该副本。

```cpp
class Counter {
private:
    int value;
public:
    Counter(int val) : value(val) {}
    Counter operator++(int) {
        Counter old(*this);
        ++value;
        return old;
    }
};
```

- 在后置自增中，operator++(int) 参数中的 int 用来区分前置和后置操作。返回的是对象的副本（自增前的状态）。

**特点：**

- **返回值**：返回 **对象的副本**，即自增前的状态。会直接修改操作数，返回一个临时对象。**返回的是一个临时对象（旧值）**
- **实现**：先保存对象的副本，再进行自增，最后返回副本。

### 2.43.3 前置和后置自增重载的比较

|特性|语法|实现|返回值|返回的类型|
|---|---|---|---|---|
|前置自增 ++a|`++a`|先自增，再返回对象本身|返回当前对象的引用（*this）|当前对象的引用（Counter&）|
|后置自增 a++|`a++`|先返回当前对象的副本，再自增|返回自增前的对象副本|当前对象的副本（Counter）|

### 2.43.4 何时使用前置与后置自增

- **前置自增 **++a 通常在没有必要使用原始值时（如直接进行自增操作）使用，它的实现更加高效。
- **后置自增 **a++ 适用于需要保存原始值的场景，例如在 a++ 后需要使用自增前的值（如返回原对象的副本）。

例如，**后置自增**常常用于需要用到原始值的情况，像容器中的迭代器使用：

```cpp
for (auto it = container.begin(); it != container.end(); ++it) {
    // 使用前置自增，因为只关心自增后的迭代器
}
```

```cpp
for (auto it = container.begin(); it != container.end(); it++) {
    // 使用后置自增，可能在某些特殊场景下需要先使用原始迭代器
}
```

### 2.43.5 总结

- **前置自增 **++a 返回对象本身，修改并返回自增后的对象，可以支持链式操作。通常实现较为简单，且更为高效。
- **后置自增 **a++ 返回自增前的对象副本，通常需要多一步的复制操作，因此实现相对复杂。适用于需要保持自增前状态的情况。

在重载自增运算符时，应该根据具体需求选择前置或后置自增的重载方式。

在 C++ 中，**流操作符（**<<** 和 **>>**）** 通常用于输入输出流操作。例如，std::cout << value; 用于输出数据，std::cin >> value; 用于输入数据。为了自定义类的输入输出行为，我们需要重载这两个流操作符。通常，流操作符重载为 **友元函数**，这样可以访问类的私有成员。

## 2.44 流操作符 (<</>>) 重载

在 C++ 中，**流操作符（**<<** 和 **>>**）** 通常用于输入输出流操作。例如，std::cout << value; 用于输出数据，std::cin >> value; 用于输入数据。为了自定义类的输入输出行为，我们需要重载这两个流操作符。通常，流操作符重载为 **友元函数**，这样可以访问类的私有成员。

### 2.44.1 流操作符重载的常见场景

- **输出操作符 (**<<**)**：用于将对象输出到流中（如 std::cout）。
- **输入操作符 (**>>**)**：用于从流中读取数据并赋值给对象（如 std::cin）。

流操作符重载的目的是让自定义类能够与 C++ 的输入输出流机制兼容，从而像内置类型一样使用 << 和 >>。

### 2.44.2 流操作符重载的实现

**输出流操作符 <<**

输出流操作符的重载通常在类外部实现，并作为友元函数来访问类的私有成员。返回类型为 std::ostream&，这样可以支持链式调用（例如：std::cout << obj1 << obj2;）。

```cpp
class MyClass {
public:
    explicit MyClass(int v) : value(v) {}
    friend std::ostream& operator<<(std::ostream& os, const MyClass& obj) {
        os << "MyClass value: " << obj.value;
        return os;
    }
private:
    int value;
};

int main() {
    MyClass obj(10);
    std::cout << obj << std::endl;  // 输出 "MyClass value: 10"
    return 0;
}
```

- 在上面的例子中，operator<< 是一个 **友元函数**，它将 MyClass 对象的 value 成员输出到 std::ostream 流中。
- 输出流操作符重载时需要返回 std::ostream&，以便支持链式操作。

**输入流操作符 >>**

输入流操作符的重载也通常作为友元函数实现，用于将输入流中的数据读入对象中。返回类型为 std::istream&，以支持链式调用（例如：std::cin >> obj1 >> obj2;）。

```cpp
#include <iostream>

class MyClass {
private:
    int value;
public:
    MyClass() : value(0) {}

    // 输入流操作符重载
    friend std::istream& operator>>(std::istream& is, MyClass& obj) {
        is >> obj.value;  // 从输入流中读取数据并存入 value
        return is;  // 返回输入流以支持链式调用
    }
};

int main() {
    MyClass obj;
    std::cout << "Enter value: ";
    std::cin >> obj;  // 输入 42
    return 0;
}
```

- 在上面的例子中，operator>> 读取输入流中的数据并将其赋值给 MyClass 的 value 成员。
- 输入流操作符重载时也需要返回 std::istream&，以便支持链式操作。

### 2.44.3 注意事项

- **返回值类型**：流操作符通常返回流本身（std::ostream& 或 std::istream&），这样就能支持多个操作符连续使用（例如 std::cout << obj1 << obj2;）。
- **友元函数**：为了访问类的私有成员，流操作符通常会被设计为 **友元函数**。
- **常量引用**：在重载输出流操作符时，通常使用 **常量引用** 来传递对象，以避免不必要的拷贝。
- **输入流的验证**：在实际应用中，应在输入流重载时进行错误检查，确保从流中读取数据时没有出现错误（例如，输入类型不匹配时）。

### 2.44.4 流操作符重载的常见错误

**未返回正确的流对象**

流操作符重载时需要返回流对象本身（std::ostream& 或 std::istream&）。如果没有返回流对象，链式调用将无法工作。

**不使用常量引用**

对于输出流操作符，应该使用常量引用来传递对象，避免不必要的拷贝开销。

**输入流操作符没有进行错误处理**

输入流操作符需要确保从流中读取数据时的有效性。未进行错误处理可能导致读取无效数据或程序崩溃。

### 2.44.5 总结

- **输出流操作符 **<< 用于将对象的内容输出到流中，通常重载为友元函数，返回 std::ostream&。
- **输入流操作符 **>> 用于从流中读取数据并赋值给对象，通常重载为友元函数，返回 std::istream&。
- 重载流操作符时应注意返回流本身以支持链式调用，通常使用常量引用来避免拷贝，并在输入流操作符中加入错误处理。

通过流操作符的重载，可以让自定义类像内置类型一样方便地进行输入输出操作，从而增强代码的可读性和可维护性。

## 2.45 重写（Override）

### 2.45.1 什么是重写（Override）

**定义：**
重写是指 **派生类（子类）重新实现基类中已声明的虚函数**，以实现**运行时多态**。

### 2.45.2 重写成立的条件

1. **基类函数必须是 **virtual
2. **函数名相同**
3. **参数列表完全相同**
4. **返回类型相同**（或协变返回类型）
5. **作用域为父子类关系**

### 2.45.3 基本示例

```cpp
class Base {
public:
    virtual void func() {
        cout << "Base func" << endl;
    }
};

class Derived : public Base {
public:
    void func() override {
        cout << "Derived func" << endl;
    }
};
```

### 2.45.4 override 关键字的作用

- **编译期检查是否真正重写**
- 防止因函数签名不一致导致“伪重写”
- 提高代码可维护性

```cpp
void func() override;
```

### 2.45.5 为什么要使用 override

```cpp
class Base {
public:
    virtual void func(int x);
};

class Derived : public Base {
public:
    void func(double x); // 不是重写，是新函数
};
```

- 未使用 override：不报错，但无多态
- 使用 override：编译错误，问题暴露

### 2.45.6 重写 vs 重载 vs 隐藏

|概念|是否继承|参数|是否多态|
|---|---|---|---|
|重写|是|相同|是|
|重载|否/是|不同|否|
|隐藏|是|任意|否|

### 2.45.7 重写与多态的关系

- 通过 **基类指针 / 引用** 调用
- 实际执行 **派生类实现**

```cpp
Base* p = new Derived();
p->func();   // 调用 Derived::func
```

### 2.45.8 const 与重写

```cpp
virtual void func() const;
void func();          // 不是重写
void func() const override; // 正确
```

### 2.45.9 析构函数的重写（重要）

- 基类析构函数 **必须是 virtual**
- 否则 delete 基类指针会资源泄漏

```cpp
virtual ~Base() {}
```

### 2.45.10 总结

> 重写是派生类对基类虚函数的重新实现，是实现运行时多态的基础，override 关键字可提供编译期安全检查。重写决定“同一个接口，不同的实现”。

## 2.46 函数模板与类模板

在 C++ 中，**模板**（Template）是一个非常强大的特性，它允许编写与类型无关的代码，以便重用逻辑，简化代码。模板分为 **函数模板** 和 **类模板**，它们的核心思想相同，但用途和实现方式有所不同。

### 2.46.1 函数模板（Function Template）

函数模板允许你为一个函数定义一个通用的模板，使其能够处理不同类型的参数。在调用时，编译器会根据传递给函数的参数类型自动推导出具体类型。

**函数模板的语法**

```cpp
template <typename T>
T add(T a, T b) {
    return a + b;
}
```

**特点：**

- **定义方式**：通过 template 关键字定义，后跟一个或多个类型参数（如 typename T）。
- **用途**：用于创建通用的函数，可以处理不同数据类型的操作，如通用加法、交换等。
- **类型推导**：编译器根据函数调用时的实参自动推导出类型。
- **实例化**：当调用模板函数时，编译器根据调用时的具体类型生成该模板函数的实例化版本。

**例子：**

```cpp
T add(T a, T b) {
    return a + b;
}

int main() {
    cout << add(3, 5) << endl;  // 输出 8，类型为 int
    cout << add(2.5, 3.5) << endl;  // 输出 6，类型为 double
    return 0;
}
```

- 在上面的例子中，add 函数是一个模板函数，可以接受不同类型的参数。

### 2.46.2 类模板（Class Template）

类模板允许你为一个类定义一个通用的模板，使得类的实现能够处理不同类型的成员和方法。

**类模板的语法**

```cpp
template <typename T>
class Box {
private:
    T value;
public:
    Box(T v) : value(v) {}
    T getValue() {
        return value;
    }
};
```

**特点：**

- **定义方式**：通过 template 关键字定义，后跟一个或多个类型参数（如 typename T）。
- **用途**：用于创建通用的类，可以处理不同数据类型的成员和方法。
- **类型推导**：编译器根据类的实例化时的类型参数自动推导出具体类型。
- **实例化**：类模板在实例化时，需要明确指定类型，或者让编译器推导出类型。

**例子：**

```cpp
#include <iostream>
using namespace std;

template <typename T>
class Box {
private:
    T value;
public:
    Box(T v) : value(v) {}
    T getValue() {
        return value;
    }
};

int main() {
```

- 在上面的例子中，Box 类是一个模板类，可以容纳不同类型的 value，如 int 和 double。

### 2.46.3 函数模板与类模板的区别

- **函数模板的优势** 可以在不重复编写代码的情况下处理不同类型的函数。；编译器会根据函数参数自动推导出所需的类型，简化了模板的使用。
- **类模板的优势** 能够创建处理不同类型的类对象，避免为每种类型定义多个相似类。；可以在类模板中使用成员函数、成员变量等操作，让类更具灵活性。

|特性|函数模板|类模板|
|---|---|---|
|用途|用于定义通用的函数逻辑|用于定义通用的类，处理不同类型的成员和方法|
|实例化时机|根据函数调用时的实际参数类型进行实例化|根据类的实例化时指定的类型进行实例化|
|类型推导|可以通过函数调用时的参数自动推导类型|必须明确指定类实例化时的类型，或通过推导来确定类型|
|定义方式|`template <typename T> T function(T a)`|`template <typename T> class Class {}`|
|函数与方法的不同|主要处理函数逻辑和计算|主要处理类成员和方法|
|成员变量|没有成员变量，仅处理函数的参数类型|可以有成员变量，处理类内部的各种类型|

### 2.46.4 总结

- **函数模板** 用于定义可以接受不同类型参数的函数，编译器会根据实际调用时的类型推导来生成具体的函数实现。
- **类模板** 用于定义可以接受不同类型的类，在实例化时，需要指定类的具体类型。

两者的共同点是都通过 template 关键字定义，都允许泛化处理不同数据类型。但是，函数模板通常用来处理单一的功能，而类模板更侧重于实现通用类的设计。

## 2.47 隐藏

### 2.47.1 什么是隐藏（Hiding）

**定义：**
隐藏是指 **派生类中定义的成员**（函数或变量）**屏蔽了基类中同名成员**，使基类成员在派生类作用域内不可直接访问。

> 隐藏不要求函数参数相同，也**不产生多态**。

### 2.47.2 函数隐藏（重点）

**（1）不同参数也会发生隐藏**

```cpp
class Base {
public:
    void func(int x) {}
};

class Derived : public Base {
public:
    void func(double x) {}
};
```

- Base::func(int) 被隐藏
- 不是重载、不是重写

**（2）即使基类函数是 virtual 也会被隐藏**

```cpp
class Base {
public:
    virtual void func(int x) {}
};

class Derived : public Base {
public:
    void func(double x) {}
};
```

- 依然是隐藏
- 不发生多态

### 2.47.3 变量隐藏

```cpp
class Base {
public:
    int x;
};

class Derived : public Base {
public:
    int x;
};
```

- Derived::x 隐藏 Base::x
- 可通过作用域访问：

```cpp
Base::x
```

### 2.47.4 隐藏与重写的区别（必考）

|对比项|隐藏|重写|
|---|---|---|
|是否继承|是|是|
|函数名|相同|相同|
|参数|任意|必须相同|
|是否多态|否|是|
|virtual 要求|不需要|必须|

### 2.47.5 如何解决函数隐藏

**方法一：使用作用域运算符**

```cpp
Base::func(10);
```

**方法二：使用 using 声明（推荐）**

```cpp
class Derived : public Base {
public:
    using Base::func;
    void func(double x);
};
```

- 恢复基类同名函数可见性

### 2.47.6 隐藏的本质原因

- C++ **作用域规则**
- 派生类作用域优先级高于基类

### 2.47.7 常见误区

- “参数不同就是重载” → 错
- “virtual 就不会隐藏” → 错
- “隐藏有多态” → 错

### 2.47.8 面试高频总结句

> 隐藏是派生类成员屏蔽基类同名成员的现象，与参数是否相同无关，不产生多态。

## 2.48 模板特化（全特化与偏特化）作用

在 C++ 中，**模板特化**（Template Specialization）是一种强大的技术，允许对模板类或函数进行定制化处理，以便在特定类型下实现不同的行为。模板特化有两种主要类型：**全特化**和**偏特化**。

### 2.48.1 模板全特化（Full Specialization）

模板全特化是针对某一具体类型（或类型组合）完全定制模板的行为。全特化允许为特定类型（如 int、double 或某个自定义类型）提供一个完全不同的实现。

**全特化的语法**

```cpp
template <typename T>
class MyClass {
public:
    void display() {
        std::cout << "Generic template" << std::endl;
    }
};

// 全特化：当 T 是 int 时，提供不同的实现
template <>
class MyClass<int> {
public:
    void display() {
        std::cout << "Specialized template for int" << std::endl;
    }
};
```

**全特化的作用**

- **定制化实现**：可以为特定类型提供特殊的实现，而不影响其他类型。
- **优化性能**：对于一些特殊类型，可以做额外的优化处理。
- **解决类型冲突**：例如，某些类型可能无法使用默认模板实现，通过全特化可以避免错误并提供可行的解决方案。

**例子：**

```cpp
#include <iostream>
using namespace std;

template <typename T>
class MyClass {
public:
    void display() {
        cout << "Generic template" << endl;
    }
};

template <>
class MyClass<int> {
public:
    void display() {
        cout << "Specialized template for int" << endl;
    }
};

int main() {
    MyClass<double> generic;
    MyClass<int> specialized;
    generic.display();
    specialized.display();
}
```

- 在上面的例子中，当模板参数是 int 时，MyClass 会使用全特化的版本，而其他类型（如 float）则使用通用模板。

### 2.48.2 模板偏特化（Partial Specialization）

模板偏特化是指对模板中的部分类型或条件进行定制化处理，而不是为某个具体类型提供完全不同的实现。偏特化可以在模板的某些类型参数上做出特化，而不是全部。

**偏特化的语法**

```cpp
template <typename T, typename U>
class MyClass {
public:
    void display() {
        std::cout << "Generic template" << std::endl;
    }
};

// 偏特化：当 T 是 int 时，U 保持不变
template <typename U>
class MyClass<int, U> {
public:
    void display() {
        std::cout << "Specialized template for int" << std::endl;
    }
};

// 偏特化：当 U 是 char 时，T 保持不变
template <typename T>
class MyClass<T, char> {
public:
    void display() {
        std::cout << "Specialized template for char" << std::endl;
    }
};
```

**偏特化的作用**

- **灵活性**：可以根据模板参数的某些特征进行定制，而不需要对所有类型做出改变。
- **减少冗余**：偏特化使得模板的重用性得到增强，可以根据类型的某些条件对行为进行优化或修改。
- **提高可读性**：可以通过偏特化对常见的特定类型进行处理，避免编写冗长的模板代码。

**例子：**

```cpp
#include <iostream>
using namespace std;

template <typename T, typename U>
class MyClass {
public:
    void display() {
        std::cout << "Generic template" << std::endl;
    }
};

// 偏特化：当 T 是 int 时，U 保持不变
template <typename U>
class MyClass<int, U> {
public:
    void display() {
        std::cout << "Specialized template for int" << std::endl;
    }
};

// 偏特化：当 U 是 char 时，T 保持不变
template <typename T>
class MyClass<T, char> {
public:
    void display() {
        std::cout << "Specialized template for char" << std::endl;
    }
};

int main() {
    MyClass<float, double> obj1;  // 使用通用模板
    obj1.display();                // 输出 "Generic template"

    MyClass<int, double> obj2;     // 使用偏特化模板
    obj2.display();                // 输出 "Specialized template for int"

    MyClass<int, char> obj3;       // 使用偏特化模板
    obj3.display();                // 输出 "Specialized template for int"

    MyClass<double, char> obj4;    // 使用偏特化模板
    obj4.display();                // 输出 "Specialized template for char"

    return 0;
}
```

- 在这个例子中，偏特化通过在模板参数 T 或 U 为特定类型时改变类的行为，提供了更多的灵活性。可以针对 T 为 int 或 U 为 char 的情况进行不同的处理。

### 2.48.3 全特化与偏特化的区别

|特性|定义方式|使用场景|实例化方式|灵活性|代码示例|
|---|---|---|---|---|---|
|全特化|对模板的所有参数提供具体的类型实现|当需要为某些特定类型完全定制模板|明确指定模板参数的具体类型|只能为某一具体类型完全定制，灵活性低|`template<> class MyClass<int> {}`|
|偏特化|对模板的部分参数或条件进行定制化处理|当需要为模板的部分参数提供特殊处理|根据模板参数匹配情况实例化|可为多个类型或条件提供特化，灵活性高|`template<typename T> class MyClass<T, int> {}`|

### 2.48.4 总结

- **全特化**：是对整个模板进行完全的定制，为某个具体类型提供完全不同的实现。全特化的主要用途是为特定类型提供特有的行为或优化。
- **偏特化**：是对模板的部分类型参数进行定制，保持其他参数的通用性。偏特化的主要用途是为特定类型的部分参数提供优化或特殊处理，而不需要完全为每种类型单独编写代码。

通过模板特化，C++ 能够为不同类型提供灵活的定制化实现，从而提高代码的复用性和性能。

## 2.49 C语言模拟多态、继承、重载

### 2.49.1 概述

C 语言不支持面向对象特性，但可以通过**结构体、函数指针、宏等技巧**模拟：

- **继承** → 结构体嵌套
- **多态** → 结构体 + 函数指针（类似虚函数表）
- **函数重载** → 不直接支持，可通过函数名 + 参数类型/数量区分或宏实现

### 2.49.2 模拟继承

```c
#include <stdio.h>

typedef struct {
    int x;
} Base;

typedef struct {
    Base base;  // 模拟继承 Base
    int y;
} Derived;

int main() {
    Derived d;
    d.base.x = 10;  // 访问 Base 成员
    d.y = 20;
    printf("%d %d\n", d.base.x, d.y);
}
```

- **结构体嵌套**实现“父类成员”访问

### 2.49.3 模拟多态（虚函数表）

```c
#include <stdio.h>

typedef struct Animal {
    void (*speak)(struct Animal*); // 函数指针模拟虚函数
} Animal;

```

- **函数指针** + **基类指针**实现运行时动态绑定
- 可扩展多种派生类型

### 2.49.4 模拟函数重载

- C 不支持直接重载
- 常用技巧：
1. **不同函数名**：

```c
int add_int(int a, int b);
double add_double(double a, double b);
```

2. **宏定义**：

```c
#define ADD(a, b) _Generic((a), \
    int: add_int, \
    double: add_double \
)(a, b)
```

- C11 _Generic 可实现类似重载效果

### 2.49.5 注意事项

1. 需手动管理类型安全
2. 函数指针和结构体嵌套增加代码复杂度
3. 仅模拟，语法不如 C++ 简洁

### 2.49.6 面试高频总结句

> 在 C 中，多态通过结构体+函数指针实现，继承通过结构体嵌套模拟，重载可用不同函数名或 C11 _Generic 实现。
> C 模拟 OOP = 结构体嵌套 + 函数指针 + 宏/泛型，实现继承、多态和重载。

## 2.50 如何保证临界区操作的原子性？

### 2.50.1 概念

- **临界区**：指在多线程或多进程环境中，访问共享资源的代码区域。为了避免竞态条件（Race Condition），必须保证在任何时刻只有一个线程能够进入临界区，访问共享资源。
- **原子性**：原子操作是不可分割的操作，即在执行过程中不会被中断或分割成多个步骤。保证临界区的原子性意味着一旦某个线程开始执行临界区操作，其他线程无法打断该操作，直到当前操作完成。

### 2.50.2 保证临界区操作原子性的常见方法

**1. 互斥锁（Mutex）**

- **原理**：互斥锁是最常用的同步机制，用于保护临界区，确保每次只有一个线程能够访问临界区。当一个线程获得互斥锁时，其他线程无法访问该临界区，直到锁被释放。
- **实现**：
    - 使用 pthread_mutex（POSIX）或 std::mutex（C++）进行锁定和解锁。

**示例（C++）：**

```cpp
#include <iostream>
#include <mutex>
#include <thread>

std::mutex mtx;  // 声明互斥锁
int shared_data = 0;

void increment() {
    mtx.lock();  // 进入临界区前加锁
    shared_data++;  // 临界区操作
    mtx.unlock();  // 离开临界区后解锁
}

int main() {
    std::thread t1(increment);
    std::thread t2(increment);

    t1.join();
    t2.join();

    std::cout << "Shared data: " << shared_data << std::endl;
    return 0;
}
```

- **优点**：简单、直接。
- **缺点**：锁的竞争会导致性能下降；可能发生死锁（如果锁没有正确释放）。

**2. 自旋锁（Spinlock）**

- **原理**：自旋锁是一种忙等待锁，在锁无法立即获得时，线程会持续循环检查锁的状态，而不是被挂起。适用于锁争用较小的情况。
- **实现**：
    - 使用 std::atomic_flag 或 std::atomic<bool> 来实现自旋锁。

**示例（C++）：**

```cpp
#include <iostream>
#include <atomic>
#include <thread>

std::atomic_flag lock_flag = ATOMIC_FLAG_INIT;
int shared_data = 0;

void increment() {
    while (lock_flag.test_and_set(std::memory_order_acquire)) {
        // 自旋，等待锁释放
    }
    shared_data++;  // 临界区操作
    lock_flag.clear(std::memory_order_release);  // 解锁
}

int main() {
    std::thread t1(increment);
    std::thread t2(increment);

    t1.join();
    t2.join();

    std::cout << "Shared data: " << shared_data << std::endl;
    return 0;
}
```

- **优点**：在锁争用很小的情况下效率较高。
- **缺点**：如果锁被持有时间较长，会浪费 CPU 资源；不能被挂起，因此在锁持有时间较长时效率较低。

**3. 读写锁（Read-Write Lock）**

- **原理**：读写锁允许多个线程并发读取共享资源，但写操作是互斥的。即，如果有线程在写数据时，其他线程不能读取或写入数据；而如果只有读取操作，多个线程可以同时进行。
- **实现**：
    - 使用 pthread_rwlock（POSIX）或 std::shared_mutex（C++）。

**示例（C++）：**

```cpp
#include <iostream>
#include <mutex>
#include <shared_mutex>
#include <thread>

std::shared_mutex rwlock;  // 声明读写锁
int shared_data = 0;

void read_data() {
    std::shared_lock<std::shared_mutex> lock(rwlock);  // 共享读锁
    std::cout << "Reading data: " << shared_data << std::endl;
}

void write_data() {
    std::unique_lock<std::shared_mutex> lock(rwlock);  // 独占写锁
    shared_data++;
    std::cout << "Writing data: " << shared_data << std::endl;
}
```

- **优点**：读多写少的情况下效率较高。
- **缺点**：在写操作较多的情况下，效率较低。

**4. 原子操作（Atomic Operations）**

- **原理**：使用硬件提供的原子操作来保证对共享资源的修改是不可分割的，通常用于简单的变量更新操作。
- **实现**：
    - 使用 std::atomic（C++11及以上）进行原子操作。

**示例（C++）：**

```cpp
#include <iostream>
#include <atomic>
#include <thread>

std::atomic<int> shared_data(0);

void increment() {
    shared_data++;  // 原子操作，保证修改是原子性的
}

int main() {
    std::thread t1(increment);
    std::thread t2(increment);

    t1.join();
    t2.join();

    std::cout << "Shared data: " << shared_data.load() << std::endl;
    return 0;
}
```

- **优点**：高效，不需要显式锁。
- **缺点**：适用于简单的操作，不适合复杂的临界区。

### 2.50.3 总结：如何保证临界区操作的原子性

|方法|适用场景|优点|缺点|
|---|---|---|---|
|互斥锁（Mutex）|适用于复杂的临界区|简单易用，能够保护复杂的操作|锁竞争会影响性能，可能导致死锁|
|自旋锁（Spinlock）|锁竞争较小的场景|对锁争用小的情况效率较高|锁竞争严重时浪费 CPU 资源|
|读写锁（Read-Write Lock）|读多写少的情况|读操作并发性好，效率较高|写操作频繁时效率低|
|原子操作（Atomic）|简单变量操作|高效，避免了锁的开销|只适用于简单的操作，不适合复杂的临界区|

### 2.50.4 推荐

- **简单操作**：如果只需要对简单变量进行原子性修改，使用 std::atomic。
- **复杂操作**：如果临界区内的操作较复杂，且需要多个资源的保护，使用 **互斥锁**。
- **读多写少**：可以考虑使用 **读写锁** 来提高效率。
- **锁争用较少**：如果锁的持有时间较短且竞争较少，可以使用 **自旋锁**。

选择合适的同步机制可以有效提高多线程程序的并发性能，同时保证临界区操作的原子性。

## 2.51 模板实例化发生在什么时候？

模板实例化是指编译器根据模板定义和具体的类型参数，生成特定类型的代码。模板本身并不直接生成机器代码，而是在实际调用或使用模板时，编译器根据所使用的类型生成相应的代码。模板实例化是在编译时发生的，只有在某些特定条件下，编译器才会实例化模板。

当你显式调用一个模板函数或类时，编译器会根据传递给模板的具体类型参数实例化该模板。

```cpp
template <typename T>
void print(T value) {
    std::cout << value << std::endl;
}

int main() {
    print(5);   // 实例化 print<int>
    print(3.14); // 实例化 print<double>
}
```

- 在这个例子中，当调用 print(5) 时，编译器会实例化 print<int>；当调用 print(3.14) 时，编译器会实例化 print<double>。

**类模板的实例化**

类模板的实例化是在使用该类模板创建对象时发生的。例如：

```cpp
template <typename T>
class MyClass {
public:
    T value;
    MyClass(T v) : value(v) {}
};

int main() {
    MyClass<int> obj1(5);   // 实例化 MyClass<int>
    MyClass<double> obj2(3.14); // 实例化 MyClass<double>
}
```

- 在上面的例子中，MyClass<int> 和 MyClass<double> 会在创建 obj1 和 obj2 时实例化。

**编译器在需要时进行隐式实例化**

当模板函数或类模板在调用时没有提供具体类型时，编译器会自动推导并实例化模板。例如：

```cpp
template <typename T>
void display(T val) {
    std::cout << val << std::endl;
}

int main() {
    display(10);   // 自动推导出 T 为 int
    display("Hello"); // 自动推导出 T 为 const char*
}
```

- 在这种情况下，编译器会根据传递给模板函数的参数自动推导出 T 的类型并实例化模板。

**模板的显式实例化（Explicit Instantiation）**

在某些情况下，程序员可以显式地请求编译器实例化某个模板。例如，通过 template<> 或 extern 来显式实例化模板。

```cpp
template <typename T>
void print(T value) {
    std::cout << value << std::endl;
}

// 显式实例化
template void print<int>(int);   // 实例化 print<int>
template void print<double>(double); // 实例化 print<double>
```

- 显式实例化会告诉编译器为指定类型（如 int 和 double）生成模板的实例。这样做可以避免多次实例化，提高编译效率，尤其是当模板函数在多个文件中使用时。

### 2.51.1 模板实例化的时机

模板实例化发生在以下几种情况下：

**显式调用模板函数或类时**

当你显式调用一个模板函数或类时，编译器会根据传递给模板的具体类型参数实例化该模板。

```cpp
template <typename T>
void print(T value) {
    std::cout << value << std::endl;
}

int main() {
    print(5);   // 实例化 print<int>
    print(3.14); // 实例化 print<double>
}
```

- 在这个例子中，当调用 print(5) 时，编译器会实例化 print<int>；当调用 print(3.14) 时，编译器会实例化 print<double>。

**类模板的实例化**

类模板的实例化是在使用该类模板创建对象时发生的。例如：

```cpp
template <typename T>
class MyClass {
public:
    T value;
    MyClass(T v) : value(v) {}
};

int main() {
    MyClass<int> obj1(5);   // 实例化 MyClass<int>
    MyClass<double> obj2(3.14); // 实例化 MyClass<double>
}
```

- 在上面的例子中，MyClass<int> 和 MyClass<double> 会在创建 obj1 和 obj2 时实例化。

**编译器在需要时进行隐式实例化**

当模板函数或类模板在调用时没有提供具体类型时，编译器会自动推导并实例化模板。例如：

```cpp
    display("Hello"); // 自动推导出 T 为 const char*
}
```

- 在这种情况下，编译器会根据传递给模板函数的参数自动推导出 T 的类型并实例化模板。

**模板的显式实例化（Explicit Instantiation）**

在某些情况下，程序员可以显式地请求编译器实例化某个模板。例如，通过 template<> 或 extern 来显式实例化模板。

```cpp
template <typename T>
void print(T value) {
    std::cout << value << std::endl;
}

// 显式实例化
template void print<int>(int);   // 实例化 print<int>
template void print<double>(double); // 实例化 print<double>
```

### 2.51.2 模板实例化的过程

模板实例化的过程通常包括以下几个步骤：

**模板定义**

模板本身仅是一个模板蓝图，不包含实际代码，编译器无法生成机器代码。只有在模板被实例化时，编译器才会为模板生成代码。

```cpp
template <typename T>
void print(T value) {
    std::cout << value << std::endl;
}
```

**模板参数推导**

当模板函数或类被调用时，编译器会根据传递的实参推导出模板参数的类型。

```cpp
print(5);   // 编译器推导出 T 为 int
print(3.14); // 编译器推导出 T 为 double
```

**实例化模板**

编译器根据推导出的模板参数类型生成对应类型的代码，称为模板实例化。

```cpp
void print<int>(int value) { // 实例化 print<int>
    std::cout << value << std::endl;
}

void print<double>(double value) { // 实例化 print<double>
    std::cout << value << std::endl;
}
```

**生成对象代码**

编译器为每个模板实例生成目标代码，然后将其编译成二进制形式。

### 2.51.3 延迟实例化（Lazy Instantiation）

C++ 模板实例化通常是**延迟实例化**的，意味着只有在实际使用某个模板时，编译器才会实例化它。这种机制被称为“懒惰实例化”或“延迟实例化”。这种方式减少了不必要的实例化，节省了编译时间。

例如，以下代码中的 MyClass<int> 和 MyClass<double> 只会在使用时被实例化：

```cpp

int main() {
    MyClass<int> obj1(5);   // 只有在这里才实例化 MyClass<int>
    MyClass<double> obj2(3.14); // 只有在这里才实例化 MyClass<double>
}
```

### 2.51.4 模板实例化的优化

- **避免重复实例化**：如果模板实例化的类型在多个文件中被使用，编译器会多次实例化相同的模板，为了避免重复实例化，可以使用**显式实例化**，将实例化的定义放在一个源文件中，其他地方只引用它。

```cpp
// 在一个源文件中显式实例化
template class MyClass<int>;

// 在其他源文件中，只需声明
extern template class MyClass<int>;
```

- **模板实例化的显式控制**：在一些情况下，程序员可以显式控制模板实例化。例如，可以通过 extern template 显式声明模板实例化，告诉编译器某个模板实例已经在其他地方定义过了。

### 2.51.5 总结

模板实例化是模板在 C++ 中的核心机制，发生在编译时。当模板被调用时，编译器根据传递的类型参数生成具体的模板代码。实例化的时机可以通过显式调用模板、类型推导或显式实例化控制。

- **显式实例化**：模板函数或类实例化可以通过 template 显式指定。
- **延迟实例化**：模板通常是延迟实例化的，只有在实际使用时才会生成代码。

模板实例化提高了代码的复用性和灵活性，并且通过优化机制减少了编译时间和冗余代码。

## 2.52 被隐藏的基类函数如何调用？

### 2.52.1 问题背景

当派生类定义了与基类同名的成员（函数或变量）时，基类成员在派生类作用域内 **被隐藏（Hiding）**。

- 隐藏不依赖参数是否相同
- 隐藏不会产生多态

```cpp
class Base {
public:
    void func(int x) { cout << "Base: " << x << endl; }
};

class Derived : public Base {
public:
    void func(double y) { cout << "Derived: " << y << endl; }
};
```

- Derived::func(double) 隐藏了 Base::func(int)
- Derived 内直接调用 func(10) 会报错或匹配不到

### 2.52.2 调用被隐藏的基类函数方法

**（1）使用 作用域运算符**

```cpp
Derived d;
d.Base::func(10);  // 调用基类函数
```

- 明确指定作用域
- 可以访问被隐藏的函数

**（2）使用 using 声明（推荐）**

```cpp
class Derived : public Base {
public:
    using Base::func;   // 将基类 func 引入派生类作用域
    void func(double y) { cout << "Derived: " << y << endl; }
};

Derived d;
d.func(10);   // 调用 Base::func(int)
d.func(3.14); // 调用 Derived::func(double)
```

- 通过 using，基类函数恢复可见性
- 允许函数重载共存

### 2.52.3 注意事项

1. **隐藏函数不会多态**
2. **作用域运算符和 using** 仅改变可见性，不改变虚函数多态行为
3. **静态成员函数和成员变量**也可能被隐藏，用法相同

### 2.52.4 面试高频总结句

> 被隐藏的基类函数可以通过作用域运算符 Base::func() 或 using Base::func; 在派生类中访问。
> 同名即隐藏，用 Base:: 或 using 把基类函数叫回来。

## 2.53 C++11 中 typename 与 template 的用法？

在 C++11 中，typename 和 template 是两个重要的关键字，通常用来处理模板中的类型依赖和模板模板参数。虽然它们有时看起来相似，但它们各自有不同的用法和含义。

### 2.53.1 typename 的用法

typename 关键字的作用是指示编译器某个名称是类型名称。在模板编程中，它主要用于以下两个场景：

**用于类型依赖的名字**

当模板中的某个名字依赖于模板参数时，必须使用 typename 来告诉编译器这个名字是一个类型。

```cpp
template <typename T>
class MyClass {
public:
    typename T::value_type value; // 依赖模板参数 T 的类型
};
```

- 在上面的代码中，T::value_type 依赖于模板参数 T，因此我们需要使用 typename 来告诉编译器这是一个类型，而不是其他类型的成员。

**用于嵌套类型声明**

在模板中，typename 也可以用于声明嵌套类型。尤其是在模板类中，访问嵌套类型时，必须显式地使用 typename 来指明该成员是一个类型。

```cpp
template <typename T>
class MyClass {
public:
    typename T::nested_type *ptr; // 这里 T::nested_type 是类型
};
```

**示例代码：**

```cpp
#include <iostream>
#include <vector>
using namespace std;

template <typename T>
void printFirstElement(const T& container) {
    typename T::const_iterator it = container.begin(); // 使用 typename 来指定迭代器类型
    cout << *it << endl;
}

int main() {
    vector<int> vec = {1, 2, 3};
    printFirstElement(vec);  // 输出 1
    return 0;
}
```

在此代码中，typename 用于指定 T::const_iterator 是类型，而 T 是一个容器类型（如 std::vector）。

### 2.53.2 template 的用法

在 C++11 中，template 关键字用于指示一个模板参数是一个模板。它通常与 typename 结合使用，解决模板模板参数的问题。

**模板模板参数（Template Template Parameters）**

C++11 引入了模板模板参数的概念，这使得你可以将模板本身作为另一个模板的参数。

```cpp
template <typename T>
class MyClass {
public:
    T value;
};

template <template <typename> class Container>
class Wrapper {
public:
    Container<int> c;  // 这里 Container 是一个模板
```

- 在上面的例子中，Wrapper 类接受一个模板模板参数 Container，它本身是一个模板（如 std::vector 或 std::list）。

**示例代码：**

```cpp
#include <iostream>
#include <vector>

template <typename T>
class MyClass {
public:
    T value;
};

template <template <typename> class Container>
class Wrapper {
public:
    Container<int> c;  // c 是一个 int 类型的容器
    Wrapper() {
        c.push_back(10);
        std::cout << c[0] << std::endl;  // 输出 10
    }
};

int main() {
    Wrapper<std::vector> wrapper;  // 将 std::vector 作为模板模板参数
    return 0;
}
```

- 在此例中，Wrapper 使用模板模板参数 Container，然后实例化为 std::vector<int>。

**template 与 typename 结合使用的场景**

通常，template 和 typename 结合使用，用来声明模板模板参数。

```cpp
template <template <typename> class Container>
void printContainer(const Container<int>& c) {
    std::cout << c[0] << std::endl;  // 输出容器的第一个元素
}
```

在上面的代码中，Container 是一个模板（例如 std::vector 或 std::list），int 是 Container 的类型参数。

### 2.53.3 typename 与 template 关键字的区别

|特性|typename|template|
|---|---|---|
|主要用途|主要用于表示某个名称是类型，解决类型依赖问题|用于模板模板参数，指示参数是模板类型|
|常见使用场景|1. 访问模板中依赖于模板参数的类型 2. 声明嵌套类型|1. 作为模板模板参数传递模板类型 2. 声明并实例化模板模板参数|
|实例|`typename T::value_type`|`template <typename T> class Wrapper<template <typename> class Container>`|
|作用|用于指示编译器某个名称是类型|用于声明接受模板类型作为参数的模板|

### 2.53.4 总结

- typename 关键字用于指示模板中的某个名字是类型，特别是在处理模板参数依赖时。它主要用于声明类型依赖、嵌套类型以及迭代器类型等。
- template 关键字用于声明模板模板参数，允许你将模板作为参数传递给另一个模板，从而实现更灵活的模板编程。

这两个关键字在 C++11 中的作用有很大的区别，typename 主要用于类型声明，而 template 用于更复杂的模板模板参数，能使模板更加灵活和强大。

## 2.54 静态绑定与动态绑定

### 2.54.1 定义

- **静态绑定（Static Binding / Early Binding）**
    - 函数调用在 **编译期就确定**
    - 典型场景：普通函数、非虚函数、模板函数
    - 优点：效率高
    - 缺点：不支持运行时多态
- **动态绑定（Dynamic Binding / Late Binding）**
    - 函数调用在 **运行期根据对象实际类型确定**
    - 典型场景：虚函数
    - 优点：支持运行时多态
    - 缺点：开销稍大（vtable 间接寻址）

### 2.54.2 示例说明

**（1）静态绑定**

```cpp
class Base {
public:
    void func() { cout << "Base func" << endl; }
};
```

**（2）动态绑定**

```cpp
class Base {
public:
    virtual void func() { cout << "Base func" << endl; }
};

class Derived : public Base {
public:
    void func() override { cout << "Derived func" << endl; }
};

Base* p = new Derived();
p->func();  // 输出 Derived func，运行期确定调用 Derived::func
```

### 2.54.3 实现机制

- **典型用法**：缓存、调试计数器、延迟初始化等
- **示例**：

```cpp
#include <iostream>
using namespace std;

class Test {
private:
    mutable int counter; // 即使在 const 对象中也能改
public:
    Test() : counter(0) {}
    void increment() const {
        counter++; // 合法
    }
    int getCounter() const { return counter; }
};

int main() {
    const Test t;
    t.increment();
    cout << t.getCounter() << endl; // 输出 1
}
```

|类型|静态绑定|动态绑定|
|---|---|---|
|机制|编译期可确定被调实体，通常生成直接调用|按对象动态类型选择最终覆盖函数；主流 ABI 通常通过 vptr/vtable 实现|

### 2.54.4 影响因素

- **表达式的静态类型与值类别**：普通非虚调用通常由静态类型决定。
- **是否通过指针/引用进行虚调用**：对多态类的虚函数调用通常发生动态绑定；使用限定名（如 `obj.Base::func()`）会抑制虚分派。
- **构造与析构阶段**：虚调用只分派到当前正在构造/析构的类层次，不会调用尚未构造或已经析构的更派生覆盖。
- **编译器去虚化**：当编译器能证明动态类型时，可以在保持语义不变的前提下将虚调用优化为直接调用。

### 2.54.5 面试高频总结句

> 非虚函数、重载选择等通常在编译期静态绑定；通过多态类指针或引用进行的虚函数调用通常在运行期按动态类型分派。VTable/VPtr 是主流实现方式，不是标准强制布局。

## 2.55 mutable 和 volatile

### 2.55.1 mutable

- **作用范围**：**类的成员变量**（不能修饰全局变量或局部变量）
- **目的**：突破 const 限制，让特定成员可以在 const 对象中被修改
- **典型用法**：缓存、调试计数器、延迟初始化等
- **示例**：

```cpp
#include <iostream>
using namespace std;

class Test {
private:
    mutable int counter; // 即使在 const 对象中也能改
public:
    Test() : counter(0) {}
    void increment() const {
        counter++; // 合法
    }
    int getCounter() const { return counter; }
};

int main() {
    const Test t;
    t.increment();
    cout << t.getCounter() << endl; // 输出 1
}
```

### 2.55.2 volatile

- **作用范围**：**所有变量类型**（全局、局部、类成员、指针等）
- **目的**：告诉编译器对该对象的访问具有可观察副作用，不能随意消除或合并访问
- **典型用法**：内存映射硬件寄存器，以及实现定义允许的信号处理场景；`volatile` 不提供线程同步或原子性，多线程共享数据应使用 `std::atomic` 或互斥锁
- **示例**：

```cpp
volatile int flag = 0;

int main() {
    while (flag == 0) {
        // 因为是 volatile，编译器会每次重新读取 flag
    }
    cout << "Flag changed!" << endl;
}
```

### 2.55.3 对比总结

|特性|mutable|volatile|
|---|---|---|
|修饰范围|类成员变量|所有变量|
|作用点|允许 `const` 成员函数修改该成员|使对该对象的访问成为可观察副作用，不能任意省略或合并|
|典型场景|缓存、统计、调试信息|硬件寄存器、特定信号处理场景|
|与 const 关系|破坏 const 对象的不可变性|可以和 const 共存（const volatile）|
|编译器行为影响|改变类型系统中的 const 约束，不等于关闭优化|约束对该 volatile 对象的访问；不等于全面禁止优化或提供 CPU 内存屏障|

## 2.56 内存泄漏可能发生的情况

内存泄漏是指程序在运行过程中动态分配的内存未被正确释放，导致系统的内存逐渐耗尽。内存泄漏可能导致程序性能下降、崩溃甚至系统死机。以下是一些常见的内存泄漏发生的情况：

### 2.56.1 未释放动态分配的内存

最常见的内存泄漏原因是动态分配内存后没有正确释放，尤其是在 malloc、new 等内存分配函数调用后，忘记使用 free 或 delete 释放内存。

**示例：**

```cpp
void func() {
    int* ptr = new int[10]; // 动态分配内存
    // 忘记释放内存
}
```

在上述代码中，new 分配了 10 个整数的内存，但没有相应的 delete[] 来释放它。

### 2.56.2 提前丢失最后一个所有者指针

如果覆盖或清空了指向动态分配块的最后一个指针而没有先释放该块，就会失去释放它的途径并造成泄漏。内存已经释放但指针仍指向原地址则叫“悬空指针”，属于另一类生命周期错误，本身不是内存泄漏。

**示例：**

```cpp
void func() {
    int* ptr = new int[10];  // 动态分配内存
    ptr = nullptr;            // 改变指针的值，原先分配的内存无法释放
}
```

这里，ptr 在指向动态分配的内存后被设置为 nullptr，导致原本分配的内存丢失，无法释放，从而引发内存泄漏。

### 2.56.3 异常抛出后忘记释放内存

在程序中使用动态内存分配时，如果抛出异常而没有在异常处理机制中释放已经分配的内存，也会导致内存泄漏。这通常发生在异常发生后，程序无法正常执行到释放内存的代码部分。

**示例：**

```cpp
void func() {
    int* ptr = new int[10];
    throw std::runtime_error("Exception"); // 异常抛出
    delete[] ptr; // 这行代码永远不会被执行，内存未被释放
}
```

在这种情况下，delete[] ptr 语句不会被执行，导致内存泄漏。可以使用 try-catch 块来避免这种情况。

### 2.56.4 忘记释放资源对象

某些类的成员变量可能会持有动态分配的内存，如果类的析构函数没有正确释放这些资源，会导致内存泄漏。

**示例：**

```cpp
class MyClass {
private:
    int* ptr;
public:
    MyClass() {
        ptr = new int[10];
    }
    // 没有析构函数释放内存
};
```

在上述例子中，MyClass 类没有析构函数来释放成员变量 ptr 指向的内存，导致内存泄漏。

### 2.56.5 循环引用导致内存无法释放（特别是在智能指针中）

在使用智能指针（如 std::shared_ptr）时，若存在两个或多个对象相互持有对方的 shared_ptr，会导致循环引用，最终使得内存无法被释放。

**示例：**

```cpp
#include <memory>

class A;
class B;

class A {
public:
    std::shared_ptr<B> b;
};

class B {
public:
    std::shared_ptr<A> a;
};

void func() {
    std::shared_ptr<A> a = std::make_shared<A>();
    std::shared_ptr<B> b = std::make_shared<B>();

    a->b = b;
    b->a = a;  // 循环引用
}
```

此时，a 和 b 相互引用，导致它们的引用计数永远不为零，从而无法释放内存，产生内存泄漏。

### 2.56.6 容器中的元素未被正确释放

容器（如 std::vector、std::map 等）中存储的是指针类型的元素时，如果没有正确管理这些指针，也可能导致内存泄漏。

**示例：**

```cpp
std::vector<int*> vec;

void func() {
    vec.push_back(new int(10));
    // 未释放内存
}
```

在上述代码中，std::vector 存储了动态分配的指针，但在销毁容器时并没有释放这些指针指向的内存，导致内存泄漏。

### 2.56.7 手动内存管理与智能指针混合使用

手动使用 new 和 delete 与智能指针（如 std::unique_ptr 或 std::shared_ptr）混合使用时，如果没有正确配合，也可能发生内存泄漏。

**示例：**

```cpp
std::unique_ptr<int> ptr1;
int* ptr2 = new int(10);

void func() {
    ptr1 = std::make_unique<int>(20);
    ptr2 = nullptr; // ptr2 没有释放，导致内存泄漏
}
```

在上述代码中，ptr2 被设为 nullptr，但是没有用 delete 来释放 new 分配的内存，从而发生内存泄漏。

```cpp
class MemoryPool {
public:
    void* allocate(size_t size) {
        // 分配内存
    }
    void deallocate(void* ptr) {
        // 错误的释放机制
    }
};
```

如果内存池没有正确管理内存释放的逻辑，或者分配和释放不匹配，也会导致内存泄漏。

### 2.56.8 内存池管理不当

内存池如果没有正确记录块的所有权和状态，或者出现重复归还、越界写、分配/释放接口不匹配，也会造成泄漏或内存破坏。应为分配路径和所有失败路径建立成对的归还规则，并用边界检查和统计信息监控池状态。

### 2.56.9 总结

内存泄漏通常发生在以下几种情况：

- 动态内存分配后未释放内存
- 指针丢失，导致原本分配的内存无法访问和释放
- 异常发生时未释放内存
- 类成员没有正确释放动态分配的内存
- 循环引用导致智能指针无法释放内存
- 容器存储指针类型的元素时未正确管理内存
- 手动内存管理与智能指针混合使用时不当
- 内存池管理不当

要避免内存泄漏，可以采用以下方法：

- 使用智能指针（如 std::unique_ptr、std::shared_ptr）自动管理内存
- 在使用 new 或 malloc 分配内存后，确保在不再使用时调用 delete 或 free
- 使用 RAII（资源获取即初始化）原则，确保资源在对象生命周期结束时自动释放
- 使用工具如 Valgrind 来检测内存泄漏

## 2.57 栈溢出的常见原因

### 2.57.1 栈溢出定义

**栈溢出（Stack Overflow）** 是指程序在运行时，调用栈超出其分配的空间，导致程序异常或崩溃。

- 栈用于存放：函数局部变量、函数参数、返回地址等
- 栈空间有限（通常几百 KB 到几 MB）

### 2.57.2 常见原因

**（1）无限递归**

```cpp
void func() { func(); }  // 无限递归
```

- 每次调用函数，栈帧增加
- 递归没有终止条件 → 栈空间耗尽

**（2）局部变量过大**

```c++
void func() {
    int arr[1000000]; // 太大导致栈溢出
}
```

- 栈空间有限，数组、结构体过大
- 大对象应放在堆（new / malloc）

**（3）函数调用层级过深**

```c++
void func1() { func2(); }
void func2() { func3(); }
// 多层函数调用，栈帧累积过多
```

- 多层嵌套函数调用
- 栈帧累积 → 栈空间耗尽

**（4）错误的指针操作**

- 栈指针被错误覆盖或越界访问
- 修改返回地址导致栈异常
- 常见于 C/C++ 未初始化指针、数组越界等

### 2.57.3 避免方法

- 为递归设置可靠的终止条件，并限制最大递归深度。
- 避免在栈上分配超大数组或对象，可改用堆、静态存储或分块处理。
- 减少不必要的深层调用，在嵌入式/线程环境中合理配置栈大小。
- 使用编译器栈保护、静态分析和运行时工具检查越界或栈破坏。

## 2.58 为什么要字节对齐？

### 2.58.1 定义

**字节对齐（Byte Alignment / Data Alignment）** 是指在内存中按 **特定边界存放数据**，使数据首地址为其类型大小的整数倍或特定规则。

> 更准确地说，地址应是该类型**对齐要求** `alignof(T)` 的整数倍，该要求不一定等于 `sizeof(T)`。

- 目的是提高访问效率，符合 CPU 对内存访问的要求

### 2.58.2 为什么要字节对齐

**（1）提高访问效率**

- CPU 读取内存通常按字（word）为单位
- 未对齐的数据可能需要 **多次内存访问**
- 对齐后，CPU 可一次读取完整数据，提高效率

**（2）满足硬件要求**

- 某些 CPU 不支持非对齐访问
- 非对齐访问可能导致 **硬件异常或性能下降**

**（3）结构体访问优化**

- 编译器通过在结构体成员间插入 **填充字节（padding）**
- 保证每个成员按其对齐规则存放

### 2.58.3 示例

```cpp
struct A {
    char c;   // 1 字节
    int i;    // 4 字节
};
```

- 内存布局可能是：

| 地址 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 数据 | c | pad | pad | pad | i | i | i | i |

- int 对齐到 4 字节边界，前面填充 3 字节

### 2.58.4 对齐规则（常见 ABI）

1. **基本类型对齐**：由目标 ABI 和编译器决定，可用 `alignof(T)` 查询。
2. **结构体对齐**：默认情况下，对象大小通常补齐到结构体对齐量的整数倍，以便数组中每个元素都正确对齐。
3. **手动控制**：标准 C++ 提供 `alignas`；`#pragma pack` 和 `__attribute__((packed))` 是常见实现扩展。

### 2.58.5 面试高频总结句

> 字节对齐是为了保证 CPU 高效访问内存，避免非对齐访问异常，同时便于结构体成员按对齐规则存储。

- **对齐规则**：
    a. 成员变量的地址满足其有效对齐要求（可由 ABI、`alignas` 或实现扩展影响）
    b. 结构体总大小是最大成员对齐数的整数倍
    c. 编译器在必要时添加填充字节

## 2.59 字节对齐的实现

### 2.59.1 基本原则

字节对齐通过 **在变量或结构体成员之间插入填充字节（padding）** 来实现，使每个成员的地址满足其对齐要求：

- **对齐规则**：
    a. 成员变量的地址满足其有效对齐要求

### 2.59.2 示例说明

```cpp
struct A {
    char c;  // 1 字节
    int i;   // 4 字节
    short s; // 2 字节
};
```

- 假设对齐按 **4 字节边界**：
- **填充字节（pad）**确保 int 和 short 对齐
- **结构体大小**为 12（4 的倍数），满足最大成员 int 的对齐要求

### 2.59.3 控制对齐方式

**（1）编译器默认对齐**

- 大多数编译器按 CPU 平台默认对齐
- 常用 sizeof 查看结构体实际大小

**（2）手动控制对齐**

- **GCC / Clang**：

```cpp
struct __attribute__((packed)) B {
    char c;
    int i;
};
```

- **MSVC**：

```cpp
#pragma pack(1)
struct B {
    char c;
    int i;
};
#pragma pack()  // 恢复默认
```

- `packed` 或 `#pragma pack(1)` 通常减少成员间填充，不是“取消 CPU 对齐要求”。它们可能产生未对齐成员，直接访问可降低性能或在部分平台异常；与外部字节布局交换时还要处理端序，常用 `memcpy` 或显式序列化避免未对齐解引用。

### 2.59.4 对齐与性能

1. 对齐访问 → CPU 一次读取完成，效率高
2. 非对齐访问 → 可能需要多次内存访问或触发异常
3. 结构体过度对齐 → 占用额外内存，空间浪费

### 2.59.5 面试高频总结句

> 字节对齐通过填充字节实现，让每个成员按类型对齐，提高 CPU 访问效率，同时结构体总大小为最大对齐数的倍数。
> 字节对齐 = 成员地址对齐 + 填充字节 + 结构体大小对齐，兼顾效率和内存布局。

## 2.60 static静态成员变量

### 2.60.1 定义

**静态成员变量（Static Data Member）** 是类的 **所有对象共享** 的变量，而不是每个对象独有。

```cpp
class A {
public:
    static int count;  // 静态成员变量
};
```

- 属于类，不属于对象
- 所有对象访问同一份内存

### 2.60.2 特点

1. **共享性**
    - 所有对象共享一份静态成员
    - 修改一个对象的值，其他对象看到的也会改变
2. **存储位置**
    - 具有静态存储期，存储位置由编译器和链接器决定
    - 生存期贯穿整个程序执行
3. **访问方式**
    - 通过类名访问（推荐）
    - 也可通过对象访问，但不推荐

```cpp
A::count = 10;  // 推荐
```

### 2.60.3 静态成员变量的初始化

- 传统静态成员通常在类外提供一个定义。C++17 起可将其声明为 `inline static` 并在类内定义/初始化；`constexpr` 静态数据成员也隐式为 `inline`。

```cpp
int A::count = 0;
```

```cpp
class A {
public:
    static int count;
    A() { count++; }
};

int A::count = 0;

int main() {
    A a1, a2;
    cout << A::count << endl;  // 输出 2
}
```

- 每次构造对象，count 自增
- 静态成员变量在所有对象间共享

### 2.60.4 注意事项

1. 类内初始化规则随标准版本不同：早期主要支持特定 `const` 整型/枚举静态成员；C++17 的 `inline static` 可直接在类内定义。
2. 静态成员函数没有 `this` 指针，因而不能不经对象直接访问非静态成员；若显式拿到某个对象/指针，仍可按访问权限访问其成员。
3. 静态成员变量可用于**计数、共享资源、全局状态**

### 2.60.5 面试高频总结句

> 静态成员变量属于类共享所有对象，存储在静态区，生命周期贯穿程序执行，可用于计数或共享数据。
> static 成员变量 = 类的全局共享变量，不随对象而异。

## 2.61 静态成员函数与普通成员函数的区别?

### 2.61.1 定义

- **静态成员函数（static member function）**
    - 属于类本身，不依赖于对象
    - 可以访问 **静态成员变量**，不能访问非静态成员
- **普通成员函数（non-static member function）**
    - 属于对象，需要通过对象调用
    - 可以访问 **对象的所有成员变量**

### 2.61.2 区别总结

```cpp
class A {
public:
    static int count;
    int id;

    static void printCount() { cout << count << endl; }  // 静态成员函数
    void printId() { cout << id << endl; }               // 普通成员函数
};

int A::count = 0;

int main() {
    A a;
    a.id = 100;

    A::printCount(); // 调用静态成员函数
    a.printId();     // 调用普通成员函数
}
```

|特性|静态成员函数|普通成员函数|
|---|---|---|
|所属|类|对象|
|this 指针|没有|有，指向当前对象|
|成员访问|无 `this`，可直接访问静态成员；通过显式对象也可访问非静态成员|可直接访问当前对象的非静态成员和类的静态成员|
|调用方式|类名或对象都可调用（推荐类名）|必须通过对象调用|
|函数代码存续期|不随对象创建/销毁|同样不随对象创建/销毁；只是调用需要对象|

### 2.61.3 使用场景

1. **静态成员函数**
    - 访问共享数据或工具函数
    - 与对象无关
2. **普通成员函数**
    - 操作对象状态
    - 与对象数据绑定

### 2.61.4 面试高频总结句

> 静态成员函数属于类，不依赖对象，不能访问非静态成员；普通成员函数属于对象，有 this 指针，可访问对象所有成员。
> static 函数是“类的函数”，普通函数是“对象的函数”。

## 2.62 静态变量的初始化时机

### 2.62.1 定义

**静态变量（static variable）** 包括：

1. **全局静态变量**（在文件作用域的 static）
2. **类的静态成员变量**
3. **函数内的静态局部变量**
- 存储在 **静态存储区**，生命周期贯穿整个程序

### 2.62.2 初始化时机

|静态变量类型|初始化时机|特点|
|---|---|---|
|非局部静态存储期对象（包括类静态数据成员）|先零初始化，再进行常量初始化或动态初始化；动态初始化的跨翻译单元顺序可能不确定|内置类型未显式初始化时会零初始化；复杂构造不宜笼统概括为全部在 `main` 前完成|
|块作用域静态局部变量|第一次执行到声明时初始化（若初始化抛异常，后续进入可重试）|只成功初始化一次；C++11 起该初始化保证线程安全|

### 2.62.3 示例

**（1）全局静态变量**

```cpp
static int g_val = 5;  // 常量初始化，通常在程序启动前完成
```

**（2）类静态成员变量**

```cpp
class A {
public:
    static int count;
};
int A::count = 0;  // 零/常量初始化
```

**（3）函数内静态局部变量**

```cpp
void func() {
    static int x = 10; // 第一次调用 func 时初始化
    x++;
    cout << x << endl;
}

int main() {
    func(); // 输出 11
    func(); // 输出 12
}
```

### 2.62.4 注意事项

1. **非局部静态存储期对象**先零/常量初始化；需要运行代码的动态初始化还要考虑顺序和延迟初始化规则。
2. **函数内静态变量**延迟到第一次执行其声明时初始化，但对象的存储期仍贯穿整个程序。
3. **多线程环境**：C++11 以后，函数内静态局部变量初始化是线程安全的

### 2.62.5 面试高频总结句

> 静态存储期对象的存储期贯穿程序；非局部对象遵循静态/动态初始化规则，块作用域静态对象在第一次执行到声明时完成初始化。

## 2.63 typeid 与 RTTI 的用途

### 2.63.1 RTTI（运行时类型识别）简介

RTTI（Run-Time Type Information，运行时类型信息）是 C++ 提供的一项机制，它允许在程序运行时确定对象的类型。RTTI 可以在程序运行时查询对象的实际类型，从而使程序在执行期间更加灵活。RTTI 通过 typeid 和 dynamic_cast 来实现。

### 2.63.2 typeid 的用法

typeid 是 C++ 提供的一个操作符，它用于获取对象的类型信息。通过 typeid，可以在运行时获取一个对象的类型，并且能够与类型进行比较。

- **用法**：typeid(expression)，expression 是一个对象或者指针。
- **返回值**：typeid 返回一个类型为 const std::type_info& 的对象，该对象包含了类型的信息。

```cpp
#include <iostream>
#include <typeinfo>

class Base { public: virtual ~Base() = default; };
class Derived : public Base { };

int main() {
    Base* basePtr = new Derived();

    // 使用 typeid 获取实际类型
    std::cout << "basePtr 的实际类型: " << typeid(*basePtr).name() << std::endl;

    // 使用 typeid 和基类指针进行比较
    if (typeid(*basePtr) == typeid(Derived)) {
        std::cout << "basePtr 实际上是 Derived 类型" << std::endl;
    }

    delete basePtr;
    return 0;
}
```

在这个例子中，`typeid(*basePtr)` 返回 Derived 的类型信息。只有当表达式是多态类型（含至少一个虚函数）的左值或解引用结果时，`typeid` 才报告动态类型；`typeid(basePtr)` 得到的仍是指针的静态类型。

**与指针和引用结合使用**

如果使用 typeid 来操作指针或引用时，typeid 会根据指向对象的实际类型来返回类型信息，而不是指针或引用的静态类型。

- 对于指针：`typeid(ptr)` 返回指针类型；要查询所指对象，应使用 `typeid(*ptr)`，且基类必须是多态类型。
- 对于引用：当引用绑定到多态对象时，`typeid(ref)` 可返回对象的动态类型；否则返回表达式的静态类型。

```cpp
Base* basePtr = new Derived();
std::cout << "basePtr 的类型: " << typeid(*basePtr).name() << std::endl;  // 输出 Derived 类型
```

**typeid 和多态的关系**

如果使用 typeid 来操作多态类（即类中有虚函数），那么 typeid 会根据对象的动态类型来返回实际的类型，而不仅仅是对象指针或引用的静态类型。

### 2.63.3 RTTI 的作用与用途

RTTI 主要用于以下两个方面：

**多态类型识别**

在使用继承和多态的情况下，RTTI 可以帮助程序在运行时识别对象的实际类型，而不仅仅依赖于指针或引用的静态类型。

**示例：**

```cpp
Base* basePtr = new Derived();

    // 使用 typeid 判断动态类型
    if (typeid(*basePtr) == typeid(Derived)) {
        std::cout << "basePtr 实际是 Derived 类型" << std::endl;
    }

    delete basePtr;
    return 0;
}
```

- 在此例中，尽管 basePtr 是 Base* 类型，但使用 typeid(*basePtr) 判断它实际指向的是 Derived 类型。

**动态类型识别和类型比较**

typeid 可以用来检查一个对象是否是某个特定类型的实例。它使得程序能够在运行时判断某个类型是否符合某种类型或其派生类型。

**示例：**

```cpp
class Base { public: virtual ~Base() = default; };
class Derived : public Base { };

void checkType(Base* basePtr) {
    if (typeid(*basePtr) == typeid(Derived)) {
        std::cout << "这是一个 Derived 类型的对象" << std::endl;
    } else {
        std::cout << "这不是 Derived 类型的对象" << std::endl;
    }
}

int main() {
    Base* basePtr = new Derived();
    checkType(basePtr);
    delete basePtr;
    return 0;
}
```

- 在此示例中，checkType 函数使用 typeid 来判断 basePtr 指向的对象是否是 Derived 类型。

### 2.63.4 typeid 与类型信息的获取

typeid 返回的类型信息是 std::type_info 类型的对象，包含了对象的类型信息。通过 std::type_info 类，程序可以获取类型的名字、比较类型等信息。

**type_info 的常见成员**

- name()：返回类型的名称，通常是一个字符串。
- hash_code()：返回类型的哈希值，通常用于类型比较。
- operator==：可以用于比较两个 type_info 对象，判断它们是否表示相同的类型。

```cpp
#include <iostream>
#include <typeinfo>

class Base { public: virtual ~Base() = default; };
class Derived : public Base { };

int main() {
    Base* basePtr = new Derived();

    if (typeid(*basePtr) == typeid(Derived)) {
        std::cout << "类型匹配，typeid(*basePtr) 的 name() 为： " << typeid(*basePtr).name() << std::endl;
    }

    delete basePtr;
    return 0;
}
```

### 2.63.5 typeid 与非虚拟函数的关系

- `typeid` 是否报告动态类型与“当前函数是否为虚函数”无关，取决于其操作数是否为多态类型的左值或解引用表达式。

### 2.63.6 总结

- typeid 是 C++ 提供的用于在运行时获取类型信息的工具，它基于 RTTI 机制工作。
- **用途**：typeid 主要用于多态和动态类型识别，帮助程序在运行时获取对象的真实类型，特别是在有虚函数的情况下。
- **typeid 和 dynamic_cast**：二者都依赖 RTTI，可用于运行时类型识别；需要类型分支时通常优先考虑虚函数多态。
- std::type_info：typeid 返回一个 std::type_info 对象，允许程序进行类型比较和访问类型名称。

## 2.64 原子操作（atomic）

原子操作（Atomic Operation）对其他线程表现为不可分割的访问：其他线程不会观察到该原子对象一次操作的中间状态。这并不意味着 CPU 或操作系统绝对不能中断执行流，也不意味着一个原子操作能自动保护多个对象组成的复合不变式。

### 2.64.1 原子操作的特点

1. **修改顺序**：对同一原子对象的修改具有全体线程一致的顺序，不会产生操作到一半的可观察值。
2. **无数据竞争的单对象访问**：多线程可以并发访问同一原子对象，但算法整体是否线程安全仍取决于逻辑和所选内存序。
3. **内存序**：默认为 `memory_order_seq_cst`；也可选择 acquire/release/relaxed 等较弱顺序，但需正确建立线程间的 synchronizes-with / happens-before 关系。

### 2.64.2 原子操作的应用

1. **多线程中的同步**：原子变量可用来实现标志、计数和底层同步原语。它们不需要在源代码中显式使用互斥锁，但实现不一定 lock-free，也不保证总比互斥锁更快。
2. **并发数据结构**：许多并发数据结构（如无锁队列、无锁栈等）依赖于原子操作来确保数据结构在多线程环境下的一致性和安全性。
3. **计数器和标志位**：原子操作广泛应用于线程安全的计数器和标志位管理。通过原子操作，多个线程可以安全地**增减计数器，或修改标志位**，而不需要锁定其他线程的访问。

### 2.64.3 常见的原子操作

1. **原子加法/减法**：对支持的 `std::atomic` 整数类型可使用 `fetch_add`、`fetch_sub` 或相应运算符，完成单个不可分割的读-改-写操作。
2. **比较并交换**（CAS）：将原子对象与预期值比较，相等时写入新值，不等时把实际值写回 `expected`；“比较+条件写入”对该原子对象是一个原子操作。CAS 可用于无锁算法，但正确性还需要处理重试、内存序和 ABA 等问题。
3. **原子交换**（Atomic Exchange）：`exchange` 用新值替换一个原子对象的旧值，并返回旧值。

**基本原子操作示例**

```cpp
#include <iostream>
#include <thread>
#include <atomic>
using namespace std;

atomic<int> counter(0); // 原子变量，初始化为 0

void increment() {
    for (int i = 0; i < 1000000; i++) {
        counter++; // 原子自增
    }
}

int main() {
    thread t1(increment);
    thread t2(increment);

    t1.join();
    t2.join();

    cout << "Final counter: " << counter << endl; // 一定是 2000000
}
```

**常用原子操作方法**

```cpp
atomic<int> x(0);

// 赋值
x.store(10);    // 原子写
int v = x.load(); // 原子读

// 原子加减
x.fetch_add(5); // x = x + 5
x.fetch_sub(3); // x = x - 3

// 原子交换
int old = x.exchange(100); // 返回旧值，把 x 设为 100

// 原子比较并交换
int expected = 100;
x.compare_exchange_strong(expected, 200);
// 如果 x == expected，则 x 设为 200
// 否则 expected 变成 x 的当前值
```

## 2.65 友元

### 2.65.1 定义

- **友元函数（Friend Function）**

### 2.65.2 语法

**（1）友元函数**

```cpp
class A {
private:
    int x;
public:
    A(int val) : x(val) {}
    friend void printX(const A& a);  // 声明友元函数
};

void printX(const A& a) {
    std::cout << a.x << std::endl;   // 可访问私有成员
}
```

**（2）友元类**

```cpp
class B;  // 前向声明

class A {
private:
    int x;
public:
    A(int val) : x(val) {}
    friend class B;  // 声明 B 为友元类
};

class B {
public:
    void showX(const A& a) {
        std::cout << a.x << std::endl;  // 可访问 A 的私有成员
    }
};
```

### 2.65.3 特点

1. **破坏封装性**：友元函数/类可以访问私有成员
2. **非成员函数也可访问私有成员**
3. **单向性**：
    - A 声明 B 为友元 → B 可访问 A 私有成员
    - B 并不自动成为 A 的普通成员
4. **非继承性**：友元关系不继承给子类

### 2.65.4 使用场景

- 操作两个类的私有数据

> 友元函数或类可以访问类的私有成员，用于实现紧密协作或运算符重载，但会破坏封装性。
> 友元 = “特权访问”，非成员函数或类也能访问私有成员。

## 2.66 类的大小

### 2.66.1 影响类大小的因素

1. **成员变量**
    - 每个成员变量占据一定空间
2. **字节对齐（Padding）**
    - 编译器会为了对齐在成员间插入填充字节
    - 类总大小通常为最大成员对齐数的整数倍
3. **虚函数（虚表指针 vptr）**
    - 主流 ABI 通常在多态对象中加入一个或多个虚表指针；具体数量、位置和大小由 ABI 决定
    - 在常见 32/64 位数据模型中，一个数据指针通常分别为 4/8 字节，但不能据此推断所有继承布局
4. **继承和访问控制**
    - 单继承、虚继承可能影响类大小
    - `private` / `public` / `protected` 本身不决定对象大小；虚继承通常引入额外布局元数据，但实现不一定就是单独增加一个指针

### 2.66.2 示例

```cpp
class A {
    char c;   // 1 字节
    int i;    // 4 字节
};
```

- 假设 4 字节对齐
- 内存布局：

| 地址 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 数据 | c | pad | pad | pad | i | i | i | i |

- 类大小 = 8 字节

### 2.66.3 有虚函数的类

```cpp
class B {
    int x;
    virtual void func() {}
};
```

- 下表只是某个常见 32 位 ABI 下的可能布局：vptr 和 `int` 各 4 字节，因此对象可能为 8 字节；标准不保证该偏移和大小。

|字段|偏移范围|大小|
|---|---|---|
|vptr|0–3|4 字节|
|x|4–7|4 字节|

### 2.66.4 注意事项

1. **静态成员变量不占对象大小**
2. **成员函数不占对象大小**，函数存储在代码段
3. **虚继承**通常需要额外布局信息来定位共享虚基类，具体形式和开销由 ABI 决定

### 2.66.5 面试高频总结句

> 对象大小由非静态数据成员、基类子对象、对齐填充及实现所需的多态/虚继承元数据共同决定；静态数据成员和成员函数代码不逐对象占用空间。最终以目标 ABI 和 `sizeof` 为准。

## 2.67 一个类怎么继承多个类?

### 2.67.1 定义

多重继承（Multiple Inheritance）是 C++ 支持的机制：**一个派生类可以同时继承多个基类**。

- 可以继承多个父类的成员和方法
- 支持组合已有类的功能

### 2.67.2 基本语法

```cpp
class Base1 {
public:
    void func1() { std::cout << "Base1" << std::endl; }
};

class Base2 {
public:
    void func2() { std::cout << "Base2" << std::endl; }
};

class Derived : public Base1, public Base2 {
    // Derived 同时继承 Base1 和 Base2
};
```

```cpp
int main() {
    Derived d;
    d.func1(); // 调用 Base1 成员
    d.func2(); // 调用 Base2 成员
}
```

- Derived 对象拥有 **两个父类的成员**

### 2.67.3 注意事项

1. **命名冲突**
    - 多个基类有同名成员，派生类访问时需限定类名
2. **虚继承（Virtual Inheritance）**
    - 用于解决**钻石继承问题**（重复继承同一个基类）

```cpp
class A {};
class B : virtual public A {};
class C : virtual public A {};
class D : public B, public C {};  // A 只继承一次
```

3. **对象布局复杂**
    - vptr、成员偏移等需要编译器处理
    - 多重继承可能增加额外开销

### 2.67.4 使用场景

- 组合多个类的功能
- 避免重复代码
- 实现接口继承（多个接口类）

### 2.67.5 面试高频总结句

> 一个类可以通过多重继承同时继承多个类，注意命名冲突和钻石继承问题，可用虚继承解决。
> 多重继承 = 派生类同时继承多个父类，注意冲突和虚继承。

## 2.68 C++ Lambda 表达式

- **什么是 Lambda 表达式** **定义**：一种匿名函数（没有名字的函数），可以直接在使用位置定义并调用。；**特点**：可以捕获作用域中的变量，并像普通函数一样调用。；**语法**：

```cpp
[capture] (parameters) mutable -> return_type { function_body }

[capture] 捕获列表
定义 lambda 可以访问哪些外部变量
常见写法：
[ ] 不捕获任何变量
[=] 以值捕获所有外部变量
[&] 以引用捕获所有外部变量
[x] 以值捕获变量 x
[&x] 以引用捕获变量 x
[=, &y] 除 y 以引用捕获，其余都以值捕获
[&, x] 除 x 以值捕获，其余都以引用捕获
(parameter) 参数列表
和普通函数一样，比如 (int a, int b)
可以省略为空 ()
mutable （可选）
如果用值捕获，默认不能修改捕获的变量副本
mutable 允许在 lambda 内部修改副本
-> return_type （可选）
指定返回类型
```

**Lambda 表达式的语法结构**

|语法部分|说明|
|---|---|
|capture|捕获外部变量的方式（值捕获、引用捕获等）|
|parameters|参数列表（可选）|
|mutable|允许修改捕获的变量（值捕获时默认不可修改）|
|return_type|返回值类型（可选，通常可省略，由编译器推导）|
|function_body|函数体|

**捕获方式详解**

|捕获方式|写法|说明|
|---|---|---|
|值捕获（按值）|`[x]`|拷贝外部变量 x|
|引用捕获（按引用）|`[&x]`|引用外部变量 x|
|捕获所有变量（值）|`[=]`|按值捕获所有可见变量|
|捕获所有变量（引用）|`[&]`|按引用捕获所有可见变量|
|混合捕获|`[x, &y]`|x 值捕获，y 引用捕获|
|不捕获任何变量|`[]`|完全独立，不依赖外部变量|

**示例代码：**

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

int main() {
    int a = 10, b = 20;

    // 1. 值捕获（捕获 a 的副本，不影响原 a）
    auto f1 = [a]() {
        std::cout << "Value capture a = " << a << std::endl; // 输出: 10
    };

    // 2. 引用捕获（捕获 b 的引用，可以修改原 b）
    auto f2 = [&b]() {
        b += 10; // 修改原 b
        std::cout << "Reference capture b = " << b << std::endl; // 输出: 30
    };

    // 3. 混合捕获（a 值捕获，b 引用捕获）
    auto f3 = [a, &b]() {
        std::cout << "Mix capture: a=" << a << ", b=" << b << std::endl; // 输出: a=10, b=30
    };

    // 4. 带参数和返回值
    auto sum = [](int x, int y) -> int {
        return x + y; // 返回 x+y
    };

    // 5. 在算法中使用 Lambda（打印容器内容）
    std::vector<int> v = {1, 2, 3, 4};
    std::for_each(v.begin(), v.end(), [](int x) {
        std::cout << x << " "; // 输出: 1 2 3 4
    });
    std::cout << std::endl;

    f1(); // 输出: 10
    f2(); // 输出: 30
    f3(); // 输出: a=10, b=30
    std::cout << "Sum = " << sum(5, 6) << std::endl; // 输出: Sum = 11

    return 0;
}

```

- **mutable 关键字** 用于允许修改**值捕获**的变量副本：

```cpp
int x = 5;
auto f = [x]() mutable {
    x += 10; // 这里修改的是捕获的副本
    std::cout << x << std::endl;
};
f(); // 输出 15
std::cout << x << std::endl; // 输出 5
```

- **使用场景** STL 算法中的回调；简单事件处理函数；异步任务（如 std::thread）的函数体；快速定义一次性函数，无需额外写函数名

**为什么要用 Lambda（而不是直接定义函数）**

**代码更简洁**

- **普通函数**需要：
    - 单独写函数名
    - 放在作用域外
    - 传参时可能不方便
- **Lambda**可以**就地写**，不用起名字，也不用在外部声明。

**例子**：

```cpp
// 普通函数
bool isEven(int x) { return x % 2 == 0; }
std::count_if(v.begin(), v.end(), isEven);

// Lambda
std::count_if(v.begin(), v.end(), [](int x){ return x % 2 == 0; });
```

➡ Lambda 一行就搞定，不需要额外声明。

- **更适合临时使用的回调** 当一个函数**只在一处用一次**，Lambda 省得写函数名，减少代码污染。

```cpp
std::for_each(v.begin(), v.end(), [](int x) { std::cout << x << " "; });
```

**STL 算法和多线程非常适配**

- 很多 STL 算法（sort, count_if）和多线程库（std::thread）都**喜欢** Lambda，因为可以：
    - 直接传递逻辑
    - 访问外部数据
    - 无需全局变量

```cpp
std::thread t([&](){ doWork(data); }); // 直接捕获 data
```

- **可直接内联优化** Lambda 通常会被编译器优化成内联函数，效率不比手写函数差。；甚至可以避免函数调用开销，性能友好。
- **可以捕获外部变量** 普通函数不能直接访问外部局部变量（除非全局变量），而 Lambda 可以用捕获列表灵活访问当前作用域变量。

```c++
int threshold = 5;
auto greaterThan = [threshold](int x) { return x > threshold; };
```

**总结对比**

|特性|普通函数|Lambda|
|---|---|---|
|是否有名字|✅ 必须有|❌ 可匿名|
|访问局部变量|❌ 不可|✅ 可捕获|
|写法|相对冗长|简洁内联|
|适合场景|公共逻辑|局部一次性逻辑|
|性能|高|高（可内联）|

## 2.69 智能指针

### 2.69.1 定义

**智能指针**是 C++ 提供的封装了原生指针的类模板，用于**自动管理动态分配的内存**，防止内存泄漏。

- 自动调用析构函数释放资源
- 常见类型：std::unique_ptr, std::shared_ptr, std::weak_ptr

### 2.69.2 常见智能指针类型

|类型|特点|使用场景|
|---|---|---|
|unique_ptr|独占所有权，不能拷贝，只能移动|单一对象管理，防止重复释放|
|shared_ptr|引用计数共享所有权，最后一个释放对象|多个对象共享同一资源|
|weak_ptr|弱引用，不增加引用计数，防止循环引用|配合 shared_ptr 避免循环引用|

```cpp
#include <memory>
#include <iostream>
using namespace std;

int main() {
    unique_ptr<int> p1 = make_unique<int>(10);
    cout << *p1 << endl;
    // unique_ptr 不可拷贝，只能移动
    unique_ptr<int> p2 = move(p1);
}
```

### 2.69.3 使用示例

**（2）shared_ptr**

```cpp
#include <memory>
#include <iostream>
using namespace std;

int main() {
    shared_ptr<int> p1 = make_shared<int>(20);
    shared_ptr<int> p2 = p1; // 引用计数 +1
    cout << *p1 << ", " << *p2 << endl;
    cout << p1.use_count() << endl; // 输出 2
}
```

**（3）weak_ptr 避免循环引用**

```cpp
#include <memory>
struct B;

struct A {
    std::shared_ptr<B> b_ptr;
};

struct B {
    std::weak_ptr<A> a_ptr; // 弱引用，避免循环引用
};
```

### 2.69.4 特点

1. **自动管理内存**，减少手动 delete 风险
2. **异常安全**，避免泄漏
3. **引用计数机制**（shared_ptr）
4. **独占或共享所有权**

### 2.69.5 使用场景

- 动态对象生命周期管理
- 避免手动释放导致的内存泄漏
- 多对象共享同一资源

### 2.69.6 面试高频总结句

> 智能指针是封装原生指针的模板类，自动管理内存，减少内存泄漏和悬挂指针风险。
> Smart Pointer = “自动管理内存的指针”，用 RAII 机制保证安全释放。

## 2.70 RAII

RAII 全称是 **Resource Acquisition Is Initialization**（资源获取即初始化），是 C++ 中非常重要的内存与资源管理思想。

RAII 并不是“自动可用”的魔法，前提是用类正确封装资源。

它的核心思想是：

- **资源的申请放在对象构造函数中**（比如 new、fopen、malloc 等操作）。
- **资源的释放放在对象析构函数中**（比如 delete、fclose、free 等操作）。

这样就保证了：

- 对象在 **创建时自动获取资源**。
- 对象在 **生命周期结束时自动释放资源**（离开作用域时自动调用析构函数）。

所以你不用手动调用“释放”，编译器会自动帮你调用析构函数 → 资源就会被释放。

**核心思想**

- **资源（Resource）**：内存、文件句柄、互斥锁、网络连接等有限的系统资源。
- **获取即初始化**：在对象构造时获取资源，在对象析构时释放资源。
- **作用域绑定**：**对象生命周期和资源生命周期绑定**，一旦对象离开作用域（如函数返回或异常抛出），析构函数会被自动调用，资源也随之释放。

**例子：**

1. 不使用 RAII 的资源管理

```cpp
void foo() {
    FILE* fp = fopen("data.txt", "r");
    if (!fp) return;  // 忘记关闭文件可能会泄漏

    // 中间可能发生异常，fclose 就没执行
    // ...
    fclose(fp);
}
```

2. 使用 RAII（C++ 封装）

```cpp
class FileHandler {
public:
    FileHandler(const char* filename, const char* mode) {
        fp = fopen(filename, mode);
    }
    ~FileHandler() {
        if (fp) fclose(fp);  // 析构时自动释放资源
    }
    FILE* get() { return fp; }
private:
    FILE* fp = nullptr;
};
```

**常见应用**

1. **内存管理**
    - std::unique_ptr / std::shared_ptr
       自动释放堆上的对象。

```cpp
std::unique_ptr<int> p(new int(42));  // 出作用域时自动 delete
```

1. **锁管理**
    - std::lock_guard<std::mutex>
       自动上锁、解锁，避免死锁或忘记解锁。

```cpp
std::mutex mtx;
void safe() {
    std::lock_guard<std::mutex> lock(mtx); // 构造时加锁，析构时解锁
    // 临界区
}
```

1. **文件/网络资源管理**
   用类封装文件、socket，使其自动关闭。

- **优点：** 避免内存泄漏和资源泄漏。；避免忘记手动释放资源。；即使发生异常，也能保证资源被正确释放。；符合 C++ 的 **异常安全性**（Exception Safety）。

总结：
 RAII 的本质就是 **让资源跟随对象的生命周期**，构造时获取，析构时释放。C++ 的智能指针、锁、文件类等都体现了这一思想。

## 2.71 RAII 原则在嵌入式开发中的应用

### 2.71.1 RAII 原则简介

RAII（Resource Acquisition Is Initialization，资源获取即初始化）是 C++ 中一种常用的编程原则，它的核心思想是：对象的生命周期管理资源的获取和释放，即通过对象的构造和析构函数来自动管理资源的分配和释放。RAII 原则通常用于内存管理、文件句柄、锁等资源的管理。

- **获取资源**：在对象的构造函数中进行资源的分配、初始化或打开。
- **释放资源**：在对象的析构函数中自动释放资源。

通过 RAII 原则，开发者可以避免资源泄漏的问题，并且代码更加简洁和易于维护。

### 2.71.2 RAII 在嵌入式开发中的资源管理场景

- **内存管理**：嵌入式系统中的内存通常非常宝贵，手动管理内存可能容易出错，导致内存泄漏或溢出，RAII 可以确保每个分配的内存都有对应的释放操作。
- **硬件资源管理**：如 I/O 设备、传感器、GPIO 等硬件资源，必须在使用时正确初始化，并在不需要时释放。

### 2.71.3 RAII 在嵌入式开发中的常见应用

**内存管理**

在嵌入式开发中，内存分配和释放是一个重要的问题。RAII 可以帮助管理动态内存的使用，防止内存泄漏。

**示例：使用 std::unique_ptr 管理内存**

```cpp
#include <memory>
#include <iostream>

class Buffer {
public:
    Buffer(size_t size) : data(new char[size]), size(size) {
        std::cout << "Buffer allocated: " << size << " bytes\n";
    }

    ~Buffer() {
        delete[] data;
        std::cout << "Buffer released\n";
    }

private:
    char* data;
    size_t size;
};

void testBuffer() {
    std::unique_ptr<Buffer> buffer = std::make_unique<Buffer>(1024);
    // buffer 在作用域结束时会自动释放
}

int main() {
    testBuffer();  // 内存会在函数退出时自动释放
    return 0;
}
```

- 在上面的例子中，Buffer 类采用 RAII 原则来管理动态分配的内存。当 Buffer 对象被销毁时，内存自动释放。通过智能指针（如 std::unique_ptr），内存的管理更加安全和自动化。

**资源锁定与释放**

在多任务或多线程嵌入式系统中，资源共享可能会导致竞争条件。通过使用 RAII 管理锁，确保在资源使用结束时自动释放锁，防止死锁或资源泄漏。

**示例：使用 RAII 管理互斥锁**

```cpp
#include <iostream>
#include <mutex>

std::mutex mtx;

void critical_section() {
    std::lock_guard<std::mutex> lock(mtx);  // 构造时获取锁，析构时自动释放锁
    std::cout << "In critical section\n";
}
```

- 在这个例子中，std::lock_guard 是一个 RAII 风格的对象，当它进入作用域时自动获取锁，并且当它离开作用域时自动释放锁。这避免了手动管理锁的复杂性，并确保不会忘记释放锁。

**硬件资源管理**

嵌入式系统中，许多硬件资源（如串口、GPIO、I2C、SPI）需要初始化和关闭。通过 RAII，可以确保每个硬件资源在不需要时被正确释放。

**示例：使用 RAII 管理硬件设备**

```cpp
class GpioPin {
public:
    GpioPin(int pin) : pin_number(pin) {
        // 初始化硬件
        std::cout << "Initializing GPIO pin: " << pin_number << "\n";
    }

    ~GpioPin() {
        // 释放硬件资源
        std::cout << "Releasing GPIO pin: " << pin_number << "\n";
    }

private:
    int pin_number;
};

void testGpio() {
    GpioPin pin(5);  // 在作用域内初始化并使用 GPIO 引脚
    // GPIO 引脚在作用域结束时自动释放
}

int main() {
    testGpio();  // 自动释放 GPIO 资源
    return 0;
}
```

- 在此例中，GpioPin 类负责管理 GPIO 引脚的初始化和释放。通过 RAII，硬件资源的释放在对象销毁时自动完成，避免了资源泄漏。

**文件操作**

在嵌入式系统中，文件操作是常见的需求。通过 RAII 原则，可以自动管理文件句柄的打开与关闭，避免文件资源的泄漏。

**示例：使用 RAII 管理文件**

```cpp
#include <fstream>
#include <utility>

class FileManager {
public:
    explicit FileManager(const char* filename) : file(filename) {}
private:
    std::fstream file;
};

void testFile() {
    FileManager file("data.txt");
    // 文件会在作用域结束时自动关闭
}

int main() {
    testFile();
    return 0;
}
```

- 通过 FileManager 类，文件句柄在对象的生命周期内自动管理，确保在使用完文件后自动关闭。

### 2.71.4 RAII 原则的优势

- **自动资源管理**：RAII 可以帮助开发者自动管理内存和其他资源，减少错误，尤其在嵌入式系统中，错误可能导致严重的系统故障。
- **提高代码的可读性与可维护性**：通过 RAII，资源的获取和释放有明确的控制，代码结构更清晰。
- **避免资源泄漏**：RAII 可以防止资源泄漏，因为资源的释放是由对象生命周期控制的，避免了手动释放资源时的疏忽。
- **异常安全**：RAII 原则能够在异常发生时确保资源得以释放，从而避免资源泄漏。

### 2.71.5 RAII 原则的挑战

- **嵌入式环境资源限制**：嵌入式系统通常资源有限，尤其是内存和存储，因此使用 RAII 时需要特别注意内存的开销。
- **硬件依赖性**：嵌入式开发常常需要处理与硬件的紧密交互，RAII 可能需要与硬件驱动程序进行紧密集成，增加了复杂性。

### 2.71.6 总结

RAII 原则在嵌入式开发中的应用可以有效地管理有限的资源，避免内存泄漏、死锁和其他资源管理问题。通过自动化的资源管理，开发者能够更加专注于嵌入式系统的功能实现，减少错误，提高系统的稳定性和可维护性。在嵌入式开发中，使用 RAII 来管理内存、文件、硬件资源和锁等是非常重要且有益的。

## 2.72 C++11的特性

### 2.72.1 概述

C++11 是 C++ 标准的重要升级，引入了**语法改进、标准库增强和并发支持**，提高了编程效率和安全性。

### 2.72.2 主要特性分类

**（1）语法增强**

- **auto 类型推导**

```cpp
auto x = 10; // int
```

- **基于范围的 for 循环**

```cpp
for (auto v : vec) { ... }
```

- **静态断言 `static_assert`**

```cpp
static_assert(sizeof(int)==4, "int不是4字节");
```

**（2）类与对象改进**

- **成员初始化列表增强**
- **委托构造函数**
- **继承构造函数 `using Base::Base;`**
- **默认/删除函数**

```cpp
class A {
    A() = default;    // 默认构造函数
    A(const A&) = delete; // 禁止拷贝构造
};
```

**（3）智能指针与内存管理**

- `std::unique_ptr`、`std::shared_ptr`、`std::weak_ptr`
- `std::make_shared` 属于 C++11；`std::make_unique` 在 C++14 才加入标准库

**（4）并发与多线程**

- <thread>、<mutex>、<future>、<atomic>
- 支持线程创建、锁、原子操作和异步执行

**（5）标准库增强**

- **容器**：array, unordered_map, unordered_set
- **正则表达式 `<regex>`**
- **时间库 `<chrono>`**
- **智能指针与内存管理工具**

**（6）右值引用和移动语义**

```cpp
std::vector<int> v1 = {1,2,3};
```

- 简化代码，提高可读性
- 高效资源管理与并发编程

### 2.72.3 面试高频总结句

> C++11 引入了 auto、Lambda、右值引用、智能指针、多线程和标准库增强，使 C++ 更现代化、安全高效。
> C++11 = “现代化 C++”，提供语法糖、智能指针、移动语义和并发支持，提高效率与安全性。

## 2.73 C++的四种强制转换

### 2.73.1 概述

C++ 提供四种具名转换，意图和适用范围比 C 风格 `(type)` 更明确；它们并非都“类型安全”，其中 `reinterpret_cast` 风险尤其高：

1. static_cast
2. dynamic_cast
3. const_cast
4. reinterpret_cast

### 2.73.2 四种强制转换详解

**（1）static_cast**

- **用途**：常规类型转换、基类/派生类指针转换（非多态安全）、算术类型转换
- **特点**：编译期检查，运行期无类型检查

```cpp
int i = 10;
double d = static_cast<double>(i);

class Base {};
class Derived : public Base {};
Base* b = new Derived;
Derived* dptr = static_cast<Derived*>(b);
```

**（2）dynamic_cast**

- **用途**：多态类型安全转换（基类指针/引用 ↔ 派生类）
- **特点**：运行时检查，转换失败返回 nullptr（指针）或抛异常（引用）
- **要求**：涉及向下/横向的运行时检查时，源类型必须是多态类；向上转换不要求源类含虚函数，而且通常也无需显式写 `dynamic_cast`

```cpp
class Base { virtual void func() {} };
class Derived : public Base {};
Base* b = new Derived;
Derived* d = dynamic_cast<Derived*>(b); // 安全转换
```

**（3）const_cast**

- **用途**：去除或添加 const/volatile 修饰
- **特点**：仅修改类型修饰，不改变对象本身

```cpp
const int x = 10;
int* px = const_cast<int*>(&x);
*px = 20; // 非常危险，修改 const 对象未定义行为
```

**（4）reinterpret_cast**

- **用途**：按位解释转换，指针类型间、整型与指针之间
- **特点**：最低安全性，适合底层操作
- **谨慎使用**

```cpp
#include <cstdint>

std::uintptr_t raw = 0x12345678u;
int* ip = reinterpret_cast<int*>(raw);  // 结果及其可解引用性依赖平台
```

### 2.73.3 总结表

|转换类型|用途|安全性|检查时机|
|---|---|---|---|
|static_cast|算术转换、已知继承关系等|取决于方向；向下转换不做运行时类型校验|编译|
|dynamic_cast|多态类指针/引用|高（运行时检查）|运行|
|const_cast|修改 const/volatile 修饰|中|编译|
|reinterpret_cast|低层指针/整数等重新解释|低，仅做受限的编译期合法性检查|编译|

### 2.73.4 面试高频总结句

> C++ 提供 `static_cast`、`dynamic_cast`、`const_cast` 和 `reinterpret_cast` 四种具名转换，让意图和风险更清楚；应选择约束最强、语义最匹配的一种，并尽量避免不必要的转换。
