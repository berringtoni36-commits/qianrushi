## 2.1 寄存器映射及 C 语言访问方法

### 2.1.1 寄存器映射的概念

- **定义**：将外设寄存器映射到 CPU 的地址空间中，使 CPU 可以像访问内存一样访问寄存器
- **类型**：
    a. **内存映射 I/O（Memory-Mapped I/O）**：寄存器占用内存地址，直接用指针访问
    b. **端口映射 I/O（Port-Mapped I/O）**：通过专用指令（如 x86 的 in/out）访问
- **作用**：
    - 提供软件对硬件外设的直接控制
    - 简化驱动程序设计

### 2.1.2 在 C 语言中访问寄存器的方法

**指针访问（最常用）**

```c
#define GPIOA_BASE 0x40020000U
#define GPIOA_ODR  (*(volatile unsigned int *)(GPIOA_BASE + 0x14))

void led_on() {
    GPIOA_ODR |= (1 << 5);  // 设置第5位，高电平点亮LED
}
```

- **说明**：
    - volatile：告诉编译器该寄存器可能随时变化，不要优化访问
    - 指针加偏移量访问寄存器特定位

**结构体映射（便于管理多个寄存器）**

```c
// 下面是与部分 STM32F4 GPIO 布局相符的示意；具体字段和偏移以目标系列头文件/参考手册为准。
#include <stdint.h>

typedef struct {
    volatile uint32_t MODER;   // 0x00
    volatile uint32_t OTYPER;  // 0x04
    volatile uint32_t OSPEEDR; // 0x08
    volatile uint32_t PUPDR;   // 0x0C
    volatile uint32_t IDR;     // 0x10
    volatile uint32_t ODR;     // 0x14
} GPIO_TypeDef;

#define GPIOA ((GPIO_TypeDef *)0x40020000U)

void led_on() {
    GPIOA->ODR |= (1 << 5);
}
```

- **优点**：
    - 可读性高
    - 便于管理同一外设的多个寄存器

### 2.1.3 注意事项

1. **硬件寄存器通常应声明为 `volatile`**，使每次读写都按源码语义发出；但 `volatile` 不提供原子性、内存序或线程同步，普通变量和所有场景并非“必须加”。
2. **避免指针越界**，必须使用正确的基地址和偏移
3. **原子操作**：对多线程或中断环境下共享寄存器，注意读-改-写的原子性
4. **对寄存器写操作谨慎**：错误写入可能导致外设不可预测行为

### 2.1.4 总结

寄存器映射是将外设寄存器映射到 CPU 地址空间，C 语言通过 volatile 指针或结构体直接访问寄存器实现外设控制。

## 2.2 STM32 的主频和外设时钟（HCLK、PCLK1/PCLK2）区别

### 2.2.1 主频（Core Clock / SYSCLK）

- **定义**：CPU 核心运行的时钟频率
- **作用**：决定 CPU 执行指令的速度
- **来源**：通常来自外部晶振或 PLL 输出
- **特点**：
    - 决定 MCU 的计算能力
    - 高主频可以提高指令处理速度，但功耗也增加

### 2.2.2 HCLK（AHB 时钟）

- **定义**：连接 CPU、内部总线（AHB）、内存和部分高速外设的时钟
- **作用**：
    - 驱动 CPU 访问内存和高速总线外设
    - 一些高速外设（如 DMA、FSMC、GPIO）以 HCLK 为时钟
- **特点**：
    - 可通过分频器从 SYSCLK 分频得到
    - HCLK ≤ SYSCLK

### 2.2.3 PCLK1 / PCLK2（APB1 / APB2 外设时钟）

- **定义**：APB 总线上的外设时钟
    - PCLK1：低速外设（APB1）
    - PCLK2：高速外设（APB2）
- **作用**：驱动外设计时和寄存器访问，如 USART、I2C、SPI、TIM 等
- **特点**：
    - PCLK = HCLK / 分频系数
    - 不同外设可能对最大时钟有限制，例如 APB1 最大 36MHz，APB2 最大 72MHz（以 STM32F1 为例）
    - 定时器特殊：当 APB 分频大于 1 时，定时器时钟 = 2 × PCLK

### 2.2.4 区别总结

|时钟|来源/关系|主要服务对象|注意事项|
|---|---|---|---|
|SYSCLK|系统时钟源或 PLL 输出|系统时钟树的根节点|最大频率、PLL 倍频和时钟源由具体系列限制|
|HCLK|SYSCLK 经 AHB 分频得到|Cortex-M 核心、AHB 总线及部分高速外设|通常不高于 SYSCLK，需满足 AHB 上限|
|PCLK1|HCLK 经 APB1 分频得到|APB1 外设|低速外设的具体归属和上限以型号手册为准|
|PCLK2|HCLK 经 APB2 分频得到|APB2 外设|高速外设的具体归属和上限以型号手册为准|
|APB 定时器时钟|由对应 PCLK 与 APB 预分频共同决定|TIM 外设|部分 STM32 在 APB 预分频不为 1 时将定时器时钟加倍，不能套用于所有系列|

## 2.3 STM32 NVIC（中断控制器）优先级配置

### 2.3.1 NVIC 的基本概念

- **NVIC（Nested Vectored Interrupt Controller）**：嵌套向量中断控制器
- **作用**：
    a. 管理 Cortex-M 的可屏蔽外部中断/IRQ；复位、NMI、HardFault、SysTick 等系统异常由内核/SCB 等共同管理
    b. 支持中断嵌套（高优先级中断可以打断低优先级中断）
- **优先级分级**：
    - STM32 通过**抢占优先级（Preemption Priority）**和**响应优先级（Subpriority）**控制
    - 抢占优先级高的中断可以打断低的
    - 响应优先级用于同一抢占优先级中同时触发的中断顺序

### 2.3.2 配置步骤（以 STM32 HAL 为例）

1. **设置优先级分组（Priority Grouping）**：

```c
// 将抢占优先级分为 2 位，响应优先级 2 位
HAL_NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_2);
```

- **说明**：
    - 分组决定抢占优先级和响应优先级的位数
    - 常用分组：
2. **设置中断优先级**：

```c
// 配置 EXTI0（外部中断0）中断优先级
HAL_NVIC_SetPriority(EXTI0_IRQn, 1, 1); // 抢占优先级 1，响应优先级 1
```

3. **使能中断**：

```c
HAL_NVIC_EnableIRQ(EXTI0_IRQn);
```

### 2.3.3 配置注意事项

1. **低数值 = 高优先级**
    - 抢占优先级 0 > 1 > 2
2. **中断嵌套原则**：
    - 高优先级中断可打断低优先级中断
    - 相同抢占优先级中，中断不会互相打断，由响应优先级决定先后
3. **RTOS 下使用 NVIC**：
    - FreeRTOS 会使用 SysTick 和 PendSV
    - 不能笼统地说“核心中断高于应用中断”。调用 `FromISR` API 的外部中断必须处于端口允许的优先级范围（Cortex-M 中通常数值越大优先级越低），应遵守 `configMAX_SYSCALL_INTERRUPT_PRIORITY`；SysTick/PendSV 的具体优先级按 FreeRTOS 端口配置
4. **避免优先级冲突**：
    - 对时间敏感任务分配高抢占优先级
    - 对低优先级任务可降低响应优先级

### 2.3.4 总结

STM32 NVIC 通过抢占优先级和响应优先级控制中断嵌套，低数值优先级高；配置时先设置优先级分组，再设置具体中断优先级并使能中断。

## 2.4 了解systick定时器吗，说说有什么作用

### 2.4.1 什么是 SysTick 定时器

- SysTick 是 **Cortex-M 内核**自带的一个简单定时器。
- 24 位递减计数器，内置于处理器内核，独立于外部定时器。
- 主要用于产生周期性中断。

### 2.4.2 SysTick 的主要作用

- **提供系统节拍（系统时基）**
    - FreeRTOS 和其他 RTOS 通常使用 SysTick 作为系统滴答中断，驱动任务调度。
    - 它定时产生中断，操作系统内核在中断中更新系统时间（Tick 计数器）。
- **实现任务调度和时间管理**
    - 定时唤醒延时任务。
    - 实现时间片轮转和调度切换。
- **可用作简单延时或周期触发事件**
    - 在裸机程序中也常用它做周期性任务调度。

### 2.4.3 SysTick 的特点

- 计数器为 24 位，适合产生系统节拍和短周期定时；可计时的最长周期仍受内核时钟频率与 `LOAD` 上限限制，不能仅凭“24 位”断言适合长时间计数。
- 计数器自动重装载，产生周期性中断。
- 占用资源少，集成度高。

### 2.4.4 SysTick 在 FreeRTOS 中的典型配置

- 配置计数周期对应 configTICK_RATE_HZ（如 1000Hz，即1ms中断一次）。
- 在常见 Cortex-M 端口中，SysTick 处理函数更新 tick 并请求调度，真正的上下文切换通常由 PendSV 等异常完成；具体使用哪个定时器和异常以 FreeRTOS 端口配置为准。

## 2.5 CPU寄存器中哪几个比较关键

### 2.5.1 通用寄存器（General Purpose Registers）

- 用于存放临时数据、操作数和计算结果。
- 例如 ARM Cortex-M 的 R0-R12 寄存器，x86 的 EAX、EBX 等。
- 关键作用：算术运算、数据传递、函数参数传递等。

### 2.5.2 程序计数器（Program Counter，PC）

- 指向当前执行指令的地址。
- CPU 根据 PC 取指令并执行。
- 程序执行流的关键控制。

### 2.5.3 堆栈指针（Stack Pointer，SP）

- 指向当前线程/程序的栈顶位置。
- 用于函数调用时保存返回地址、局部变量、函数参数。
- 线程切换和上下文保存依赖 SP。

### 2.5.4 链接寄存器（Link Register，LR） — 仅 ARM 架构

- 保存函数返回地址。
- 函数调用时自动存储返回地址，函数返回时使用。

### 2.5.5 状态寄存器（Program Status Register，PSR）

- 存储当前 CPU 状态信息（条件标志、中断状态、模式位等）。
- 影响指令执行流程（如条件跳转）。

## 2.6 CPU有哪几种架构

### 2.6.1 ARM 架构

- **特点**：RISC（精简指令集计算）架构，指令集简单、高效，功耗低。
- **应用**：广泛应用于移动设备、嵌入式系统、IoT 设备。
- **优势**：低功耗、良好的性能功耗比、丰富生态。
- **版本**：如 Cortex-M（微控制器）、Cortex-A（应用处理器）等。

### 2.6.2 x86 架构

- **特点**：CISC（复杂指令集计算）架构，指令集复杂，兼容性强。
- **应用**：个人电脑、服务器、工作站主流架构。
- **优势**：指令丰富，性能强大，软件生态成熟。
### 2.6.3 RISC-V 架构

- 特点：开源 RISC 架构，指令集开放且简洁。
- 应用：嵌入式、科研、教育、新兴芯片设计。
- 优势：灵活定制，免授权费，创新空间大。

### 2.6.4 MIPS 架构

- **特点**：早期流行的 RISC 架构，指令简单。
- **应用**：嵌入式设备、路由器等。
- **现状**：应用减少，但仍用于部分领域。

### 2.6.5 PowerPC 架构

- **特点**：RISC 架构，曾广泛用于高性能计算。
- **应用**：嵌入式系统、服务器、老款苹果电脑。

## 2.7 STM32 的 Cortex-M 核心特点

### 2.7.1 精简指令集（RISC 架构）

- 采用 **ARM RISC 指令集**
- 指令长度固定（Cortex-M3/M4 主要 16/32 位 Thumb 指令）
- 优势：执行效率高，功耗低

### 2.7.2 低功耗设计

- 支持多种节能模式（Sleep、Stop、Standby）
- 可根据外设和任务需求动态调节功耗
- 适合嵌入式和 IoT 场景

### 2.7.3 中断与异常处理

- 内建 **NVIC（嵌套向量中断控制器）**
- 支持中断嵌套，高优先级中断可打断低优先级
- 支持系统异常（硬件故障、SysTick 定时器、PendSV 等）

### 2.7.4 系统定时器（SysTick）

- 内建 24 位可编程定时器
- 常用于操作系统心跳、任务调度或定时中断

### 2.7.5 堆栈与异常处理优化

- 支持 **主栈（MSP）** 和 **进程栈（PSP）**
- 异常自动保存寄存器，简化中断/异常处理
- 提高实时性和可靠性

### 2.7.6 支持浮点运算（可选）

- 部分 Cortex-M4/M7 实现带 **单精度浮点单元（FPU）**；是否存在以及是否启用取决于具体内核型号、芯片和编译选项
- 提高 DSP 或控制算法的计算效率
- Cortex-M0/M3 不含硬件 FPU，需要软件库支持

### 2.7.7 总结

- Cortex-M 核心特点：RISC 精简指令、低功耗、快速中断响应、内建 SysTick 定时器、双栈结构优化异常处理
- 高端型号（M4/M7）支持硬件浮点运算和 DSP 指令，适合控制和信号处理应用

## 2.8 GD32/STM32的启动文件（startup_stm32xxxX.s)的作用，从上电复位到进入 main 函数的步骤说明

### 2.8.1 启动文件作用

- 初始化系统堆栈指针（SP）
- 设置中断向量表
- 复位处理函数入口（Reset_Handler）
- 初始化内存（.data 和 .bss 段）
- 跳转到用户程序入口 main()
- 定义中断和异常处理函数入口

### 2.8.2 从上电复位到进入 main 函数的步骤

|步骤序号|步骤名称|说明|
|---|---|---|
|1|上电复位（Power-On Reset）|MCU 上电，内部复位电路触发，寄存器和外设恢复默认状态|
|2|初始化堆栈指针（SP）|设置主堆栈指针，通常由启动文件（startup.s）完成|
|3|跳转 Reset_Handler|MCU 根据复位向量地址跳转到启动代码入口|
|4|初始化数据段（DATA）|将编译时初始化的全局/静态变量从 Flash 拷贝到 RAM|
|5|清零 BSS 段|将未初始化的全局/静态变量置零|
|6|可选的初始化函数|调用系统或库初始化函数，如 SystemInit() 配置时钟、外设等|
|7|调用 main() 函数|启动用户程序，进入主函数执行|

### 2.8.3 简单流程图示意

```text
[上电复位]
      ↓
[设置堆栈指针 SP]
      ↓
[加载中断向量表]
      ↓
[跳转 Reset_Handler]
      ↓
[复制 .data 到 RAM]
      ↓
[清零 .bss]
      ↓
[调用 SystemInit()]
      ↓
[调用 main()]
```

## 2.9 中断向量表

### 2.9.1 定义

中断向量表（Interrupt Vector Table）是一张存放中断服务程序入口地址的表格，位于内存的固定位置。它告诉 CPU 在发生特定中断或异常时，跳转到哪个地址执行对应的处理函数。

### 2.9.2 作用

- **定位中断处理函数**：当硬件中断或异常发生时，CPU 根据中断向量表找到对应的中断处理程序入口地址。
- **实现快速响应**：通过中断向量表，CPU 能迅速跳转执行对应中断代码，保证系统响应及时。
- **系统初始化关键部分**：启动时，复位向量（复位处理函数地址）也存放在这里。

### 2.9.3 结构特点

- 每个中断源（复位、中断、异常）对应一项，存储该中断处理函数的地址。
- 向量表一般是一个指针数组，指针指向各个中断处理函数的入口。
- 在 ARM Cortex-M 系列，复位后的默认映射通常使向量表可从 `0x00000000` 取到；第一项是初始 MSP，第二项是复位入口。启用 `SCB->VTOR` 后，向量表可以按对齐要求重定位到其他地址，具体以内核/芯片实现为准。

## 2.10 SystemInit() 的作用及位置

### 2.10.1 SystemInit() 的作用

- **系统初始化函数**，负责芯片上电或复位后，进行硬件相关的初始化配置。
- 主要任务包括：
    - 配置系统时钟（时钟源选择、PLL 配置、时钟树分频等）。
    - 配置闪存等待状态。
    - 初始化外设时钟（如总线时钟）。
    - 配置系统低功耗模式相关设置（可选）。
- 为后续程序运行提供稳定的时钟和硬件环境。

### 2.10.2 SystemInit() 的位置

- 通常定义在芯片厂商提供的 **CMSIS 库** 或 **启动代码文件中**。
- 在 STM32 和 GD32 系列中，SystemInit() 一般实现于 system_stm32xxx.c 或类似文件。
- 该文件在启动文件（startup_stm32xxx.s）的复位处理函数 Reset_Handler 调用 main() 之前被调用。

### 2.10.3 调用时机

- 在启动文件的复位处理函数中，Reset_Handler 调用 SystemInit()，完成硬件初始化后，再进入 main()。

## 2.11 GD32与STM32启动文件的区别

### 2.11.1 对比表格

|对比项|GD32|STM32|
|---|---|---|
|启动文件名称|startup_gd32xxx.s|startup_stm32xxx.s|
|厂商|兆易创新（GigaDevice）|ST（意法半导体）|
|内核架构|ARM Cortex-M（兼容）|ARM Cortex-M|
|启动流程|与 STM32 类似|标准 Cortex-M 启动流程|
|向量表定义|基本一致，但中断数量/名称不同|标准定义，按型号区分|
|中断命名|GD32 自定义外设名称|STM32 标准命名（如 USARTx）|
|默认中断处理函数|弱定义（weak）|弱定义（weak）|
|堆栈初始化|在 Reset_Handler 中设置 SP|同样在 Reset_Handler 设置 SP|
|系统初始化函数|SystemInit()（GD32 实现）|SystemInit()（CMSIS 标准实现）|
|时钟初始化|GD32 库函数实现（略有差异）|STM32 HAL/CMSIS 实现|
|库支持|GD32 标准库（StdPeriph-like）|HAL / LL / StdPeriph|
|启动文件风格|接近 STM32，但有厂商差异|官方 CMSIS 标准模板|

### 2.11.2 核心区别

1. **整体结构高度一致**
- 两者都基于 ARM Cortex-M
- 启动流程几乎一样：
    - 初始化 SP
    - 调用 SystemInit()
    - 跳转 main()

2. **主要差异在外设和中断定义**
- GD32 和 STM32 外设不同
- 导致：
    - 中断向量表数量不同
    - 中断函数命名不同

3. **库和初始化实现不同**
- GD32 使用自家标准库
- STM32 使用 HAL / LL / CMSIS
- SystemInit() 内部实现差异较大（尤其时钟配置）
4. **兼容性**
- GD32 在设计上 **兼容 STM32（尤其 F1 系列）**
- 很多启动文件结构几乎可以互换，但**不能完全通用**

### 2.11.3 面试回答

> 两者启动流程基本一致，都是基于 Cortex-M 架构，完成堆栈初始化、调用 SystemInit 和进入 main。主要区别在于中断向量表和外设定义不同，以及 SystemInit 中的时钟初始化和底层库实现不同。GD32 在结构上兼容 STM32，但不能完全通用。

## 2.12 MSP 和 PSP

### 2.12.1 MSP（Main Stack Pointer，主堆栈指针）

- **作用**：系统复位后默认使用的堆栈指针。
- **使用场景**：用于处理异常和中断服务程序（ISR）时的堆栈。
- **特点**：
    - Cortex-M 内核上电或复位后，MSP 是默认堆栈指针。
    - 系统异常（如硬件中断）自动切换到 MSP 进行堆栈操作。

### 2.12.2 PSP（Process Stack Pointer，进程堆栈指针）

- **作用**：用户线程或任务运行时使用的堆栈指针。
- **使用场景**：在操作系统中，用户任务（线程）使用 PSP，系统异常仍使用 MSP。
- **特点**：
    - 允许操作系统分离用户态任务堆栈和异常堆栈。
    - 通过 CONTROL 寄存器切换堆栈指针（MSP 或 PSP）。

### 2.12.3 区别总结

|特性|MSP（Main Stack Pointer）|PSP（Process Stack Pointer）|
|---|---|---|
|用途|复位后默认使用；Handler 模式（异常/中断）使用，Thread 模式也可配置为使用 MSP|通常由 RTOS 在线程模式下选择；Cortex-M 的 Thread 模式通过 `CONTROL.SPSEL` 选择 MSP 或 PSP|
|堆栈空间|通常用于中断处理、异常处理|用于普通线程/任务栈|
|初始化时机|MCU 上电复位时自动加载|由操作系统或程序切换到线程模式时设置|
|切换机制|内核模式自动切换|线程切换时由调度器或程序显式切换|
|应用场景|异常处理、启动代码和 RTOS 内核栈|FreeRTOS 等 RTOS 的任务栈（具体端口决定）|

### 2.12.4 作用总结

- MSP 保证系统异常处理的可靠性和安全性。
- PSP 支持多任务操作系统的任务堆栈隔离。

---

## 2.13 为什么需要两个栈指针（MSP 和 PSP）？

### 2.13.1 分离异常处理和任务运行的堆栈

- **MSP** 用于系统异常（中断、故障）处理，确保异常处理的堆栈独立且安全。
- **PSP** 用于普通线程/任务的运行，支持多任务环境下每个任务拥有独立堆栈。

### 2.13.2 提升系统稳定性和安全性

- 异常使用 MSP 堆栈，避免任务堆栈因异常处理而损坏。
- 任务切换时，独立的 PSP 堆栈保证任务上下文的隔离。

### 2.13.3 支持多任务操作系统（如 FreeRTOS）

- 任务使用 PSP，使得每个任务拥有自己的独立堆栈空间。
- 异常处理切换回 MSP，避免任务间干扰。

### 2.13.4 灵活的堆栈管理机制

- 通过 CONTROL 寄存器可在 MSP 和 PSP 之间切换，满足不同运行模式需求。

---

## 2.14 启动第一个任务时为什么要获取 MSP 初始值？

- 在 Cortex-M 的 FreeRTOS 端口中，启动第一个任务时通常会从向量表第一项读取复位时的初始 MSP，并写回 MSP。
- 目的，是让异常/中断继续使用启动文件为系统预留的主栈，并清理启动阶段可能消耗的临时栈空间；它不是用来推算任务栈大小，也不是保存第一个任务上下文。

### 2.14.1 MSP 存储了初始堆栈顶地址

- 系统复位后，MSP 指向系统初始堆栈顶（一般在启动文件的向量表中第一个值）。
- 该值是芯片上电后硬件自动加载的初始栈指针，代表系统内存中预留的堆栈空间顶端。

### 2.14.2 启动第一个任务时保存上下文

- 第一个任务的初始寄存器帧由 `pxPortInitialiseStack()` 等端口代码预先放入任务栈，启动时通过 `SVC`/异常返回恢复；任务上下文并不是从 MSP 初值复制出来的。

### 2.14.3 MSP 用于异常和系统级堆栈

- 在典型 Cortex-M FreeRTOS 端口中，线程态任务使用 PSP，Handler 态异常/中断使用 MSP；恢复正确的 MSP 初值可避免异常处理继续使用启动阶段已经变化的栈顶。

### 2.14.4 具体流程中的作用

- 启动时处理器先以 MSP 运行；启动第一个任务的汇编例程读取向量表初始 MSP、重新设置 MSP，然后通过 `SVC`/异常返回切换到任务的 PSP。
- 不同 Cortex-M 内核、编译器和 FreeRTOS 端口的细节可能不同，应以实际 `port.c`/启动汇编为准。

### 2.14.5 总结

启动第一个任务前，获取 MSP 初始值是为了：

- 准确保存系统初始堆栈状态。
- 保证异常和调度机制正常工作。
- 正确切换到任务使用的 PSP 堆栈。

## 2.15 STM32 GPIO 几种常用模式

### 2.15.1 输入模式

- **功能**：用来读取外部信号，如开关、按钮、传感器的输入。
- **配置**：默认引脚为输入模式，通常需要配置上拉或下拉电阻来稳定信号。
- **类型**：
    - **GPIO_MODE_INPUT**：普通输入
    - **GPIO_MODE_INPUT_PULLUP**：带上拉电阻的输入
    - **GPIO_MODE_INPUT_PULLDOWN**：带下拉电阻的输入

### 2.15.2 输出模式

**功能**：用来控制外部设备，如点亮 LED 或控制继电器。

**配置**：可以配置为推挽输出或开漏输出。

**类型**：

- **GPIO_MODE_OUTPUT_PP**：推挽输出（强驱动能力，适合驱动 LED、马达等）
- **GPIO_MODE_OUTPUT_OD**：开漏输出（需要外部上拉电阻，适合 I2C 总线等）

### 2.15.3 复用功能模式（Alternate Function）

GPIO 作为外设功能引脚，比如：

- **AF 推挽**：SPI、USART、CAN 等高速信号
- 例如：STM32F1 标准外设库中的 `GPIO_Mode_AF_PP`，或较新 HAL 中的 `GPIO_MODE_AF_PP`；枚举名称随库和系列变化

### 2.15.4 模拟模式（Analog Mode）

- 用于 ADC 输入、DAC 输出、节省功耗（禁止数字输入）
- 例如：GPIO_Mode_AIN

### 2.15.5 区别总结

- **推挽**：主动输出高/低电平，适合驱动能力强的场景
- **开漏**：只能拉低，需要上拉才能输出高，适合多设备共用总线
- **上拉/下拉输入**：用于稳定输入状态，防止悬空
- **模拟模式**：禁用数字电路，直接传给 ADC/DAC

### 2.15.6 常用外设 GPIO 模式

| 用途 | 常见模式 | 电气行为 | 典型外设/场景 | 注意事项 |
|---|---|---|---|---|
| 普通输入 | 浮空、上拉、下拉 | 输入数据寄存器采样引脚电平 | 按键、数字传感器 | 输入悬空会产生不确定电平；内部上下拉能力和可选项随系列变化 |
| 推挽输出 | 推挽输出 | 高低电平都由端口主动驱动 | LED、片选、控制信号 | 注意输出电流、速度和外部负载，不能与其他强驱动输出直接并联 |
| 开漏输出 | 开漏输出 | 只能主动拉低，高电平依靠上拉 | I²C、线与信号、共享告警线 | 上拉电阻决定上升时间和静态电流，必须确认电平兼容 |
| 复用推挽 | 复用功能推挽 | 由 USART/SPI/TIM 等外设控制输出 | UART TX、SPI SCK/MOSI、PWM | 需要正确选择复用映射、端口速度和外设时钟 |
| 复用开漏 | 复用功能开漏 | 外设输出保持开漏特性 | I²C SDA/SCL、部分共享总线 | 结合外部上拉和总线电容校核时序 |
| 模拟 | 模拟输入/模拟开关关闭 | 关闭数字输入路径，降低泄漏和噪声 | ADC、低功耗模拟输入 | 不要把模拟引脚误配置成数字输入；DAC 输出能力需按芯片手册确认 |

STM32 不同系列的 HAL/LL/标准外设库枚举值并不完全相同，尤其是 F1 的复用配置与较新系列的 `Alternate` 字段不同。回答时应以目标芯片参考手册和库版本为准；不能把 `GPIO_MODE_INPUT_PULLUP` 等枚举直接当作所有 STM32 都存在。

## 2.16 常用外设及基本功能与应用场景

### 2.16.1 ADC（Analog-to-Digital Converter，模数转换器）

- **功能**：将模拟信号（电压、电流）转换为数字信号
- **使用场景**：
    a. 传感器数据采集（温度、压力、光强等）
    b. 工业控制系统输入测量
    c. 音频信号采样
- **注意事项**：
    - 分辨率（8/10/12/16 位）决定精度
    - 采样速率影响实时性
    - 输入阻抗匹配与参考电压稳定性影响精度

### 2.16.2 DAC（Digital-to-Analog Converter，数模转换器）

- **功能**：将数字信号转换为模拟信号
- **使用场景**：
    a. 模拟信号输出（电压控制器、电机驱动）
    b. 音频播放
    c. 信号生成器
- **注意事项**：
    - 分辨率影响输出精度
    - 输出滤波（RC 或低通滤波器）减少阶梯噪声

### 2.16.3 定时器/计数器（Timer/Counter）

- **功能**：
    a. 精确计时
    b. 事件计数
    c. PWM 生成
- **使用场景**：
    a. 定时任务触发（周期中断）
    b. PWM 控制电机、LED 调光
    c. 测量频率、脉宽、信号周期
- **注意事项**：
    - 时钟源选择影响精度
    - 溢出中断需合理处理

### 2.16.4 USART/UART（Universal Synchronous/Asynchronous Receiver/Transmitter）

- **功能**：串行通信接口，支持同步/异步传输
- **使用场景**：
    a. PC 端调试输出
    b. 模块间通信（GPS、蓝牙、GPRS）
    c. 简单协议数据传输
- **注意事项**：
    - 波特率匹配
    - 数据位、停止位、校验位需一致
    - 短距离适合异步 UART，长距离可选 RS-485

### 2.16.5 SPI（Serial Peripheral Interface，串行外设接口）

- **功能**：高速全双工同步串行通信
- **使用场景**：
    a. 外设数据传输（Flash、ADC/DAC、传感器）
    b. 高速短距离模块间通信
- **特点**：
    - 主从模式，支持多个从设备
    - 速度快，适合大数据量传输
- **注意事项**：
    - 时钟极性、相位（CPOL/CPHA）需匹配
    - 需单独 CS 信号选择从设备

### 2.16.6 I2C（Inter-Integrated Circuit，集成电路间串行通信）

- **功能**：两线（SCL、SDA）同步串行通信，支持多主多从
- **使用场景**：
    a. 低速外设通信（EEPROM、温湿度传感器、RTC）
    b. 嵌入式板子内部模块互连
- **特点**：
    - 简化引脚占用
    - 支持多设备，地址寻址
- **注意事项**：
    - 总线电阻拉高（上拉电阻）
    - 数据速率有限（标准 100kHz、快速 400kHz、快速模式+ 1MHz）
    - 确保设备唯一地址

### 2.16.7 总结

ADC/DAC 负责模拟数字互转，定时器用于计时与 PWM，USART/UART 做串口通信，SPI 高速短距离主从通信，I2C 两线低速多设备通信。

## 2.17 DMA 与中断结合使用的场景

### 2.17.1 基本概念

- **DMA（Direct Memory Access，直接内存访问）**：外设与内存之间直接传输数据，无需 CPU 干预
- **中断（Interrupt）**：当某事件发生时通知 CPU 处理
- **结合使用**：DMA 完成数据传输后触发中断通知 CPU，处理后续逻辑

### 2.17.2 数据采集类场景

- **ADC 数据采集**：
    - 大量采样数据写入内存
    - DMA 自动存储，采集完成触发中断处理数据
    - 优势：减少 CPU 占用，保证高采样速率
- **传感器连续数据读取**：
    - SPI/I2C 连续读取温度、压力、光强等
    - DMA 自动填充缓冲区，中断通知上层处理

### 2.17.3 数据发送/输出场景

- **DAC 或 PWM 数据输出**：
    - DMA 将数组数据传输到 DAC 寄存器
    - 输出完成中断触发下一批数据传输
    - 应用：音频播放、信号生成器
- **USART/SPI/TFT 显示数据发送**：
    - DMA 自动将数据发送到外设寄存器
    - 中断在传输完成或半传完成时触发
    - 优势：实现高速、连续、非阻塞通信

### 2.17.4 大块数据传输场景

- **内存-内存传输**：
    - DMA 直接在 RAM/Flash 之间搬运数据
    - 中断通知搬运完成，用于下一步处理
- **USB/以太网数据包传输**：
    - DMA 自动填充缓冲区
    - 中断用于接收完成或发送完成处理

### 2.17.5 总结

DMA 与中断结合使用可实现高效非阻塞数据传输：DMA 完成搬运，CPU 通过中断处理后续逻辑，常用于 ADC 采集、DAC 输出、USART/SPI 发送、USB/以太网及内存搬运场景。

## 2.18 UART 收发中断和 DMA 的优缺点

UART 数据的收发可以采用中断方式或 DMA 方式，二者在 CPU 占用、实时性和适用场景上各有侧重，具体见下文。

### 2.18.1 UART 收发中断（Interrupt）

- 优点：
    - 实现简单，适合数据量小的场景
    - 代码逻辑清晰，易于调试
    - CPU 可以及时处理每一字节数据

- 缺点：
    - 高速、大量数据时 CPU 占用高
    - 中断频繁，可能影响实时任务
    - 不适合连续大数据流

### 2.18.2 UART 收发 DMA

- **优点**：
    - CPU 参与少，适合大数据量或高速通信
    - 支持连续传输，降低中断频率
    - 与中断结合可在传输完成或半传完成时处理数据
- **缺点**：
    - 配置复杂，需要正确设置缓冲区和 DMA 通道
    - 调试较困难
    - 只适合块传输，不适合频繁、零散的小数据

### 2.18.3 总结

- 中断方式适合小数据量、实时性要求高、实现简单的场景
- DMA 方式适合大数据量、连续通信，降低 CPU 占用
- 实际应用中常结合使用：DMA 负责数据搬运，中断负责处理传输完成后的逻辑

## 2.19 STM32 内部看门狗（IWDG）和独立看门狗（WWDG）区别

### 2.19.1 IWDG（Independent Watchdog，独立看门狗）

- **时钟源**：内部低速独立时钟 LSI（32 kHz 左右）
- **特点**：
    - 独立于主系统时钟，CPU 停机或挂死也能工作
    - 配置后无法通过软件关闭（增强可靠性）
    - 用于系统硬件故障或死循环恢复
- **典型应用**：确保系统在 CPU 停机或主时钟异常时能复位

### 2.19.2 WWDG（Window Watchdog，看门狗）

- **时钟源**：通常来自对应 APB 时钟（例如部分 F1 器件为 PCLK1 经固定分频），具体分频和时钟门控以系列参考手册为准
- **特点**：
    - 可设置**时间窗口**（Window）
    - 必须在窗口期内刷新，否则复位
    - 适合捕获软件异常或逻辑错误
    - 启动后通常不能仅靠写寄存器停止，只能通过复位重新初始化；是否支持重新配置、窗口规则和写保护以具体系列手册为准
- **典型应用**：软件监控，防止任务长时间阻塞或错误执行

### 2.19.3 IWDG 与 WWDG 的区别

|特性|IWDG（独立看门狗 Independent Watchdog）|WWDG（窗口看门狗 Window Watchdog）|
|---|---|---|
|驱动源|独立低速内部时钟（LSI）|对应 APB 时钟及芯片规定的预分频|
|功能|防止系统死循环或卡死，自动复位|限定刷新窗口，防止过早或过晚刷新，增强安全性|
|刷新要求|可在任意时间刷新，只要不超时|必须在窗口时间内刷新，否则复位|
|可用性|始终运行，与主程序独立|需由主程序启动，依赖系统时钟|
|应用场景|核心系统稳定性保护|高安全性任务，需要严格监控操作节奏|

### 2.19.4 总结

- IWDG 用于硬件级复位，独立于系统时钟，防止 CPU 死锁
- WWDG 用于软件级复位，窗口期控制刷新，防止任务阻塞
- 实际应用中通常同时使用 IWDG + WWDG，提高系统可靠性

## 2.20 STM32 的低功耗模式区别

### 2.20.1 Sleep 模式

- **特性**：CPU 停止执行，外设保持运行
- **功耗**：通常高于 Stop/Standby，但唤醒延迟较小
- **唤醒方式**：外部中断或内部中断
- **适用场景**：短时间空闲等待中断，快速响应任务

### 2.20.2 Stop 模式

- **特性**：CPU 和大部分外设停止，主 PLL 停止，HCLK 停止，部分外设时钟可保留
- **功耗**：比 Sleep 更低
- **唤醒方式**：外部事件、RTC 等；IWDG 若在低功耗模式继续运行，超时通常表现为复位而非普通唤醒，是否运行由系列电源/看门狗配置决定
- **适用场景**：空闲时间较长，需要极低功耗，但希望保留 SRAM 内容

### 2.20.3 Standby 模式

- **特性**：CPU 停止，外设关闭，主时钟和 PLL 停止；多数 STM32 系列的主 SRAM 和普通寄存器内容不保留，仅备份域内容可保留，具体保留项以系列电源章节为准
- **功耗**：最低，接近断电
- **唤醒方式**：按系列可由 WKUP/外部事件、RTC 等唤醒；IWDG 超时通常导致复位而不是普通唤醒，具体行为以芯片手册为准
- **适用场景**：长时间休眠，最大限度降低功耗，系统完全复位后恢复

### 2.20.4 总结

- Sleep：CPU 停，外设运行，快速唤醒，功耗低
- Stop：CPU 停，大部分外设停，保留 SRAM，唤醒稍慢，功耗更低
- Standby：CPU 和外设停，多数系列的主 SRAM 不保留，功耗最低，唤醒后通常按复位路径重新启动

## 2.21 STM32  Bootloader的作用

### 2.21.1 基本概念

- **Bootloader**：启动加载程序；只有在启动引脚/选项字节选择相应启动介质，或用户 Flash 中的引导代码被复位向量选中时，它才会成为复位后首先执行的软件
- **存放位置**：用户自定义 Bootloader 通常位于片内 Flash 的固定区域；ST 出厂系统存储器中的 ROM/系统 Flash Bootloader 是另一套固件，地址和功能随系列不同
- **主要功能**：初始化系统、跳转用户应用程序或进行固件升级

### 2.21.2 主要作用

1. **初始化系统**
    - 配置时钟、堆栈、内存和基本外设
    - 准备 MCU 进入应用程序运行环境
2. **用户程序加载**
    - 将用户应用程序从 Flash 或外部存储（如 UART、USB、SPI Flash）加载到执行地址
    - 支持上电直接执行用户程序
3. **固件升级（OTA 或串口升级）**
    - 通过 UART、USB DFU、CAN 等接口更新应用程序
    - Bootloader 自身通常不修改，保证升级安全
4. **系统恢复**
    - 当应用程序损坏或升级失败时，Bootloader 可提供最小功能的恢复接口

### 2.21.3 总结

- 在选定的启动配置下，Bootloader 是 MCU 上电或复位后首先执行的应用软件；默认从用户 Flash 启动时也可能直接进入应用，而不经过独立 Bootloader
- 负责系统初始化、加载和跳转用户程序
- 支持安全可靠的固件升级和系统恢复
- 对嵌入式系统可靠性和维护性非常重要
