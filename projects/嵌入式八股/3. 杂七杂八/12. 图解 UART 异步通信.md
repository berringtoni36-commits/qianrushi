大家好，我是蟹老板~

要问我最常用的通信接口是哪个？

那就是 UART，没有之一。

你说它高级吧，确实不高级；你说它过时吧，每个项目都离不开它。可以说它是嵌入式界的“万金油”。

## 一、前置知识

### 1.1 串行通信 vs 并行通信

所有硬件数据传输，本质上就分两种模式，串行通信和并行通信。我们日常接触的UART、I2C、SPI都是串行通信，而单片机的并口、老式电脑的打印口，用的都是并行通信逻辑。

问你个问题：数据怎么从A设备传到B设备？

我们用上面的2种方式，并行通信是一次性传多位数据，8位数据就拉8根线，16位就拉16根线。

```
发送端                         接收端D7  ─────── 1 ───────────────> D7D6  ─────── 0 ───────────────> D6D5  ─────── 1 ───────────────> D5D4  ─────── 1 ───────────────> D4D3  ─────── 0 ───────────────> D3D2  ─────── 1 ───────────────> D2D1  ─────── 0 ───────────────> D1D0  ─────── 0 ───────────────> D0
```

串行通信是一根线挨个bit往外吐。

```
时间  ─────────────────────────────────────>数据线      1     0     1     1     0     1     0     0          ────  ____  ────  ────  ____  ────  ____  ____
```

并行快不快？快。但代价是什么呢？

线太多了，8位数据需要8根线，通常还得加时钟、片选、读写控制和地线。接口一宽，PCB 空间就开始告急。连接器变大，线缆变粗，焊接和维护成本也跟着涨。稍微有点干扰，数据就对不齐。传输距离稍微长一点，信号衰减得没法看。

串行通信的逻辑刚好相反。一根数据线搞定发送，一根搞定接收，再加一根地线。PCB走线清爽得多，成本也低。缺点嘛就是速度确实比不上并行——毕竟一次只能传一个bit。但对于单片机之间的通信、传感器数据采集这些场景，串行那点速度完全够用。

UART选择串行，图的就是简单、省线、够用。

![[assets/embedded-interview/图解 UART 异步通信/img-001.jpg]]

### 1.2 异步通信 vs 同步通信

同步通信和异步通信。其实核心差异就一个，时钟信号的同步方式不一样。

同步通信的通信双方，必须连接一根专用的时钟信号线。主设备会持续输出固定频率的时钟脉冲，从设备完全跟随这个时钟节奏工作。时钟信号为高电平或者低电平时，对应完成数据的采样和发送。双方所有操作完全同步，节奏高度统一，数据传输的容错率很高。

以简化后的 SPI 为例：

```
主机                         从机CLK   ─────────────────────> 时钟输入MOSI  ─────────────────────> 数据输入
```

时钟每跳一次，双方就按约定采样一位数据。数据线告诉接收端“值是什么”，时钟线告诉它“现在该读了”。

SPI、I2C这些常用高速串行协议，用的都是同步通信机制。它们的优势是传输速度快、数据准确率高，适配高频、大批量的数据传输场景。但缺点也很明显，需要额外占用设备引脚，布线数量变多，硬件结构会更复杂。

异步通信就完全舍弃了时钟信号线。通信的两个设备之间，没有任何统一的时钟信号做同步。看到这里很多人会疑惑，没有统一时钟，设备怎么知道什么时候收数据、什么时候读数据？

```
设备 A                       设备 BTX   ──────────────────────> RXRX   <────────────────────── TXGND  ─────────────────────── GND
```

这就是UART的设计精髓。设备出厂前会提前约定好一套统一的通信规则，也就是我们常说的波特率、数据位、校验位、停止位四大参数。两个独立的设备，各自依靠自身的本地时钟，按照约定好的相同速率收发数据。

![[assets/embedded-interview/图解 UART 异步通信/img-002.jpg]]

### 1.3 常见串口协议区分（UART/USART/RS232/RS485）

UART只支持异步通信。USART比UART多了一个“S”——Synchronous，也就是支持同步通信。当USART工作在异步模式时，跟UART没有任何区别。区别在于USART多了一根时钟线，可以像SPI那样用。

UART是协议层——它定义了数据怎么组帧、怎么传输、时序什么样。RS232和RS485是物理层——它们定义了信号用什么电平、多大电压、什么接口。

打个比方：UART是“说话的内容和语法”，RS232/RS485是“说话的声音大小和传播方式”。

具体来说，UART本身不规定电压电平，直接使用CPU的电平（03.3V或05V），这叫TTL电平。RS232用的是负逻辑电平，-3V到-15V表示逻辑1，+3V到+15V表示逻辑0，传输距离也就十几米。RS485用的是差分信号，抗干扰能力强，传输距离可达1200米。

所以当你看到有人说“RS232串口”或“RS485串口”时，本质上都是在说UART协议 + 不同的物理层实现。

本文讲的是UART协议本身，也就是TTL电平那一套。RS232和RS485的电气特性咱们先不展开。

## 二、UART 整体架构与硬件原理

### 2.1 UART 核心硬件结构

UART通信的硬件连接极其简单——就三根线：

- TX（Transmit）：发送引脚
- RX（Receive）：接收引脚
- GND：地线

TX引脚是数据发送端，负责从本机向外输出串口数据。RX引脚是数据接收端，负责接收外部设备传输过来的串口数据。

两台设备直接通信时，TX 和 RX 要交叉连接。

```
┌──────────────┐                    ┌──────────────┐│    设备 A     │                    │    设备 B     ││              │                    │              ││  TX  o───────┼───────────────────>o  RX          ││              │                    │              ││  RX  o<──────┼────────────────────o  TX          ││              │                    │              ││ GND  o───────┼────────────────────o  GND         │└──────────────┘                    └──────────────┘
```

发送端的 TX，要接接收端的 RX。

这个地方很容易在丝印上绕进去。USB 转串口模块标出的 TX，通常表示模块自己的发送端，因此应该接目标板 RX；有些转接板为了照顾接线习惯，丝印可能标成“接对端 TX”，不能只看字母，最好确认原理图或说明书。

如果只需要看设备日志，可以只接：

```
目标设备 TX  ─────>  调试器 RX目标设备 GND ─────>  调试器 GND
```

如果还要向设备发送命令，才需要把另一条方向也接上。

![[assets/embedded-interview/图解 UART 异步通信/img-004.jpg]]

### 2.2 串口通信必备前提：共地原理

GND这根线很多人不当回事，觉得就是“接地嘛，随便接接就行”。大错特错。

不共地会导致通信失败。为什么？

UART的信号电平是以GND为参考的。发送端输出一个高电平（比如3.3V），这个3.3V是相对于发送端自己的GND而言的。接收端怎么判断这个信号是高还是低？它得用自己的GND作为参考基准。

如果两个设备的GND没有连在一起，它们的“0V”基准就不一样。发送端认为的3.3V高电平，接收端可能读出来是2V或者4V——完全乱套。

我遇到过最离谱的一次，两个板子用同一个USB供电，但USB线质量太差，GND压降将近1V。结果串口数据时好时坏，排查了两天才找到原因。从那以后，我养成了一个习惯：串口调试必测GND连通性，万用表蜂鸣档响一声才放心。

所以接线的时候记住：TX对RX、RX对TX、GND对GND，三根线一根都不能少。

### 2.3 UART 模块内部工作框图

从程序员视角看，发送一个字节似乎很简单。

```
uart_send_byte(0x41);
```

函数一调用，字符就出去了。

芯片内部其实做了不少事。

一个典型 UART 模块可以抽象成下面这样。

```
                       UART 发送部分CPU 或 DMA   │   ▼发送数据寄存器或 FIFO   │   ▼发送移位寄存器   │   ├── 加入起始位   ├── 按低位优先移出数据   ├── 可选加入校验位   └── 加入停止位   │   ▼TX 引脚                       UART 接收部分RX 引脚   │   ▼起始位检测与采样电路   │   ▼接收移位寄存器   │   ├── 拼接数据位   ├── 检查校验位   └── 检查停止位   │   ▼接收数据寄存器或 FIFO   │   ▼CPU 或 DMA                公共时序部分外设时钟   │   ▼波特率发生器   │   ├── 发送位时钟   └── 接收过采样时钟
```

发送缓冲区负责暂存 CPU 写入的数据。

没有缓冲区时，CPU 必须等当前字节完整发送后，才能写入下一个字节。有了发送寄存器或 FIFO，CPU 可以提前放入一批数据，UART 硬件自己慢慢移出去。

发送移位寄存器是真正贴近 TX 引脚工作的部分。

假设 CPU 写入 `0x41`，硬件会根据当前配置生成起始位、数据位、校验位和停止位，然后按波特率逐位输出。

数据不是一下子从寄存器跳到电线上，而是一位一位被移出去，所以叫移位寄存器。

接收端的过程反过来。

RX 引脚检测到起始位后，采样电路按照波特率节奏读取电平。接收移位寄存器把每一位放到正确位置。等数据位收齐，再做校验和停止位检查。

确认完成后，一个字节才会被放进接收数据寄存器或接收 FIFO，等待 CPU 读取。

波特率发生器则负责把芯片外设时钟分频成 UART 所需节奏。

比如外设时钟是 48MHz，串口要工作在 115200 波特。硬件会根据分频寄存器生成接近目标值的发送时钟和接收采样时钟。

这里通常会出现一点误差。48MHz 不一定能被某个数整除后刚好得到 115200。误差小的时候没事，误差大了就会让采样点逐渐偏离。

这也是串口配置里波特率计算那么重要的原因。

## 三、UART 异步通信帧格式

这一章是全文的重中之重，是UART通信的核心底层逻辑。UART所有数据传输都以帧为单位，一帧完整的数据包含五个固定部分，分别是空闲状态、起始位、数据位、校验位、停止位。每一帧数据严格按照这个顺序排列，没有任何例外。

![[assets/embedded-interview/图解 UART 异步通信/img-007.jpg]]

### 3.1 空闲状态与起始位

这是整个UART最核心的设计。

空闲状态：没有数据传输时，TX引脚保持高电平（逻辑1）。

```
空闲状态                    检测到下降沿───────────────┐               │               └────────────────               ^               接收器准备对齐起始位
```

起始位：要发数据了，先把电平拉低（逻辑0），持续一个bit的时间。

```
起始位下降沿             中心采样点  │                    │  v                    v──┐  └──────────────────────┐                         └── D0
```

就这么一个从高到低的跳变，接收端就知道“有数据来了”。这就是异步通信实现帧同步的唯一手段。

接收端一直在监测RX引脚的电平。看到高电平变低电平的下降沿，立刻开始计时——按照约定的波特率去采样后面的每一个bit。

这就像接力赛，发令枪一响（起始位），大家就按照训练好的节奏（波特率）开始跑。

![[assets/embedded-interview/图解 UART 异步通信/img-008.jpg]]

### 3.2 数据位（5~8位）

起始位之后就是数据位——真正要传的数据。

UART 常见数据位长度为 5、6、7、8 位，一些控制器还支持 9 位。最常用的是8位，因为一个字节正好8位。7 位配置在早期 ASCII 通信里较常见，5 位和 6 位更多见于旧设备或特殊协议。

数据传输顺序：低位在前（LSB First）。

比如要发送十六进制0x55（二进制01010101），先发最低位——也就是先发1，再发0，再发1……最后发最高位的0。

这个顺序很多新手搞反。我第一次用逻辑分析仪抓波形的时候，明明发的是0x55，波形上看到的却是0xAA——就是因为忘了低位在前这回事。

为什么数据位不固定？早期的电传机用5位、6位、7位都有。现在基本统一用8位了。如果你用7位数据位去传ASCII字符，最高位会被截掉或者当成校验位，解析出来全是乱码。

![[assets/embedded-interview/图解 UART 异步通信/img-009.jpg]]

### 3.3 奇偶校验位（校验原理与作用）

一帧数据的最后部分是停止位，协议支持1位、1.5位、2位三种配置，日常开发默认使用1位停止位。

校验位在数据位之后，可选。

三种模式：

- 无校验（None）：不加校验位
- 奇校验（Odd）：数据位加上校验位后，“1”的个数为奇数
- 偶校验（Even）：数据位加上校验位后，“1”的个数为偶数

举个例子：发送字符'A'，ASCII码是01000001，里面有两个1。

- 奇校验：校验位=1，因为2+1=3是奇数
- 偶校验：校验位=0，因为2+0=2是偶数

校验位能干嘛？检测单bit错误。如果传输过程中某一位翻转了，接收端计算奇偶性发现对不上，就知道数据有问题了。

但校验位的局限性也很明显——只能检测奇数个bit的错误。两个bit同时翻转，奇偶性不变，检测不出来。而且它只能检错不能纠错。所以现在很多应用干脆不用校验位，把校验交给上层协议去做。

![[assets/embedded-interview/图解 UART 异步通信/img-010.jpg]]

### 3.4 停止位（1/1.5/2位）

数据位（和校验位）传完之后，发送端把电平拉高，持续1个、1.5个或2个bit的时间。

```
最后一个数据位        停止位             下一帧起始位       │                  │                    │       v                  v                    v───────┐          ┌─────────────────────┐       └──────────┘                     └────────
```

这就是停止位。

停止位的作用有两个：

1. 1. 标记一帧数据的结束
2. 2. 给接收端一个“喘息”的机会，重新校准时钟

停止位时间越长，容错能力越强。但代价是传输效率降低——停止位占用的时间越长，单位时间内能传的有效数据就越少。

停止位固定为高电平，常用配置是1个停止位。1.5位和2位主要在特殊场合使用。

![[assets/embedded-interview/图解 UART 异步通信/img-011.jpg]]

### 3.5 完整案例：一个字节如何变成 UART 波形

用字符 `A` 做完整推导。

#### 第一步：找到 ASCII 编码

```
'A' = 0x41
```

#### 第二步：转成 8 位二进制

```
0x41 = 0100 0001
```

按位编号：

```
D7 D6 D5 D4 D3 D2 D1 D0 0  1  0  0  0  0  0  1
```

#### 第三步：按 UART 的低位优先重新排列

```
发送顺序：D0 D1 D2 D3 D4 D5 D6 D7 1  0  0  0  0  0  1  0
```

#### 第四步：按 8N1 加上起始位和停止位

```
起始位  D0 D1 D2 D3 D4 D5 D6 D7  停止位   0     1  0  0  0  0  0  1  0     1
```

整帧一共 10 bit：

```
0 1 0 0 0 0 0 1 0 1
```

注意，这串数字是按时间顺序写的，不是把它当成普通二进制数再转一次十六进制。

#### 第五步：画到时间轴上

```
时间  ─────────────────────────────────────────────────────────────>字段   Idle Start  D0   D1   D2   D3   D4   D5   D6   D7  Stop Idle数值     1    0     1    0    0    0    0    0    1    0    1    1电平  ─────┐     ┌────┐                           ┌────┐     ┌────────           │     │    │                           │    │     │           └─────┘    └───────────────────────────┘    └─────┘
```

再看一个更适合拿来检查时序的值：`0x55`。

```
0x55 = 0101 0101D0 到 D7：1 0 1 0 1 0 1 0
```

它的数据位会高低交替，逻辑分析仪上非常整齐。测波特率、查反相、看某一位是否被拉宽时，0x55 比随机字符串好用得多。

====
理论讲了一堆，咱们来走一遍完整的流程。

**场景**：发送字符'A'，ASCII码0x41（二进制01000001），配置8N1（8位数据、无校验、1位停止位），波特率9600。

**第一步：准备数据**
'A'的ASCII码是0x41 = 01000001（二进制）。

**第二步：低位在前**
01000001从低位到高位排列：1 → 0 → 0 → 0 → 0 → 0 → 1 → 0。

也就是说，先发最低位（LSB），再依次往上，最后发最高位（MSB）。

**第三步：组帧**
完整的一帧长这样：
`起始位(0) + 数据位(10000010) + 停止位(1)`

注意数据位是低位在前，所以顺序是1、0、0、0、0、0、1、0。

**第四步：生成波形**

- 空闲状态：高电平
- 起始位：拉低（0）
- 数据位bit0：1（高）
- 数据位bit1：0（低）
- 数据位bit2：0（低）
- 数据位bit3：0（低）
- 数据位bit4：0（低）
- 数据位bit5：0（低）
- 数据位bit6：1（高）
- 数据位bit7：0（低）
- 停止位：拉高（1）

每个bit持续的时间 = 1/9600 ≈ 104微秒。

整个帧总共10个bit（1个起始位+8个数据位+1个停止位），耗时10×104≈1.04毫秒。

这就是一个字节变成UART波形的完整过程。你拿逻辑分析仪去抓TX引脚，看到的就是这个波形。

### 3.6 UART 字节流特性：无消息边界说明

讲完了一帧怎么传，但有个事儿得专门拎出来说一下——UART只认识字节，不认识“包”。

你在应用层发了一个“数据包”，比如`[0xAA, 0x55, 0x01, 0x02, 0x03]`这5个字节。UART不管这些，它就老老实实把这5个字节挨个发出去。

接收端收到的是什么？也是一串连续的字节流。

问题来了：如果发送端连续发了两包数据——
第一包：`[AA 55 01 02 03]`
第二包：`[AA 55 04 05 06]`

接收端可能一次性收到`[AA 55 01 02 03 AA 55 04 05 06]`——两包粘在一起了，这叫粘包。

也可能只收到`[AA 55 01]`，剩下的`[02 03 AA 55 04 05 06]`下次才到——一包被拆开了，这叫拆包（也叫半包）。

这不是Bug，这是UART的天然特性。UART本身就没有“帧”的概念，它只是字节流的搬运工。

那怎么办呢？我们可以在应用层自己定义协议。比如用帧头帧尾来标识边界（`AA 55`开头、`0D 0A`结尾），或者固定每个包的长度，再或者加个长度字段。

很多人被粘包搞崩溃，觉得是自己代码写错了。其实不是——是UART“太老实”了，它只管传字节，不管分包裹。

![[assets/embedded-interview/图解 UART 异步通信/img-013.jpg]]

## 四、波特率

如果说帧格式是UART的骨架，那波特率就是UART的心跳。异步通信能正常工作的唯一核心前提，就是收发双方波特率完全一致。

### 4.1 波特率定义与核心作用

波特率表示每秒传输多少个符号，单位是 Baud。常见的波特率有9600、19200、38400、115200等。

比特率表示每秒传输多少个 bit，单位是 bit/s。

在普通二进制 UART 中，一个符号只有高、低两种状态，每个符号承载 1 bit，因此二者数值通常相同：

```
115200 Baud ≈ 115200 bit/s
```

概念上仍然不是同一个量。在一个符号能表达多个 bit 的调制系统里，波特率和比特率就不会相等。

异步通信双方波特率必须一致。这跟两个人说话得用同一种语言一个道理。

发送端更快时，实际位宽更短；接收端更慢时，采样点会逐位向后漂。反过来则逐位向前漂。偏移积累到位边界附近，读到的可能已经是相邻 bit。

![[assets/embedded-interview/图解 UART 异步通信/img-014.jpg]]

### 4.2 常用标准波特率与误差分析

为什么是9600、115200这些“奇怪”的数字？

因为这些都是从晶振频率分频得来的。比如11.0592MHz晶振，分频下来刚好能得到9600、19200等整数。

波特率误差是怎么来的？分频除不尽。

举个例子，系统主时钟72MHz，要得到115200波特率：
USARTDIV = 72×10⁶ / (16×115200) = 39.0625

这个0.0625就是误差的来源。实际波特率跟理论值差一点点。

波特率误差超过3%就可能导致间歇性的帧错误。表现就是：大部分数据正常，偶尔冒出来几个乱码。

我在一个项目里遇到过这种情况——设备批量生产时，一批板子的晶振精度不够，波特率偏差了4%。结果就是通信时好时坏，排查了一个星期才发现是晶振批次的问题。

![[assets/embedded-interview/图解 UART 异步通信/img-015.jpg]]

### 4.3 波特率时钟采样原理

接收端怎么从波形里把数据“读”出来？

它用比波特率高N倍的采样时钟去采样RX引脚。最常用的是16倍频采样。

啥意思？
波特率9600，采样时钟就是9600×16=153.6kHz。每个bit被采样16次。

具体怎么采？在每一个bit的中间位置取一个样点——因为bit边沿可能有抖动，中间最稳定。

16倍频采样还有个好处——容错。如果波特率有微小偏差，16次采样里选中间那几次的值，能有效抵抗偏差。

![[assets/embedded-interview/图解 UART 异步通信/img-016.jpg]]

### 4.4 帧长度与有效传输速率精准计算

8N1配置：1个起始位 + 8个数据位 + 0个校验位 + 1个停止位 = 10个bit/帧。

波特率115200bps，每秒传115200个bit。

每帧10个bit，所以每秒能传 115200/10 = 11520帧/秒。

每帧1个字节的有效数据，所以有效数据速率 = 11520 字节/秒 ≈ 11.25 KB/s。

传输损耗 = (10-8)/10 = 20%。每传10个bit，只有8个是有效数据，2个是“包装”（起始位和停止位）。

如果用了校验位（8N1变成8E1），每帧变成11个bit，有效数据速率进一步降低到 115200/11 ≈ 10472 字节/秒 ≈ 10.2KB/s。

这就是为什么高速传输场景一般不推荐用UART——协议开销太大。但低速传感器数据采集、调试信息打印这些场景，UART完全够用。

![[assets/embedded-interview/图解 UART 异步通信/img-017.jpg]]

## 五、UART 数据收发完整流程

我们把整套流程串联起来，完整拆解单字节、多字节的收发全过程。

### 5.1 单次字节数据发送全过程

假设 CPU 要发送 `0x41`，UART 配置为 8N1。

发送路径可以拆成下面几步：

```
CPU 写入 0x41      │      v发送数据寄存器或 TX FIFO      │      v搬入 TX 移位寄存器      │      v补起始位 0      │      v按 D0 到 D7 依次发送      │      v发送停止位 1      │      v线路恢复空闲高电平
```

移位寄存器工作时，CPU 不需要每隔 8.68 μs 手工翻转一次 GPIO。硬件按波特率发生器提供的节拍自动完成。

连续发送时，常见状态是：

```
TX 移位寄存器：正在发送当前字节TX 数据寄存器：已经装好下一个字节CPU：可以准备后续数据
```

只要软件补数据足够及时，字符之间可以无缝连接：

```
帧 1 停止位  帧 2 起始位      1            0───────┐      ┌─────       └──────┘
```

中间不要求额外空闲时间。

整个过程发送端不需要接收端的任何回应。发完就完了，至于接收端有没有收到、收到的是不是对的——发送端不管。

这就是UART的“草率”之处——没有握手机制。

![[assets/embedded-interview/图解 UART 异步通信/img-018.jpg]]

### 5.2 单次字节数据接收全过程

接收过程稍复杂，因为它要处理时序误差和非法帧。

```
RX 保持高电平      │检测到下降沿      │等待到起始位中心      │确认仍为低电平      │依次采样 D0～D7      │按位拼入 RX 移位寄存器      │检查校验位      │检查停止位是否为高      │写入接收寄存器或 RX FIFO      │产生中断、DMA 请求或状态标志
```

接收端最核心的任务就是找准每个bit的采样点。起始位的下降沿是“起点”，之后每隔一个bit的时间采一次样。

如果停止位位置仍然为低，硬件一般会记录帧错误；校验结果不对，则记录校验错误；新数据到达时旧数据还没被软件取走，可能产生溢出错误。

不同芯片对错误字节的处理不同：

- 有的仍把错误数据放入接收寄存器，只设置错误标志；
- 有的可以配置为丢弃；
- 有的要求按特定顺序读取状态寄存器和数据寄存器，才能清除错误；
- 有的 FIFO 中会给每个字节附带错误状态。

驱动只读数据、不处理错误标志，现场出现乱码时就会少掉一半线索。

![[assets/embedded-interview/图解 UART 异步通信/img-019.jpg]]

### 5.3 连续多字节通信的缓冲区机制

连续收发多个字节时，缓冲区就派上用场了。

没有缓冲区会怎样？发送端一个字节一个字节地发，接收端来一个字节处理一个字节。如果处理得慢，下一个字节来了，上一个还没处理完——数据就丢了。

缓冲区就是个临时仓库。接收端把收到的字节先存起来，CPU有空了再来取。只要缓冲区没满，就不会丢数据。

常见的缓冲区设计是环形缓冲区（Ring Buffer/Circular Buffer）。写指针和读指针在缓冲区里转圈，只要不追尾就没事。

缓冲区大小怎么定？看数据量和处理速度。如果每秒收100个字节，CPU每毫秒能处理一个字节——那缓冲区有几十个字节就够了。如果数据来得又快又猛，缓冲区就得大一点。

![[assets/embedded-interview/图解 UART 异步通信/img-020.jpg]]

## 六、UART 关键特性与通信规则总结

### 6.1 全双工通信原理

UART是全双工的——发送和接收可以同时进行。

```
设备 A TX ─────────────> 设备 B RX设备 A RX <───────────── 设备 B TX
```

两根线可以同时变化，所以设备 A 在发送数据时，也能接收设备 B 的数据。

为什么？因为TX和RX是独立的两个引脚、两套移位寄存器。发送数据的时候不影响接收，接收数据的时候也不影响发送。收发不会因为共用一根数据线而互相抢占。

这是全双工。

但是加上外部收发器后，系统未必仍然全双工。两线制 RS485 常把发送和接收共用在同一对 A/B 线上，需要控制方向，一般按半双工使用。UART 控制器本身支持全双工，不代表板级接口一定全双工。

这跟对讲机不一样——对讲机是半双工的，说的时候不能听，听的时候不能说。UART是打电话，两边可以同时说话。

### 6.3 通信双方必须匹配的四大参数

UART通信要想正常，双方必须在四个参数上保持一致：

1. 1. 波特率（Baud Rate）：9600、115200等
2. 2. 数据位（Data Bits）：通常8位
3. 3. 校验位（Parity）：无/奇/偶
4. 4. 停止位（Stop Bits）：通常1位

任何一个不匹配，结果就是乱码。

波特率不匹配：接收端采样的节奏不对，读出来的bit全是错的。数据位不匹配：接收端不知道哪里是数据哪里是校验/停止，帧结构全乱。校验位不匹配：接收端把校验位当数据读，或者反过来。停止位不匹配：接收端找不准下一帧的起始位置。

所以调试串口的时候，第一步永远是对参数。参数对了再查别的，能省一半时间。

## 七、常见UART通信问题与乱码排查（实战向）

### 7.1 数据乱码核心原因

串口打印出来全是乱码？别慌，按这个顺序排查。

**1. 波特率不匹配**（最常见）
发送端115200，接收端9600——读出来的数据绝对是天书。解决方法：检查两边的波特率设置是不是一样的。

**2. 参数配置不一致**
数据位、校验位、停止位任何一个对不上，都会导致乱码。比如发送端8N1，接收端8E1——接收端把校验位当数据读，肯定乱。

**3. 未共地**
GND没接好，电平基准不对，读出来的全是错的。用万用表测一下两个设备GND之间的电阻，应该接近0Ω。

**4. 电平不匹配**
3.3V的UART接到5V的UART。如果5V设备不兼容3.3V电平，可能读不到高电平。解决方法：加电平转换芯片。

**5. 缓冲区溢出**
数据来得太快，CPU来不及处理，后面的数据就把前面的覆盖了。表现出来的现象是：数据断断续续，中间缺了一段。解决方法：加大缓冲区，或者用DMA。

![[assets/embedded-interview/图解 UART 异步通信/img-024.jpg]]

### 7.2 丢包、断连、数据错位问题排查思路

**丢包**——数据发出去没收到，或者收到的数据少了。
先看是不是缓冲区满了。再看是不是中断优先级太低——接收中断被其他中断打断了，数据来不及取就没了。

**断连**——通信时好时坏。
先查硬件连接——线是不是松了。再查电源——供电不稳定可能导致电平异常。最后查干扰——电机、开关电源这些强干扰源可能影响信号质量。

**数据错位**——收到的数据整体偏移了。
最典型的是少了一个字节或者多了一个字节，导致后面所有的数据都错位了。这通常是帧同步丢失造成的——某个字节的起始位没被正确识别，接收端从错误的位置开始采样。波特率偏差累积到一定程度就会这样。

### 7.4 基于逻辑分析仪的波形故障判断方法

软件调不通的时候，上逻辑分析仪。

逻辑分析仪能看到物理层的波形。波特率对不对、起始位有没有、停止位正不正常——一目了然。

**怎么抓波形**：
把逻辑分析仪的通道夹到TX引脚上，GND夹到板子的GND上。设置好采样率（至少是波特率的4倍），触发方式选下降沿触发。然后让设备发数据，就能抓到波形了。

**怎么看波形**：
正常波形：空闲时高电平，起始位拉低，数据位按LSB first排列，停止位拉高。每个bit的宽度一致。

波特率偏移：bit宽度不对。9600应该是104微秒一个bit，你测出来120微秒——那就是波特率不对。

帧错误：停止位的位置不是高电平。接收端在停止位的位置读到了低电平，说明帧结构出问题了。

数据错误：波形看起来正常，但解码出来不是你要发的数据——检查是不是低位/高位顺序搞反了。

噪声干扰：波形上有毛刺、边沿不干净——说明信号质量不行，可能是线太长或者有干扰。

抓一次波形胜过看一百遍代码。物理层的问题，物理层的工具来解决。

## 八、UART 典型应用场景

**单片机串口调试**：最经典的应用。printf重定向到串口，把程序运行状态打印出来。变量值、函数调用、错误信息——全都看得到。

**蓝牙/WiFi模块通信**：蓝牙模块、WiFi模块基本都是通过UART跟MCU通信的。MCU发AT指令控制模块，模块返回数据。四轴飞行器、智能家居、可穿戴设备——背后都是UART在干活。

**传感器数据传输**：温湿度传感器、气压计、GPS模块——很多都走UART。传感器定时往外吐数据，MCU负责收。

**设备串口打印与日志**：工业设备、医疗设备、智能仪表——通过串口输出运行日志。出了问题接上串口就能看，不需要拆机。

**OTA固件升级**：通过串口给设备烧录新固件。很多产品的bootloader就是基于UART做的。

## 总结

好，咱们从头捋一遍。

UART的核心就三根线——TX、RX、GND。它用起始位的下降沿来同步，靠双方约定的波特率来保证每个bit的节奏。一帧数据由起始位、数据位（可选校验位）、停止位组成。收发各走各的线，所以能全双工。

参数必须匹配——波特率、数据位、校验位、停止位，一个都不能错。出了问题先查参数，再查硬件（共地、接线），最后上逻辑分析仪看波形。

说起来就这么点东西，但用好了能解决百分之八十的设备间通信需求。

学完UART之后可以往哪走？

往上走是串口编程——怎么用中断、怎么用DMA、怎么写稳定的串口驱动。再往上走是协议设计——怎么定义帧格式、怎么处理粘包、怎么做校验和重传。往下走可以看看RS485和Modbus——把UART的距离拉长、把单点通信变成多点通信。
