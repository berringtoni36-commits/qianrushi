今天我们聊聊嵌入式开发中5种总线协议： **UART、RS232、RS485、I²C、SPI**

## 一、通信基础知识

### 1.1 为什么要学习串行通信接口

我做嵌入式开发也有几个年头了，面试过不少人，也被人面试过。有个面试题继续必出现——“你用过哪些通信接口？”说实话，能把 **UART、RS232、RS485、I²C、SPI** 这五个讲明白的候选人，真不多。大多数人停留在“调过例程”的层面，稍微问深一点就露馅了。

这些接口是嵌入式系统的“神经系统”。传感器要读数、显示屏要刷新、固件要升级、设备要联网，哪一样都离不开它们。 **搞不懂这些，你写的代码再漂亮，数据也传不出去。**

### 1.2 通信系统的基本组成

任何通信系统都能拆成三块： **发送端** 、 **传输介质** 、 **接收端** 。发送端把数据变成电信号，电信号沿着介质跑，接收端再把电信号变回数据。

听起来简单对吧？但实际情况是—— **信号会在路上变形、被干扰、甚至完全丢失** 。所以咱们不光要会发数据，还得知道怎么让数据安全到达。

![[img-001.png]]

### 1.3 串行通信与并行通信

**串行通信** 就像单车道公路，数据一个比特一个比特地排队通过。 **并行通信** 呢，是多车道——8位、16位甚至32位同时传输。

并行看起来快，但有个致命问题：车道之间信号会互相干扰（这叫 **串扰** ），而且线太多了。你想想，32条数据线加上控制线，PCB上得占多大地方？所以现在除了内存和某些专用接口， **大部分通信都改成串行了** 。串行虽然“慢”一点，但省线、抗干扰、适合长距离。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-002.png]]

### 1.4 同步通信与异步通信

**同步通信** 带一根时钟线（SCLK），发送方和接收方跟着同一个节拍走。 **I²C和SPI就是同步的** 。

**异步通信** 没有时钟线，双方得事先约好速度（ **波特率** ），各走各的节奏。 **UART就是典型的异步通信** 。

同步的优势是速度快、时序准；异步的优势是省一根线、连接简单。没有谁绝对好，看场景。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-003.png]]

### 1.5 单端通信与差分通信

**单端通信** 用一根信号线加一根地线，信号电压是对地测量的。RS232和TTL串口都是单端的。

**差分通信** 用两根线（A和B），信号是两根线之间的电压差。 **RS485就是差分的** 。

**差分的抗干扰能力强太多了** 。你想啊，干扰信号同时出现在两根线上，一减就抵消了。这就是为什么 **RS485能传1200米，而RS232只能传15米** 。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-004.png]]

### 1.6 单工、半双工与全双工

- • **单工** ：只能一个方向传，比如电视遥控器发信号给电视。
- • **半双工** ：两个方向都能传，但不能同时，比如对讲机。
- • **全双工** ：两个方向同时传，比如打电话。
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-005.png]]

### 1.7 点对点通信与多节点通信

**点对点** 就是两个设备之间通信，UART和RS232都是这种。

**多节点通信** 是一条总线上挂多个设备，RS485和I²C都支持。 **RS485标准最多支持32个节点** ，用特殊芯片能到128甚至256个。 **I²C理论上支持127个设备** （7位地址去掉广播地址）。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-006.png]]

### 1.8 主机、从机与通信节点

主机（Master）发起通信、产生时钟、控制总线。从机（Slave）被动响应。I²C和SPI是明确的主从结构。UART是点对点，两边平等，但通常也约定一个发起方。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-007.png]]

### 1.9 数据位、波特率与比特率

**数据位** 就是一帧里实际传的数据有多少个比特，常见的是8位。

**波特率（Baud Rate） **是每秒传多少个符号。对于串口通信，一个符号就是一个比特，所以** 波特率=比特率** 。 **115200** 就是每秒传115200个比特。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-008.png]]

### 1.10 起始位、停止位与校验位

UART一帧数据的标准结构是： **1个起始位（低电平）+ 8个数据位 + 1个停止位（高电平）** 。

- • **起始位** 告诉接收端“我要开始发了”。
- • **停止位** 告诉接收端“这帧结束了”。
- • **校验位** 用来检查数据有没有传错，可以选奇校验、偶校验或者不要校验。
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-009.png]]

### 1.11 时钟信号与数据同步

同步通信有时钟线，数据在时钟的边沿采样，精确可靠。

异步通信没有时钟线，接收端靠采样来恢复数据。 **UART通常用16倍波特率的时钟采样** ，取中间的采样值，这样就算有点时钟误差也能正确接收。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-010.png]]

### 1.12 TTL、CMOS与差分电平

- • **TTL电平** ：逻辑1是3.3V或5V，逻辑0是0V。单片机内部直接用的就是这种。
- • **RS232电平** ：逻辑1是-3V到-15V，逻辑0是+3V到+15V。跟TTL完全不一样，所以不能直接连。
- • **差分电平** ：用两根线的电压差表示逻辑， **RS485的逻辑1是A比B高2-6V，逻辑0是B比A高2-6V** 。
	![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-011.png]]

### 1.13 通信速率、距离与抗干扰能力的关系

这三个东西是互相制约的。 **速率越高、距离越远，信号就越容易出问题** 。差分信号抗干扰强，所以能传得远、传得快。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-012.png]]

## 二、UART通信原理详解

UART是所有嵌入式开发者接触的第一个通信接口，也是最基础、使用率最高的接口。

### 2.1 UART的基本概念

UART的全称是 **Universal Asynchronous Receiver/Transmitter，通用异步收发器** 。它本身是一个硬件模块，不是协议。很多单片机里都集成了UART外设。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-013.png]]

### 2.2 UART硬件接口与引脚定义

#### 2.2.1 TX发送引脚

数据从这颗引脚发出去。

#### 2.2.2 RX接收引脚

数据从这颗引脚收进来。

#### 2.2.3 GND参考地

**必须共地** ，不然电平参考点不一样，数据全乱套。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-014.png]]

### 2.3 UART异步通信原理

发送端把数据变成串行的比特流，接收端按照约定的波特率去采样。因为没有时钟线，双方得各自维护一个时钟， **靠起始位来同步** 。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-015.png]]

### 2.4 UART数据帧格式

#### 2.4.1 空闲状态

线路空闲时是 **高电平** 。接收端一直盯着这根线，等它变低。

#### 2.4.2 起始位

一个 **低电平** 信号，标志着数据帧开始。接收端检测到这个下降沿就开始计时采样。

#### 2.4.3 数据位

实际要传的数据， **通常是8位，从最低位开始发** 。

#### 2.4.4 奇偶校验位

可选的，用来做简单的错误检测。

#### 2.4.5 停止位

**高电平** ，标志着帧结束，可以是1位或2位。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-016.png]]

### 2.5 UART波特率与采样机制

接收端用 **16倍波特率的时钟** 采样，在每个数据位的中间点取值。这样能容忍一定的时钟误差。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-017.png]]

### 2.6 UART全双工通信方式

**TX和RX独立工作，可以同时收发** 。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-018.png]]

### 2.7 UART数据发送与接收流程

- • **发送** ：CPU把数据写到发送寄存器→硬件自动加上起始位、校验位、停止位→按波特率移位输出。
- • **接收** ：硬件检测起始位→按波特率采样数据位→检查校验位和停止位→把数据放到接收寄存器→通知CPU。
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-019.png]]

### 2.8 轮询、中断与DMA收发方式

- • **轮询** ：CPU一直盯着标志位，简单但浪费CPU。
- • **中断** ：数据到了触发中断，CPU去处理，效率高。
- • **DMA** ：数据直接在内存和UART之间搬，CPU完全不用管， **最高效** 。
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-020.png]]

### 2.9 UART软件实现要点

**配置波特率、数据位、停止位、校验位时，收发双方必须完全一致** 。用 **11.0592MHz晶振** 算波特率比较准，因为能整除常见的波特率。

```
// STM32 UART初始化示例
void uart_init(void) {
    // 使能时钟
    RCC->APB1ENR |= RCC_APB1ENR_USART2EN;
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
    
    // 配置GPIO为复用功能
    GPIOA->MODER &= ~(GPIO_MODER_MODER2 | GPIO_MODER_MODER3);
    GPIOA->MODER |= (GPIO_MODER_MODER2_1 | GPIO_MODER_MODER3_1);  // 复用模式
    GPIOA->AFR[0] |= (7 << GPIO_AFRL_AFSEL2_Pos) | (7 << GPIO_AFRL_AFSEL3_Pos);
    
    // 配置UART参数：115200, 8N1
    USART2->BRR = 0x1D4C;  // 16MHz下115200的取值
    USART2->CR1 = USART_CR1_TE | USART_CR1_RE | USART_CR1_UE;  // 使能发送、接收、UART
}
```
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-021.png]]

### 2.10 UART常见通信错误

#### 2.10.1 波特率不一致

**最常见的问题** 。两边波特率不一样，收出来的数据全是乱码。

#### 2.10.2 数据位配置错误

一边8位一边7位，数据解析错位。

#### 2.10.3 奇偶校验错误

校验位不匹配，数据会被丢弃。

#### 2.10.4 帧错误

没收到正确的停止位，说明数据同步丢了。

#### 2.10.5 接收溢出错误

上一个数据还没读走，下一个又来了，数据被覆盖。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-022.png]]

### 2.11 UART调试方法

最直接的办法： **用USB转TTL模块连到电脑，用串口助手看数据** 。发几个已知的字节（比如0x55、0xAA），看波形对不对。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-023.png]]

### 2.12 UART优缺点与应用场景

- • **优点** ：简单、线少、全双工、几乎所有MCU都有。
- • **缺点** ：点对点、距离短、抗干扰差。
- • **应用场景** ：调试输出、GPS模块、蓝牙模块、单片机之间通信。

## 三、RS232通信原理详解

很多人分不清UART和RS232的区别，甚至直接当成同一个东西。其实两者完全不是一个层级的概念，一个是控制器协议，一个是电气标准。

### 3.1 RS232标准简介

RS232是历史悠久的串行通信标准，由EIA（电子工业协会）制定。电脑上的COM口就是RS232。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-025.png]]

### 3.2 RS232与UART的关系

**UART是协议层（数据怎么打包），RS232是物理层（电信号长什么样）** 。UART负责组帧，RS232负责把帧变成符合标准的电信号。两者配合使用。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-026.png]]

### 3.3 RS232电平标准

**RS232的逻辑1是-3V到-15V，逻辑0是+3V到+15V** 。负电压表示1，正电压表示0， **跟直觉相反** 。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-027.png]]

### 3.4 TTL串口与RS232电平的区别

**TTL是0V/3.3V或0V/5V，RS232是±3V到±15V** 。电压范围不同、极性相反， **绝对不能直接连** 。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-028.png]]

### 3.5 RS232接口与DB9引脚定义

DB9是9针的D型接口，常用引脚是：

- • **2脚：RXD** （接收数据）
- • **3脚：TXD** （发送数据）
- • **5脚：GND** （地）
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-029.png]]

### 3.6 MAX232电平转换原理

**MAX232是专门做电平转换的芯片** ，把RS232的±12V转成TTL的0/5V，反过来也能转。内部有电荷泵，能把5V升到±10V左右。

```
单片机(3.3V TTL) <--> MAX232 <--> RS232(±12V) <--> 电脑COM口
```
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-030.png]]

### 3.7 RS232点对点通信结构

RS232是 **点对点** 的，一个发送端对一个接收端。不能像RS485那样挂多个设备。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-031.png]]

### 3.8 RS232硬件连接与线缆类型

#### 3.8.1 直连线

同一端的引脚一一对应，用来连接DTE和DCE。

#### 3.8.2 交叉线

**2脚接3脚、3脚接2脚** ，用来连接两个DTE设备（比如两台电脑）。

#### 3.8.3 公头与母头

DB9有公头和母头，设备端通常用公头，线缆端用母头。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-032.png]]

### 3.9 RS232通信距离与通信速率

RS232的典型通信距离是 **15米** ，速率通常到115200bps，最高能到1Mbps左右。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-033.png]]

### 3.10 RS232软件实现要点

软件层面跟UART完全一样，只是在硬件上多了个电平转换芯片。配置好波特率、数据位这些参数就行。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-034.png]]

### 3.11 RS232常见故障排查

- • 没反应：检查电平转换芯片有没有焊反、供电正不正常
- • 乱码：检查波特率配置
- • 只能发不能收：检查交叉线有没有接对
- • 信号不稳定：检查地线有没有接好
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-035.png]]

### 3.12 RS232优缺点与应用场景

- • **优点** ：标准成熟、设备多、简单可靠。
- • **缺点** ：距离短（15米）、速度慢、点对点、抗干扰差。
- • **应用场景** ：老式工控设备、串口服务器、调试终端。
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-036.png]]

## 四、RS485通信原理详解

做工业开发、物联网组网，RS485是绕不开的刚需接口。它解决了RS232距离短、不能组网、抗干扰差的所有痛点，是工业现场最通用的串行通信标准。

### 4.1 RS485标准简介

RS485是为了克服RS232的缺点而设计的—— **距离短、节点少、抗干扰差** 。它采用 **差分信号传输** ，抗干扰能力强、支持多节点、传输距离远。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-037.png]]

### 4.2 RS485与UART的关系

跟RS232一样，RS485也是 **物理层标准** 。UART负责数据组帧，RS485负责差分信号传输。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-038.png]]

### 4.3 RS485差分通信原理

数据通过一对双绞线上的 **电压差** 来表示。 **A比B高2-6V是逻辑1，B比A高2-6V是逻辑0** 。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-039.png]]

### 4.4 A线与B线的信号定义

A是“+”端，B是“-”端。逻辑1：A>B；逻辑0：B>A。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-040.png]]

### 4.5 两线制半双工与四线制全双工

**两线制（A和B）是半双工** ，收发不能同时。四线制（再加一对线）可以实现全双工，但用得少。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-041.png]]

### 4.6 RS485收发器工作原理

收发器把UART的TTL信号转成差分信号发出去，同时把收到的差分信号转成TTL信号给UART。常用芯片有 **MAX485、SP3485** 等。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-042.png]]

### 4.7 DE与RE引脚控制方法

- • **DE** 是发送使能， **RE** 是接收使能（低电平有效）。
- • 发送数据：DE=1，RE=1（或不管）
	- • 接收数据：DE=0，RE=0
- • **半双工模式下，发送和接收不能同时进行，需要软件切换方向** 。
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-043.png]]

### 4.8 RS485总线拓扑结构

RS485采用 **总线式拓扑** ，所有节点挂在一对双绞线上。终端要加匹配电阻。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-044.png]]

### 4.9 多节点通信与设备地址

标准RS485最多支持 **32个节点** 。每个节点需要有唯一地址，通过软件协议（比如Modbus）来寻址。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-045.png]]

### 4.10 终端电阻的作用与选取

终端电阻用来做 **阻抗匹配** ，防止信号在总线末端反射。阻值等于电缆的特性阻抗，双绞线通常是 **120Ω** 。 **只在总线两端各放一个** 。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-046.png]]

### 4.11 上拉、下拉偏置电阻设计

偏置电阻保证总线空闲时有一个确定的逻辑状态（A高B低）。否则接收器可能输出不确定的电平。 **偏置电阻要保证A比B高200mV以上** 。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-047.png]]

### 4.12 RS485方向切换时序

**从发送切到接收时，要先等最后一个字节完全发完（包括停止位），再把DE拉低** 。否则最后一个字节可能发不完整。

```
// RS485发送一个字节
void rs485_send_byte(uint8_t data) {
    RS485_DE_HIGH();    // 切换到发送模式
    delay_us(1);        // 等待收发器切换完成
    uart_send_byte(data);
    while(!uart_tx_complete());  // 等待发送完成
    delay_us(1);        // 等待最后一个位完全发出
    RS485_DE_LOW();     // 切换回接收模式
}
```
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-048.png]]

### 4.13 RS485通信距离与通信速率

RS485标准传输距离 **1200米** （9600bps时），实际能到3000米。速率和距离成反比，距离越远速率要越低。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-049.png]]

### 4.14 RS485软件实现要点

跟UART一样配置， **多了一个方向切换的逻辑** 。发送前切到发送模式，发完切回接收模式。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-050.png]]

### 4.15 RS485与Modbus RTU的关系

**RS485是物理层，Modbus RTU是应用层协议** 。Modbus RTU定义了帧格式、地址、功能码、CRC校验。两者经常搭配使用。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-051.png]]

### 4.16 RS485常见通信问题

#### 4.16.1 A、B线接反

信号极性反了，所有数据都反相。

#### 4.16.2 未共地或地电位差过大

虽然RS485是差分传输，但收发器的地还是要连的，不然共模电压可能超出芯片承受范围。

#### 4.16.3 终端电阻配置错误

该加的地方没加，或者不该加的地方加了。 **只在总线两端加** 。

#### 4.16.4 偏置电阻配置不合理

总线空闲时电平不确定，接收端可能收到随机数据。

#### 4.16.5 总线分支过长

分支线太长会引起反射，分支延迟不能超过信号上升沿的1/3。

#### 4.16.6 收发方向控制错误

**最常见的问题之一** 。发送时没切到发送模式，或者切早了/切晚了。

#### 4.16.7 多节点同时发送数据

总线冲突，数据全乱。要靠上层协议来避免。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-052.png]]

### 4.17 RS485隔离、防雷与保护设计

工业现场经常有高压、雷击、地电位差。需要用 **隔离收发器** （比如ADM2486）加TVS管做保护。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-053.png]]

### 4.18 RS485优缺点与应用场景

- • **优点** ：距离远（1200米）、抗干扰强、支持多节点（32个）。
- • **缺点** ：半双工（两线制）、需要方向切换、硬件比RS232复杂。
- • **应用场景** ：工业控制、智能仪表、楼宇自动化、Modbus网络。
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-054.png]]

## 五、I²C通信原理详解

I²C是嵌入式最省引脚的通信接口，两根线就能搞定多设备组网，几乎所有温湿度、气压、陀螺仪、EEPROM等低速传感器，全部用I²C通信。

### 5.1 I²C总线简介与基本特点

I²C（Inter-Integrated Circuit）是Philips（现NXP）发明的 **两线制串行总线** 。只用两根线—— **SDA和SCL** ——就能挂多个设备。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-055.png]]

### 5.2 SDA与SCL信号线

**SDA是数据线，SCL是时钟线** 。所有设备的SDA接一起、SCL接一起。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-056.png]]

### 5.3 开漏输出与上拉电阻

I²C的引脚是 **开漏输出** 的，只能拉低不能拉高。所以要外接 **上拉电阻** 把电平拉高。开漏输出的好处是支持“线与”——任何一个设备拉低总线，总线就是低电平。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-057.png]]

### 5.4 I²C主机、从机与设备地址

主机产生时钟、发起通信。从机响应主机的命令。 **每个从机有一个唯一地址** 。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-058.png]]

### 5.5 7位地址与10位地址

标准I²C用 **7位地址** ，理论支持127个设备。扩展的10位地址支持更多设备，但用得少。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-059.png]]

### 5.6 起始条件、停止条件与重复起始条件

- • **起始条件（Start）** ：SCL为高时，SDA从高到低。
- • **停止条件（Stop）** ：SCL为高时，SDA从低到高。
- • **重复起始条件（Repeated Start）** ：在传输中间再发一个起始条件，不用先发停止。
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-060.png]]

### 5.7 I²C数据传输格式

**主机发起始条件→发7位地址+读写位→从机回应答→传数据→从机回应答→...→主机发停止条件** 。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-061.png]]

### 5.8 I²C读操作与写操作

- • **写操作** ：主机发地址（写位=0）→发数据→从机应答。
- • **读操作** ：主机发地址（读位=1）→从机发数据→主机应答（或不应答结束）。
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-062.png]]

### 5.9 ACK与NACK应答机制

每传完一个字节，接收方要 **拉低SDA表示ACK（应答）** 。如果接收方不拉低（SDA保持高），就是 **NACK（不应答）** ，主机就知道出问题了。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-063.png]]

### 5.10 总线仲裁机制

多个主机同时想用总线时，谁先发低电平谁赢。因为开漏输出支持“线与”，仲裁在硬件层面完成。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-064.png]]

### 5.11 时钟同步与时钟拉伸

- • **时钟同步** ：多个主机时，SCL的低电平时间由最长的那一个决定。
- • **时钟拉伸** ：慢速从机可以把SCL拉低，让主机等一等。
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-065.png]]

### 5.12 标准模式、快速模式与高速模式

- • **标准模式** ：100kbps
- • **快速模式** ：400kbps
- • **高速模式** ：3.4Mbps
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-066.png]]

### 5.13 I²C上拉电阻计算与选择

上拉电阻不能太小（否则灌电流太大），也不能太大（否则上升沿太慢）。

- • 最小值公式： **Rp(min) = (Vdd - Vol(max)) / Iol**
- • 最大值公式： **Rp(max) = tr / (0.8473 × Cb)**
- • 常用值是 **4.7kΩ** 或 **2.2kΩ** 。
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-067.png]]

### 5.14 总线电容、通信速率与通信距离

总线电容越大，上升沿越慢，通信速率就得越低。 **I²C通常只用于板内通信，距离很短（<1米）** 。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-068.png]]

### 5.15 软件模拟I²C与硬件I²C

- • **硬件I²C** ：MCU内置的外设，自动处理时序，CPU干预少。
- • **软件模拟I²C** ：用GPIO手动拉高拉低SDA和SCL。灵活性高，但占用CPU。
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-069.png]]

### 5.16 I²C软件实现要点

**时序要准确** ，尤其是起始条件和停止条件。用逻辑分析仪抓波形是最靠谱的调试方法。

```
// 软件模拟I2C - 起始条件
void i2c_start(void) {
    SDA_HIGH();
    SCL_HIGH();
    delay_us(5);
    SDA_LOW();      // SCL高时SDA从高到低 -> 起始条件
    delay_us(5);
    SCL_LOW();
}

// 软件模拟I2C - 停止条件
void i2c_stop(void) {
    SDA_LOW();
    SCL_HIGH();
    delay_us(5);
    SDA_HIGH();     // SCL高时SDA从低到高 -> 停止条件
    delay_us(5);
}
```
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-070.png]]

### 5.17 I²C常见故障排查

#### 5.17.1 设备地址错误

地址不对，从机不响应。检查数据手册确认地址。

#### 5.17.2 从机无应答

发完地址后没收到ACK。可能地址错、从机没电、或者总线被拉死了。

#### 5.17.3 SDA或SCL被持续拉低

某个设备死锁了，一直拉着总线。可以给设备重新上电，或者在硬件上设计复位电路。

#### 5.17.4 上拉电阻选择不当

电阻太大→上升沿太慢→通信失败。电阻太小→灌电流太大→可能损坏引脚。

#### 5.17.5 时序不满足要求

起始条件、停止条件、数据建立/保持时间不满足规格。

#### 5.17.6 总线电容过大

挂的设备太多或线太长，总线电容太大，上升沿爬不上去。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-071.png]]

### 5.18 I²C优缺点与应用场景

- • **优点** ：线少（2根）、支持多设备、有应答机制。
- • **缺点** ：速度慢、距离短、抗干扰差、软件比SPI复杂。
- • **应用场景** ：传感器（温湿度、加速度计）、EEPROM、RTC、小屏。
![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-072.png]]

## 六、SPI通信原理详解

如果说I²C是低速省心神器，那SPI就是嵌入式高速传输的天花板。所有高速外设，OLED、TFT屏幕、Flash、SD卡、高速采样芯片，清一色使用SPI通信。

### 6.1 SPI总线简介

SPI（Serial Peripheral Interface）是Motorola发明的 **同步串行总线** 。 **全双工、高速、主从结构** 。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-073.png]]

### 6.2 SPI主机与从机结构

一个主机可以带一个或多个从机。主机产生时钟、控制片选。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-074.png]]

### 6.3 SPI信号线定义

#### 6.3.1 SCLK时钟线

主机产生的时钟，控制数据传输的节奏。

#### 6.3.2 MOSI主发从收

Master Out Slave In，数据从主机到从机。

#### 6.3.3 MISO主收从发

Master In Slave Out，数据从从机到主机。

#### 6.3.4 CS或NSS片选线

主机用来选中具体的从机， **低电平有效** 。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-075.png]]

### 6.4 SPI全双工通信原理

**MOSI和MISO同时工作，发送和接收可以同时进行** 。主机发一个比特的同时，从机也在发一个比特。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-076.png]]

### 6.5 移位寄存器工作机制

主机和从机各有一个移位寄存器，时钟每跳一次，两个寄存器交换一个比特。 **8个时钟周期后，主机的数据和从机的数据就交换完了** 。

![[projects/嵌入式八股/杂七杂八/Linux 内核 eBPF 图解：理解内核扩展的核心机制.assets/img-077.png]]

### 6.6 CPOL与CPHA的含义

- • **CPOL（Clock Polarity）** ：时钟空闲时的电平。
- • CPOL=0：空闲低电平
	- • CPOL=1：空闲高电平
- • **CPHA（Clock Phase）** ：数据在哪个时钟边沿采样。
- • CPHA=0：第一个边沿采样
	- • CPHA=1：第二个边沿采样
![[img-078.png]]

### 6.7 SPI四种工作模式

| 模式 | CPOL | CPHA | 说明 |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 空闲低，上升沿采样 |
| 1 | 0 | 1 | 空闲低，下降沿采样 |
| 2 | 1 | 0 | 空闲高，下降沿采样 |
| 3 | 1 | 1 | 空闲高，上升沿采样 |

### 6.8 数据位宽与位序

### 6.12 SPI软件实现要点

**关键是模式要匹配（CPOL/CPHA），片选时序要对** 。用硬件SPI效率高，用软件模拟灵活性好。

```
// STM32 SPI初始化 - Mode 0
void spi_init(void) {
    // 使能时钟
    RCC->APB2ENR |= RCC_APB2ENR_SPI1EN;
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
    
    // 配置GPIO
    GPIOA->MODER &= ~(GPIO_MODER_MODER5 | GPIO_MODER_MODER6 | GPIO_MODER_MODER7);
    GPIOA->MODER |= (GPIO_MODER_MODER5_1 | GPIO_MODER_MODER6_1 | GPIO_MODER_MODER7_1);
    GPIOA->AFR[0] |= (5 << GPIO_AFRL_AFSEL5_Pos) | (5 << GPIO_AFRL_AFSEL6_Pos) | (5 << GPIO_AFRL_AFSEL7_Pos);
    
    // 配置SPI: 主机、模式0、8位、MSB优先
    SPI1->CR1 = SPI_CR1_MSTR | SPI_CR1_SSM | SPI_CR1_SSI | SPI_CR1_SPE;
    SPI1->CR1 &= ~(SPI_CR1_CPOL | SPI_CR1_CPHA);  // CPOL=0, CPHA=0
    SPI1->CR1 |= SPI_CR1_DFF;  // 8位
}
```

### 6.13 SPI常见故障排查

#### 6.13.1 SPI模式不一致

**主机和从机的CPOL/CPHA不匹配** 。这是SPI最常见的坑。

#### 6.13.2 片选时序错误

CS拉低和时钟开始之间的时间不够，或者传输还没完就把CS拉高了。

#### 6.13.3 数据位宽配置错误

一边8位一边16位。

#### 6.13.4 MSB与LSB配置错误

位序反了，数据全反。

#### 6.13.5 命令与数据读写顺序错误

有些器件要先发命令再读写数据，顺序搞反了就没反应。

#### 6.13.6 高速通信波形畸变

速率太高，信号在线上变形了。降速或者优化PCB走线。

### 6.14 SPI优缺点与应用场景

- • **优点** ：速度快（50Mbps+）、全双工、硬件简单。
- • **缺点** ：线多（至少4根）、每个从机要单独的片选、距离短。
- • **应用场景** ：Flash存储器、ADC/DAC、显示屏、SD卡。

## 七、五种通信接口的关系与横向对比

### 7.1 UART、RS232与RS485的关系

这三个经常被搞混，我面试的时候就遇到过好多次。其实它们的关系是这样的：

**UART是协议层（数据怎么组帧），RS232和RS485是物理层（电信号长什么样）** 。UART负责把数据打包成帧，RS232或RS485负责把帧变成符合标准的电信号发出去。

用个比喻：UART是写信的格式（开头怎么写、结尾怎么写），RS232和RS485是邮递方式（平邮还是快递）。

![[img-087.png]]

### 7.2 通信控制器、电气标准与总线协议的区别

- • **通信控制器** ：硬件模块，比如UART、USART、I²C控制器、SPI控制器
- • **电气标准** ：物理层规范，比如RS232、RS485
- • **总线协议** ：软件层面的规则，比如Modbus、I²C协议、SPI协议
![[img-088.png]]

### 7.3 UART与SPI的区别

**UART异步、不要时钟线、点对点、速度慢。SPI同步、要时钟线、主从多设备、速度快** 。

![[img-089.png]]

### 7.4 I²C与SPI的区别

**I²C线少（2根）、速度慢、有应答、支持多主机。SPI线多（4根+）、速度快、无应答、单主机** 。

![[img-090.png]]

### 7.5 RS232与RS485的区别

**RS232单端、点对点、15米。RS485差分、多节点、1200米** 。

![[img-091.png]]

### 7.6 同步通信与异步通信对比

同步有时钟线、速度快、时序精确。异步无时钟线、省线、靠波特率同步。

![[img-092.png]]

### 7.7 单端信号与差分信号对比

单端一根信号线+地线、简单、抗干扰差。差分两根信号线、复杂、抗干扰强。

![[img-093.png]]

### 7.8 通信方向与工作模式对比

UART全双工、RS232全双工、RS485半双工（两线制）、I²C半双工、SPI全双工。

![[img-094.png]]

### 7.9 信号线数量与硬件接口对比

UART：3根（TX、RX、GND）。RS232：3根（实际用到的）。RS485：2根（A、B）。I²C：2根（SDA、SCL）。SPI：4根（SCLK、MOSI、MISO、CS）。

![[img-095.png]]

### 7.10 通信速率与传输距离对比

**SPI最快（50Mbps+）但最短（<1米）。RS485最远（1200米）但速度受限。I²C居中（100k-3.4Mbps，<1米）** 。

![[img-096.png]]

### 7.11 节点数量与组网能力对比

RS485支持32个节点（可扩展）。I²C支持127个（7位地址）。SPI理论上无限（每个从机一个片选）但实际受限。UART和RS232只能点对点。

![[img-097.png]]

### 7.12 抗干扰能力对比

**RS485最强（差分）** 。RS232最弱（单端、高电压）。I²C和SPI是板内通信，抗干扰要求不高。

![[img-098.png]]

### 7.13 硬件成本与软件复杂度对比

UART最简单。RS232多一个电平转换芯片。RS485多收发器和方向控制。I²C要上拉电阻、软件稍复杂。SPI硬件简单但线多。

![[img-099.png]]

### 7.14 典型应用场景对比

UART：调试、GPS、蓝牙。RS232：老式工控、串口服务器。RS485：工业控制、Modbus。I²C：传感器、EEPROM。SPI：Flash、屏幕、ADC。

![[img-100.png]]

## 八、通信接口选型方法

### 8.1 通信接口选型的主要指标

**距离、速率、节点数、抗干扰、成本、软件复杂度、硬件资源** 。

![[img-101.png]]

### 8.2 板内短距离芯片通信如何选型

板内通信首选I²C或SPI。 **传感器用I²C（线少），高速外设用SPI（速度快）** 。

![[img-102.png]]

### 8.3 板间短距离通信如何选型

板间短距离（<1米）可以用UART（TTL电平）。如果两个板子距离稍远，加个RS232或者用差分SPI。

![[img-103.png]]

### 8.4 工业现场远距离通信如何选型

远距离（几十米到上千米） **首选RS485** 。搭配Modbus协议是工业标准配置。

![[img-104.png]]

### 8.5 多传感器系统如何选型

传感器多的话用I²C（线少，地址区分）。如果传感器速度快或者数据量大，用SPI加独立片选。

![[img-105.png]]

### 8.6 高速数据传输如何选型

高速 **首选SPI** ，能到50Mbps以上。如果还不够快，考虑并行接口或者USB。

![[img-106.png]]

### 8.7 多节点组网如何选型

多节点组网用RS485。节点多的话注意总线负载，标准32个，可以用1/8负载的芯片扩到256个。

![[img-107.png]]

### 8.8 强干扰环境如何选型

强干扰环境 **必须用差分信号，RS485是首选** 。还可以考虑CAN总线，抗干扰更强。

![[img-108.png]]

### 8.9 成本敏感型产品如何选型

成本敏感用UART（TTL）或者I²C。不需要电平转换芯片、不需要收发器，最省。

![[img-109.png]]

### 8.10 不同场景下的推荐方案

- • **调试输出** ：UART
- • **板内传感器** ：I²C
- • **板内高速外设** ：SPI
- • **短距离板间** ：UART/RS232
- • **工业远距离** ：RS485+Modbus
- • **汽车电子** ：CAN
![[img-110.png]]

## 十、软件设计与通信可靠性

### 10.1 通信驱动程序分层设计

驱动分三层： **硬件层（寄存器操作）、协议层（组帧解帧）、应用层（业务逻辑）** 。分层之后好维护、好移植。

![[img-123.png]]

### 10.2 数据发送与接收状态机

接收用 **状态机** 管理：空闲→收帧头→收数据→校验→处理。状态机让代码清晰可控。

![[img-124.png]]

### 10.3 阻塞、非阻塞与异步通信

- • **阻塞** ：等数据到了才返回，简单但浪费CPU。
- • **非阻塞** ：没数据就返回错误。
- • **异步** ：用中断或回调通知。
![[img-125.png]]

### 10.4 轮询、中断与DMA的选择

简单应用用轮询。大部分情况用中断。大数据量用DMA。

![[img-126.png]]

### 10.5 环形缓冲区设计

接收数据先放 **环形缓冲区** ，主循环再从缓冲区取。这样收和处理的节奏可以分开。

```
// 环形缓冲区
typedef struct {
    uint8_t *buffer;
    uint16_t head;
    uint16_t tail;
    uint16_t size;
} ring_buffer_t;

bool ring_buffer_push(ring_buffer_t *rb, uint8_t data) {
    uint16_t next = (rb->head + 1) % rb->size;
    if (next == rb->tail) return false;  // 满了
    rb->buffer[rb->head] = data;
    rb->head = next;
    return true;
}

bool ring_buffer_pop(ring_buffer_t *rb, uint8_t *data) {
    if (rb->tail == rb->head) return false;  // 空了
    *data = rb->buffer[rb->tail];
    rb->tail = (rb->tail + 1) % rb->size;
    return true;
}
```

### 10.6 帧头、帧尾与长度字段

定义协议时加 **帧头（比如0xAA 0x55）** 、长度字段、帧尾。接收端通过这些字段来识别完整的一帧。

### 10.7 校验和与CRC校验

简单的用校验和（所有字节加起来），可靠地用 **CRC16或CRC32** 。Modbus就用CRC16。

![[img-129.png]]

### 10.8 数据粘包与拆包处理

连续接收数据时，一帧可能被拆成多次收到，或者多帧粘在一起。 **需要用帧头和长度来拆包** 。

### 10.9 超时、重发与应答机制

发完数据启动超时定时器，超时没收到应答就重发。重发几次还不行就报错。

SHT30、AHT20这些传感器都是I²C接口。先发命令启动测量，再读结果。

```
// 读取AHT20温湿度
uint8_t read_aht20(float *temp, float *humi) {
    uint8_t data[6];
    
    i2c_start();
    i2c_write(0x38 << 1);  // 写地址
    if (!i2c_check_ack()) { i2c_stop(); return 1; }
    i2c_write(0xAC);       // 触发测量命令
    i2c_check_ack();
    i2c_write(0x33);
    i2c_check_ack();
    i2c_write(0x00);
    i2c_check_ack();
    i2c_stop();
    
    delay_ms(80);  // 等待测量完成
    
    i2c_start();
    i2c_write((0x38 << 1) | 1);  // 读地址
    i2c_check_ack();
    for (int i = 0; i < 6; i++) {
        data[i] = i2c_read(i == 5 ? NACK : ACK);
    }
    i2c_stop();
    
    // 解析数据...
    return 0;
}
```

## 十三、常见面试题

### 13.1 UART和RS232是不是同一种协议

**不是** 。UART是协议层（数据组帧），RS232是物理层（电平标准）。

### 13.2 UART为什么不需要时钟线

因为是异步通信，靠约定的波特率来同步。起始位提供帧同步，之后按波特率采样。

### 13.3 UART波特率误差会造成什么影响

误差在一个字节内累积。超过一定范围（通常5%）就会采错位。用11.0592MHz晶振就是为了减少误差。

### 13.4 RS485为什么适合远距离通信

**差分信号抗共模干扰强** 。干扰同时出现在A和B上，一减就抵消了。

### 13.5 RS485为什么需要终端电阻

做阻抗匹配，防止信号反射。电阻值等于电缆特性阻抗（通常120Ω）。 **只在总线两端加** 。

### 13.6 RS485的A、B线定义为什么容易混淆

不同厂家定义不一样。有些把A当正、B当负，有些反过来。接上没反应就交换试试。

### 13.7 I²C为什么必须使用上拉电阻

**开漏输出只能拉低不能拉高** 。需要上拉电阻把电平拉到高电平。

### 13.8 I²C总线被拉低后如何恢复

某个设备死锁了。可以给所有设备重新上电，或者 **发9个时钟脉冲** 试图恢复。

### 13.9 SPI为什么通常比I²C快

**SPI是推挽输出** ，驱动能力强、上升沿快。I²C是开漏输出加电阻上拉，上升沿受限。SPI没有应答开销。

### 13.10 SPI四种模式如何区分

看CPOL（时钟空闲电平）和CPHA（采样边沿）。 **Mode 0最常用：CPOL=0、CPHA=0** 。

### 13.11 多个SPI从机如何连接

每个从机用独立的片选（CS）。或者用菊花链。

### 13.12 五种通信接口的选型思路

**距离近用I²C/SPI、距离远用RS485、调试用UART、高速用SPI、多节点用RS485/I²C** 。
