## 一、PLC到底是个啥？

### 1.1 PLC的定义

**PLC**，全称Programmable Logic Controller，可编程逻辑控制器。

别看名字里带个“逻辑”，现在的PLC可不止干点“与或非”的杂活。算数、通信、PID调参、玩复杂的运动控制它基本都在行，本质上就是一台**专为工业现场这种“脏乱差”环境打造的实时嵌入式小钢炮**。

官方说这玩意儿是个电子系统，专门在工业环境下混，能用存起来的指令干逻辑、顺序、定时、计数和算术运算的活儿，再通过I/O点去指挥各种机械和生产过程。

听着是不是有点懵？翻译成**人话**就是：**PLC是一台皮糙肉厚、能在车间里一边吃灰一边抗震动，还绝对不出错的工业专用小电脑！**

那它跟咱们用的PC最大的不同在哪儿呢？

PC蓝屏了，你重启一下骂两句娘就完了。PLC要是死机，整条生产线当场直接趴窝。所以PLC从娘胎里带出来的设计哲学就六个大字：**稳定压倒一切！**

### 1.2 PLC的发展历程与技术优势

PLC出现以前，工业控制基本全靠继电器、时间继电器那一大堆硬件接线。

**跟继电器系统比**，PLC那就是降维打击！改功能不用重新接线，改两行程序就完事！体积小、可靠性高，用简直不要太爽。

后来有人抬杠了：既然PLC是台工业电脑，那为啥不直接用普通工控机？

问得好！因为控制系统不光要算得快，还得算得准、算得稳，出了错知道怎么安全收场。

普通电脑跑的是通用操作系统，后台指不定在干啥，磁盘一忙、网络一卡，程序响应时间就飘了。PLC不一样，它的任务调度是确定性的，说几毫秒就几毫秒，稳如老狗。而且它的I/O模块天生就是为24V工业信号、抗干扰、电磁隔离设计的，皮实得很。

| 对比项目 | 继电器控制 | PLC控制 | 普通微机或工业PC |
| --- | --- | --- | --- |
| 逻辑修改 | 拆线、接线、头大 | 改程序，下载，收工 | 改软件，重启 |
| 实时确定性 | 简单回路贼快 | 高，任务周期可配 | 看操作系统心情 |
| 复杂运算 | 基本白给 | 中等到较强 | 强，但可能卡 |
| 工业I/O适配 | 天生适配 | 天生适配 | 得加采集卡，麻烦 |
| 通信能力 | 约等于没有 | 工业协议一箩筐 | 网络协议丰富，但现场适配差 |
| 维护难度 | 越复杂越要命 | 相对省心 | 得靠码农团队 |
| 环境适应能力 | 挺能抗 | 极其能抗 | 得看工控机等级 |
| 适合项目 | 简单固定逻辑 | 机器和过程控制 | 视觉、数据库、高级算法 |

当然PLC也不是能干掉所有的对手。要搞视觉识别、深度学习、海量数据存储？那还得是工业PC上。

### 1.3 PLC的应用场景与行业定位

PLC的应用场景，基本覆盖了工业自动化的九成以上江山。按工控圈主要分三大块：

**离散制造**是大家见得最多的。汽车生产线、包装机、贴标机、灌装机——这些场景PLC玩了几十年了，电机启停、变频调速、位置检测，全是它的看家本领。

**过程控制**多在化工、水处理、暖通这些行业。石油管道、污水厂、楼宇空调的温湿度采集、PID闭环调节、报警联锁，对模拟量处理要求贼高，用PLC很适合。

**运动控制**中的伺服驱动、多轴联动、机器人协同，高端PLC配上EtherCAT这种高速总线，玩起微秒级的同步控制一点都不在话下。

说白了，只要你工厂里有设备在动、有传感器在叫、有执行器在干——那背后八成有台PLC在默默撑着。

## 二、PLC硬件系统组成与架构

### 2.1 PLC硬件整体架构与总线系统

PLC硬件看着就几个模块拼一块儿，但内部模块之间是靠背板总线或内部扩展总线来交换数据的。CPU通过这根“总线神经”去识别输入模块、输出模块、通信模块这些小弟，并按配置去读状态、下命令。

我们来看一个典型的模块式PLC数据流：

```
现场传感器    ↓输入端子与保护电路    ↓输入模块信号调理与隔离    ↓背板总线（数据高速路）    ↓CPU与存储器（大脑）    ↓背板总线（数据高速路）    ↓输出模块隔离与驱动    ↓接触器、电磁阀、指示灯或执行器
```

总线不光传数据，还管模块识别、诊断、参数配置和时间同步，功能全得很。

设备越来越大以后，如果所有传感器线都拉回主控柜，那电缆数量就超级多了。所以远程I/O就成了常规配置。现场模块通过PROFINET、EtherNet/IP、EtherCAT这些工业以太网协议，跟CPU远程“打电话”交换数据。

但这里很多人以为接上工业以太网，远程I/O就跟本地I/O一样快了。

实际上并不是。

远程I/O的数据更新时间还得看网络周期、交换机转发、设备刷新周期和控制器任务周期。逻辑上看着是一个变量，物理上它可是绕了好几圈才到你手里的。

### 2.2 核心硬件模块功能深度解析

#### 2.2.1 CPU模块（运算与控制核心、工作模式切换）

CPU模块就是PLC的大脑，负责读输入、跑程序、处理通信、更新输出、做诊断，啥活都干。

CPU内部集成了处理器、工作存储器、系统时钟、通信控制器和看门狗电路。高端CPU还能集成运动控制、安全控制、Web服务器、OPC UA服务端，甚至数据记录功能。

PLC通常有RUN和STOP两种主要模式。

RUN模式下，控制器玩命地执行用户程序并刷新I/O。STOP模式下，程序歇菜，输出按配置进入关闭、保持或替代值状态。有些PLC支持在RUN状态下下载部分程序修改，但只要动了数据布局、硬件组态或安全程序，基本都得乖乖切到STOP模式。

CPU里的看门狗专门盯着扫描周期。程序要是死循环、通信阻塞或者指令执行时间异常，扫描时间超了设定上限，控制器二话不说直接进入故障处理流程。

这也就是为啥PLC程序里绝对不能随便写一个没有退出条件的WHILE循环。

普通软件卡住了，用户顶多重启一下。PLC卡住了，机械设备可还带着惯性在飞呢。性质完全不一样。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-005.jpg]]

#### 2.2.2 电源模块（供电方案与掉电保护机制）

电源模块是PLC的心脏，负责给整套系统稳定供电。工业现场的电压波动、瞬时断电很频繁，普通电源根本扛不住，PLC专用电源模块做了专属稳压、滤波、抗干扰设计。

常见的PLC供电分为220V交流供电和24V直流供电两种。电源模块会把输入电压转换成PLC内部硬件、背板总线、IO模块需要的稳定电压，杜绝电压波动导致的程序错乱、硬件烧毁问题。

这儿重点讲的是掉电保护机制，这是工程中特别关键、却经常被忽略的功能。电源模块内置储能电容或备用电池，设备瞬时断电时，不会立刻停机。会利用剩余电量完成最后一次数据保存、寄存器状态锁定，避免关键参数、计数数据、配方数据丢失。

很多新手遇到过设备断电重启后，计数器数据清零、配方参数丢失的问题。大概率就是掉电保护设置不当，或者备用电池亏电导致的。我现场调试时，每次验收都会重点检查掉电保持区域配置，这细节真的能避免后期无数售后麻烦。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-006.jpg]]

#### 2.2.3 输入/输出模块（I/O信号交互）

I/O模块是PLC跟外部世界打交道的窗口。

**输入模块**负责把现场的开关信号、传感器信号转换成PLC能识别的数字信号。中间有**光耦隔离**——这玩意用电光信号转换的方式把现场和PLC内部隔开，现场那边哪怕电压浪涌把模块烧了，CPU这边屁事没有。

**输出模块**反过来，把PLC的运算结果转换成能驱动执行器的信号。输出有三种形式：

- **继电器输出**：便宜、能带大负载，但动作慢、有机械寿命限制
- **晶体管输出**：速度快、寿命长，但只能带直流负载
- **晶闸管输出**：适合交流负载

选哪种看你带什么负载。带接触器用继电器输出没问题，带伺服驱动器最好用晶体管输出——速度快、响应及时。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-007.jpg]]

#### 2.2.4 存储器模块（物理芯片级划分：RAM/ROM/EEPROM）

从物理芯片角度看，PLC的存储器分两大类：易失性和非易失性。

RAM读写快得像闪电，适合放程序运行时的变量、中间结果、映像区数据。但断电就失忆，所以得靠电池、超级电容或者掉电保存机制撑着。

ROM通常存固件、启动程序和系统底层代码，用户一般动不了。

EEPROM或Flash断电不失忆，专门用来存用户程序、配置、配方和保持数据。但Flash有擦写寿命限制，可别把每个扫描周期都在变的数据往里写。正确做法是检测到数据变化了，在合适的时间或者受控周期内保存一次。

逻辑存储区和物理芯片不是一一对应的。你程序里看到的M区、DB区、V区或者标签，可能被控制器映射到不同的物理介质上。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-008.jpg]]

#### 2.2.5 通信与扩展模块（现场总线与工业以太网接口）

现在 PLC的通信早就不是“接个串口读几个寄存器”那么简单了，还有各家品牌的专用网络。

- **RS-232/RS-485**：老牌串口，速度慢但稳定
- **Modbus**：应用最广的现场总线协议之一
- **PROFINET**：西门子的工业以太网
- **EtherCAT**：高速实时以太网，运动控制的首选
- **OPC UA**：未来的方向，跨平台、安全

扩展模块用来增加I/O点数或特殊功能。I/O点数不够了加I/O模块，要控制伺服加运动控制模块，要联网加通信模块——模块式PLC的扩展就是这么灵活。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-009.jpg]]

### 2.3 I/O信号采集与输出物理原理

#### 2.3.1 开关量信号（干接点/湿接点）采集与驱动原理

干接点自己不带电，就是个纯粹的机械开关，只负责接通或断开电路。按钮、继电器触点、部分限位开关都属于这类。

湿接点自己会输出电压或电流。三线制接近开关、光电传感器、某些控制器输出，通常都是湿接点。

数字量输入模块内部一般有限流、滤波、阈值判断和光电隔离电路。

输入电压达到规定范围时，内部光耦导通，模块告诉CPU“哥们儿，这儿有信号了”，也就是逻辑1。电压低于关闭阈值时，光耦截止，通道识别为逻辑0。开启阈值和关闭阈值之间通常有个滞回区间，防止信号在边界附近抖个不停。

输入滤波会带来延迟。

机械按钮抖几毫秒，滤波能完美消除。但高速编码器脉冲只有几十微秒，普通滤波一口就把信号吃掉了。所以高速计数必须走专门的高速输入通道，别把普通DI当万能插口用。

输出侧也不是简单地把程序里的TRUE变成24V。

CPU先把输出数据给模块，模块经过隔离，再由继电器、晶体管或晶闸管去驱动负载。电磁阀和接触器线圈是感性负载，断电瞬间会产生反向电压。直流线圈得配续流二极管，交流线圈常用RC吸收或压敏器件保护。

PLC输出点烧了，很多时候真不是程序的问题。是电气设计拿它当大力士用了，小马拉大车，能不坏吗？

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-010.jpg]]

#### 2.3.2 模拟量信号（4-20mA / 0-10V）的A/D与D/A转换原理

模拟量输入模块先对信号进行保护、滤波和调理，再送入模数转换器（A/D）。

A/D转换器把连续的电压或电流掰成离散的数字。分辨率越高，能掰的等级就越多。12位转换器理论上能分4096个等级，16位就是65536个等级。

位数高不代表现场测的就准。

传感器精度、模块误差、线路干扰、接地、电源波动、温漂——随便哪一个都比量化误差大得多。用一支误差1%的变送器接16位模块，然后盯着小数点后四位使劲看，多少有点自我感动了。

4-20mA信号在工业现场特别常见。零点不是0mA而是4mA，一来能表示量程下限，二来方便检测断线。线路一断，电流直接掉到0mA，控制器立马知道出事了。

0-10V接线简单，但容易受压降和电磁干扰影响，只适合距离短、环境干净的场景。

模拟量输出正好反过来。CPU给个数字值，D/A转换器变成电压或电流，再经过输出驱动电路去指挥变频器、调节阀这些执行机构。

## 三、PLC核心工作原理

### 3.1 PLC“程序存储、循环扫描”的控制核心逻辑

PLC最经典的工作方式就八个字：**程序存储、循环扫描**。

你把控制逻辑下进去，CPU切到RUN模式以后，就开始不知疲倦地重复“读输入→跑程序→处理系统任务→更新输出”这一套流程。

你可以把它想象成一个**永远不下班、精神还特别好的值班员**。

这位值班员先把现场所有输入状态抄到小本本上，然后从程序第一行读到最后一行的计算结果写进“输出计划表”。等整轮逻辑全搞定了，再把输出计划一起发出去。接着立马开始下一轮。

**用户程序从不直接操作物理I/O**。这是PLC设计的一条铁律。程序操作的是**映像寄存器**——输入映像寄存器和输出映像寄存器。物理I/O跟映像寄存器之间的数据交换由系统在固定的时间点完成。

这个设计的核心目的是**确定性**。如果程序直接操作物理I/O，输入信号在程序执行到一半的时候突然变了怎么办？程序的行为就变得不可预测了。用映像寄存器做中间层，整个扫描周期内数据是固定的——程序的行为就是确定的、可重复的。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-012.jpg]]

### 3.2 循环扫描工作模式四阶段详解

大部分人说PLC扫描分三个阶段。但我习惯分成四个——多了个**自诊断**。别杠，三阶段也没错，但四阶段更完整。

#### 3.2.1 自诊断阶段（硬件状态与程序语法自检）

PLC上电以后，会先给自己做个全身检查：硬件检测、存储器校验、模块识别、配置检查。

严格说，程序语法在编译下载阶段就查完了。运行时的诊断主要关注模块丢失、地址访问出错、看门狗超时、通信故障、电源异常、存储器错误这些运行时毛病。

有些故障允许CPU继续运行，只记录一条诊断信息。严重故障则会触发错误处理组织块、故障任务，甚至直接停机。

程序员心里要有杆秤：报警、故障、停机，这三件事得分清楚。

温度传感器断线了，停掉加热、提示维修就行了。安全控制器通信丢了，那整个系统可能得立刻进入安全状态。别什么异常都直接让PLC停机，那不叫安全，那叫偷懒。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-013.jpg]]

#### 3.2.2 输入采样阶段（物理信号→输入映像寄存器的刷新机制）

输入采样阶段，PLC会去读取物理输入模块的所有状态，然后一股脑写进输入过程映像区。

假设按钮接在I0.0。程序里读I0.0的时候，并不是每次都直接去摸接线端子，而是去输入映像区里找对应的位。

这么干有两个好处：

- 同一个扫描周期内，程序看到的输入快照是一致的，不会出现读到一半信号变了的情况。
- CPU不用每执行一条触点指令就去访问一次硬件总线，省事儿多了。

当然，有些平台支持直接读取外设输入或者用立即输入指令。它们可以绕过映像区，获取更接近当前时刻的状态。代价是程序时序变复杂了，访问速度也可能不一样。

普通逻辑就老老实实用过程映像。只有真的需要时才考虑立即访问。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-014.jpg]]

#### 3.2.3 程序执行阶段（梯形图逻辑顺序扫描与输出映像暂存）

程序执行阶段，CPU按照任务和程序的组织顺序一路往下跑。

梯形图一般是从上到下、从左到右求值。结构化文本就按语句顺序执行。调用函数、功能块、子程序的时候，CPU跳进去干完活再回来。

程序里修改输出变量时，结果通常先写进输出映像区，不会立刻去改变物理端子的状态。

同一个输出在程序里被写了多次，那后面执行的会覆盖前面的。

比如下面这段逻辑，能编译，但维护起来就是颗定时炸弹：

```
MotorRun := StartCommand AND NOT Fault;IF ManualMode THEN    MotorRun := ManualJog;END_IF;IF EmergencyStop THEN    MotorRun := FALSE;END_IF;
```

最终结果看执行顺序。急停逻辑在最后，暂时没事。哪天有人调整程序结构，把第一行挪到最后，MotorRun就可能被重新写成TRUE，那乐子就大了。

更稳妥的做法是集中计算最终命令：

```
RunPermission :=    NOT EmergencyStop    AND NOT Fault    AND SafetyDoorClosed;IF ManualMode THEN    RequestedRun := ManualJog;ELSE    RequestedRun := StartCommand;END_IF;MotorRun := RequestedRun AND RunPermission;
```

一只输出线圈满程序飞，是很多老项目的传统艺能。我年轻时也这么写，后来查故障查到凌晨三点，才真正理解了“最后一次赋值生效”这几个字有多沉重。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-015.jpg]]

#### 3.2.4 输出刷新阶段（输出映像寄存器→物理输出锁存与驱动）

程序执行完了，PLC会把输出映像区的数据一股脑发给物理输出模块。

输出模块把这些状态锁存住，然后持续驱动负载，直到下一次刷新。

所以，一个普通数字量输入发生变化以后，最坏情况下可能要等到下一轮输入采样、程序执行、输出刷新，才能体现在物理输出上。

当然，部分PLC、远程I/O和任务模型并不死板地遵循这个四阶段顺序。有些平台会异步更新I/O，有些采用周期任务，还有些模块有自己独立的刷新周期。

比如罗克韦尔的Logix平台更强调任务、标签和异步I/O更新，不能把传统PLC-5的固定文件扫描思维直接搬过去。学习的时候可以从经典扫描模型入手，但真做项目的时候必须回到具体控制器的手册。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-016.jpg]]

### 3.3 扫描周期（Scan Cycle）深度剖析

#### 3.3.1 扫描周期的构成要素与典型毫秒级数值

扫描周期就是PLC完成一轮主要循环所花的时间。

它通常包括输入处理、程序执行、输出处理、系统管理、通信服务、诊断任务这些环节。不同平台对扫描周期的定义可能有点区别，在线监控里看到的周期时间可能只是主循环任务的时间。

以我做过的普通包装机和输送线项目来看，主循环一般跑在2ms到15ms之间。要是加上复杂通信、字符串处理、大量浮点运算，跑到几十毫秒也不稀奇。

但注意了，这个经验值可不能拿来当验收标准。

扫描周期得由设备的响应要求来倒推。一个温控系统允许100ms级的响应，20ms周期就非常宽裕了。但高速切标信号只有1ms宽，你5ms的扫描周期根本抓不到。

西门子S7-1200的系统手册里，最大循环时间保护值可以配到1ms到6000ms。这个参数是看门狗边界，可不是让你把程序真的跑成几秒钟一圈。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-017.jpg]]

#### 3.3.2 影响扫描周期的三大因素（程序步数/指令类型/通信请求）

**第一，程序步数**。程序越长，扫描时间越长。这个最直接。

**第二，指令类型**。简单指令（常开、常闭、线圈）执行快；复杂指令（浮点运算、PID、通信指令）执行慢。不同指令的执行时间在PLC的文档里都有。

**第三，通信请求**。扫描周期中间如果插入了通信处理（比如HMI读取数据、上位机监控），扫描时间会变长。

我有一次就遇到这情况：设备平时跑得好好的，只要工程师在线打开一个巨大的监控表，扫描周期就蹭蹭往上涨。大家怀疑网络、怀疑CPU，最后发现监控表里一次性订阅了好几千个变量。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-018.jpg]]

#### 3.3.3 扫描周期与I/O响应滞后的因果关系

假设一个输入刚好在输入采样结束后发生了变化。

那它就得等到下一次输入采样才能进映像区，然后程序跑逻辑，再等到输出刷新阶段才能生效。这还不算模块滤波和机械动作的时间。响应时间大概在一个到两个扫描周期之间。

再加上输入滤波、远程I/O刷新、网络传输、输出模块延迟，总响应时间会更长。

可以这么近似理解：

```
总响应时间≈ 输入模块滤波时间+ 等待输入刷新时间+ 程序任务等待与执行时间+ 等待输出刷新时间+ 输出模块响应时间+ 执行机构动作时间
```

强调一下，PLC逻辑响应快，不代表机械系统动作就快。

电磁阀可能要十几毫秒，气缸可能要几百毫秒，电机加速更久。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-019.jpg]]

### 3.4 中断工作机制与特殊运行逻辑

#### 3.4.1 时间中断与硬件中断的触发机制

中断这玩意**不受扫描周期限制**。允许PLC暂时打断普通循环，优先去执行某段更紧急的任务。

时间中断按设定的周期触发。比如每10ms执行一次速度计算，每100ms采集一次过程数据。这比在主循环里用普通定时器触发更稳定，因为触发时刻跟主循环扫到哪儿没关系。

硬件中断由输入边沿、模块事件、比较结果或者外部信号触发。高速传感器来了个上升沿，CPU立刻停下手中的活去响应中断程序，避免普通扫描漏掉这个短脉冲。

当然中断也不是越多越高级。

高优先级任务执行太久，会压榨低优先级任务的时间。多个中断频繁嵌套，主循环可能会被抖得怀疑人生。中断程序应该短、小、精悍，复杂计算最好转交给普通任务慢慢搞。

常见的做法是在中断里只记录时间戳、保存数据、置位一个事件标志，然后由主循环去处理后续的复杂逻辑。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-020.jpg]]

#### 3.4.2 高速计数/脉冲输出对中断的依赖

高速计数器通常由专用硬件模块来完成计数工作。

编码器脉冲可能达到几十K甚至更高，普通PLC扫描根本来不及一个个数。高速计数模块在硬件层面默默累计脉冲，CPU只需要去读一下结果，或者在达到比较值时响应一个中断就行了。

高速脉冲输出也是类似，由专用硬件发生器完成。CPU负责配置频率、脉冲数和加减速参数，硬件模块精确输出。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-021.jpg]]

## 四、数制与编码基础

### 4.1 计算机常用数制及其转换

#### 4.1.1 二进制（Binary）、十进制（Decimal）、十六进制（Hexadecimal）

PLC内部所有数据，最终都是二进制形式存储的。

二进制只有0和1，每一位的权值是2的幂。十进制是咱们人最习惯的。十六进制用0到9和A到F，每一位对应4个二进制位，看位模式、地址、通信报文的时候特别好用。

比如十进制45，可以写成：

```
十进制    45二进制    0010 1101十六进制  16#2D
```

十六进制2D拆开，2对应0010，D对应1101，拼起来正好是00101101。

做通信调试的时候，十六进制比十进制直观太多了。

一个状态字是16[#002D](javascript:;)，转成二进制，一眼就能看出第0、2、3、5位是1。设备手册上经常把每一位定义成运行、故障、到位、报警这些状态。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-022.jpg]]

#### 4.1.2 八进制（Octal）在老旧PLC地址编排中的特殊应用

八进制每一位对应3个二进制位。

现代PLC编程里八进制远没有十六进制常见，但部分老PLC或者传统地址体系曾经用八进制编排I/O地址。

这就产生了一个让新手特别难受的现象：地址从X7以后直接跳到X10，根本不存在X8和X9。

因为八进制只有0到7。

维护老设备的时候，看到地址突然跳号，先别急着骂前任。可能人家只是活在另一个进制里。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-023.jpg]]

### 4.2 BCD码（二进制编码的十进制数）的工程意义

BCD码用4个二进制位表示一个十进制数字。

十进制45，普通二进制是00101101，BCD表示则是0100 0101。前4位是4，后4位是5。

BCD会浪费一部分编码空间——4位二进制本来能表示0到15，它只用了0到9。但它特别适合数码管、老式仪表和那些直接面向十进制显示的设备。

有些老PLC的定时器预置值、计数器、外部拨码开关会用BCD。现代项目里BCD见得少了，但跟老设备通信的时候还是会遇到。

转换的时候千万要确认：这个数到底是个普通二进制整数，还是BCD？

16[#45作为普通整数等于十进制69](javascript:;)，作为BCD则表示十进制45。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-024.jpg]]

### 4.3 有符号数的三种机器码表示（原码、反码、补码）

原码用最高位表示符号，其余位表示绝对值。

反码对负数的数值位取反。补码在反码基础上加1。

现代计算机和PLC里的有符号整数，基本都是用二进制补码表示。以8位数据为例，十进制-5的补码是这么算的：

```
+5        0000 0101逐位取反  1111 1010加1       1111 1011
```

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-025.jpg]]

#### 4.3.1 补码在PLC整数加减法中的运算优势

补码最大的好处是：加法器可以统一处理正数和负数，不用搞两套逻辑。

比如5加上-5：

```
  0000 0101+ 1111 1011-----------1 0000 0000
```

最高位的进位直接丢弃，结果是0，完美。

补码还消灭了正零和负零两种表示。8位有符号整数的范围是-128到127，而不是对称的-127到127。

这也解释了一个奇怪的现象：8位有符号数-128取绝对值的时候，结果128已经超出正数范围了。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-026.jpg]]

### 4.4 位（Bit）、字节（Byte）、字（Word）、双字（DWord）的层级关系与物理存储长度

一个Bit只能表示0或1。

8个Bit组成一个Byte。16个Bit组成一个Word，也就是2个Byte。32个Bit组成一个DWord，4个Byte。

```
1 Byte  = 8 Bit1 Word  = 2 Byte = 16 Bit1 DWord = 4 Byte = 32 Bit
```

有些平台还支持64位的LWord。

数据长度和数据含义是两码事。

WORD占16位，INT通常也占16位。它们底层比特数量一样，但解释方式完全不同。WORD更像一组没有正负意义的位，INT则把最高位当符号位，表示范围是-32768到32767。

同一串二进制位，换个数据类型，数值就完全变了。

这不是PLC在变魔术，是你在告诉它应该怎么理解这些位。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-027.jpg]]

## 五、PLC数据存储体系与寻址方式

### 5.1 PLC存储器的逻辑区域划分

#### 5.1.1 系统程序存储区（固件区）

这块存的是PLC的**操作系统**——出厂就写好了，用户动不了。

包括啥？**指令解释器**（把你写的梯形图翻译成机器码）、**扫描调度程序**（控制循环扫描的节奏）、**通信协议栈**（跟HMI、上位机通信）、**自诊断程序**。

这块区域在**ROM**里。掉电不丢，也不能改。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-028.jpg]]

#### 5.1.2 用户程序存储区（工作逻辑区）

用户程序区存着你的梯形图、结构化文本、功能块、数据块、任务配置和硬件组态。

下载到PLC的内容可能包含源代码，也可能只有编译后的执行代码，具体看品牌和保护设置。

大型项目应该划清程序层次。设备控制、报警、通信、配方、HMI接口、系统管理——别一股脑全塞进一个主程序里。

能跑不代表能维护。

一个三千行的大程序，刚写完的人可能觉得逻辑尽在掌握。半年以后他自己回来，都得重新考古。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-029.jpg]]

#### 5.1.3 数据存储区（核心数据载体：I/Q/M/V/T/C区详解）

传统PLC常把数据区分成：输入I、输出Q、内部位M、变量V、定时器T、计数器C。

I区存输入映像，Q区存输出映像，M区存内部状态，V区存通用变量，T和C给定时器和计数器用。

不同品牌的命名不统一。

三菱传统常见X、Y、M、D、T、C。欧姆龙传统常见CIO、WR、HR、DM。西门子S7常见I、Q、M、DB。罗克韦尔新一代Logix更强调标签，不要求你必须围着固定数据文件组织变量。

所以，I/Q/M/V这种划分适合理解原理，不能当成所有PLC的统一地址表。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-030.jpg]]

### 5.2 输入/输出映像寄存器（I区与Q区）的刷新规则

输入映像区是物理输入在某个时刻的快照。

CPU读了模块数据以后写进I区，程序用这份快照完成计算。

输出映像区是这一轮程序生成的输出计划。程序可以多次修改它，最终结果在输出刷新阶段才交给物理模块。

下面这段代码展示了“映像思维”：

```
StartButtonState := InputImage_StartButton;MotorOutputImage := StartButtonState AND SafetyReady;
```

在真实PLC里，InputImage_StartButton可能对应I0.0，也可能是映射后的符号变量。MotorOutputImage可能对应Q0.0，也可能先写进内部命令，再由统一输出层处理。

大型项目里，我强烈建议建立I/O映射层：

```
// 输入映射DI_StartButton      := I_StartButton;DI_StopButton       := I_StopButton;DI_SafetyDoorClosed := I_SafetyDoor;// 输出映射Q_MotorContactor := Cmd_MotorRun AND SafetyOutputPermission;
```

这样多写了几行，但物理地址和控制逻辑彻底分开了。以后换模块、调地址、做仿真，都会轻松得多。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-031.jpg]]

### 5.3 内部辅助继电器（M区）、特殊标志位（SM区）与变量存储区（V区）

M区通常存内部逻辑状态。

比如自动模式、手动模式、步骤完成、报警存在、启动请求、通信就绪——这些都不是物理继电器，只是存储器里的一个位而已。

特殊标志位由系统维护。常见的有首次扫描、固定周期时钟、常开位、常闭位、运算溢出、通信状态、诊断标志。

不同品牌对特殊位的定义差异很大，用之前一定查手册。

首次扫描位特别好用。PLC从STOP切到RUN的第一个周期，可以靠它来做变量初始化：

```
IF FirstScan THEN    StepNumber := 0;    StartRequest := FALSE;    AlarmQueueWriteIndex := 0;END_IF;
```

变量存储区可以放字节、整数、浮点数、数组、结构体。现代符号化编程越来越强调变量名和数据类型，而不是死记硬背绝对地址。

三菱iQ-R平台的官方资料也强调标签可以声明名称和数据类型，让程序不直接依赖设备号和缓冲区地址，提高移植性。不是要让地址消失，而是让程序表达业务含义。

D100你能看出什么？Tank01_LevelRaw一眼就知道是1号罐的液位原始值。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-032.jpg]]

### 5.4 PLC寻址方式深度对比

#### 5.4.1 直接寻址（绝对地址与符号寻址）

**直接寻址**就是直接在指令里写地址。

绝对地址直接指定位置，比如I0.0、Q0.1、MW10、D100：

```
LD I0.0      // 读取输入I0.0的状态OUT Q0.0     // 输出到Q0.0
```

优点是调试老设备的时候特别直观。缺点是硬件地址变了程序就得跟着改，可读性差，复杂数据结构不好表达。

符号寻址：

```
LD StartButton    // StartButton是I0.0的符号名OUT MotorRun      // MotorRun是Q0.0的符号名
```

符号寻址可读性强多了。看到`StartButton`就知道是启动按钮，看到`I0.0`还得翻图纸。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-033.jpg]]

#### 5.4.2 间接寻址（指针寻址与索引寻址的应用场景）

**间接寻址**不直接写地址，而是**通过指针动态计算地址**。

西门子的指针是一个**DWORD**变量，存的是一个内存地址。用`&`取地址，用`*`解引用。

```
// 西门子S7-200 SMART的间接寻址示例MOVD &VB100, VD200    // 把VB100的地址存入VD200（VD200就是指针）MOVB 50, *VD200       // 把50写入VD200指向的地址（也就是VB100）
```

三菱的方式不太一样——用的是**变址寄存器**V和Z。V和Z的值会加到地址上形成偏移。

```
// 三菱的变址寻址示例MOV K3 V0             // V0 = 3MOV K100 D10V0        // 把100写入D10+3 = D13
```

两种方式的本质区别：

- **西门子指针**：存的是绝对地址，可以指向任何区域
- **三菱变址**：存的是偏移量，必须依附于一个基地址

间接寻址最典型的应用是**遍历数组**。比如你有100个配方参数存在V区，用指针循环递增就能依次访问。不用写100条一模一样的指令。

## 六、PLC数据类型系统

### 6.1 数据类型概述与IEC 61131-3标准体系

数据类型定义了存储长度、数值范围、解释方式，以及允许对它做什么操作。

同样是32位数据，可以是DWORD、DINT，也可以是REAL。DWORD强调位模式，DINT表示有符号整数，REAL按浮点格式解释。

IEC 61131-3给PLC编程语言和数据类型立了个标准框架。2025年第4版继续保留了LD、FBD、ST、SFC体系，还加入了UTF-8字符串及相关函数。但具体控制器完整支持哪些类型，还得看厂商、CPU型号和固件版本。

标准归标准，别看到标准里写了POINTER，就想当然以为手里的小型PLC一定支持。也别看到某品牌支持LREAL，就觉得所有CPU跑64位浮点运算都一样快。

标准提供共同语言，产品决定实际边界。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-035.jpg]]

### 6.2 基本数据类型详解

#### 6.2.1 布尔型（BOOL）：1位存储与开关量/故障标志应用

BOOL只有FALSE和TRUE两个值。

适合表示按钮状态、传感器状态、运行命令、故障标志、条件结果。

```
SafetyReady :=    EmergencyStopReleased    AND SafetyDoorClosed    AND AirPressureOK;
```

BOOL逻辑看着简单，但命名不清很容易产生歧义。

EmergencyStop为TRUE，到底是急停已经按下，还是急停回路正常？

我个人的习惯是带上状态含义，比如EmergencyStopPressed或EmergencyStopReleased。变量名稍微长一点，总比维修时让人猜谜强。

BOOL逻辑上占1位，但某些控制器为了对齐和访问效率，可能按字节或更大的单位来分配结构体空间。别用“1000个BOOL一定只占125字节”这种理论值去直接估算实际内存。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-036.jpg]]

#### 6.2.2 字节型（BYTE）：8位组合与底层通信裸数据处理

BYTE占8位，常用于通信报文、字符编码、位组合。

假设一个设备状态字节里每位代表一种状态，可以用掩码提取：

```
RunState   := (StatusByte AND 16#01) <> 0;FaultState := (StatusByte AND 16#02) <> 0;RemoteMode := (StatusByte AND 16#04) <> 0;
```

BYTE适合处理裸数据，但不适合直接表示有符号温度或累计数量。数据本身没错，错的是你的解释方式。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-037.jpg]]

#### 6.2.3 字型（WORD）/ 双字型（DWORD）：位串逻辑与移位指令载体

WORD占16位，DWORD占32位。

常用于状态字、控制字、位掩码、移位寄存器、通信数据。

```
AlarmWord := 16#0000;IF MotorOverload THEN    AlarmWord := AlarmWord OR 16#0001;END_IF;IF AirPressureLow THEN    AlarmWord := AlarmWord OR 16#0002;END_IF;IF SafetyDoorOpen THEN    AlarmWord := AlarmWord OR 16#0004;END_IF;
```

移位操作可用于流水线跟踪：

```
IF ConveyorPitchPulse THEN    TrackingBits := SHL(IN := TrackingBits, N := 1);    TrackingBits.0 := ProductDetected;END_IF;
```

实际语法随平台变化，有些控制器不允许直接访问DWORD的“.0”成员，得用位索引或掩码。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-038.jpg]]

#### 6.2.4 有符号整型（INT / DINT）：数值范围与运算溢出陷阱

INT通常16位，范围-32768到32767。

DINT通常32位，范围-2147483648到2147483647。

INT适合模拟量原始值、小范围计数、参数。DINT适合累计数量、时间计算、大范围位置值、中间运算。

溢出是整数运算最常见的坑。

```
VAR    ValueA : INT := 30000;    ValueB : INT := 10000;    Result : INT;END_VARResult := ValueA + ValueB;
```

数学结果是40000，超出INT范围。不同平台可能发生回绕、置位错误标志，或者触发运行异常。

更安全的做法是先把中间运算类型扩大：

```
ResultDInt := INT_TO_DINT(ValueA) + INT_TO_DINT(ValueB);
```

注意表达式的中间类型特别重要。即使最终结果变量是DINT，某些平台仍可能先按INT做完运算再转成DINT。前面已经溢出了，后面把错误结果装进更大的箱子里也没用。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-039.jpg]]

#### 6.2.5 无符号整型（UINT / UDINT）：特殊地址运算场景

UINT通常16位，范围0到65535。

UDINT通常32位，范围0到4294967295。

无符号类型适合计数、位地址、长度、索引、协议字段。没有负数，所有位都能用来表示正数。

但无符号数也有自己的坑。

```
VAR    Counter : UINT := 0;END_VARCounter := Counter - 1;
```

从0减1，可能直接回绕到65535。

所以无符号数并不天然安全。做减法之前，该检查边界还得检查。

罗克韦尔较新的Logix版本扩展了UINT、UDINT、LINT、ULINT、LREAL这些原子类型，但旧控制器或老版本项目可能不支持，迁移的时候一定要确认控制器代际。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-040.jpg]]

#### 6.2.6 浮点数/实数型（REAL / LREAL）：32位单精度与64位双精度的存储原理及精度取舍

REAL通常用32位IEEE 754单精度格式。

它由符号位、指数、尾数组成，能表示非常大或非常小的数，但有效精度有限——大约能保持6到7位十进制有效数字。

LREAL通常64位双精度，精度和范围都更高，代价是占空间更大，部分PLC执行也更慢。

REAL非常适合量程换算、PID、滤波、工程单位计算。

```
PressureBar :=    (INT_TO_REAL(PressureRaw) - RawMin)    * (EngineeringMax - EngineeringMin)    / (RawMax - RawMin)    + EngineeringMin;
```

REAL不适合做精确货币累计、超大整数计数、完全相等判断。

```
IF MeasuredValue = 0.3 THEN    // 这段逻辑可能永远不触发END_IF;
```

浮点数0.1、0.2、0.3在二进制里通常无法精确表示。计算结果可能是0.30000001，也可能是0.29999998。

更稳妥的写法是用允许误差：

```
IF ABS(MeasuredValue - 0.3) < 0.001 THEN    ValueIsNearTarget := TRUE;END_IF;
```

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-041.jpg]]

### 6.3 时间与日期数据类型（TIME / DATE / TOD / DTL）的存储结构

TIME表示一段持续时间，比如500ms、10s、2h。

```
DelayTime := T#2s500ms;
```

DATE表示日期，TOD或TIME_OF_DAY表示一天中的时刻。DT、DATE_AND_TIME或DTL把日期和时间组合起来。

时间段和时间点可不能混为一谈。

电机延时启动用TIME。记录报警发生在2026年8月3日16:20，得用日期时间类型。

西门子S7-1200/1500编程指南推荐用DTL表示日期时间，可以通过Year、Month、Day、Hour、Minute、Second、Nanosecond这些成员直接访问。时间计算还得考虑时区、夏令时、UTC。

设备只在工厂内部跑的时候，本地时间看着够用。数据要上云、跨国部署、多设备事件排序时，最好统一存UTC时间戳，由上层系统负责转换显示。

不然夏令时切换那天，凌晨一点可能被记两遍。数据库没疯，是人类规定时间的方式太复杂了。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-042.jpg]]

### 6.4 复杂数据类型（构造数据类型）

#### 6.4.1 数组（ARRAY）：批量数据管理的工程应用

数组是一组相同类型的元素。

```
VAR    ZoneTemperature : ARRAY[0..9] OF REAL;    StationReady    : ARRAY[1..20] OF BOOL;END_VAR
```

数组特别适合工位、温区、轴、配方参数、历史数据。

```
AverageTemperature := 0.0;FOR Index := 0 TO 9 DO    AverageTemperature :=        AverageTemperature + ZoneTemperature[Index];END_FOR;AverageTemperature := AverageTemperature / 10.0;
```

用数组得防着索引越界。

```
IF (SelectedIndex >= 0) AND (SelectedIndex <= 9) THEN    SelectedTemperature := ZoneTemperature[SelectedIndex];ELSE    IndexFault := TRUE;END_IF;
```

某些PLC越界会触发运行错误，有些可能访问到错误位置。别赌。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-043.jpg]]

#### 6.4.2 结构体（STRUCT）与用户自定义类型（UDT）：面向对象编程思维的落地

结构体能把不同类型的数据组织成一个整体。

```
TYPE MotorData :STRUCT    StartCommand  : BOOL;    StopCommand   : BOOL;    Running       : BOOL;    Fault         : BOOL;    Current       : REAL;    RuntimeHours  : DINT;END_STRUCTEND_TYPE
```

创建变量以后，一个电机的所有相关数据就都放在一块了。

```
VAR    ConveyorMotor : MotorData;END_VAR
```

多个设备还能组成结构体数组。

```
VAR    Motor : ARRAY[1..12] OF MotorData;END_VAR
```

UDT最大的价值不是省几行代码，而是统一数据模型。

HMI、PLC、上位机、通信接口，都可以围绕同一种设备结构来组织数据。以后要新增一个故障复位字段时，影响范围也更容易定位。

罗克韦尔的官方文档把数据类型分成预定义类型、模块定义类型和用户自定义类型。模块I/O数据本身也经常以结构体标签的形式出现。

结构体负责组织数据，功能块封装状态和行为。两者一结合，确实能建立可复用的设备对象。工业控制更关心确定性和可维护性，不用照搬互联网软件里所有的设计模式。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-044.jpg]]

### 6.5 特殊/高级数据类型

#### 6.5.1 字符串（STRING / WSTRING）：HMI报文与故障码存储

STRING用来存字符序列。

```
AlarmText := 'Motor overload';
```

WSTRING用于Unicode宽字符。新版IEC 61131-3还引入了UTF-8字符串相关能力，但具体厂商怎么实现、哪些CPU支持，得查平台资料。

字符串常用于HMI提示、产品条码、设备名、配方名、通信报文。

但它也很吃资源。

字符串拼接、查找、转换，比BOOL逻辑重太多了。长度规划不合理还会造成截断。

```
AlarmMessage :=    CONCAT(        'Station ',        INT_TO_STRING(FaultStation)    );
```

大型报警系统不建议在PLC里实时拼接所有完整中文句子。更常见的做法是PLC只发报警编号和参数，由HMI或上位机查表显示文本。

PLC负责说“我这儿发生了10023号报警”，HMI负责翻译成“3号工位气压过低”。各管一摊，维护也轻松。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-045.jpg]]

#### 6.5.2 定时器（TIMER）与计数器（COUNTER）的内部数据类型本质

定时器可不是一只藏在PLC里的实体继电器。

IEC定时器本质上是功能块实例，内部包含输入、预置时间、累计时间、输出状态。

```
MotorStartDelay(    IN := StartRequest,    PT := T#2s);MotorRun := MotorStartDelay.Q;
```

MotorStartDelay自己得保存上一次的调用状态和累计时间，所以它绝不是一个简单的BOOL变量。

计数器也一样，包含当前值、预置值、边沿状态。

```
ProductCounter(    CU := ProductPulse,    R  := ResetCounter,    PV := 100);
```

为什么定时器功能块必须每个周期都调用？

因为它需要持续比较时间、更新内部状态。你要是把它放进一个偶尔才执行的分支里，计时行为肯定不符合预期。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-046.jpg]]

#### 6.5.3 指针（POINTER）与引用（REF）：动态寻址与间接访问

指针存变量地址，引用以更受约束的方式指向对象或变量。

适合通用库、动态数据访问、复杂通信处理。下面是概念性写法，具体语法依平台而定。

```
pValue := ADR(ProcessValue);pValue^ := 12.5;
```

引用通常比裸指针安全，编译器能帮你多检查一层类型关系。

指针最怕三件事：地址无效、类型不匹配、目标生命周期结束。

PLC项目不像普通应用那样频繁动态分配内存，但错误指针依然可能造成极其隐蔽的问题。我的建议比较保守：没有明确收益，别用。团队里没人能维护，也别用。

能炫出来的技术，不一定适合留在生产线里跑十年。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-047.jpg]]

## 七、数据类型转换与工程避坑指南

### 7.1 标准数据类型转换指令（CONV / INT_TO_REAL / BCD_TO_INT 等）

PLC通常提供显式的类型转换指令。

常见的有INT_TO_REAL、REAL_TO_INT、DINT_TO_INT、WORD_TO_INT、BCD_TO_INT，还有通用的CONV。

```
TemperatureReal := INT_TO_REAL(TemperatureRaw);DisplayValue    := REAL_TO_INT(TemperatureFiltered);
```

类型转换可能发生截断、舍入、溢出。

REAL_TO_INT到底是四舍五入还是直接截断？不同指令、不同平台可能不一样。做精确控制时别凭感觉，查手册。

缩小类型转换尤其危险。

```
LargeValue := 50000;SmallValue := DINT_TO_INT(LargeValue);
```

50000超出INT范围。转换结果可能回绕，也可能触发错误。

安全写法是先检查范围：

```
IF (LargeValue >= -32768) AND (LargeValue <= 32767) THEN    SmallValue := DINT_TO_INT(LargeValue);    ConvertError := FALSE;ELSE    ConvertError := TRUE;END_IF;
```

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-048.jpg]]


### 7.2 进制转换与位/字节/字层级拆解实战

假设通信收到了一个DWORD数据16[#1234ABCD](javascript:;)，需要拆成两个WORD。

```
LowWord  := DWORD_TO_WORD(DataValue AND 16#0000FFFF);HighWord := DWORD_TO_WORD(SHR(IN := DataValue, N := 16));
```

继续拆成字节：

```
Byte0 := DWORD_TO_BYTE(DataValue AND 16#000000FF);Byte1 := DWORD_TO_BYTE(SHR(IN := DataValue, N := 8));Byte2 := DWORD_TO_BYTE(SHR(IN := DataValue, N := 16));Byte3 := DWORD_TO_BYTE(SHR(IN := DataValue, N := 24));
```

这里还得注意字节序。

大端模式把高位字节放低地址，小端模式把低位字节放低地址。PLC、仪表、上位机、网络协议的字节序不一致时，数值会变得极其离谱。

一个REAL温度25.0，字节顺序交换后可能变成几万亿，也可能变成一个接近零的小数。

看到这种数值，先别怀疑传感器坏了。先看看字节序吧。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-049.jpg]]

### 7.3 工程中高频数据类型匹配问题与解决方案

#### 7.3.1 整数溢出（Overflow）的诊断与预防

整数溢出通常出现在累计、乘法、中间表达式里。

```
TotalPulse := PulsePerCycle * CycleCount;
```

两个INT相乘，即使结果存到DINT，中间乘法仍可能按INT执行。

```
TotalPulse :=    INT_TO_DINT(PulsePerCycle)    * INT_TO_DINT(CycleCount);
```

累计值还得考虑运行年限。

设备每秒产100件，一天跑20小时，一年就超过6.3亿次。32位有符号整数两年差不多就到头了。项目验收时看着一切正常，两年后产量突然变成负数——现场会以为PLC被什么邪门东西附体了。

累计计数可以用LINT、ULINT，或者设计分段累计和上位机归档。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-050.jpg]]

#### 7.3.2 浮点数精度丢失与“相等比较”的替代写法（阈值区间法）

浮点数比较应该用允许误差。

```
Difference := ABS(ActualPressure - TargetPressure);PressureReached :=    Difference <= PressureTolerance;
```

控制逻辑还可以用上下限回差，避免输出频繁抖动。

```
IF Temperature >= HighLimit THEN    HeaterEnable := FALSE;ELSIF Temperature <= LowLimit THEN    HeaterEnable := TRUE;END_IF;
```

这比判断Temperature = Setpoint靠谱得多。

真实温度有噪声，传感器有误差，浮点数有精度限制。指望它正好等于37.000000，多少有点为难物理世界。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-051.jpg]]

#### 7.3.3 字符串长度预规划与动态缓存区的冲突规避

字符串变量应该根据业务需求预留长度。

产品条码最长40个字符，你就别只留10个。报警说明最多80字符，也没必要每条都给分配1000字符。

通信接收缓存区还得考虑终止符、长度字段、分包。

```
IF ReceivedLength <= MAX_BUFFER_LENGTH THEN    MessageBuffer := ReceivedData;ELSE    BufferOverflow := TRUE;END_IF;
```

多个任务或通信通道共享同一个字符串缓存区时，可能发生覆盖——一个任务还没处理完，另一个已经写入了新数据。

更稳妥的做法是用独立缓存，或者建立生产者-消费者队列。

![[assets/embedded-interview/PLC 原理 + 数据类型，工控入门天花板知识点/img-052.jpg]]

### 7.4 基于数据类型选择的程序扫描效率优化技巧

优化PLC程序，不能只盯着指令数量。

不需要小数的时候，整数运算通常更直接。批量状态可以用WORD或DWORD做掩码处理。大量重复设备可以用数组加循环，但循环上限必须可控。

字符串处理别毫无节制地放在每个扫描周期执行。

```
IF AlarmChanged THEN    AlarmText := BuildAlarmText(AlarmCode);END_IF;
```

比下面这种好得多：

```
AlarmText := BuildAlarmText(AlarmCode);
```

后者每个周期都重新生成字符串，即使报警根本没变化。

结构体对齐也会影响内存占用。把BOOL、INT、REAL胡乱交错排列，某些平台会往里插填充字节。大型数组里，这些填充会被成倍放大。

不过，别为了省几个字节就把结构体排得没人看得懂。

PLC优化的顺序应该是：先保正确，再保可维护，最后才处理有证据的性能瓶颈。凭感觉把代码改得七零八落，扫描周期可能只快了0.1ms，维修时间却多了两小时。

## 八、工作原理与数据类型综合实训案例

### 8.1 实训一：基于BOOL与定时器的电机启停/联锁控制（循环扫描逻辑验证）

这个案例实现电机的启动、停止、故障联锁、延时启动。

控制要求不复杂：按启动按钮后锁存运行请求。安全门关着、急停没按、热继电器正常、气压正常——满足这堆条件后延时两秒启动电机。按停止、出故障、或者安全条件丢了，立刻撤销运行命令。

变量定义如下：

```
VAR    StartButton          : BOOL;    StopButton           : BOOL;    EmergencyStopOK      : BOOL;    SafetyDoorClosed     : BOOL;    MotorOverloadOK      : BOOL;    AirPressureOK        : BOOL;    StartRequest         : BOOL;    RunPermission        : BOOL;    MotorCommand         : BOOL;    MotorFeedback        : BOOL;    StartDelay           : TON;    FeedbackTimeout      : TON;    MotorStartFault      : BOOL;END_VAR
```

主逻辑这样写：

```
// 运行许可集中计算RunPermission :=    EmergencyStopOK    AND SafetyDoorClosed    AND MotorOverloadOK    AND AirPressureOK;// 启停请求锁存IF StartButton AND RunPermission THEN    StartRequest := TRUE;END_IF;IF StopButton OR NOT RunPermission THEN    StartRequest := FALSE;END_IF;// 启动延时StartDelay(    IN := StartRequest AND RunPermission,    PT := T#2s);MotorCommand := StartDelay.Q AND RunPermission;// 接触器反馈超时检测FeedbackTimeout(    IN := MotorCommand AND NOT MotorFeedback,    PT := T#3s);MotorStartFault := FeedbackTimeout.Q;// 启动失败后撤销请求IF MotorStartFault THEN    StartRequest := FALSE;END_IF;
```

从扫描原理看：StartButton在输入采样后进了输入映像。程序检测到按钮为TRUE，把StartRequest置位。定时器每个周期累计时间，到两秒后Q输出变TRUE，MotorCommand跟着进输出映像区。

输出刷新完成，物理输出点驱动接触器。

接触器吸合以后，辅助触点返回MotorFeedback。三秒内没收到反馈，FeedbackTimeout触发故障。

这里有个细节：StartDelay和FeedbackTimeout每个周期都得调用。有人喜欢把定时器塞进IF内部，条件为FALSE时完全不理它。不同平台对功能块未调用时的状态处理不同，很容易留下历史状态。

把定时器持续调用，用IN控制启停，逻辑更清楚。

为了验证循环扫描，可以在线盯着这几个变量：

```
StartButtonStartRequestStartDelay.ETStartDelay.QMotorCommandMotorFeedbackFeedbackTimeout.ETMotorStartFault
```

你会发现状态不是瞬间同时变化的，而是沿着扫描和物理反馈逐步传播。

这就是PLC的节奏。

### 8.2 实训二：基于模拟量（INT/REAL）的温度/压力采集、量程换算与滤波处理

假设压力变送器量程0到10bar，输出4-20mA。模拟量模块把电流转成INT原始值。

为了适配不同PLC，不把原始范围写死，用参数：

```
VAR    PressureRaw          : INT;    RawAt4mA             : REAL := 5530.0;    RawAt20mA            : REAL := 27648.0;    PressureMinBar       : REAL := 0.0;    PressureMaxBar       : REAL := 10.0;    PressureBar          : REAL;    PressureFiltered     : REAL;    FilterCoefficient    : REAL := 0.1;    SensorWireBreak      : BOOL;    SensorOverRange      : BOOL;END_VAR
```

注意了，不同品牌、不同模块、不同配置下的原始范围可能完全不同。上面的5530和27648只是常见量程示例，不能抄到所有设备里。

线性换算公式：

```
工程值 =（原始值 - 原始下限）×（工程上限 - 工程下限）÷（原始上限 - 原始下限）+ 工程下限
```

对应程序：

```
SensorWireBreak :=    INT_TO_REAL(PressureRaw) < (RawAt4mA * 0.9);SensorOverRange :=    INT_TO_REAL(PressureRaw) > (RawAt20mA * 1.05);IF NOT SensorWireBreak AND NOT SensorOverRange THEN    PressureBar :=        (INT_TO_REAL(PressureRaw) - RawAt4mA)        * (PressureMaxBar - PressureMinBar)        / (RawAt20mA - RawAt4mA)        + PressureMinBar;END_IF;
```

现场信号经常有小幅波动，可以加一阶低通滤波：

```
PressureFiltered :=    PressureFiltered    + FilterCoefficient    * (PressureBar - PressureFiltered);
```

FilterCoefficient越小，输出越平滑，响应也越慢。

0.1不是宇宙真理。采样周期变化以后，滤波效果也会跟着变。更严谨的做法是根据采样周期和时间常数算系数：

```
α = Δt /（τ + Δt）
```

Δt是采样周期，τ是滤波时间常数。

```
FilterCoefficient :=    SampleTimeSeconds    / (FilterTimeConstant + SampleTimeSeconds);
```

建议把模拟量处理放进固定周期任务里。比如每100ms跑一次，而不是跟着波动的主循环跑。这样滤波、积分、变化率计算都更稳定。

报警逻辑可以加延时和回差：

```
IF PressureFiltered >= 8.0 THEN    HighPressureCondition := TRUE;ELSIF PressureFiltered <= 7.5 THEN    HighPressureCondition := FALSE;END_IF;HighPressureDelay(    IN := HighPressureCondition,    PT := T#2s);HighPressureAlarm := HighPressureDelay.Q;
```

短暂尖峰不会立刻触发报警，压力回到7.5bar以下才解除高压状态。

有滤波、有回差、有延时——三层都不是为了显得代码有点东西，而是因为真实传感器从来没教科书里那么听话。

### 8.3 实训三：基于数组（ARRAY）与双字（DWORD）的多工位参数批量存储与配方管理

假设一台设备有八个工位，每个工位需要保存目标速度、压力、延时时间、功能使能位。

先建结构体：

```
TYPE StationRecipe :STRUCT    TargetSpeed       : REAL;    TargetPressure    : REAL;    DelayTime         : TIME;    EnableMask        : DWORD;END_STRUCTEND_TYPE
```

再建配方数组：

```
VAR    RecipeData        : ARRAY[0..9, 1..8] OF StationRecipe;    ActiveRecipeIndex : INT;    ActiveStation     : ARRAY[1..8] OF StationRecipe;    StationIndex      : INT;    RecipeIndexValid  : BOOL;END_VAR
```

这里存了十套配方，每套八个工位的参数。

加载配方时先检查索引：

```
RecipeIndexValid :=    (ActiveRecipeIndex >= 0)    AND (ActiveRecipeIndex <= 9);IF LoadRecipeCommand AND RecipeIndexValid THEN    FOR StationIndex := 1 TO 8 DO        ActiveStation[StationIndex] :=            RecipeData[ActiveRecipeIndex, StationIndex];    END_FOR;    LoadRecipeDone := TRUE;ELSE    LoadRecipeDone := FALSE;END_IF;
```

EnableMask用DWORD存多个布尔配置：

```
Bit 0  启用吹气Bit 1  启用检测Bit 2  启用二次定位Bit 3  启用数据记录Bit 4  启用不良品剔除
```

读取状态用掩码：

```
BlowEnabled :=    (ActiveStation[StationIndex].EnableMask AND 16#00000001) <> 0;InspectionEnabled :=    (ActiveStation[StationIndex].EnableMask AND 16#00000002) <> 0;RepositionEnabled :=    (ActiveStation[StationIndex].EnableMask AND 16#00000004) <> 0;
```

置位用OR：

```
ActiveStation[1].EnableMask :=    ActiveStation[1].EnableMask OR 16#00000002;
```

清除用AND配合取反掩码：

```
ActiveStation[1].EnableMask :=    ActiveStation[1].EnableMask AND NOT 16#00000002;
```

配方加载可不能设备正跑着呢随便执行。

稳妥的条件是：设备停了、所有工位在安全位置、自动循环没跑、操作者有权限。

```
RecipeChangeAllowed :=    MachineStopped    AND AllStationsSafe    AND NOT AutoCycleRunning    AND OperatorAuthorized;
```

配方修改还得记下版本、时间和操作者。

工业事故不一定都来自复杂算法。有时候只是有人在设备运行中，把压力参数从0.5改成了5.0。

### 8.4 实训四：基于字符串（STRING）与中断的HMI实时报警推送机制

这个案例实现报警事件捕获和HMI消息队列。

中断或高优先级任务不负责拼接长字符串，只记报警编号、时间和来源。普通任务再把报警转成HMI能读的数据。

先定义报警事件结构体：

```
TYPE AlarmEvent :STRUCT    AlarmCode      : DINT;    SourceStation  : INT;    Active         : BOOL;    Timestamp      : DTL;END_STRUCTEND_TYPE
```

建环形队列：

```
VAR_GLOBAL    AlarmQueue       : ARRAY[0..99] OF AlarmEvent;    WriteIndex       : INT;    ReadIndex        : INT;    QueueCount       : INT;    QueueOverflow    : BOOL;END_VAR
```

硬件中断或事件任务里只做最少的工作：

```
IF QueueCount < 100 THEN    AlarmQueue[WriteIndex].AlarmCode := 10023;    AlarmQueue[WriteIndex].SourceStation := 3;    AlarmQueue[WriteIndex].Active := TRUE;    AlarmQueue[WriteIndex].Timestamp := CurrentTimestamp;    WriteIndex := WriteIndex + 1;    IF WriteIndex > 99 THEN        WriteIndex := 0;    END_IF;    QueueCount := QueueCount + 1;ELSE    QueueOverflow := TRUE;END_IF;
```

普通循环任务负责读取事件：

```
IF QueueCount > 0 THEN    CurrentAlarm := AlarmQueue[ReadIndex];    ReadIndex := ReadIndex + 1;    IF ReadIndex > 99 THEN        ReadIndex := 0;    END_IF;    QueueCount := QueueCount - 1;    NewAlarmForHMI := TRUE;END_IF;
```

PLC只给HMI提供结构化数据：

```
HMI_AlarmCode    := CurrentAlarm.AlarmCode;HMI_Station      := CurrentAlarm.SourceStation;HMI_AlarmTime    := CurrentAlarm.Timestamp;HMI_NewAlarm     := NewAlarmForHMI;
```

HMI根据AlarmCode查表显示中文：

```
10021  1号工位安全门打开10022  2号工位气压过低10023  3号工位电机过载
```

如果PLC确实需要自己生成文本，可以在普通任务里处理：

```
CASE CurrentAlarm.AlarmCode OF    10021:        HMI_AlarmText := 'Safety door open';    10022:        HMI_AlarmText := 'Air pressure low';    10023:        HMI_AlarmText := 'Motor overload';ELSE    HMI_AlarmText := 'Unknown alarm';END_CASE;
```

为什么非要用队列？

因为报警可能在极短时间内连续发生。只用一个NewAlarm变量的话，后来的事件会直接把前面的覆盖掉。队列能保住先后顺序。

为什么中断里不直接拼字符串、写数据库、发网络报文？

因为中断必须快进快出。复杂操作拖得越久，其他控制任务就越容易被耽搁。

这套结构不算多高深，但非常实用。报警系统最怕的不是没弹窗，而是发生了十个报警，最后只记住了最后一个。

## 九、总结

### 9.1 PLC工作原理核心要诀（扫描闭环）与数据类型选型总纲

理解PLC，脑子里始终要有一条闭环。

现场信号进输入模块，输入模块调理、隔离、转换，CPU把数据刷到输入映像区，程序按任务和顺序执行，结果写进输出映像区，输出模块驱动现场设备。

扫描周期决定PLC多久看一次世界，也决定控制结果多久传出去。

数据类型决定PLC怎么理解这些信息。

开关状态用BOOL，通信字节用BYTE，位组合用WORD或DWORD，普通整数用INT或DINT，工程量换算用REAL，长期累计考虑LINT或更大范围，批量数据用ARRAY，设备模型用STRUCT和UDT。

别为了省空间乱用小类型，也别什么都往LREAL里塞。

选型要同时考虑范围、精度、执行效率、通信兼容性、维护习惯。

### 9.2 PLC编程与数据应用中的常见认知误区全汇总

输入端子灯亮了，不代表程序此刻已经读到了新状态。

输出变量为TRUE，也不代表物理输出和接触器一定已经动作。

INT和WORD虽然都占16位，但含义不一样。

REAL能表示小数，不等于它能精确表示所有十进制小数。

保持变量不是越多越安全。有些中间状态断电保持以后，反而会让设备重启流程失控。

扫描周期短不代表系统响应一定快。输入滤波、远程I/O、网络、输出模块、机械机构都会产生延迟。

中断优先级高，不代表可以往里塞一堆代码。

符号化编程也不是随便起个英文名就完事了。好的变量名应该表达设备对象、信号来源、状态含义。

还有一个误区特别常见：程序下载成功，设备跑起来了，大家就觉得项目结束了。

真正的PLC项目还需要考虑：故障处理、断电恢复、通信中断、传感器异常、手自动切换、维护模式、权限控制、安全状态验证。

正常流程只占程序的一部分。异常流程才是项目经验真正拉开差距的地方。

### 9.3 面向未来的PLC技术趋势（OPC UA、数字孪生、AI边缘计算对数据类型的新要求）

PLC正在从单纯的逻辑控制器，变成工业数据链路里的边缘节点。

OPC UA让设备不仅能传地址和值，还能传结构、类型、语义。未来上位系统读取的不再是DB10.DBD4，而应该知道这个变量代表1号反应釜温度，单位摄氏度，量程多少，质量状态是否正常。

数字孪生要求控制程序建立更清晰的数据模型。

设备状态、运行模式、报警、维护信息、能耗、寿命数据——这些都得用结构化形式组织起来。散落在几千个M点和D寄存器里的数据，很难直接支撑孪生模型。

AI边缘计算又带来了更复杂的数据类型。

传统PLC擅长BOOL、整数、实数。视觉模型可能输出类别、置信度、目标坐标、特征向量、时间戳。PLC不一定直接跑大模型，但得可靠地接收结果，并转化成确定性的控制逻辑。

AI说目标存在的概率是92%，PLC还得决定气缸到底伸不伸。

一个给概率，一个必须给动作。中间需要阈值、状态机、超时、质量标志、故障降级。

未来PLC程序员不仅要会画梯形图，还得懂结构化数据、通信模型、时间同步、边缘计算、网络安全。

听着好像压力挺大。

不过别慌。无论技术怎么变，底层规律没变：信号从哪来，数据怎么表示，程序什么时候执行，结果怎么作用于现场。把这几件事想清楚，新概念就不会把人绕晕。

### 附录C 常用工业模拟量信号（4-20mA / 0-10V）与数字量（INT/REAL）换算公式

通用线性换算公式：

```
工程值 =（原始值 - 原始下限）×（工程上限 - 工程下限）÷（原始上限 - 原始下限）+ 工程下限
```

反向换算：

```
原始值 =（工程值 - 工程下限）×（原始上限 - 原始下限）÷（工程上限 - 工程下限）+ 原始下限
```

4-20mA直接按电流算：

```
工程值 =（电流mA - 4）×（工程上限 - 工程下限）÷ 16+ 工程下限
```

比如0到10bar变送器输出12mA：

```
压力 =（12 - 4）×（10 - 0）÷ 16+ 0压力 = 5bar
```

0-10V：

```
工程值 =电压×（工程上限 - 工程下限）÷ 10+ 工程下限
```

带零点偏移的通用版本还是用完整线性公式，别每种信号都重新背一套。

PLC代码里可以封装成通用函数：

```
FUNCTION ScaleLinear : REALVAR_INPUT    RawValue       : REAL;    RawMinimum     : REAL;    RawMaximum     : REAL;    ScaleMinimum   : REAL;    ScaleMaximum   : REAL;END_VARIF RawMaximum <> RawMinimum THEN    ScaleLinear :=        (RawValue - RawMinimum)        * (ScaleMaximum - ScaleMinimum)        / (RawMaximum - RawMinimum)        + ScaleMinimum;ELSE    ScaleLinear := ScaleMinimum;END_IF;
```

调用示例：

```
PressureBar := ScaleLinear(    RawValue     := INT_TO_REAL(PressureRaw),    RawMinimum   := 5530.0,    RawMaximum   := 27648.0,    ScaleMinimum := 0.0,    ScaleMaximum := 10.0);
```

为了防止除以零，函数里检查了RawMaximum和RawMinimum。

工程中还得加限幅：

```
IF PressureBar < 0.0 THEN    PressureBar := 0.0;ELSIF PressureBar > 10.0 THEN    PressureBar := 10.0;END_IF;
```

限幅不能替代传感器故障诊断。

传感器断线以后，把结果强制限制成0bar，HMI上看起来一切正常，实际上故障信息已经被悄悄吃掉了。正确做法是同时输出工程值和质量状态：

```
PressureQualityGood :=    NOT SensorWireBreak    AND NOT SensorOverRange;
```
