## 6. 重要纠错、原表述与适用边界

| 范围 | 原表述/风险 | 处理结果与边界 |
|---|---|---|
| C | “局部变量未初始化就是随机值” | 改为不确定值；声明不等于立即产生未定义行为，读取不确定值可能触发未定义/错误行为。 |
| C | `char s[3] = "abc"` 被一概判错 | 说明它是合法数组初始化但没有结尾 `\\0`；需要 C 字符串时必须预留终止字节。 |
| C/C++ | 宏一定占内存、静态成员一定在某个段 | 改成编译/链接与实现相关；静态成员强调静态存储期，段布局交给实现和链接脚本。 |
| C++ | 虚表、vptr、虚函数内联被写成标准保证 | 改为主流 ABI 模型；多态目标无法确定时通常不能直接内联，但编译器可去虚化。 |
| C++ | `typeid` 总是得到运行时类型 | 区分多态对象左值/解引用与指针表达式：`typeid(ptr)` 得到指针的静态类型。 |
| 操作系统 | 所有系统调用都属于“软中断” | 区分 x86 `int 0x80`、x86-64 `syscall`、ARM SVC、CPU 异常和 Linux softirq。 |
| 操作系统 | 线程退出等于进程退出、detach 可隔离崩溃 | 普通线程退出只结束该线程；致命信号或未捕获异常通常结束整个进程；detach 只改变回收方式。 |
| 操作系统 | 跨进程操作天然原子、有统一内存屏障 | 改为依赖共享映射、CPU 原子指令、锁和 C/C++ 内存序；跨进程同步要选可跨进程的机制。 |
| 操作系统 | `mmap` 就是零拷贝、管道只能父子直接用 | 改为机制依赖映射/驱动；匿名管道可通过继承或 FD 传递建立关联，`socketpair` 另有语义。 |
| 操作系统 | 32/64 位地址分界写成固定十六进制 | 改为 32 位 x86 3G/1G 等配置示例；64 位有效地址位数、内核布局依架构和配置变化。 |
| STM32 | NVIC 管理所有中断；SysTick 一定直接切任务；待机 SRAM/IWDG 行为固定 | 限定为 Cortex-M 可屏蔽外部 IRQ；调度请求通常经 PendSV/port 完成；保持/唤醒源按系列参考手册确认。 |
| FreeRTOS | 临界区必然关闭所有中断、RTOS 保证 deadline | 改为屏蔽范围由 port 决定；调度受配置/优先级/中断影响，V9.0.0 也不提供通用硬实时保证。 |
| FreeRTOS | 任意 ISR API 都能在中断里调用 | 统一使用 `FromISR` 版本和必要的 higher-priority-task-woken 流程；不能在 ISR 中阻塞。 |
| 网络 | TCP 有消息边界、握手代表业务成功、ACK 每次都单独返回 | 改为 TCP 字节流；握手只建立传输状态；ACK 可延迟/累计，业务成功要由应用层确认。 |
| 网络 | Nagle 解决粘包；HTTPS 只等于 TCP+公钥加密 | 改为应用层 framing 与 Nagle 分离；TLS 负责认证/协商/加密，承载可为 TCP 或 QUIC。 |
| 网络 | CRC/MD5 就能保证 OTA 安全 | CRC 主要检错，OTA 完整性/真实性应使用哈希加签名和回滚策略；MD5 不适合作安全抗碰撞依据。 |
| 通讯协议 | CAN 仲裁失败是错误并立即自动重传 | 改为仲裁失败节点退出本次仲裁、下次机会重试；协议错误由控制器按实现处理重传。 |
| 通讯协议 | UART 吞吐、SPI 最高速率、I²C 模式适用于所有芯片 | 增加 bit/s 与帧格式换算、STM32 系列/APB/数据手册、I²C 标准模式和总线电容边界。 |
| Linux 应用 | epoll、timerfd、sysfs GPIO 被写成固定 O(1)/绝对可靠/固定内核版本 | 改为常见实现和使用边界；timerfd 需处理过期次数和共享 FD；sysfs GPIO 标为旧接口，libgpiod v1/v2 分开。 |
| Linux 驱动 | `read/write` 可无界复制，`mmap` 必然零拷贝，kmalloc 内存直接给 DMA | 加入长度检查、用户指针检查、锁/并发说明；DMA 使用一致性/流式 DMA API，mmap 按驱动映射策略决定。 |
| Bootloader/RootFS | TPL、`bootz`、initramfs 形式和 rootfs 位置被写成固定流程 | 标注平台/版本/架构边界；initramfs 是 cpio 归档（常压缩），rootfs 由 bootargs、`/init` 和挂载流程决定。 |
