## 5. 重要技术纠错与边界

### C/C++

- C++ 局部内置类型未初始化改为“不确定值”；声明本身不等于未定义行为，但读取不确定值可能产生未定义/错误行为。
- 虚函数内联改为“多态目标无法确定时通常不能直接内联，编译器可去虚化”；虚表/vptr 的共享和静态区位置改为主流 ABI 模型，不再当作 C++ 标准保证。
- 静态成员变量改用“静态存储期”，段布局交给实现和链接脚本。

### 操作系统/Linux

- 系统调用入口不再笼统称为“软中断”：区分 `int 0x80`、x86-64 `syscall`、ARM SVC、CPU 异常和 Linux `softirq`。
- 线程章节修正为：普通线程退出通常只结束该线程；POSIX/Linux 中 SIGSEGV 等致命信号和未捕获 C++ 异常通常终止整个进程；`pthread_detach`/`std::thread::detach` 只改变 joinable 和回收方式，不能提供故障隔离。
- 中断上下文是否嵌套由 CPU、中断控制器和屏蔽配置决定；ISR、Linux softirq、工作队列的睡眠和调度边界分别说明。
- `vfork()` 补充“在 exec/_exit 前限制访问父进程状态”的安全边界；`clone()` 补充 flags 和 Linux 任务模型；`ioremap()` 与 DMA 映射明确区分。
- Linux 调度默认策略改为 `SCHED_OTHER/SCHED_NORMAL`，并注明传统 CFS 与 Linux 6.6 起逐步采用的 EEVDF 版本边界；`SCHED_DEADLINE` 不再被写成脱离系统分析的硬实时保证。

### STM32

- `volatile` 改为“硬件寄存器通常需要”，同时明确它不提供原子性、内存序或线程同步。
- NVIC 改为管理 Cortex-M 可屏蔽外部 IRQ；NMI、HardFault、SysTick 等系统异常不再归为“STM32 所有中断源”。
- GPIO 模式答案注明 F1 复用配置与新系列 HAL/LL 枚举不同，必须以具体芯片参考手册和库版本为准。

### FreeRTOS

- 调度和时间片说明增加 `configUSE_PREEMPTION`、`configUSE_TIME_SLICING`、中断和临界区条件；不再承诺 RTOS 自动保证任务 deadline 或固定 O(1) 延迟。
- 临界区改为“屏蔽范围由 port 决定”，不再写成所有中断必然关闭；ISR 使用 `FromISR` API，不能在临界区内调用会阻塞的队列/信号量操作。
- 参数存储说明改为符合 ABI：参数可能在寄存器中，溢出参数和局部状态才进入栈；补充 FreeRTOS V9.0.0 项目基线兼容性提示。

### 网络、驱动和启动

- TCP 可靠性明确为字节流，不保留消息边界；HTTPS 说明 TLS 版本/握手由实现决定；ARP、Socket/WebSocket、阻塞 I/O 的适用层次补充。
- HTTPS 章节区分 TCP/QUIC 承载与 TLS 握手，修正“客户端用公钥加密整个会话密钥”的过时简化；TCP 挥手补充 ACK/FIN 合并时不一定出现四个报文。
- 匿名 pipe 的可用范围改为“通过继承或 FD 传递建立”，`socketpair(SOCK_STREAM)` 与报文型 socket 的边界语义分开说明。
- 通讯协议章节修正 baud 与 bit/s 的关系、I²C 1 Mbit/s/3.4 Mbit/s 模式名称和总线电容边界，并把 STM32 SPI 最高时钟改为系列相关结论。
- `socketpair()`、`read/write` 与 `mmap`、`ioremap` 与 DMA、`init_module`/`module_init`、initrd/initramfs 的 API 和版本差异均已写入对应对比表。
