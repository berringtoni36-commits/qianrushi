# Q002：const 关键字有什么作用？

## 元数据

| 项目 | 内容 |
|---|---|
| 题号 | Q002 |
| 难度 | 中等，6/10 |
| 目标时长 | 240 秒以内 |
| 视觉模板 | code-compare |
| 核心目标 | 让学习者能说清 const 约束的是哪一层，以及它在指针、接口和嵌入式工程中的边界 |

## 核心回答

`const` 的核心是表达只读语义：通过这个名字或这个接口不能修改被约束的数据，编译器可以帮助检查误写。它不是线程同步机制，也不等于数据一定被放进 Flash。

回答时按三层展开：

1. `const int MAX = 100;`：通过 `MAX` 不能修改对象。
2. `const int *p`、`int * const p`、`const int * const p`：看 `const` 在 `*` 的左边还是右边，分别判断内容和指针是否只读。
3. 在嵌入式中用于查表数组、只读函数参数和固定配置；实际存储到 Flash 或其他只读区由工具链、链接脚本和目标平台决定。

## 屏幕脚本

### 0:00-0:18 主动回忆

屏幕先提出“`const` 核心约束了什么？”并给出 6 秒回忆时间。右侧只显示模糊的路线卡，倒计时结束后显示三个入口：数据只读、指针组合、工程边界。

### 0:18-0:40 答案地图

依次显示三张卡：

- 数据只读：`const int MAX = 100;`，通过这个名字不能修改对象。
- 指针组合：`const int *p`，`const` 的位置决定内容或指针的约束范围。
- 接口语义：`void read(const uint8_t *buf)`，告诉调用者函数不会改它的数据。

### 0:40-1:35 指针组合

先让学习者回答“`const int *p` 能改指向吗？能改内容吗？”。随后在同一张代码和对照表中依次强调：

- `const int *p`：指针可以改指向，不能通过 `p` 修改内容。
- `int * const p`：指针不能改指向，可以修改内容。
- `const int * const p`：指向和内容都不能改。

屏幕口诀为：“`const` 在 `*` 左边，内容只读；在 `*` 右边，指针只读。”

### 1:35-1:50 嵌入式用法

先回忆三个场景，再逐一高亮查表数组、函数参数和固定配置。字幕明确说明：只读表可能被工具链放到 Flash/只读区，但这不是 C/C++ 语言本身对物理存储位置的保证。

### 1:50-2:08 边界对比

左侧比较 `const` 与 `#define`：前者有类型检查、作用域和调试信息，后者是预处理阶段的纯文本替换。右侧用 `undefined.cpp` 展示 `const_cast<int *>`：如果对象本来就是 `const`，再写入它属于未定义行为。底部强调：`const` 不负责原子性、锁和线程同步。
