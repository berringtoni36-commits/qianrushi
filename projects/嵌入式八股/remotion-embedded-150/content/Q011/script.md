# Q011：delete 和 delete[] 有什么区别？

## 元数据

- 题号：Q011
- 难度：中等
- 难度分：6/10
- 目标时长：240 秒以内
- 实际设计时长：218 秒（3:38）
- 视觉模板：delete-array-lifecycle
- 核心记忆句：delete 释放单个对象，delete[] 释放对象数组；分配和释放必须保持同一层级。

## 学习目标

看完视频后，能够连续说清：

1. delete 适用于 new 创建的单个对象，delete[] 适用于 new[] 创建的对象数组。
2. 单对象只结束一个对象的生命周期；数组释放要逐个结束元素生命周期。
3. new 与 delete、new[] 与 delete[] 必须配对，混用是未定义行为，不能描述成某个固定故障。
4. delete 不会把指针变量自动改成 nullptr；嵌入式还要考虑资源收尾、碎片、失败和最坏时延。

## 屏幕脚本

### 1. 主动回忆（0:00-0:12）

屏幕问题：delete 和 delete[]，到底差在哪里？

先给 6 秒，要求观看者先回答“单个对象”还是“对象数组”。随后显示路线：单个对象、对象数组、边界与工程。

结论字幕：delete 释放单个对象，delete[] 释放对象数组。

### 2. 答案地图（0:12-0:26）

三个并列模块：

- delete：对应 new T，调用一个析构过程并释放对应存储。
- delete[]：对应 new T[n]，逐个结束数组元素，再释放数组存储。
- 共同原则：分配和释放必须保持同一层级，混用进入未定义行为。

底部流程：分配 → 构造 → 使用 → 析构 → 释放。

### 3. 单个对象（0:26-0:54）

主动回忆问题：new Widget 后，delete 会做哪两件事？

代码轨迹：

1. new Widget(7)：分配存储并调用一次构造函数。
2. use(*p)：对象存活，指针指向有效对象。
3. delete p：先调用析构函数，再释放这一个对象的存储。
4. p = nullptr：主动清空指针句柄。

字幕：delete = 结束 1 个对象 + 释放对应存储。

### 4. 对象数组（0:54-1:28）

主动回忆问题：new Widget[3] 最后要调用几次析构？

用三个固定槽位显示数组元素：

- new Widget[3] 创建 3 个对象，构造次数为 3。
- 数组使用阶段保持 3 个 live objects。
- delete[] 逐个析构，画面显示 items[2] → items[1] → items[0]，最后 live objects 为 0。

字幕：delete[] 不是只释放首地址；它要结束数组中每个元素的生命周期。

### 5. 配对边界（1:28-1:58）

主动回忆问题：new Widget[3] 用 delete 释放，能说只是少析构吗？

依次展示：

- new Widget → delete：正确。
- new Widget[3] → delete[]：正确。
- malloc(bytes) → free：正确。
- new Widget[3] → delete：未定义行为。

字幕：不能承诺“只析构第一个”或“一定马上崩溃”；未定义行为没有可依赖的固定结果。

### 6. 悬空指针（1:58-2:20）

主动回忆问题：delete 之后，指针会自动变成 nullptr 吗？

状态轨迹：

1. delete 后 p 仍保存旧地址，对象存储已经释放，p 是悬空指针。
2. p = nullptr：句柄明确表示没有对象。
3. delete nullptr：不执行释放动作，本身安全。

字幕：释放对象不等于清空指针。

### 7. 嵌入式边界（2:20-2:44）

主动回忆问题：嵌入式里，delete[] 之外还要防什么？

依次显示：

1. 静态分配优先：减少碎片和失败路径。
2. 固定块内存池：容量和最坏时延更容易证明。
3. 资源绑定所有权：析构不完整可能留下外设、DMA 或锁。
4. 失败必须可处理：申请失败、提前返回和所有权转移都要有清晰路径。

字幕：析构次数要对，资源边界也要能证明。

### 8. 面试追问（2:44-3:20）

四个追问，每个先留 4 秒主动回答：

1. new 和 malloc 有什么区别？
   - new 负责对象初始化并返回类型相关指针；malloc 只取得原始存储，不调用构造函数。
2. delete 后指针变什么？
   - 指针仍保留旧地址，已经悬空；应立即置为 nullptr。
3. delete nullptr 安全吗？
   - 安全，但不能替代释放后置空，也不能修复已经发生的悬空访问。
4. 嵌入式一般怎么管理？
   - 静态分配为主，必要时使用固定块内存池或启动阶段一次分配，避免运行期频繁 new/delete。

### 9. 最终复述（3:20-3:38）

三个复述卡，每个先停 3.2 秒：

1. 单个对象：new T 对 delete。
2. 对象数组：new T[n] 对 delete[]，逐个析构元素。
3. 边界：绝不混用，释放后置 nullptr，嵌入式优先静态或固定块。

收束字幕：same level, same pair。
