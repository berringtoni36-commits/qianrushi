# Q003：volatile 关键字在嵌入式开发中有什么作用？

## 元数据

| 项目 | 内容 |
|---|---|
| 题号 | Q003 |
| 难度 | 困难，8/10 |
| 目标时长 | 270 秒以内 |
| 视觉模板 | event-visibility |
| 核心目标 | 让学习者区分“编译器必须保留访问”和“并发修改需要同步保护” |

## 核心回答

`volatile` 告诉编译器：这个对象的值可能被当前代码之外的事件改变，必要的读写访问必须保留下来，不能按普通不变变量缓存或删除。

它常见于三类场景：

1. 中断与主循环共享的标志位。
2. 硬件寄存器映射。
3. DMA 或 RTOS 中其他执行者可能修改的状态。

但 `volatile` 不保证原子性、互斥、内存序或竞态安全，不能替代锁、临界区或原子操作。`const volatile` 可以同时表达“当前代码不写，但外部可能改变”，常见于只读硬件状态寄存器。

### 0:42-1:40 轮询机制

代码为：

```c
volatile uint8_t rx_done = 0;
while (!rx_done) {
    wait_for_interrupt();
}
// ISR: rx_done = 1;
```

先让学习者回答没有 `volatile` 可能发生什么，再按确定性轨迹显示：第一次读到 0、优化器看到的风险、中断路径写入 1、下一次观察读到 1 并退出循环。重点不是声称每个编译器一定会优化成死循环，而是说明普通变量不能表达“外部路径会改变它”的访问边界。
