# Q010：malloc/free 和 new/delete 有什么区别？

## 元数据

- 题号：Q010
- 难度：中等
- 难度分：6/10
- 目标时长：240 秒以内
- 实际设计时长：238 秒（3:58）
- 视觉模板：allocation-lifecycle-compare
- 核心记忆句：`malloc/free` 管原始存储，`new/delete` 管对象生命周期。

## 学习目标

看完视频后，能够在面试中连续说清：

1. `malloc/free` 和 `new/delete` 的抽象层次不同。
2. `new` 表达式不仅取得存储，还会初始化对象；`delete` 会结束对象生命周期后再释放存储。
3. `new` 与 `delete`、`new[]` 与 `delete[]` 必须保持配对，混用是未定义行为。
4. 嵌入式系统中应优先静态分配或固定块内存池；动态分配必须有失败处理、所有权和时延边界。

## 屏幕脚本

### 1. 主动回忆（0:00-0:14）

屏幕问题：`malloc/free` 和 `new/delete`，到底谁负责什么？

先给观看者 6 秒，要求脑中回答“原始内存”还是“对象生命周期”。随后展示路线：原始内存、对象生命周期、配对与嵌入式边界。

结论字幕：malloc 管字节，new 管对象。

### 2. 答案地图（0:14-0:30）

用三个并列模块建立地图：

- `malloc/free`：原始存储，手动计算字节数，不调用构造和析构。
- `new/delete`：对象生命周期，类型相关，负责初始化和销毁。
- 共同边界：接口必须成对，错误混用进入未定义行为。

底部流程：`allocate → initialize → use → destroy → release`。

### 3. 原始存储与对象生命周期（0:30-1:06）

主动回忆问题：`static_cast<Device*>(storage)` 后，构造函数运行了吗？

状态轨迹：

1. `std::malloc(sizeof(Device))` 只取得一块可用字节存储。
2. 把地址解释为 `Device*`，不等于已经构造出 `Device`。
3. placement new 执行构造函数，对象生命周期开始。
4. 先显式析构，再 `std::free` 归还原始存储。

字幕：类型指针不是构造函数；非平凡 C++ 对象不能只靠 `malloc` 伪装出来。

### 4. `new[]` 与 `delete[]`（1:06-1:40）

主动回忆问题：`new Device[3]` 最后应该调用几次析构？

用单对象与数组两条轨迹对照：

- `new Device`：构造 1 个对象，`delete` 结束 1 个对象。
- `new Device[3]`：构造 3 个数组元素，`delete[]` 按数组形式逐个结束对象生命周期。

字幕：`new` 对 `delete`，`new[]` 对 `delete[]`。

### 5. 错误配对（1:40-2:16）

主动回忆问题：`new Device[3]` 用 `delete` 释放，能不能只说“少析构两次”？

依次高亮正确配对：

- `malloc → free`
- `new → delete`
- `new[] → delete[]`

最后显示错误配对：`new[] → delete`、`new → free`。结论必须使用标准术语“未定义行为”，不能把结果简化为某一种固定的析构次数。

补充：释放后的指针仍是旧地址，属于悬空指针；释放后立即置为 `nullptr`。

### 6. 嵌入式边界（2:16-2:46）

主动回忆问题：嵌入式里动态分配最该先防什么？

依次展示：

1. 静态分配优先：从源头减少碎片和失败路径。
2. 启动阶段一次分配：如果必须动态申请，避免运行期反复申请释放。
3. 固定块内存池：大小固定时更容易控制上限和最坏时延。
4. 失败与所有权：检查 `nullptr` / `std::bad_alloc`，确保每条路径能释放。

结论：RAII 能减少泄漏，但不能自动消除碎片和不确定分配时延。

### 7. 面试追问（2:46-3:34）

四个追问，每个 5 秒主动回答后显示标准说法：

1. `new` 的底层一定直接调用 `malloc` 吗？
   - 不一定。通常先调用匹配的 `operator new`，再完成对象初始化；分配器可以自定义。
2. `malloc` 失败和 `new` 失败一样吗？
   - `malloc` 通常返回 `nullptr`；普通 `new` 默认抛 `std::bad_alloc`，`new (std::nothrow)` 返回 `nullptr`。
3. `delete` 之后指针会自动变 `nullptr` 吗？
   - 不会。它变成悬空指针，应立即置为 `nullptr`。
4. 嵌入式为什么不建议频繁 `new/delete`？
   - RAM 有限，通用堆会带来碎片、泄漏和难以证明的分配时延。

### 8. 最终复述（3:34-3:58）

四个复述卡，每个 3.8 秒后显示答案：

1. `malloc/free` 管原始存储，不负责构造析构。
2. `new/delete` 管对象生命周期，先初始化，后析构再释放。
3. `new` 对 `delete`，`new[]` 对 `delete[]`，混用是未定义行为。
4. 嵌入式静态分配优先，动态分配要有上限、失败处理和清晰所有权。

收束字幕：`bytes ≠ object`。
