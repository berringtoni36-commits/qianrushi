# Q012：什么是内存泄漏？如何避免？

## 元数据

- 题号：Q012
- 难度：中等
- 难度分：6/10
- 目标时长：240 秒以内
- 实际设计时长：214 秒（3:34）
- 视觉模板：memory-leak-ownership
- 核心记忆句：内存申请成功后所有权丢失，块仍占着内存但程序已经找不到并释放它，就形成内存泄漏。

## 学习目标

看完视频后，能够连续说清：

1. 内存泄漏不是申请失败，而是申请成功后没有释放，且内存块变得不可达。
2. 常见原因包括提前 return、错误分支遗漏、容器只增不删和 shared_ptr 循环引用。
3. 防守手段包括 RAII、每条路径释放或转移所有权，以及静态分配和固定块内存池。
4. Linux 可以借助 Valgrind / ASan，FreeRTOS 可以记录剩余堆趋势，但工具不能替代所有权设计。

## 屏幕脚本

### 1. 主动回忆（0:00-0:12）

屏幕问题：内存申请成功后，什么情况会让 RAM 回不来？

先给 6 秒，要求观看者先回答“申请失败”还是“所有权断了”。随后显示路线：先看定义，再看原因，最后看防守。

结论字幕：内存还在，但程序已经找不到它。

### 2. 答案地图（0:12-0:26）

三个并列模块：

- 申请：malloc / new 得到一块内存。
- 断链：owner lost，没有指针或所有者能到达它。
- 累积：free heap 下降，长期运行可能 OOM 或系统不可用。

底部流程：allocate → own → release / or leak。

### 3. 泄漏原理（0:26-0:52）

主动回忆问题：申请成功后，哪一条路径最可能造成泄漏？

代码轨迹：

1. new Packet 创建块，p 是当前 owner。
2. read 失败后提前 return，delete 没有执行。
3. Packet 仍在堆上，但 p 已随函数退出而消失。
4. 轮询重复发生，泄漏块累积，free heap 逐步下降。

字幕：live block + owner lost = memory leak。

### 4. 路径检查（0:52-1:24）

主动回忆问题：if (err) return 之前，buf 应该怎么办？

同一段代码分叉展示：

- 坏的错误分支：buf 已申请，直接 return -2，free 被跳过。
- 修正错误分支：先 free(buf)，再返回错误。
- 正常分支：use(buf) 后 free(buf)，所有路径收口。

字幕：谁申请，谁释放；每条路径都要闭环。

### 5. 循环引用（1:24-1:50）

主动回忆问题：shared_ptr 互相引用，外部 reset 后会自动释放吗？

状态轨迹：

1. 创建 Node A、Node B，各自有 1 个 strong ref。
2. A.peer 持有 B，B.peer 持有 A，引用计数变成 2。
3. 外部 a、b reset 后，环内各剩 1 个 strong ref，析构不会发生。
4. 把反向关系改成 weak_ptr，环断开，计数可以归零。

字幕：RAII 不是引用计数的万能解。

### 6. 避免泄漏（1:50-2:20）

主动回忆问题：怎样让忘记释放变得更难发生？

三个策略：

1. RAII：make_unique / unique_ptr，让对象离开作用域自动销毁。
2. 成对释放：每个申请点有 owner，每条分支都清理或转移所有权。
3. 静态分配：嵌入式优先 static 或 fixed pool，从根源减少动态泄漏和碎片。

字幕：让所有权可见，让释放路径自动化。

### 7. 排查工具（2:20-2:40）

主动回忆问题：只看一次 free heap 快照，能证明没有泄漏吗？

依次显示：

- Linux：Valgrind / ASan，查看未释放块、调用栈和分配位置。
- FreeRTOS：定时记录 xPortGetFreeHeapSize()，看长期下降趋势。
- 通用：代码审查、申请点日志、失败钩子和所有权记录。

字幕：看趋势，留证据，再回到所有权路径。

### 8. 面试追问（2:40-3:16）

四个追问，每个先留 4 秒主动回答：

1. shared_ptr 循环引用怎么办？
   - 用 weak_ptr 表示不拥有对象的观察关系，打破引用环。
2. Valgrind 怎么查泄漏？
   - 使用 leak-check 选项观察未释放块、调用栈和分配位置，再回到代码修复。
3. FreeRTOS 怎么监控堆？
   - 定时记录 xPortGetFreeHeapSize()，观察长期趋势，并结合分配失败和申请点日志。
4. 嵌入式为什么更怕泄漏？
   - 设备长期运行，泄漏会累积，最终造成分配失败、任务异常或系统不可用。

### 9. 最终复述（3:16-3:34）

四个复述卡，每个先停 2.5 秒：

1. 定义：申请成功，所有权丢失，块不可达。
2. 原因：return、错误分支、容器增长、循环引用。
3. 防守：RAII、路径闭环、静态或固定块。
4. 排查：趋势、日志、工具和申请点。

收束字幕：reachable → releasable。
