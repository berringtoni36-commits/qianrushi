# Q004：extern 关键字有什么作用？

## 元数据

| 项目 | 内容 |
|---|---|
| 题号 | Q004 |
| 难度 | 中等，6/10 |
| 目标时长 | 240 秒以内 |

| 核心目标 | 让学习者分清声明、定义、编译、链接和 C++ 链接约定 |

## 核心回答

`extern` 用于声明某个变量或函数定义在别的文件中，是多文件工程共享符号的手段。它本身通常是声明，不负责凭空创建变量，也不替代模块接口设计。

回答时按四层展开：

1. `int g_count = 0;` 是定义，会创建实体并分配空间；`extern int g_count;` 是声明，只告诉编译器符号存在。
2. 一个 `.c` 文件提供定义，头文件提供 `extern` 声明，其他 `.c` 文件包含头文件后使用。
3. 编译器先分别生成目标文件，链接器再把多个目标文件中的同名符号匹配起来。
4. C++ 与 C 混合接口需要考虑 `extern "C"`；全局变量过多还会增加模块耦合。

## 屏幕脚本

### 0:00-0:18 主动回忆

### 0:18-0:40 答案地图

三张卡依次显示：定义、变量声明、函数声明。定义卡强调分配空间，变量声明卡强调不分配空间，函数声明卡强调函数声明通常省略 `extern`。

### 0:40-1:35 多文件链路

按四个状态展示：

- `sensor.c`：`int g_temp_value = 0;`，定义并分配空间。
- `sensor.h`：`extern int g_temp_value;`，把名字提供给使用者。
- `main.c`：`g_temp_value = 25;`，编译通过，等待链接器匹配。
- 链接器：合并 `sensor.o` 和 `main.o`，解析到同一个 `g_temp_value`。

屏幕同时保留“声明可以多次，定义要由工程提供合适的一次”的口诀。

### 1:35-2:07 链接错误

先让学习者判断三种错误在哪一步暴露，再对照展示：头文件直接定义造成重复定义、只声明没有定义造成未定义符号、两个源文件都定义造成重复定义。画面明确区分编译器和链接器的职责。

### 2:07-2:32 C++ 边界

说明 C++ 普通函数可能发生 name mangling，`extern "C"` 让 C++ 按 C 的链接约定导出接口。随后说明跨文件可见不等于应该到处暴露可写全局变量，接口封装仍然重要。
