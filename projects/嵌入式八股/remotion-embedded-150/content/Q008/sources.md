# Q008 来源与事实核对

## 原始题目

来源：`2. 嵌入式高频八股150题/01 C-C++基础（1-25题）.md`，第 8 题“堆和栈有什么区别？”。原题重点是自动/手动管理、生命周期、空间大小、碎片和嵌入式风险。

## 核对结论

- C/C++ 抽象机器区分自动存储期、静态存储期和动态存储期；标准不强制所有实现使用名为“栈”和“堆”的具体内存区域。
- 常见实现中，函数调用帧和自动存储期局部对象通常放在调用栈，由函数进入/返回的序列自动建立和回收；这是本视频的栈示意模型。
- `malloc/free` 和 `new/delete` 对应动态存储管理。动态对象的生存期不会因为某个调用函数返回而自动结束，必须沿正确的 owner/释放路径回收。
- 栈的 LIFO 回收通常带来较低的管理开销和较好的时延可预测性，但栈空间有限；大局部数组、深递归、复杂调用链和 FreeRTOS 多任务都可能消耗栈空间。
- 堆的块大小和生存期更灵活，但分配器可能产生碎片、分配失败和不确定时延；忘记释放会形成泄漏。

## 原题表述修正

- “栈一定向低地址增长、堆一定向高地址增长”改为“许多 Cortex-M/桌面布局图如此示意，实际方向由平台和运行时决定”。
- “栈速度快、堆速度慢”改为“栈分配通常更简单、更容易做上限分析；堆分配需要分配器处理空闲块，时延和失败行为取决于实现”。
- “Linux 默认栈 8MB”不作为通用答案。栈大小由系统、线程属性、链接脚本或 RTOS 配置决定；面试回答应先说平台配置，再说如何用水位监控验证。
- “堆地址就是虚拟地址”只适用于 Linux 用户态等有虚拟内存的环境。裸机 MCU 通常没有 MMU，地址直接落在芯片的内存映射中；不能把 Linux 和 MCU 混成一个结论。
- “栈没有碎片”限定为通常的调用帧 LIFO 回收，不把它写成所有自定义栈分配器的绝对保证。

## 参考方向

- ISO/IEC 9899（C 标准）：storage duration、`malloc`/`free` 和对象生命周期。
- ISO/IEC 14882（C++ 标准）：automatic/dynamic storage duration、`new`/`delete`。
- ARM Cortex-M ABI、链接脚本和启动文件：栈边界与内存布局由目标工程配置。
- FreeRTOS 官方 API：任务栈配置、`uxTaskGetStackHighWaterMark` 和栈溢出检测钩子。
