# 平衡车项目分享：简历怎么才不烂大街（上）

作者：西瓜日记


![[小红书（RedNote）/。。。。。。。/媒体（Media）/69c3ec9e000000001f007141/image-1.jpg]]

bg：煮包本硕普通9，目前研0在读，由于是非科班，没有导师的项目以及企业级项目
	
平衡车项目是每个入门的人都做过的项目，但是我的确靠这个项目拿到了大厂offer。我做的是在gitee上可以找到的项目，uu们可以自己去看源码。这里主要讲一下我的经验和总结要点。
	
项目名称：基于STM32与freertos的两轮自平衡小车控制系统设计与复现
	
技术栈：C语言，STM32基本外设开发，HAL库＋CubeMX工程配置，Freertos任务管理与调度，Usart，I2C，SPI等通信协议，PID控制（这些技术栈至少都要会了再开始项目，或者在练中学，我的PID的学习就是靠着这个项目边看源码边学会的）
	
项目介绍：这个平衡车项目是一个基于STM32F103C8T6 和 FreeRTOS 的闭环控制系统。主控是 STM32，底层接了 IMU、磁力计、编码器和电池检测模块。系统先周期性采集传感器数据，其中 IMU 提供加速度和角速度，编码器提供速度反馈。原始数据进入滤波和姿态解算模块，得到 Pitch、Roll、Yaw，其中 Pitch 是平衡控制的核心量。然后控制层采用三环结构：直立环负责防倒，速度环负责前后运动趋势，转向环负责左右轮差速修正。最终控制量映射成左右电机 PWM 输出。整个过程在 FreeRTOS 下按任务划分运行，同时通过串口和上位机进行波形观察和调参。我在准备这个项目时，重点把驱动数据流、姿态解算链路和三环控制逻辑都单独拆开梳理过。
	
⬆️以上项目介绍是从整体架构解释项目，从上层对项目有一个把控
	
核心链路：采集 → 滤波（均值滤波、中值） → 姿态解算（互补） → 三环控制 → PWM 驱动电机
	
1⃣项目最基本的把源码都看懂，最好是手敲一遍（一定每一行代码都能看懂）
	
2️⃣小车必须要带freertos (别的实时操作系统也可以)，这是区分大部分同质项目的关键，带上说明就有了对任务优先级以及实时性的意识。
	
3️⃣自己能够讲通“现象-排查-修改-验证”的闭环！因为没有项目写完代码跑出来就是完美的，必须有对应的不完美现象并且加以思考后改正：车身直立不稳定，看 Pitch 反馈是否稳定，因为直立环最依赖这个量。检查 IMU 原始数据和姿态角输出有没有明显噪声或毛刺，再看滤波是否不足。如果姿态角本身正常，再去看直立环 PID 参数是不是过大，尤其是 P 过大会引起高频振荡。之后再看控制周期是否稳定，以及 PWM 输出有没有频繁跳变。最终发现是p的参数设定过大。
