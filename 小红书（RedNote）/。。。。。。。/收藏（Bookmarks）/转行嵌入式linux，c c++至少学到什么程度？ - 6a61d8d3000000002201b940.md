# 转行嵌入式linux，c/c++至少学到什么程度？

## 正文

![[小红书（RedNote）/。。。。。。。/媒体（Media）/6a61d8d3000000002201b940/image-1.jpg|520]]

粉丝投稿：想学嵌入式 Linux，但不知道 C/C++ 具体要学到什么程度才能开始做项目？我个人认为，不要等 C/C++ 全部吃透再动手。在 AI 浪潮下，具体代码 AI 基本能写，我们更多是去 review 它写得对不对、好不好。所以 C/C++ 学到能看懂、能理解就够往下走了，不用逼自己一行行手敲。下边说一下这两门语言进 Linux 之前至少要理解到哪，以下为个人观点，仅供参考。

先说 C 语言。C 是嵌入式 Linux 的主力，不管走应用还是走驱动几乎都靠它吃饭，所以我个人建议，C 在语法层面不能留盲区，每一块都要能看懂、能讲清。数据类型、运算符、流程控制、函数这些底子要理解到位。往上走，指针是重中之重，一级指针、二级指针、指针和数组、指针与函数、函数指针加回调，这些你得读得懂，也能看出 AI 写得对不对。内存这块，malloc/free、内存分区、栈和堆的区别都要清楚，Linux 上内存的坑特别多。再往下，结构体、共用体、枚举、位操作、预处理和宏、typedef，这些代码里满地都是。工程上的编译链接过程、GCC 常用参数、Makefile 也要能看明白。最后是常用数据结构，链表、队列、栈的原理要理解，Linux 内核和一堆开源代码里全是链表。

C++特性非常之多 ，前期不需要像 C 那样要求样样精通，重点压在面向对象上。封装、继承、多态这三大特性要真理解，尤其是多态，虚函数怎么用、虚函数表大概怎么回事，这既是面试高频，平时看代码也躲不开。类和对象、构造析构、运算符重载、引用、const、命名空间这些要能看懂。STL 也要会看，常见的 vector、list、map、string 知道怎么用、用在哪，智能指针和 RAII 的思想要理解。至于模板元编程、STL 源码，前期暂时不管，后边用到了再深入。

多补充一点，C++ 要不要重点学，需要看方向。走 Linux 驱动基本是纯 C，C++ 会点基础就够；走 Linux 应用、尤其搞 QT，那面向对象和 STL 就得多花功夫。先把方向定了，再决定投入多少，别一上来盲目啃。完成上述基础要求后，就直接上手做一个 Linux 项目，让 AI 帮你把代码搭起来，你负责读懂每一行在做什么、为什么这么写、哪里可能出问题。遇到看不懂的，带着问题回去补，补一个懂一个。项目能跑通、你也能讲清楚，就说明 C/C++ 够用了。
